## 1. BW-12「流水」的订单详情：与结账单同一个部件

- **做法**：「流水 → 订单查询」点开一张结账单，用结账完成页、「结账记录」、桌台结账完成页的同一个部件 `CheckoutReceipt`（8.1.17 从 `CheckoutDialog.tsx` 搬到 `src/client/features/frontdesk/CheckoutReceipt.tsx` 单放，「流水」只引这一个文件）：
  - 抬头：单号、时间、收银（写明「收银 某某」）、已反结账、补录；
  - 每张手牌（桌台）一行：客人、门票与档、在店多久、金额；带着逐行明细的（「流水」取的是打印的那一份）在每张手牌下面列结账那一刻的明细——名称、被签赠 / 券 / 会员折扣抵到的标「赠」「券」「折」（与 80mm 小票同一个标法，颜色加字）、所属部门、数量 × 单价、技师、金额、摊到这一行的优惠；
  - 「优惠与赠送」一栏：每笔的类别、名称、说明与经办人（发放、授权、渠道），「共优惠」；
  - 收款：只列真收的钱与预付抵扣，储值写会员、消费单号、本金 / 赠金与扣前扣后的余额；合计。
  - 「流水」自己的在下面：状态（已结账 / 有退款 / 已反结账）、营业日、备注、这张单的退款单、打印结账单。
- **接口**：「流水」照旧取 `GET /api/ledger/orders/checkouts/:id`（权限照旧：「查看当日流水与日结」，不是今天的单另要「查看历史营业日」）。它本来就带打印的那一份（`doc`：结账单详情 + 每张手牌结账那一刻的明细，每行带 `perks` 标记 + 储值余额），这次每一行多带 `category`（所属部门）与 `discount`（摊到这一行的优惠，分）——按明细编号对上原来逐行算的那一份（`checkoutOrderDetail`，只读）。打印接口不带这两项。
- **补录到更早时刻的单**（按项目快照显示，`source = 'items'`）：按时刻取的明细与快照对不上，结账单部件里不列逐行（标不出抵到哪一行），下面照旧按项目快照列一张表（所属部门、数量、单价、金额、优惠）。
- 结账完成页、「结账记录」拿到的结账单详情没有逐行明细，部件照旧只列手牌一行，与以前一样。

## 2. BW-4 退菜按出品口：康美部自己退菜

- **新权限**（`src/shared/permissions.ts`，后台「岗位权限 → 餐饮：按出品口退菜」）：「退菜：餐厅的菜」「退菜：水吧的菜」「退菜：果吧的菜」（`dining.voidRestaurant` / `dining.voidWater` / `dining.voidFruit`）。
  - 原来能退菜的是有「前台挂账」（`frontdesk.operate`）的岗位（手牌的退菜接口只要它，桌台的退菜接口还要「餐饮点单」），默认是店主、店总、值班经理、店员——这四个岗位三项都有；
  - 康美部（职责 `kangmei`）默认有水吧、果吧两项（没有餐厅，与下单一样）。
- **核对**：退一条明细时逐行核对（`authorizeLineVoid` 开头的 `assertLineVoidPermission`，`src/server/modules/dining-v8117.ts`）：
  - 餐饮的菜要这道菜所在出品口的「退菜」权限。出品口与下单核对同一个判断（`diningSlotOf`：按菜现在的点单分类，后台没设的按默认归），没有的拒绝（403 `OUTLET_VOID_FORBIDDEN`，写明是哪一处、哪道菜）；
  - 别的明细（洗浴、技师、手动金额……）照旧要「前台挂账」；
  - 之后原因、时限、授权的规矩照旧：小额直接退（能退这一处的菜的就能直接退，原来是「前台挂账」）、有更正权限的直接退、当场授权、本人 15 分钟内。
- **接口**：手牌的退菜接口 `POST /api/frontdesk/lines/:id/void` 有「前台挂账」或任一项「退菜：某出品口」就进得来（康美部没有「前台挂账」），进来以后逐行核对；桌台的 `POST /api/dining/tables/lines/:id/void` 照旧要「餐饮点单」+「前台挂账」，再逐行核对出品口。退大额的菜申请当场授权（`POST /api/auth/authorize`，用途 `line_void`）也按这道菜的出品口核对申请人（原来是「前台挂账」），康美部能为水吧、果吧的菜申请。
- **页面**：点单页「还没上的菜」、桌台详情里，只在有这道菜所在出品口退菜权限时显示「改」「退菜」（菜单里没有的菜照样显示，服务端核对）；有不能退的菜时写一句「你的岗位只能退水吧、果吧的菜，别的退菜、改单请找有权限的同事」。
- **与菜品那一份的接头**：退主菜连带加料（BW-8）是先把要退的几行列出来再逐行走 `authorizeLineVoid`，出品口的核对在逐行的那一步，两边各改各的。
- **迁移 199**：后台「岗位权限」里给哪个岗位加了「前台挂账」，也给它加上这三项；去掉了「前台挂账」的也去掉这三项（不然原来不能退菜的岗位升级以后反而能退）；再跑一次不重复加。
