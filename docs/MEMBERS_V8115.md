# 8.1.15 追加 · 会员中心：建档先选卡类型、表单字段补全

《浴族系统需求汇总》会员中心的两条（会员 1、会员 2），对照与分块见 `docs/YUBA_V8115.md` 第 3 节 F。迁移 `192_member_cards_v8115.sql`。这一版自己定的默认做法都标「待确认」，汇总在第 8 节。

## 1. 做了什么

- **新建会员两步**：先选卡类型（电子卡 / 实体卡 / 匿名卡，每种一行说明），再填表；选的类型固定在表单顶上，「上一步」回去改，填过的内容留着。
- **三种卡**
  - 电子卡：凭手机号认人，不发实体卡。手机号必填、全公司不重复。
  - 实体卡：手机号必填；刷卡或手输卡号；同一笔里发卡、按后台设的金额收押金。之后在会员详情「会员卡」里挂失、补卡、退卡。
  - 匿名卡：手机号可以不留；姓名页面预填「匿名会员」（可以改）；可以配一张实体卡（同样收押金），刷卡认人。
- **表单字段**：固定必填姓名、手机号（匿名卡除外）、卡类型、会员等级；选填性别、生日、来源渠道、推荐人（找一位已有的会员）、偏好项目、会员标签、备注。
- **会员等级**：默认「按规则自动」（从 L0 起，充值升档）；有「手动调整会员档阶」权限的人可以当场指定档阶（要写原因），走的是手动调整那一条路，等级卡的记录里看得到。
- **字段显隐按门店配**：后台「会员体系 → 渠道与标签 → 建档表单」里每个选填项设「显示 / 不显示」「必填 / 选填」，同一张卡片里设实体卡押金；第二家店单独设的存 `store_settings`。服务端按这份设置核对（页面看到的不算数）。
- **手机号**：照旧全公司不重复；改手机号照旧要写原因、要「改会员手机号」权限或当场授权。匿名卡补登手机号也算改号。

## 2. 数据

迁移 `192`（只加列、加表、放宽约束）：

- `members.card_type`：`ecard` / `physical` / `anonymous`。现有会员都是电子卡；名下有在用或挂失的实体卡的记成实体卡。
- `members.phone` 可以为空，但只有匿名卡可以（`members_phone_card_type_check`）；唯一约束与格式约束不变。
- `members.referrer_member_id`（推荐人，不能是自己）、`members.preferred_items`（文字数组，最多 10 个、每个最多 12 个字）。
- `members.client_key` / `request_hash`：建档的操作编号。匿名卡没有手机号去重、实体卡同时收钱，都靠它不重复登记。
- `member_card_deposits`：押金台账，只追加。一行是一笔收或退：会员、卡、方式、金额、备注 / 原因、班次、营业日、经办人、门店、操作编号。
- `member_card_returns`：退卡记录，只追加。退回哪张卡、退了多少押金。
- `member_cards.status` 多一种「已退卡」（`returned`）；卡号可以再发。
- `member_phone_changes.old_phone` 可以为空（匿名卡补登手机号时原来没有号）。
- 操作编号与「确认作废」多两种业务类型：`member_create`（建档）、`member_card_return`（退卡退押金），在当时的约束上追加。
- 设置 `member_form_rules`（按门店）：`{ cardDeposit, fields: { gender | birthday | channel | referrer | preferredItems | tags | note: { show, required } } }`。

卡类型跟着卡走：电子卡发了实体卡以后是实体卡；实体卡退了卡记回电子卡；匿名卡一直是匿名卡，补登了手机号以后可以在编辑里「转成实名」（转成电子卡，名下有在用的卡的转成实体卡）。

## 3. 押金的钱怎么记

照客房押金（`room_deposits`）的做法：

- **押金是负债**：不进会员储值（钱包一分不动）、不算营业额。
- **记班次**：收、退都是收款，记到经办人当班的班次；现金计入交班的应有现金（收 − 退），交班表、日结、交班小票、日结小票、对账包各有一段「会员卡押金」。
- **一位会员押一份**：发卡时名下没有押金的按后台设的金额收（默认 20 元，0 = 不收）；换下在用的卡（卡坏了当场换）不另收；补卡沿用原来的押金。
- **挂失不退**。之后补卡（押金照旧押着），或者不补了、在「退卡」里把押金退掉。
- **退卡全额退**：在用的卡记「已退卡」，押着的押金全额退——现金从经办人当班的钱箱退，扫码、银行卡登记商户后台的退款单号。这一版没有罚没、没有工本费。
- **页面看到的金额不算数**：页面带上它看到的押金，与服务端此刻该收（该退）的不一致就整笔拒绝，不悄悄多收少收。
- **合并会员**：来源会员还押着押金的不能合并，先退卡退押金。
- 自检（`check`）多一项：每位会员押着的押金不为负、每笔收的押金都有对应的卡、退的都有退卡记录、押金不在储值流水里。

加锁顺序在 `docs/LOCKING.md` 第 2 节「会员建档与会员卡押金（8.1.15）」。

## 4. 接口

- `POST /api/members`：多了 `clientKey`、`cardType`、`grade`（手动指定）、`card`（卡号与押金）、`referrerMemberId`、`preferredItems`。原来只带姓名、手机号的调用照旧（电子卡）。原样重提返回 200 与原来那位，新建返回 201。
- `PUT /api/members/:id`：多了 `referrerMemberId`、`preferredItems`、`convertToNamed`（匿名卡转实名）。
- `POST /api/members/:id/cards`：多了 `deposit`（该收押金的时候要带）。
- `POST /api/members/:id/cards/return`：退卡退押金。
- `GET /api/members/:id/card-deposits`：押着多少、押金台账。
- `PUT /api/settings` 的 `memberForm`：建档表单与押金（`settings.manage`）。

## 5. 手机号可以为空以后

- 页面、打印写「未留手机号」；导出里留空；手机号后四位没有的写「—」。
- 查找照旧按姓名、会员号、手机号片段、实体卡号；没留手机号的不会被手机号查到，也不会排到前面。
- 批量发券的短信：没留手机号的不发短信，券与会员端提醒照发。
- 小程序绑定按手机号找会员，没留手机号的匿名卡绑不了（小程序线的目录没有改）。
- 管家部自己的服务档案里手机号是文字、空着算没留，系统会员没留手机号的按空着带过去。

## 6. 权限

没有加新权限：建档 `member.write`；建档同时发卡、之后的发卡 / 挂失 / 补卡 / 退卡与收退押金 `member.card`；手动指定等级 `member.adjust`；改建档表单与押金 `settings.manage`。

## 7. 没做的

- 手动指定等级的「当场授权」（`docs/YUBA_V8115.md` 写了「有调整等级的权限或当场授权」）：这一版只认权限，没有权限的人只能选「按规则自动」。
- 押金的罚没、工本费。
- 管家部自己的「新建会员」没有动。
