# 8.1.15 追加 · 会员中心：建档先选卡类型、表单字段补全

《浴族系统需求汇总》会员中心的两条（会员 1、会员 2），对照与分块见 `docs/YUZU_REQ_V8115.md` 第 3 节 F。迁移 `192_member_cards_v8115.sql`。这一版自己定的默认做法汇总在第 8 节，都待店主确认。

## 1. 做了什么

- **新建会员两步**：先选卡类型（电子卡 / 实体卡 / 匿名卡，每种一行说明），再填表；选的类型固定在表单顶上，「上一步」回去改，填过的内容留着。
- **三种卡**
  - 电子卡：凭手机号认人，不发实体卡。手机号必填、全公司不重复。
  - 实体卡：手机号必填；刷卡或手输卡号；同一笔里发卡、按后台设的金额收押金。之后在会员详情「会员卡」里挂失、补卡、退卡。
  - 匿名卡：手机号可以不留；姓名页面预填「匿名会员」（可以改）；可以配一张实体卡（同样收押金），刷卡认人。
- **表单字段**：固定必填姓名、手机号（匿名卡除外）、卡类型、会员等级；选填性别、生日、来源渠道、推荐人（找一位已有的会员）、偏好项目、会员标签、备注。
- **会员等级**：默认「按规则自动」（从 L0 起，充值升档）；有「手动调整会员档阶」权限的人可以当场指定档阶（要写原因），走的是手动调整那一条路，等级卡的记录里看得到是谁、为什么。
- **字段显隐按门店配**：后台「会员体系 → 渠道与标签 → 建档表单」里每个选填项设「显示 / 不显示」「必填 / 选填」，同一张卡片里设实体卡押金；第二家店单独设的存 `store_settings`，只管它自己。服务端按这份设置核对（页面看到的不算数）。
- **手机号**：照旧全公司不重复；改手机号照旧要写原因、要「改会员手机号」权限或当场授权。匿名卡补登手机号也算改号；登记以后不能清空。
- **建档带操作编号**：没收到结果时记录留在本机，会员列表上方查回、按原内容重新提交（同一编号只建一位、只收一次押金）或确认作废。

## 2. 数据

迁移 `192`（只加列、加表、放宽约束）：

- `members.card_type`：`ecard` / `physical` / `anonymous`。现有会员都是电子卡；名下有在用或挂失的实体卡的记成实体卡（升级前发的卡没有押金）。
- `members.phone` 可以为空，但只有匿名卡可以（`members_phone_card_type_check`）；唯一约束与格式约束不变。
- `members.referrer_member_id`（推荐人，不能是自己）、`members.preferred_items`（文字数组，最多 10 个、每个最多 12 个字）。
- `members.client_key` / `request_hash`：建档的操作编号。匿名卡没有手机号去重、实体卡同时收钱，都靠它不重复登记；电子卡原来的调用可以不带（手机号不重复兜底）。
- `member_card_deposits`：押金台账，只追加。一行是一笔收或退：单号（收 `KY`、退 `KT`）、会员、卡、方式、金额、备注 / 原因、班次、营业日、经办人、门店、操作编号。
- `member_card_returns`：退卡记录，只追加。退回哪张卡、退了多少押金。
- `member_cards.status` 多一种「已退卡」（`returned`）；卡号可以再发。
- `member_phone_changes.old_phone` 可以为空（匿名卡补登手机号时原来没有号）。
- 操作编号与「确认作废」多两种业务类型：`member_create`（建档）、`member_card_return`（退卡退押金），在当时的约束上追加。
- 设置 `member_form_rules`（按门店）：`{ cardDeposit, fields: { gender | birthday | channel | referrer | preferredItems | tags | note: { show, required } } }`。

卡类型跟着卡走：电子卡发了实体卡以后是实体卡；实体卡退了卡记回电子卡；匿名卡一直是匿名卡，留了手机号以后可以在编辑里勾「转成实名的卡」（记成电子卡，名下有在用的卡的记成实体卡）。

## 3. 押金的钱怎么记

照客房押金（`room_deposits`）的做法：

- **押金是负债**：不进会员储值（钱包一分不动、没有储值流水）、不算营业额。
- **记班次**：收、退都是收款，记到经办人当班的班次——入账前先对班次加共享锁，收款开始时所在的班次已经交班就整笔拒绝（`SHIFT_CLOSED`），要先开班的门店没开班的拒绝（`SHIFT_REQUIRED`）。现金计入交班的应有现金（收 − 退）。
- **哪里看得到**：交班页与交班表打印、交班小票；日结页与日结打印、日结小票、日结导出；每日对账包的「05-交班」押金现金一列（客房押金与会员卡押金合在这一列）、「14-会员卡押金」逐笔明细与汇总、「00-说明」里一行。都单列成「会员卡押金」，与客房押金分开。
- **一位会员押一份**：发卡时名下没有押金的按后台设的金额收（默认 20 元，0 = 不收，上限 1,000 元）；换下在用的卡（卡坏了当场换）不另收；补卡沿用原来的押金。
- **挂失不退**。之后补卡（押金照旧押着），或者不补了、在「退押金」里把押金退掉。
- **退卡全额退**：在用的卡记「已退卡」，押着的押金全额退——现金从经办人当班的钱箱退，扫码、银行卡、其他方式要登记退款单号或写明怎么退的。这一版没有罚没、没有工本费。
- **页面看到的金额不算数**：页面带上它看到的押金，与服务端此刻该收（该退）的不一致就整笔拒绝（`CARD_DEPOSIT_REQUIRED` / `CARD_DEPOSIT_CHANGED`），不悄悄多收少收。
- **什么都没建的情况**：实体卡建档时手机号重复、卡号已发给别人或已挂失、押金对不上、没开班——整笔回滚，会员、卡、押金都没有。
- **合并会员**：来源会员还押着押金的不能合并，先退卡退押金。
- 自检（`check`）多一项「会员卡押金」：每位会员押着的押金不为负、每笔收的押金都有对应的卡、退的都有退卡记录、押金不在储值流水里。

加锁顺序在 `docs/LOCKING.md` 第 2 节「会员建档与会员卡押金（8.1.15）」。

## 4. 接口

- `POST /api/members`：多了 `clientKey`、`cardType`、`grade`（手动指定：档级、阶位、原因）、`card`（卡号与押金）、`referrerMemberId`、`preferredItems`。原来只带姓名、手机号的调用照旧（电子卡）。原样重提返回 200 与原来那位，新建返回 201。
- `PUT /api/members/:id`：多了 `referrerMemberId`、`preferredItems`、`convertToNamed`（匿名卡转实名）。
- `POST /api/members/:id/cards`：多了 `deposit`（该收押金的时候要带）。
- `POST /api/members/:id/cards/return`：退卡退押金。
- `GET /api/members/:id/card-deposits`：押着多少、押金台账。
- `PUT /api/settings` 的 `memberForm`：建档表单与押金（`settings.manage`）；会话里的 `rules.memberForm` 是页面按它显示的那一份。

## 5. 手机号可以为空以后

- 页面、打印写「未留手机号」；导出（流水、按标签筛的会员、到期提醒名单、余额变动）里留空；手机号后四位没有的不写尾号。
- 查找照旧按姓名、会员号、手机号片段、实体卡号；没留手机号的不会被手机号查到，也不会排到前面。
- 批量发券的短信：没留手机号的不发短信，券与会员端提醒照发。
- 小程序绑定按手机号找会员，没留手机号的匿名卡绑不了（小程序线的目录没有改）。
- 管家部自己的服务档案里手机号是文字、空着算没留，系统会员没留手机号的按空着带过去（那边照旧要「手机号和收银卡号至少填一项」）。
- 期初导入、邀请体验当场建档、旧系统流水导入都按手机号建档或对会员，照旧只有电子卡；不按后台的建档表单核对必填。

## 6. 权限

没有加新权限：建档 `member.write`；建档同时发卡、之后的发卡 / 挂失 / 补卡 / 退卡与收退押金 `member.card`；手动指定等级 `member.adjust`；改建档表单与押金 `settings.manage`。「确认作废」按原业务的权限（建档 `member.write`、退卡 `member.card`）。

## 7. 没做的

- 手动指定等级的「当场授权」（`docs/YUZU_REQ_V8115.md` 写了「有调整等级的权限或当场授权」）：这一版只认权限，没有权限的人只能选「按规则自动」。
- 押金的罚没、工本费；押金收了以后后台改金额不追补、不退差。
- 管家部自己的「新建会员」没有动。
- 偏好项目是手填的短文字，没有接价目表。

## 8. 待确认

1. 实体卡押金默认 20 元（0 = 不收），按门店设，上限 1,000 元。
2. 押金一位会员押一份：名下没有押金时发卡才收；换下在用的卡不另收；补卡沿用。
3. 挂失不退押金；退卡（含卡丢了不补的）全额退；没有罚没、工本费。
4. 匿名卡：姓名预填「匿名会员」；可以配一张实体卡（同样收押金）；没留手机号的绑不了小程序。
5. 卡类型跟着卡走（电子卡发了卡记成实体卡，退了卡记回电子卡）；匿名卡留了手机号以后手动「转成实名」。
6. 手动指定等级只认「手动调整会员档阶」权限（默认只有店主），没有做当场授权。
7. 偏好项目是自由文字（最多 10 个、每个最多 12 个字）。
8. 后台能配显隐、必填的是七个选填项；不显示的字段已有的内容保持原样；必填只管页面上的建档与编辑。
9. 匿名卡补登手机号算改号（写原因、要权限或授权）；手机号登记以后不能清空。
10. 还押着押金的会员不能合并到别人。
11. 没留手机号的：页面写「未留手机号」，导出留空，批量发券不发短信。
12. 升级时名下有在用或挂失实体卡的现有会员记成实体卡（押金按 0）。
13. 收退押金沿用「会员实体卡：发卡、挂失、补卡」这一项权限，没有单独的权限。
