## 3. 店主要做的配置（一次）

### 3.1 选一种 Gemini

| 用哪个 | 装在哪 | 怎么读到规矩 |
| --- | --- | --- |
| **Gemini CLI**（命令行，推荐） | 店主自己的电脑（推荐）或单独一台电脑 | 在仓库文件夹里运行 `gemini`；仓库里的 `.gemini/settings.json` 让它同时读 `AGENTS.md` 与 `GEMINI.md` |
| Google Antigravity（桌面编辑器） | 同上 | 打开仓库文件夹即可，它本来就读 `AGENTS.md` 与 `GEMINI.md` |

用别的 Gemini 产品也行，只要它能读仓库、推分支、开 PR；第一条消息里让它先读这两个文件（第 4 节的提示词已经写了）。

**不要装在门店 Mac mini 的部署目录里**：Mac mini 上跑着内网测试服（演练库、演示库）和 Codex。实在要用 Mac mini，另建一个文件夹单独克隆仓库，用自己的数据库与端口，不在部署目录里执行任何 `docker compose` 或 `scripts/` 命令。

### 3.2 GitHub

1. **让 Gemini 能推分支、开 PR**：在 Gemini 那台电脑上登录 GitHub 命令行 `gh auth login`（用有写权限的账号）；或建一个只给 `Venture-VV/yuzu` 的细粒度令牌（Contents、Pull requests、Issues 三项读写），存在那台电脑的凭据管理里。令牌不发在聊天里、不写进仓库。
2. **保护 `main`（建议，做过就跳过）**：GitHub 仓库 Settings → Rules → Rulesets 给 `main` 加规则：必须经 PR 合并、禁止强推；可以把 CI 的各项与「线范围 / 小程序线只改自己的文件」设成必须通过。这样哪个 AI 都推不进 `main`。
3. **关掉 #90**：原来的草稿 PR（分支 `claude/nice-gauss-3p3urd`）没有待合的代码，关掉即可；Gemini 从最新 `main` 开新的。「小程序线」标签已经有了。

### 3.3 Gemini 那台电脑的开发环境

- Node 22、Git；跑集成用例要一个 PostgreSQL 16（装 Docker 后用仓库里的 `compose.dev.yaml` 起，或本机装）。
- 测试库只能是新建的独立库（用例会清空它），绝不指向测试服、正式服或任何门店的库。
- 微信开发者工具不用装：小程序页面的自动化与真手机测试照旧由 Codex「小程序助手」在门店 Mac mini 上做。

## 5. 每个小程序 PR 的验收流程

| 步 | 谁 | 做什么 | 过的标准 |
| --- | --- | --- | --- |
| 1 | Gemini | 在 `gemini/*` 开发、自测三条，推送；开草稿 PR（【小程序线】开头、带标签） | 自测全过 |
| 2 | CI（自动） | 平时的 9 项 + 「线范围 / 小程序线只改自己的文件」 | 全绿。线范围红了是阻断项，撤掉范围外的改动或请主线改 |
| 3 | 主线开发会话（Claude） | 线范围检查的摘要里列出了登记处或新迁移时：Gemini 在主线开着的 PR 上留言「请复核登记处」并附链接，主线在小程序线的 PR 上回【主线·开发】复核结果 | 登记处只是加挂接的几行；迁移号已在 ROADMAP 第 7 节登记、只建小程序线自己的表 |
| 4 | Codex「小程序助手」 | 在完整 SHA 上预检：开发者工具、独立合成环境、页面自动化、真机计划；报告第一行 `【小程序线·测试】→ 小程序线 · PR #<号> · <完整 SHA>` | 没有 P1；P2 修了或店主同意以后再修 |
| 5 | Claude 测试会话 | 照旧预检两条线的 PR，问题按线发 | 同上 |
| 6 | Gemini | 照报告修，在新 SHA 上请复测（旧 SHA 的通过不算）；都过了把 PR 改成待审 | — |
| 7 | 店主 | 合并（照旧 12:00 / 21:00 两个窗口） | — |
| 8 | Codex | 随主线下一个版本标签部署；小程序的体验版按 `docs/DEPLOY_GATEWAY.md` 上传 | 小程序线不改 yuzu 的版本号 |

**阻断项**（任何一条都不能合并）：CI 或线范围不绿；动到钱（充值、退款、券、点餐结账）没有集成用例、模拟支付没走通；改了核心或已有的迁移；账错、串单、越权、数据丢失、重复扣款、破坏旧模块自检（`AGENTS.md`）。
