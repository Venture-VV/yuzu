## 0. 升级后会看到的变化

- **ERP「供应链」多一个「零采备用金」**：
  - 采购（供应链）岗位与店主看得到；
  - 总额在「ERP 设置 → 报销与备用金」里填；
  - 没填以前面板上提示去填，不能申用。
- **费用报销**：登记报销单时「钱从哪来」多一个「零采备用金」，选了它就勾报的是哪几笔申用。
- **库存页**：
  - 多两个按钮「库管入库」「导入入库台账」；
  - 收货单上标「库管入库」；
  - 库存规则里多一个「库管入库」开关，默认开。
- **签赠**：
  - 后台「会员与营销」组多一个分区「签赠」，有配置、知识库、台账三个页签；
  - 管家部顶栏多「签赠台账」，客户部多一个页签「签赠台账」；
  - 前台结账的「券抵扣」列表里，签赠券标「签赠 · 板块」，后面写授权人、渠道、事由。
- **岗位权限**多四项：看签赠台账、发放签赠、签赠授权、维护签赠（默认见 `docs/GIFTS_V819.md` 2.5）。
- **普通券的「券模板」列表**里看不到签赠券类型。签赠券类型不能用于以下几处：
  - 发券规则；
  - 无记名；
  - 批量发券；
  - 会员权益；
  - 小程序领取。
- **工作台**：8.1.8 存过、带着 `dot` 的平板菜单版面，读到时去掉这一项。版面里引用 `$dot` 的颜色，换成当时存的颜色。

## 1. 范围

### 1.1 零采备用金（`docs/ERP_V819.md` 第 2 节，迁移 `182`）

- 服务端 `src/server/modules/petty-pool.ts`，页面 `features/pool/`。
- **申用**即占用额度，超过剩余可用时拦下（`POOL_EXCEEDED`）。
- **提交报销**：
  - 选「未补单」，或「已补单」加选一张采购单；
  - 以后能更新补单；
  - 没挂有效报销单的申用可以撤回或作废。
- **登记报销**：财务在「费用报销」登记，钱从「零采备用金」来，勾这几笔申用（`expense_claim_pool_uses`）。
- **状态从报销单推出来**，不另存：
  - 报销单确认后这几笔不再占用（自动回补）；
  - 撤回、冲销以后又回到占用。
- **自检**「零采备用金」：申用与报销单对得上。
- **采购台账**的区间合计、导出多一行「支出（零采备用金）」（Codex 审查 `785ca18`）。
- **模块关掉以后**：关之前已经提交报销的申用，财务照样能在「费用报销」里选「零采备用金」登记（Codex 审查 `785ca18`）。

### 1.2 库管入库（`docs/ERP_V819.md` 第 3 节，迁移 `183`）

- **手填**：与收货入库一样，只是不选采购单（`inv_docs.direct`）。
  - 照样记应付与成本，以后照样能补采购单；
  - 开关关了拒绝（`DIRECT_RECEIPT_OFF`）。
- **台账导入**（`src/server/modules/inventory/direct-import.ts`）：
  - 下载 Excel 模板；
  - 逐行预览核对，按「日期 + 供应商 + 分组」合单；
  - 有一行不对整份不写；
  - 同一份文件只能导一次（文件摘要唯一）；
  - 带操作编号（`receipt_import`）。
- **自检**「收货都有采购单」放过库管入库。
- **导入锁住物料以后再算一遍**：预览到上锁之间有人改了物料的换算、效期，整份不导（`IMPORT_STALE`），请重新预览（Codex 审查 `785ca18`）。

### 1.3 全局签赠（`docs/GIFTS_V819.md`，迁移 `184`）

- **做成「签赠券」**：
  - 券模板里标了签赠的那一类，只能是兑换券或代金券；
  - 抵扣、反结账退回、作废、过期都是券原来的；
  - 日结、营销成本的口径不变。
- **服务端** `src/server/modules/gifts.ts`：
  - 配置（`settings` 的 `gift_rules`）；
  - 知识库：经 `createTemplate`、`updateTemplate` 带上板块、权益内容、规则说明；
  - 授权人：有「签赠授权」的在职员工，按岗位权限算，含后台改过的；
  - 找会员：手机号按权限打码；
  - 发放：`kind = 'manual'`，加授权人与渠道，操作编号 `gift_issue`；
  - 作废：只认签赠券；
  - 台账：明细、按授权人、按个人、占比、导出。
- **结账**（`coupon-checkout.ts`）：
  - 券列表带签赠信息；
  - 收款明细的备注写「签赠·券名（券码，授权 某某）」。
- **页面**：
  - `features/gifts/`：后台分区、台账、发放弹窗、知识库；
  - 管家部 `/concierge/gifts`；
  - 客户部 `/customer?tab=gifts`；
  - 前台结账券列表（`features/frontdesk/payments.tsx`）。
- **兜底**：
  - 迁移里的触发器：签赠券类型的发券记录必须有授权人与渠道，别的券必须没有；发过券的模板不能改签赠标记。
  - 签赠发放还在路上或结果待确认时，「签赠发放」按钮挡住，处理完那一笔才能再发（Codex 审查 `785ca18` 的 P1）。
  - 签赠发放先锁住会员一行再核对，与停用、合并串行，券不会发到合并掉的会员名下（Codex 审查 `cf81873`）。
  - 台账导出一次最多 20000 张，超过整份拒绝、请缩短日期范围，不截掉一部分（Codex 审查 `cf81873`）。
  - 普通发券、规则、无记名、批量发券、会员权益、小程序领取都在代码里先拒绝（`GIFT_TEMPLATE`）。
  - 会员权益的自动发放跳过签赠类型。

### 1.4 退回 8.1.7（`docs/EMENU.md` 16.9）

## 4. 验收要点

1. **零采备用金**：
   - 采购岗位看得到面板，成本核算等别的岗位看不到；
   - 申用超过剩余可用被拦；
   - 财务按申用登记报销、确认后面板回补；
   - 冲销报销单后又占用。
2. **库管入库**：
   - 不选采购单也能确认入库，应付与成本照记；
   - 导入的预览与合单对；
   - 同一份文件导第二次被拦；
   - 开关关了不能用。
3. **签赠**：
   - 发放时不选授权人、选了没有「签赠授权」的人都被拒；
   - 普通发券、发券规则、无记名、批量发券、会员权益里选不到也用不了签赠类型；
   - 前台结账券列表写着授权人与渠道，用掉以后台账是「已使用」，记着结账单号与抵扣金额；
   - 反结账退回成「未使用」；
   - 按授权人、按个人、占比的数与明细对得上；
   - 管家（没有「查找与查看会员」）看到的手机号打码；
   - 开关关了不能发，已发的照常能用；
   - 结果待确认：断网时发放，刷新后在台账上方查回或确认作废。
4. **退回 8.1.7**：8.1.8 的版面里选了 `dot` 的颜色，升级后颜色不变，退回 8.1.7 也不变。
5. **三台设备**：上面这些页面在四个尺寸上不横向滚动，按钮在屏幕里。
