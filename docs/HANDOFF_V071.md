# v0.7.1 交接说明 · S6 技师第二步：钟房看板、轮钟排队、上下钟计时、提成

ROADMAP 第 10 节 S6 的第二步（G6）。**技师功能仍默认关闭**：升级后不开启时，主导航没有「钟房」，前台挂账、结账、交班、日结、对账包的金额与升级前完全一样（对账包技师表多三列提成，内容为 0）。开启后，钟房派钟、加钟是给客人挂账（与前台挂账同一条路径），退钟、取消派钟是作废明细——这些都在前台挂账的资金路径上，按 T0 验收；提成只是报表，不动钱。

同一个 PR 还带上 PR #15 / #16 复核的修正（第 5 节），其中 P1（在店信息越权）与两个 P2（跨日反结账口径、反结账重结后会员占用）请在新 SHA 上复测。

**资金口径改动：跨钱箱退款**（店主 2026-10-30 定方案 A，第 6 节）。反结账退现金时选从哪个钱箱退，退款记到那个钱箱当班的班次。这改变了反结账退款记到哪个班次（原来一律记到反结账人的班次），影响交班的应有现金，请按资金候选版本验收（F1–F7）。

规则按店主 2026-10-30「按你推荐的来，多参考汤泉实际提成规则」定默认值，全部标「待确认」，见 `docs/PENDING_DECISIONS.md`「钟房与提成」与「复核后待店主确认」两节。版本号按店主 2026-10-30 的规则只加最后一位（原计划的 v0.8.0 改为 v0.7.1）。

## 2. 迁移与数据

- 迁移 `021_clockroom.sql`：新表 `technician_sessions`（钟单）、`technician_status`（上牌状态与排位，每位技师一行）、`technician_events`（钟房日志，只追加）、`commission_rule_versions`（提成规则版本，只追加）；`bill_lines.session_id`。只加不改：已有明细没有钟单。
- 钟单状态与时间由约束保证一致（待上钟没有开始时间；上钟中有开始没有结束；已下钟两者都有；取消 / 被退钟有原因）；`technician_sessions_serving_uq` 保证一位技师同一时间只在一个钟上。
- 重建明细保护触发器 `yuzu_bill_line_guard()`：`session_id` 加进不可改的字段，唯一允许的变化仍是「有效 → 已作废」。
- 新设置项 `clockroom_rules` 有代码默认值，迁移不写入；没有提成版本时按默认规则（待确认）。
- 演示数据没有改（`src/server/seed*.ts` 归测试会话）：演示库里没有技师。E2E 用例沿用 v0.7.0 的「E2E 技师足疗」与 `E8`，另建 `E9`，结束时关闭技师功能。需要演示钟房时测试会话可以补到演示数据里（建议另起固定预期）。
- 加锁顺序（AGENTS.md 已更新）：手牌 → 同行组 → 来访 → 账单 → 明细 → 技师队列（咨询锁）→ 钟单 → 技师状态 → 会员。钟房的上牌、上钟、下钟不锁来访与账单，只拿技师队列锁再锁钟单与技师状态。

## 6. 跨钱箱退款（资金验收）

做法：反结账的单收过现金时，反结账页面列出此刻当班的班次（谁的钱箱、班次号、几点开班），默认原单收款的班次；那个班次已交班时默认反结账人自己的班次；只有一位当班时默认那一位；都没有时要先开班。退款（现金扣减应有现金、其他方式的原路退回提醒）记到所选的班次，原单仍算在收款时的班次。沿用 `checkouts.void_shift_id`（含义改为「退款记入的班次」），没有新迁移。

| # | 操作 | 预期 |
| --- | --- | --- |
| F1 | 店员开班（备用金 500），现金结账 499；值班经理（开了 0 元的班）反结账，看「从哪个钱箱退现金」 | 列出店员和值班经理两个班次，默认选中店员的（标「原单收款的班次」）；确认后店员应有现金 = 500（原单 499 与退款 499 相抵），值班经理的应有现金不变（不再出现负数） |
| F2 | 店员的交班页、交班单（80mm）与交班后的快照 | 反结账一行写「值班经理反结账、从本班钱箱退」；退款按原收款方式列出 |
| F3 | 店员交班页面在反结账之前打开，反结账后直接提交交班 | 拒绝（`SHIFT_CHANGED`），刷新后按新的应有现金交班 |
| F4 | 原单的班次已交班；值班经理没开班、只有晚班店员当班 | 默认晚班店员的钱箱；值班经理不用开班也能反结账，退款记到晚班店员的班次。不选钱箱的请求（原单只有扫码）仍要求反结账人先开班（`SHIFT_REQUIRED`） |
| F5 | 在两台电脑上：A 打开反结账页面选了店员的钱箱，B 先把店员的班次交掉，A 再确认 | A 被拒（`REFUND_SHIFT_CLOSED`，写明哪位的哪个班次已交班），结账单仍是已结账，什么都没改；重新选钱箱后可以办理 |
| F6 | 店员调 `GET /api/frontdesk/checkouts/:id/refund-shifts` 或带 `refundShiftId` 反结账 | 403（只有能反结账的岗位） |
| F7 | 一天里有跨钱箱退款后看日结、交班汇总、对账包 | 日结的营业额、收款构成不受选哪个钱箱影响；各班次应有现金变动合计 = 当天现金净收；`check` 全 ✓ |
