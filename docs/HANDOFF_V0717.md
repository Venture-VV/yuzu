# v0.7.17 交接说明 · 飞书需求 RQ-004 第三段（下）：第一级实时位置

店主 2026-11-02 合并 v0.7.16（房态图）后开工。第一级 = 业务推导定位（D17、D24）：不加硬件，由刷卡点刷卡与业务动作推出客人在哪个区、技师在哪间房，精度到区域与房间，位置停在上一次业务动作。表结构按第二级精确定位预留，第二级只换数据源。设计见 `docs/ROOMMAP.md` 第 3 节（定稿）；默认做法（待确认）见 `docs/PENDING_DECISIONS.md`「第一级实时位置」。同版补了 v0.7.15 验收报告提的五项测试缺口（第 6 节）；Codex 复审 `92d2ab1` 的五项与 `516928d` 的一项发现已修正（第 5 节）。

- **迁移 `035`**：
  - 新表 `location_readers`（刷卡点：编号唯一、装在区域或空间二选一、版本号、不能删）、`location_events`（位置事件，只追加；第二级预留 `x_mm`、`y_mm`、`accuracy_mm`、`device_id`）、`location_tracks`（轨迹段，每人最多一段没结束，结束了的段不能改）、`current_locations`（当前位置，每人一行）。
  - `service_items` 加 `zone_id`（项目所在区域，可空）。
  - 只加表、加列；升级后开关关着（`location_rules` 没有就按默认：关、不选区域），业务照旧，不产生任何位置数据。
- **阻断项**：
  - 位置推导让业务出错或变慢到超时（发牌、挂账、开房、上下钟、结账任何一步因为位置报错、不生效）。
  - 越权：没有「看实时位置」的岗位能取 `/api/locations/current`、`/tracks`；没有「上报位置」的能上报；后台配置不是店主、店总也能改。
  - 位置接口或页面带出会员姓名、手机号。
  - 离店的客人还在平面图上；同一个操作编号重发记了两条；迟到的刷卡改了当前位置；模拟刷卡结果不明后按原内容重新提交记了两条，或确认作废后原请求晚到又记上；上一位客人的刷卡算到了拿同一张手牌的下一位客人头上。
  - `check` 不是全 ✓；破坏原有客房、钟房、前台、空间台账、底图、房态图功能。
