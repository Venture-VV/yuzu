## 1. 范围

### 1.1 管家部（PR #99 进来的内容 + 整合时改的）

PR #99 带进来的功能（口径 GJ12–GJ34 照它的不动）：会员身份由前台会员系统统一办理、管家只建服务档案；档阶与余额实时读会员系统；协调预约的资源从空间 / 桌台 / 客房台账级联；储值扣费明细；「会员情况」（按最后到访分四段）、「会员中心」（按档阶）、会员概览四个数可下钻；「管家好评中心」（荣誉墙、月榜、原图凭证）。设计见 `docs/CONCIERGE_LINKS.md`。

整合时改的（验收发现的，#99 上的 P2-1 到 P3-4）：

| 哪里 | 原来 | 现在 |
| --- | --- | --- |
| 每 3 秒的同步（`GET /api/concierge/revision`） | 原生指纹从 `members` 整表起算；递归查询的估算成本还会触发 PostgreSQL 的 JIT。2 万会员的库实测 0.6 秒 / 次，每个开着的管家页每 3 秒一次 | 从已关联的会员出发走主键，在这一个只读事务里关 JIT：同一个库 5–8 毫秒 |
| 工作区的会员摘要 | 每个服务档案各查一遍（一位 8 条以上查询） | `nativeMemberSummaries` 一批取（含被合并的旧编号落到主账号） |
| 会员名单（会员情况、会员中心、下钻弹窗） | 每次请求读全部会员与到访，页面每 3 秒轮询 | 页面不再 3 秒轮询：同步发现有变时再取，另加慢速刷新（名单 30 秒、会员详情 10 秒、扣费明细 15 秒）；查询去掉逐位会员的子查询 |
| 管家保存时对原生表的行锁 | 对 `members`、`spaces` / `dining_tables` / `rooms`、`staff` 加 `FOR SHARE`，与「只锁管家自己的行」不一致，并与前台预约到店（预约 → 空间）反向 | 改回只读核对、不加行锁（存在由外键兜底） |
| 没有会员查看权限的管家看全店会员 | 完整手机号 | 没建服务档案的会员手机号打码（`199 **** 8001`，仍可按手机号查找）；建了服务档案的照旧；权限说明写明能看到什么 |
| 金额、时间的格式 | 各部件自己写一套，时区写死 | `features/concierge/format.ts`，用全店的格式函数（跟门店时区） |
| 好评中心的颜色 | 十几个写死的颜色值 | 全店的颜色变量 |
| 管家页顶上的导航 | 页面里的状态，刷新回工作台 | 写进地址：`/concierge/members`、`/appointments`、`/praise`、`/followup`、`/situation`、`/tasks`、`/tiers`、`/manager`、`/receipts` |
| 自检 | 不核对预约的系统资源 | 协调预约的 `resourceKey` 与三列 `native_*_id` 对不上时报出来 |
| 备份导出的格式标记 | `yuzu-concierge-8.0.12` | `yuzu-concierge-8.0.18`（内容多了好评两张表与预约的三列） |

没改、请店主定的（V8–V10）：服务端还接受新的人工余额（页面没有入口，不碰钱包）；「本月新增」遇到合并与期初导入；好评登记没有限制给自己登记、重复用图、补登过去日期。

### 1.2 ERP 整理

| 哪里 | 改了什么 |
| --- | --- |
| ERP 导航（`src/shared/erp.ts` 的 `ERP_NAV_GROUPS`） | 概览 / **审批**（审批中心单列）/ 供应链（库存、采购、采购需求单、本部门小仓、资产与易耗）/ **财务**（付款、**应付货款**、费用与备用金、发票台账、应收与挂账）/ **合同**（原「法务」）/ 设置。导航的顺序单独登记，不跟模块的依赖顺序走 |
| **ERP 设置**（新，`/erp/settings/<页签>`） | 七个页签：模块开关、采购规则、库存与审批开关、审批规则与代理人、付款规则、报销与备用金、其他数值。每个页签里是原来那张卡片（接口、权限、保存按钮都没变）。谁看得到哪个页签在 `features/erp/settingsTabs.ts` |
| 后台「门店基本规则」 | 「库存与采购」页签挪到 ERP 设置；「可调的数值」只留门店的（扫码点餐、平台核销、营销与短信、打印、次卡），底下有去 ERP 设置的链接 |
| 采购 | 右上角 9 个去子页的按钮改成每个子页顶上同一排页签（采购单、流程进度、询价比价、补货建议、下单物料、急采、供应商比价、供应商评分、集采导入）；地址没变 |
| 费用与备用金 | 同上：报销、备用金与每日平账、费用预算、采购台账、账目自检、旧账对照 |
| 审批中心、付款 | 「审批规则」「付款规则」的入口指到 ERP 设置（代理人是日常要用的，审批中心里照旧留着） |
| 员工食堂、安保巡场 | 页面挪到后台「人员与行政」（`/admin/canteen`、`/admin/patrol`）。权限、接口（`/api/erp/canteen`、`/api/erp/patrol`）、模块开关都没变；只有这两项权限的岗位（食堂负责人、安保主管）也进得了后台，只看得到自己的分区；模块关着时页面提示去 ERP 设置开。员工手机端不变 |
| 营业数据 | 数据看板的一个页签（`/admin/dashboard/revenue`）；权限仍是 `erp.revenue` |
| 规则总表 | ERP 的规则「去 ERP 设置」直达页签；补上部门主管确认、环节标红、固定付款日、三单容差、挂合同的货款、报销门槛、备用金超期、开饭时间、巡场间隔 |
| 二级页签部件（`components/SubNav.tsx`） | 页签可以自带地址与测试标识（采购、报销的子页地址各不相同） |

## 5. 验收要点

1. **管家部**
   - 用只有「管家」职责的账号（没有会员查看权限）打开「会员中心」「会员情况」：没建服务档案的会员手机号是打码的，建了的是完整的；店主看都是完整的。
   - 前台改一位已建服务档案的会员的姓名或充值：开着的管家页几秒内自己变；没建档的会员的变化最多等 30 秒，或点「刷新」。
   - 点顶上的「会员中心」「管家好评中心」：地址跟着变；刷新留在原页；浏览器后退回上一页。
   - 金额都是 `1,280.00` 的样子，时间跟门店时区；好评中心的颜色与全店一致。
   - `node dist/server/cli.js check` 里「管家部的记录与修订历史一致」为 ✓。
2. **ERP**
   - ERP 侧栏：审批 / 供应链 / 财务 / 合同四组，应付货款在财务里，最后是「ERP 设置」。
   - ERP 设置的七个页签各自能保存；点页签地址变、刷新还在。第 2 节表里的旧地址逐个打开，都到对应的新位置。
   - 物资经办（只有查看库存）进 ERP 设置只看得到采购规则（只读），没有模块开关。
   - 采购、费用与备用金：每个子页顶上都有同一排页签。
   - 后台「人员与行政」里有员工食堂、安保巡场；模块关着时页面提示去 ERP 设置开。只有食堂管理权限的账号登录后进后台、只看得到员工食堂。
   - 数据看板有「营业数据」页签（有 `erp.revenue` 的看得到）；数字与原来的 ERP 营业数据、经营总览一致。
   - 规则总表里搜「付款日」「主管」「巡场」：有对应的行，「去 ERP 设置」到对应的页签。

## 6. 已知的限度

- 会员名单的接口每次仍读全部会员（2 万会员约 0.35 秒）。现在只在进页面、翻页、筛选、有变化与慢速刷新时取，够用；会员到十万级时要改成在数据库里分页与统计。
- 管家部仍是它自己的一套版面与样式表（8.0.12 接过来时定的不重画）；这一版只对齐了格式、颜色变量与导航的规矩。
- 管家部的手机、平板竖屏版面这一版没有逐屏看（受阻未测：本地只看了 1440×900）。
- ERP 导航里「已挪到后台」这一组（营业数据、员工食堂、安保巡场的跳转）下一个版本去掉。
- 门店日常入口的整理（发券、停车登记、微信解绑挪到会员工作台，本机终端进用户菜单）是第三步，8.0.19。
