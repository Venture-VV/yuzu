**这一版做**：

1. **协议 v0.1**：打印机、标签机、读卡器、扫码四类设备的登记与能力、指令、事件、错误码，写成文档与类型定义（`src/shared/devices.ts`），服务端、页面、桥共用一份。
2. **设备登记**：每台设备一行（编号、名称、型号、区域、接法、IP 与端口、挂在哪台终端或打印服务器下），按采购清单导入（默认预览），与采购清单的数量对得上。
3. **网口打印**：服务端直连打印机打中文测试页（标签机打测试标签）；打印任务按台排队、超时重试、错误码明确；心跳查状态（拔线 10 秒内在页面上变灰，插回自动恢复；缺纸、开盖能报出来）。
4. **Android 终端**：页面端收「模拟键盘」设备的输入；桥的协议与页面端；**模拟桥**（`device-bridge-mock`）在没有真机时代替，可配置延迟、断开、失败。桥的 APK 等真机与规格到了再做（见第 9 节）。
5. **一屏看全部设备**：门店主导航「设备」，按区域分组，在线 / 离线 / 故障一眼看到，2 秒刷新；可测试打印；本机终端的读卡、扫码记录。
6. **模拟设备与自检**：模拟网口打印机（本机 TCP，懂 ESC/POS 与 TSPL 的常用指令，能回状态）、模拟桥，可配置延迟、离线、失败；`node dist/server/cli.js device-selftest` 不连数据库、不要真机，一条命令把打印、离线、恢复、读卡、扫码走一遍。

**这一版不做**（需求原文）：业务单据的版式（结账单、交班表、A4 日结单照旧用浏览器打印，后置）；发卡、挂失等读卡业务；多门店的设备路由；断网时的打印队列（列入 v0.2）；客房门锁与客控、手牌柜锁控、闸机（采购清单里没有，D8 本期不做）。

## 1. 设备、能力与接法

**设备种类**（`kind`）：

| 种类 | 说明 | 能接的指令 | 会发的事件 |
| --- | --- | --- | --- |
| `printer` | 小票打印机（ESC/POS） | 测试页、打印文字 | 状态 |
| `label_printer` | 标签打印机（芯烨 TSPL；爱普生 TM-L100 是 ESC/POS） | 测试标签 | 状态 |
| `card_reader` | 读卡器（RC300、商米 NFC） | — | 读到卡号、状态 |
| `scanner` | 扫码（小闪2） | — | 扫到的码、状态 |
| `terminal` | 商米终端（承载读卡、扫码与页面） | — | 状态（桥在线） |
| `print_server` | 打印服务器（华科 G4） | — | 状态 |

**接法**（`connection`）：`network`（IP + 端口，TCP 直连）、`print_server`（挂在打印服务器下，IP 是打印服务器的、端口是它给这台 USB 打印机的）、`bridge`（挂在终端下，经桥上报）、`keyboard`（模拟键盘，页面直接收输入）、`none`（终端、打印服务器本身，只看状态）。

**状态**：`online` 在线、`offline` 离线、`error` 故障（能连上但报错：缺纸、开盖、切刀错误）、`unknown` 还没查过；附带原因码（下面的错误码）与最近一次联系上的时间。

**错误码**（指令失败、状态原因都用这一套）：

| 码 | 意思 |
| --- | --- |
| `DEVICE_OFFLINE` | 设备离线（最近 10 秒没联系上），指令不发 |
| `DEVICE_TIMEOUT` | 连接或回复超时 |
| `DEVICE_REFUSED` | 连接被拒（IP 对但端口没开，或设备拒绝） |
| `DEVICE_UNREACHABLE` | 网络不通（没有路由、地址不对） |
| `DEVICE_INTERRUPTED` | 发送到一半断了，或发完之后打印机复位连接、出错、到时没确认收完；**不自动重发**（可能已经打出一部分），由人看过再重打 |
| `DEVICE_PAPER_OUT` | 缺纸 |
| `DEVICE_COVER_OPEN` | 开盖 |
| `DEVICE_FAULT` | 打印机报错（切刀、过热等） |
| `DEVICE_BUSY` | 这台正在打别的，排队超时 |
| `DEVICE_DISABLED` | 设备已停用（停用时这台排着还没发的打印任务记这个，不再发） |
| `DEVICE_CHANGED` | 设备设置刚改过：这台排着还没发的打印任务不按新设置发送、不改投新地址（请重新提交） |
| `DEVICE_UNSUPPORTED` | 这种设备不接这条指令 |
| `BRIDGE_OFFLINE` | 终端上的桥没连上（页面连不到本机设备服务） |
| `BRIDGE_PROTOCOL` | 桥的报文不对（版本不符、字段缺失） |
| `READ_FAILED` | 读卡 / 扫码失败（桥报上来的） |

## 2. 网口打印

- **连接**：服务端按设备登记的 IP 与端口（默认 9100）建 TCP 连接，发完关闭；不经门店电脑。打印服务器（G4）下的 USB 打印机一样按 IP + 端口登记。服务端要在门店局域网里能直连打印机（每台打印机要固定 IP，由 IT 分配）；云上的测试服连不到门店打印机，在测试服上用模拟打印机。
- **中文**：ESC/POS 进入汉字模式（`FS &`），文字按 GB18030 编码（用 Node 自带的 GB18030 解码表反查，不加依赖；表里没有的字打「?」）。纸宽 80 毫米每行 48 个半角字、58 毫米 32 个（登记时选）。
- **测试页**：门店名、实例标识（不是正式服时醒目标出）、设备编号与名称、区域、IP 与端口、中文样张（常用字、全角标点）、倍高倍宽的大字、打印时间，最后切纸。标签机打一张测试标签（芯烨用 TSPL：`SIZE` / `GAP` / `CLS` / `TEXT`（中文字库 `TSS24.BF2`）/ `PRINT`；TM-L100 用 ESC/POS）。
- **打印任务**：每台一个队列，同一台一次打一张；应用重启时，开端口之前先把上次还在发送的记失败（不自动重发）、排队的接着打；每次连接与发送限时 5 秒，**还没开始发**就连不上的自动重试 2 次（共 3 次），之后记失败（`DEVICE_TIMEOUT` / `DEVICE_REFUSED` / `DEVICE_UNREACHABLE`）；**已经开始发**中途断开的记 `DEVICE_INTERRUPTED`、不自动重发。**发完之后**要等打印机正常关连接（收完）才算打出；对方复位连接、出错，或 10 秒内没关的，同样记 `DEVICE_INTERRUPTED`、不自动重发（写入成功只说明数据交给了本机网络，不说明打印机收下了）。领取任务时先锁设备一行、用那时的设置发送：停用设备时这台排着还没发的记 `DEVICE_DISABLED`，修改设备时记 `DEVICE_CHANGED`，都不再发、不改投新地址；已经在发的照常发完。设备离线时提交直接失败（`DEVICE_OFFLINE`），不攒着等它恢复（断网打印队列在 v0.2）。任务带操作编号，同一编号重提返回原任务，不会打两张。
- **心跳与状态**：服务端每 2 秒查一次所有启用的网口设备：连上后发 `DLE EOT 1/2/4`（实时状态；TSPL 标签机发 `ESC ! ?`，打印服务器只看能不能连上），按回复判断缺纸、开盖、故障；连上但不回状态的按在线处理（有的型号网口不回）；连不上的，**最近一次联系上已超过 5 秒**才记离线（一次没连上不算）；再连上马上回到在线。加上设备页 2 秒刷新，拔线 10 秒内在页面上变灰。正在打印的那台心跳跳过（多数打印机网口同时只接一个连接）；要打印时如果这台正在心跳，先等这次心跳放开连接再连（不回状态的型号一次心跳要占 1.5 秒）。打成了也算联系上。心跳与打印成功的结果都按探测、领取时读到的设置写回：期间设备被修改、停用（版本变了）的，这次结果作废，不覆盖新设置的状态。状态变化记一条设备事件（只追加）。

## 3. Android 终端：读卡与扫码

- **模拟键盘（不用装程序）**：扫码盒、读卡器工作在「模拟键盘」模式时，号码像键盘输入一样打进页面。设备页（与以后的接待页）按「很短时间内连续输入、以回车结束」认作一次扫码 / 读卡，与人打字区分开（默认：字符间隔不超过 50 毫秒、至少 4 个字符）。
- **桥（终端上的设备服务）**：串口模式的读卡器、商米 NFC 要在终端上装设备服务。桥在本机开 `ws://127.0.0.1:17890`（端口可在页面上改），页面连上去收事件。报文都是 JSON：

  ```
  { "v": 1, "type": "hello", "bridge": { "terminal": "TRM-ZY-01", "version": "0.1.0" }, "devices": [{ "key": "rc300", "kind": "card_reader", "status": "online" }] }
  { "v": 1, "type": "status", "key": "rc300", "status": "offline", "code": "DEVICE_OFFLINE" }
  { "v": 1, "type": "card", "key": "rc300", "cardNo": "0012345678", "at": "2026-11-03T12:00:00.000Z" }
  { "v": 1, "type": "scan", "key": "scanner", "code": "6901234567890", "at": "…" }
  { "v": 1, "type": "error", "key": "nfc", "code": "READ_FAILED", "message": "…" }
  页面 → 桥：{ "v": 1, "type": "ping" } / { "v": 1, "type": "hello", "page": "yuzu 0.7.21" }
  ```

  版本不符、字段缺失的报文页面不认（`BRIDGE_PROTOCOL`），并在页面上提示。
- **状态上报**：开着门店页面的终端每 2 秒把桥和它下面设备的状态、读卡与扫码事件报给服务端（用页面的登录身份，要有「看设备状态」；桥不需要账号和密钥）；不在设备页也照常上报。服务端 5 秒没收到就把这台终端与它下面的设备记离线；页面连不上桥时报「桥没连上」，挂在它下面的设备记离线（`BRIDGE_OFFLINE`）。页面要先在设备页选一次「这台终端是哪一台」（记在本机）。桥报的设备按「终端 + 设备键」对应到设备登记；登记里没有的设备键（如终端自带的 NFC）的事件记在终端名下，并在页面上提示。事件带编号，重发不会记两次。事件内容最长 200 字：桥报的错误拼成「错误码：说明」后整条截到 200；错误码只认第 1 节表里的，别的不写进去。
- **模拟桥**：`node dist/server/cli.js device-bridge-mock [--port 17890] [--terminal 编号]`，按协议发 hello、心跳，命令行输入卡号、条码就发读卡、扫码事件，也可以按设定的间隔自动发；能模拟延迟、读卡失败、设备拔掉、整个桥断开。浏览器验收与自检都用它。
- **APK**：真机与规格到了、确认商米终端能装自签名的 APK（不能就改用商米 SDK 或网口设备）之后再做，协议照这一版。

## 4. 设备登记与采购清单

- **登记**：编号（唯一，如 `PRN-SY-01`：类型前缀 + 区域 + 序号）、名称、种类、品牌型号、区域（接待、收银、助浴、水吧、娱乐、餐厅、休息、按摩、后厨、候钟房，可以再挂空间台账里的空间）、接法、IP 与端口、纸宽与编码（打印机）、标签语言与尺寸（标签机）、挂在哪台终端或打印服务器下、桥里的设备键、启用 / 停用、备注；修改带版本号，对不上拒绝。设备不能删除，只能停用。
- **按采购清单导入**：`node dist/server/cli.js import-devices --quote` 预览按上表的数量与区域分配生成的设备，`--apply` 才写入（真实门店数据，门店环境须店主同意；编号已有的跳过）；后台也能导入。导入后 IP、端口由现场填。
- **对数**：设备页与后台显示每种型号「采购 N · 已登记 N · 在线 N」，与采购清单不一致的标出来。

## 5. 页面

- **门店主导航「设备」**（看设备状态的权限）：按区域分组的设备卡片，状态颜色（在线、离线灰、故障红）与原因、最近联系时间、IP；2 秒刷新；顶部是各状态的台数。能测试打印的岗位在打印机卡片上点「测试打印」，结果（成功、失败的错误码与说明）当场显示。右侧是**本机终端**：选这台终端是哪台、桥是否连上、最近的读卡与扫码记录（也收模拟键盘输入）。
- **管理后台「设备」分区**（维护设备的权限）：设备登记（新建、修改、停用）、按采购清单导入（预览后写入）、采购清单对数、最近的打印任务与设备事件。

## 7. 数据（迁移 `038`）

- `devices`：设备登记（上面第 4 节的字段 + 状态、原因码、最近联系时间、状态改变时间、版本号）。
- `device_jobs`：打印任务（设备、种类、内容、状态 排队 / 发送中 / 完成 / 失败、尝试次数、错误码与说明、操作编号、经办人、时间）。
- `device_events`：设备事件，只追加（状态变化、读卡、扫码、错误；读卡号只存在这里，不进会员与手牌）。

锁顺序：修改、停用设备只锁设备一行（带版本号），同一事务把这台排着还没发的打印任务记失败；打印任务：建任务先锁设备一行（同一台串行，再建任务），领取时设备一行（共享锁）→ 任务，发送在事务外、之后只改任务一行；心跳与桥上报只改设备状态一行（按设备 id 升序；心跳按探测前的版本写回），不等业务锁。

## 10. 做出来的东西怎么用（没有真机时用模拟设备）

```bash
node dist/server/cli.js device-selftest                       # 一键自检：不连数据库、不要真机，24 项
node dist/server/cli.js device-printer-mock --port 9100       # 模拟网口打印机：收到的内容打到屏幕上；输入 stop（拔线）、start（插回）、mode paper_out
node dist/server/cli.js device-bridge-mock --terminal TRM-SY-01   # 模拟终端上的设备服务：输入 card 0012345678、scan 6901234567890、unplug rc300
node dist/server/cli.js import-devices --quote                # 预览按采购清单登记 81 台；--apply 才写入（真实门店数据，门店环境须店主同意）
```

1. 后台「设备」按采购清单导入（或逐台登记）；在模拟打印机所在机器上，把一台小票机的 IP 填 `127.0.0.1`、端口填模拟打印机的端口。
2. 门店主导航「设备」：几秒内这台变「在线」；点「测试打印」，模拟打印机的屏幕上出现中文测试页；在模拟打印机里输入 `stop`，10 秒内这台变灰（离线），输入 `start` 恢复。
3. 同一页右侧「本机终端」：设备服务地址填模拟桥的地址（默认 `ws://127.0.0.1:17890`），点「连接」；选「这台终端是」哪一台（要先在后台把读卡器挂到这台终端、设备键填 `rc300`）；在模拟桥里输入 `card …`、`scan …`，「最近的读卡与扫码」里出现，后台「设备」的设备事件里也有；`unplug rc300` 后读卡器变离线。
4. 模拟键盘：焦点不在输入框时，扫码枪（或很快地打一串号码再回车）在设备页扫一下，记录里出现「键盘」。

真机到货后：网口打印机分好固定 IP 填进后台即可直连；USB 打印机接华科 G4，按 G4 给的端口登记；终端上的设备服务（APK）照第 3 节的协议做，做好之前模拟键盘模式的扫码枪、读卡器可以直接用。
