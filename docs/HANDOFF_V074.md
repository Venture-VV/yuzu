# v0.7.4 交接说明 · S7 客房（G7，资金候选版本）

店主 2026-10-31 选定 v0.7.4 做一个完整模块 S7 客房（ROADMAP 第 10 节第 3 项）。设计见 `docs/ROOMS.md`；规则默认值按洗浴中心客房、酒店的常见做法定，标「待确认」，见 `docs/PENDING_DECISIONS.md`「客房」。

同一个 PR（[PR #20](https://github.com/Venture-VV/yuzu/pull/20)，目标分支 `main`）还带着 v0.7.3 验收后的修正，见第 6 节。

- **客房功能默认关闭**：关闭时主导航没有「客房」，前台、结账、交班、日结与 v0.7.3 完全一样。店主在「后台 → 客房」开启。
- **迁移 `024_rooms.sql`**：只加表、加列、放宽约束，不改已有数据。
- **押金与退房结账涉及收款，按资金候选版本验收**：钱只在两处——账单明细（房费）与押金台账（只追加）；退房结账走与手牌结账同一套收款处理，另加「押金抵扣」。

## 1. 范围

| 项 | 内容 |
| --- | --- |
| 后台「客房」 | 客房规则（店主）：开关、全天房退房时间 12:00、加收一晚的时刻 18:00、钟点房宽限 15 分钟、只住房客人默认押金 ¥200（都待确认）。房型与房价：全天房按晚、钟点房按段（每段时长按房型）。房间：房号、楼层、房型。停用不删除；有人住的房间不能停用、不能改房型。规则总表列出客房规则 |
| 客房页 `/rooms` | 按楼层的房态看板：空闲、在住、待打扫、维修。点空闲的房入住；点在住的房看入住单；点待打扫、维修的房改房态（入住对话框里也有「改房态」）。夜审提醒、「夜审」「结账记录」按钮 |
| 入住 | 只住房的客人：开客房账单，默认收押金。洗浴客人：填在店手牌，房费挂手牌账单，默认不收押金。入住时挂第一晚 / 第一段。房价按员工看到的核对，刚改了价拒绝（`PRICE_CHANGED`） |
| 入住单 | 房费（每一晚 / 每一段、来源：入住 / 夜审 / 续住 / 退房；只住房客人的可以作废）、押金台账与各方式余额、换房记录。续住（全天房改预计离店；钟点房加一段）、换房（写原因，房价不变，原房间待打扫）、改登记、收押金、退押金（原路退、写原因）、撤销入住 |
| 退房 | 洗浴客人「退房」：按此刻补齐房费挂到手牌账单、押金全部原路退回、房间待打扫；手牌结账前必须先退房（`ROOM_OPEN`）。只住房的客人「退房结账」：可合并几间房，押金抵扣 + 其他收款，余下押金原路退回 |
| 反结账 | 前台「结账记录」：入住单恢复在住（房间已有人住时拒绝 `ROOM_TAKEN`）、押金抵扣恢复为押金；结账时已退回的押金不恢复 |
| 夜审 | 加收一晚的时刻以后才能做（`AUDIT_TOO_EARLY`）；给在住的全天房挂今晚房费，可重复做；夜审报告 |
| 交班、日结、看板、对账包 | 交班页与交班表列出押金收退，应有现金含押金现金；日结页与 A4 日结单有「客房押金」一节与核对项；看板「客房」；部门「客房」；对账包「07-客房与押金.csv」；自检三项 |
| 权限 | `room.operate`（店主、店总、值班经理、店员）、`room.housekeep`（再加后勤）；退房结账用「结账收款」；规则只有店主；房型房间是能管理价目的岗位 |
| 结果待确认 | 入住、续住、收押金、退押金、退房、退房结账：断网后查回 / 原样重提 / 确认作废；顶部「去处理」回到客房页对应的对话框 |

不在这一版（店主定规则后再做）：**房价含洗浴门票（住客票）**、预订、按日期浮动的房价、会员房价、钟点房封顶转全天、迷你吧与客房挂账、打扫排班、门锁 / 房卡对接。

## 2. 迁移与数据

- 迁移 `024_rooms.sql`：`room_types`、`rooms`、`room_stays`、`room_stay_charges`、`room_moves`、`room_deposits`、`room_audits` 七张表；`bills.kind` 加 `room`；`checkout_bills.room_stay_id`（账单的对象：来访、桌台、入住单三选一）；`checkout_payments.method` 加 `deposit`；幂等键与作废登记加 6 种客房业务类型。只加不改，升级不碰已有数据。
- 房费、押金台账、换房记录、夜审记录只追加（触发器拦截修改、删除）；入住单只允许规定的状态变化（反结账时由已结账恢复为在住）。
- 一间房同时最多一个在住单（部分唯一索引）；同一入住单的同一晚、同一段只有一笔房费（唯一索引）。
- **演示数据没有改**：四套演示数据里没有客房。`e2e/rooms.spec.ts` 自己建「E2E 标准间」「E2E 钟点房」与 E2E-01、02、03、08 四间房，开始时收掉上次中断留下的入住，结束时关闭客房功能。`src/server/demo/*-expected.json` 只是自检项的列表多了三项客房自检。
- `check`、`fingerprint`、备份核验、对账包不受客房开关影响；客房关着时客房自检全部为 0、照样 ✓。

## 5. 资金候选版本核对

| # | 核对 | 预期 |
| --- | --- | --- |
| M1 | 押金不是营业额 | 收押金后日结净营业额、看板营业额不变；只有退房结账的押金抵扣随结账单计入营业额（收款方式「押金抵扣」，不是实收） |
| M2 | 现金押金进出钱箱 | 交班应有现金 = 备用金 + 结账现金 + 充值现金 − 反结账退现金 + 押金现金（收 − 退）；退房结账退回的现金押金记在经办人当班的班次 |
| M3 | 押金台账只追加、余额不为负 | 每种方式余额 = 收 − 退 − 抵扣 + 恢复；已退房、已结账、已撤销的入住单余额为 0（自检「客房押金台账一致」） |
| M4 | 抵扣与结账单一致 | 押金台账的抵扣（扣除反结账恢复）= 结账单的「押金抵扣」收款（日结核对项、自检） |
| M5 | 房费不重复 | 同一晚、同一段只有一笔有效房费；每笔房费对应一条客房明细（自检「客房房费不重复」）；夜审重复做、退房补挂、并发都不重复 |
| M6 | 串单 | 储值只能用这几间房登记的会员；洗浴客人的房费只在自己的手牌账单上；手牌结账不能用押金抵扣 |
| M7 | 收款开始后班次被交班 | 整笔拒绝（`SHIFT_CLOSED`），押金不入账 |
| M8 | 升级兼容 | 升级前交班的快照、确认的日结快照不变；没有押金往来的班次汇总与升级前完全一样（没有押金一项） |

## 7. 待确认的规则与没做的部分

- 默认值都是「待确认」，店主在后台「客房」里改：退房时间 12:00、加收一晚的时刻 18:00（夜审也在这之后）、钟点房宽限 15 分钟、只住房客人默认押金 ¥200、洗浴客人默认不收押金。
- 店主选的方案里有「含几位洗浴门票」，**这一版没有做**：住客的门票怎么算（含几位、按房型还是按入住单、门票按哪一档、超时怎么算、退房结账时怎么和手牌结账合并）要先定规则，涉及门票计价与结账口径，放在「以后再做」，等店主定规则。现在洗浴客人的门票照常在手牌账单上按门票规则计，房费另算。
- 其他以后再做：预订、按日期浮动的房价、会员房价、钟点房封顶转全天、迷你吧与客房挂账、打扫排班、门锁 / 房卡对接。
