# v0.7.4 交接说明 · S7 客房（G7，资金候选版本）

店主 2026-10-31 选定 v0.7.4 做一个完整模块 S7 客房（ROADMAP 第 10 节第 3 项）。设计见 `docs/ROOMS.md`；规则默认值按洗浴中心客房、酒店的常见做法定，标「待确认」，见 `docs/PENDING_DECISIONS.md`「客房」。

店主同一天定了两条：

- **住客都是洗浴客人：门票必选，没有只住房的客人。** 入住客房要输入在店客人的手牌，房费挂在这张手牌的账单上，离店时随手牌在前台一起结账。
- **房价不含洗浴门票，分开算。** 门票照常按门票规则计价。

同一个 PR（[PR #20](https://github.com/Venture-VV/yuzu/pull/20)，目标分支 `main`）还带着 v0.7.3 验收后的修正，见第 6 节。

- **客房功能默认关闭**：关闭时主导航没有「客房」，前台、结账、交班、日结与 v0.7.3 完全一样。店主在「后台 → 客房」开启。
- **迁移 `024_rooms.sql`**：只加表、放宽约束，不改已有数据。
- **押金涉及收款，按资金候选版本验收**：钱只在两处——手牌账单上的房费明细（随手牌结账）与押金台账（只追加）。

## 1. 范围

| 项 | 内容 |
| --- | --- |
| 后台「客房」 | 客房规则（店主）：开关、全天房退房时间 12:00、加收一晚的时刻 18:00、钟点房宽限 15 分钟、入住默认押金（默认不收）（都待确认）。房型与房价：全天房按晚、钟点房按段（每段时长按房型）。房间：房号、楼层、房型。停用不删除；有人住的房间不能停用、不能改房型。规则总表列出客房规则 |
| 客房页 `/rooms` | 按楼层的房态看板：空闲、在住、待打扫、维修。点空闲的房入住；点在住的房看入住单；点待打扫、维修的房改房态（入住对话框里也有「改房态」）。夜审提醒、「夜审」按钮 |
| 入住 | 输入在店客人的手牌（必填）；房费挂在手牌账单上，入住时挂第一晚 / 第一段。房价按员工看到的核对，刚改了价拒绝（`PRICE_CHANGED`）。可以收押金 |
| 入住单 | 房费（每一晚 / 每一段、来源：入住 / 夜审 / 续住 / 退房）、押金台账与各方式余额、换房记录、「打开手牌账单」。续住（全天房改预计离店；钟点房加一段）、换房（写原因，房价不变，原房间待打扫）、改登记（称呼、人数）、收押金、退押金（原路退、写原因）、退房、撤销入住 |
| 退房与结账 | 退房：补齐此刻要付的房费挂到手牌账单、押金全部原路退回、房间待打扫。前台结账与撤销来访时客人还住着客房就拒绝（`ROOM_OPEN`）；结账对话框列出这些房间，可以直接退房，退房后房费和门票一起结 |
| 反结账 | 与平常一样：客人恢复在店，入住单仍是已退房，房费留在手牌账单上 |
| 夜审 | 加收一晚的时刻以后才能做（`AUDIT_TOO_EARLY`）；给在住的全天房挂今晚房费，可重复做；夜审报告 |
| 交班、日结、看板、对账包 | 交班页与交班表列出押金收退，应有现金含押金现金；日结页与 A4 日结单有「客房押金」一节；看板「客房」；部门「客房」；对账包「07-客房与押金.csv」；自检三项 |
| 权限 | `room.operate`（店主、店总、值班经理、店员）、`room.housekeep`（再加后勤）；规则只有店主；房型房间是能管理价目的岗位 |
| 结果待确认 | 入住、续住、收押金、退押金、退房：断网后查回 / 原样重提 / 确认作废；顶部「去处理」回到客房页对应的对话框 |

不在这一版（店主定规则后再做）：预订、按日期浮动的房价、会员房价、钟点房封顶转全天、迷你吧与客房挂账、打扫排班、门锁 / 房卡对接。

## 2. 迁移与数据

- 迁移 `024_rooms.sql`：`room_types`、`rooms`、`room_stays`、`room_stay_charges`、`room_moves`、`room_deposits`、`room_audits` 七张表；幂等键与作废登记加 5 种客房业务类型。只加不改，升级不碰已有数据。
- 入住单必须属于一位在店客人（`visit_id` 必填），房费挂在这位客人的手牌账单上。
- 房费、押金台账、换房记录、夜审记录只追加（触发器拦截修改、删除）；入住单退房、撤销之后不能再改。
- 一间房同时最多一个在住单（部分唯一索引）；同一入住单的同一晚、同一段只有一笔房费（唯一索引）。
- **024 在这个 PR 里按店主 2026-10-31 的决定改过**（去掉了只住房客人用的客房账单、结账单的入住单、押金抵扣等结构）。024 还没有发布到任何环境；如果之前用这个分支的旧提交建过演示库，请新建演示库再验收。
- **演示数据没有改**：四套演示数据里没有客房。`e2e/rooms.spec.ts` 自己建「E2E 标准间」「E2E 钟点房」与 E2E-01、02、03、08 四间房，开始时收掉上次中断留下的入住，结束时关闭客房功能。`src/server/demo/*-expected.json` 只是自检项的列表多了三项客房自检。
- `check`、`fingerprint`、备份核验、对账包不受客房开关影响；客房关着时客房自检全部为 0、照样 ✓。

## 5. 资金候选版本核对

| # | 核对 | 预期 |
| --- | --- | --- |
| M1 | 押金不是营业额，也不抵扣房费 | 收押金后日结净营业额、看板营业额不变；房费随手牌结账计入营业额；结账收款方式里没有押金 |
| M2 | 现金押金进出钱箱 | 交班应有现金 = 备用金 + 结账现金 + 充值现金 − 反结账退现金 + 押金现金（收 − 退）；退房时退回的现金押金记在经办人当班的班次 |
| M3 | 押金台账只追加、余额不为负 | 每种方式余额 = 收 − 退；已退房、已撤销的入住单余额为 0（自检「客房押金台账一致」） |
| M4 | 房费都在住客的手牌账单上 | 入住单的账单就是这位客人的手牌账单（自检「客房房态与在住单一致」）；结账单只有手牌账单 |
| M5 | 房费不重复 | 同一晚、同一段只有一笔有效房费；每笔房费对应一条客房明细（自检「客房房费不重复」）；夜审重复做、退房补挂、并发都不重复 |
| M6 | 漏结 | 客人还住着客房时结账、撤销来访都拒绝；退房补齐的房费都进了这张手牌账单 |
| M7 | 收押金、退押金开始后班次被交班 | 整笔拒绝（`SHIFT_CLOSED`），押金不入账 |
| M8 | 升级兼容 | 升级前交班的快照、确认的日结快照不变；没有押金往来的班次汇总与升级前完全一样（没有押金一项） |
