# 会员体系 v2 第二期：本店权益自动发放（v0.7.24 设计稿）

第一期（v0.7.23）把档阶与会籍做成全自动；第二期把**权益**也交给系统：本店权益清单在后台一页管理，券类每月自动发、事件礼自动发、服务类在会员详情列出「可享」并登记使用。依据 `docs/MEMBERSHIP.md` 第 3、5、13 节（店主 2026-11-03：先按一家店做、不往复杂做、保证可操作与可视化、体系自动化）。默认做法记在 `docs/PENDING_DECISIONS.md`「会员体系 v2」M27–M35，店主不改就按它做。迁移 `041`。

## 1. 权益清单

- **来源**：会员文档附录三 A「汤崎洗浴与会员服务」57 项（QY-001–QY-057）与 F 补充 2 项（专属锁牌号、行李优先寄存），按编号、名称、配置起点、内容与使用条件原样导入。PAJAMA、新生乐园、池里商业、跨业态不在本系统收银，不导入（M1）。
- **导入后全部是草稿**（会员文档：全部按待发布配置理解）；文档里写明暂缓的 4 项（QY-035 福田娱乐、QY-048 异业会籍、QY-050 免费洗车、QY-057 会员挑战）导入为暂缓。店主、店总逐项改好后**发布**，可以**暂缓**；不能删除。每次修改加版本号、留审计；已经发出的券、登记的使用不随修改变化。
- **配置起点**：「L2·初」等按档阶算；「L0·会员」是所有会员（含免费注册）；「未配置；待公布」的起点为空，设好起点才能发布。
- **谁能用**：会员现在的档阶（19 个状态按 L0 < L1·初 < L1·享 < L1·尊 < L2·初 … < L6·尊 排序）不低于起点就能用（高档阶自动包含低档阶的权益）。同一项在不同档阶数量不同时，按会员现在的档阶取那一行，不相加（M30）。
- **导入方式**：后台「会员权益」一键导入（编号已有的跳过），或命令 `import-benefits --quote` 预览、`--apply` 写入（门店环境照真实数据导入的规矩，要店主同意）。

## 2. 四类权益与系统怎么做

| 类别 | 默认归类（导入时按编号分，可改） | 系统怎么做 |
| --- | --- | --- |
| 券类 | 免费浴资、月度餐饮券、电竞 / PS5 / 棋牌免费时长、助浴、护发、SPA、头疗、按摩足浴项目券（10 项） | 发布时选一个券模板、每期张数（默认每月 1 张；免费浴资按年 1 张）。**每月第一天**营业日开始时给够格的会员发本期的券，有效到本期最后一天；月中入会、升档、升阶当场补发差额；降档不收回已发的（M29、M31） |
| 事件礼 | 首充礼、升级礼（升档、升阶）、保级礼、生日餐饮礼遇、节日关怀（5 项） | 发布时选券模板与张数；事件发生时自动发，每项去重：首充礼一次；升级礼每升到一个新档、新阶各一次；保级礼每次保级一次；生日礼每年一次；节日关怀按设置的日期每年一次（M33） |
| 服务与资格类 | 其余（会员通道、优先入场、VIP 柜、浴服、管家、代客泊车、衣物护理、贵宾厅……） | 会员详情列在「本月可享」里；设了次数的（每天 / 每月 / 每年）由服务的同事点「登记使用」，系统数次数，到上限拒绝；没设次数的只列出来，也可以登记留痕（M32） |
| 折扣类 | 包房房费折扣、同行优惠、会员日、停车折扣（4 项） | 第三期（v0.7.25）在结账时自动算；第二期只在清单里、不发放 |
| 制度说明 | 跨店余额通用（QY-056） | 只在清单里显示，不发放 |

会改收费的服务类（浴票延迟、VIP 柜、专属车位等）第二期只列为「可享」，VIP 柜照旧按「会员规则」里的档级核对；按收费规则自动执行放第三期（M35）。

## 3. 自动化

| 时机 | 系统自动做 |
| --- | --- |
| 每月第一天营业日开始（与每天的到期处理同一次巡检，先到期、再发券） | 已发布的月度券类：给够格的会员发本月的券；年度券类：每年第一个月发 |
| 充值升档、消费升阶、手动调整、上线 / 期初定档（同一事务里） | 补发本月（本年）差额；发升级礼 |
| 首笔充值入账 | 发首充礼 |
| 到期保级、补充期内保级 | 发保级礼 |
| 每天巡检 | 生日月的会员发生日礼（沿用 v0.7.20 生日礼的做法，按档阶）；到了设置的节日发节日关怀 |
| 新会员建档 | 「L0·会员」起点的月度券类当场发本月的 |

每次发放记一条发放记录（只追加，去重键防重复），会员详情、后台都能查；发券走现有的券（结账用券、作废照旧）。自检核对：发放不超过应得（同一会员、同一项、同一期发的张数不超过这期里档阶最高时应得的张数）；登记使用不超过次数。

## 4. 页面

- **管理后台「会员权益」**（店主、店总，新权限 `benefit.publish`）：清单按类别分组，每项一行（编号、名称、起点、类别、本期数量、券模板、状态）；导入按钮；编辑对话框（起点、类别、数量与周期、各档阶数量、券模板、事件、节日日期、内容与条件）；发布 / 暂缓；本月已发多少张、多少位会员。
- **会员详情「本月可享」**：按类别列出这位会员现在能用的权益——券类：本月发了几张、还剩几张没用；服务类：本期已用 / 上限，「登记使用」按钮（新权限 `benefit.use`，默认店员及以上）；事件礼：已收到的；折扣类：「第三期开通」。
- **数据看板「会员体系」**：加本月权益发放与使用汇总。

## 5. 数据（迁移 `041`）

- `benefits`：编号（唯一）、名称、类别、起点档阶（可空）、周期（每天 / 每月 / 每年 / 不计次）、数量、各档阶数量、券模板、事件、节日日期、内容、使用条件、状态（草稿 / 已发布 / 暂缓）、版本号、来源（导入 / 手工）。
- `benefit_grants`（只追加）：发放记录——会员、权益、期（2026-11 / 2026 / 事件键）、张数、对应的发券记录、原因（月发 / 补发 / 事件），去重键唯一。
- `benefit_uses`（只追加，作废留原因与经办人）：会员、权益、营业日、数量、经办人、备注、操作编号（走「结果待确认」）。
- 券的发券记录加种类「会员权益」；作废登记加「登记权益使用」。

## 7. 实现情况（v0.7.24）

按上面的设计做完，做的时候定的细节记在 `docs/PENDING_DECISIONS.md` M36–M43（待确认）。与设计稿不同或补充的地方：

- **清单**：59 项按会员文档原文导入；归类默认券类 11 项（设计稿的 10 项加暂缓的 QY-050 免费洗车，归券类方便以后直接选券发布）、事件礼 5 项、折扣类 4 项、制度说明 1 项、服务与资格类 38 项。导入、修改、发布、暂缓都记审计；修改带版本号，两人同时改后保存的被拒（`BENEFIT_CHANGED`）；没改内容的保存不加版本号。不能删除、编号不能改（数据库触发器兜底）；已发布的条件（有起点、券类与事件礼有券模板与张数、折扣类不能发布、服务类周期与次数配套）由数据库约束兜底。
- **发放**：每次发放一条发放记录（`benefit_grants`，只追加）+ 一条发券记录（种类「会员权益」）。券类的去重键带「发完以后这一期应得的累计张数」，事件礼的去重键带事件（`first`、`grade_up:e<状态变化>`、`tier_up:e…`、`retain:e…`、`birthday:<年>`、`festival:<日期>`），几个进程同时发也只发一次。档阶变化的当场补发、事件礼与状态变化在同一事务里（状态变化回滚，券也回滚）。
- **每天的自动发放**（`runBenefitsDaily`）：在会员到期处理之后跑；每页 500 位会员先在事务外算出谁还缺（本期券类、生日礼、节日关怀），只给缺的会员开事务、锁会员一行、按最新状态再核对一遍；运行记录一个营业日一条（`membership_job_runs.job = 'benefits'`），记开始时权益清单的版本合计，之后有人修改、发布、暂缓就同一天再跑一次。`membership-daily` 命令一并跑。
- **服务类登记**：`POST /api/members/:id/benefit-uses`（操作编号，走「结果待确认」，作废登记的业务类型 `benefit_use`）；本期已用 + 这次超过上限拒绝（`BENEFIT_LIMIT`，带已用与上限）；每条记下登记时这一期与上限，自检核对有效登记都没有超过。作废：`POST /api/benefit-uses/:id/void`（写原因）。
- **看得见**：后台「会员权益」（`/admin/benefits`）、会员详情「本月可享」、看板「会员体系 → 本月会员权益」；对账包「10-券」里会员权益发的券记为「发券（会员权益）」，经办人为空的写「系统（定时任务）」。
- **自检**加 4 项（共 60 项）：发放记录与发券记录一致；同一会员、同一项、同一期发的张数 = 这一期最大的应得累计；登记使用不超过登记时的上限；最近一次自动发放跑完、没有出错。
- **锁**：自动发放在调用方已经锁住的会员一行之后，对券模板加共享锁（与改模板串行），不锁权益（读已发布的）；登记使用：操作编号的咨询锁 → 会员一行 → 权益一行（共享锁）；作废登记只锁那一条；修改、发布、暂缓只锁权益一行。
- **没做的**：折扣类在第三期（v0.7.25）结账时自动算；会改收费的服务（浴票延迟、VIP 柜、专属车位）只列为「可享」（M35）；「到店次数达标」类的挑战活动对应 QY-057，会员文档写明暂缓，这一期不做。
