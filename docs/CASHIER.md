## 1. 部门营业额快照（v0.7.6）

**为什么**：部门（项目分类）原来是出报表时按价目里的分类现算的，以后改了项目的分类，已结账单的部门营业额也跟着变；优惠 / 免单只能整单单列，看不出各部门的净额。

**做法**：

- 结账时（手牌结账、桌台结账，记好收款之后）按这次要结的有效明细，记下每个部门、每个项目的数量与金额（表 `checkout_items`，只追加）；与结账金额一致。补录到更早时刻的结账也一样：之后才转走、作废的明细不算进来。
- 部门的分法与原来一样：门票、客房、其他（手动金额、赔偿等）、价目里的分类，没填分类的记「未分类」；房费按种类合并（房费（全天房）、超时半天、钟点房）。
- **优惠分摊**：这张结账单的优惠 / 免单按各项金额比例分摊，算到分；分以下的尾差按舍去部分从大到小逐项补 1 分（最大余数法），分摊合计正好等于优惠，每项不超过它的金额。例如门票 ¥499、搓澡 ¥68、修脚 ¥50，优惠 ¥10：先各分 ¥8.08、¥1.10、¥0.81（合计 ¥9.99），差的 1 分补给舍去最多的门票，得 ¥8.09。
- **反结账**：按原快照冲回（反结账那天记负数），与原来的口径相同。
- **以后改价目、改分类**：不影响已结的单，之后结的按新分类。
- **升级**：迁移 `025` 给已有的结账单补记（项目分类按升级时的）：没反结账过的结账单，它结的账单至今没动过，按这些账单现在的有效明细记；反结账过的按结账那一刻的明细重建（与原来的报表算法相同）。

**用在哪里**：

| 地方 | 显示 |
| --- | --- |
| 看板「经营总览」、今日看板的部门营业额、ERP 营业数据 | 柱条是应收（明细金额），备注写分摊到这个部门的优惠；只有优惠有变动的部门也列出（例如前一天的结账今天反结账、按同样的项目换了优惠重结） |
| 对账包「03-部门参考表.csv」 | 每个项目一行：数量、应收、优惠分摊、净额；部门小计、合计；后面单列应收、优惠 / 免单、净营业额，「核对」要应收与优惠都一致 |
| 自检 | 「部门营业额快照与结账单一致」：每张结账单的快照合计 = 结账金额，分摊的优惠 = 这张结账单的优惠 / 免单 |

## 2. 明细转到另一张手牌（v0.7.6）

**为什么**：项目挂错了手牌，原来只能作废再到正确的手牌上重挂，过了作废时限还要找店主。

**做法**：

- 前台账单「更多 → 明细转到别的手牌」：勾选一条或几条有效明细（一次最多 20 条）、填目标手牌、选原因，确认。
- 原明细作废，作废原因写明「转到手牌 X：原因」；目标手牌的账单新增同样的明细（来源、项目、名称、档位、单价、数量、技师不变，挂账人记办理的人）；记下转单记录（表 `bill_line_moves`，只追加）。
- **条件**：两位客人都在店，目标手牌不是这位客人；限女宾 / 男宾的项目只能转给同分区的客人。目标客人恰好在别的终端换了牌（锁好来访后牌号对不上）：拒绝（`TAG_CHANGED`），刷新后重新填。
- **权限**：与作废明细相同——有「前台更正」的岗位（店主、店总、值班经理）随时可以；其他人只能转自己在规定分钟内挂的。
- **不能转**：房费（随入住单走，挂错了在客房页换房或退房后处理）、餐饮的菜（有出品单，请退菜后在正确的手牌上重点）、钟房派的钟（有钟单，请在钟房处理）、门票。
- **结果待确认**：与挂账一样带操作编号，断网后查回 / 原样重提 / 确认作废；顶部「去处理」回到这位客人的转单对话框。
- **加锁顺序**：两位客人的来访（id 升序）→ 账单（id 升序）→ 明细（id 升序）。
- **自检**：「转单记录与明细一致」：原明细已作废、在原客人的账单上；新明细在目标客人的账单上，来源、项目、名称、档位、数量、金额、技师都相同。
- 对账包的异常清单照常列出作废的明细（作废原因写明转到哪张手牌）。

## 3. 退款单（v0.7.20，飞书需求 RQ-006 前半；设计稿）

店主 2026-11-02 合并 v0.7.19 后开工（v0.7.20，迁移 `037`）；同一版还做券与会员权益，见 `docs/COUPONS.md`。规则先按收银系统的常见做法定，标「待确认」，见 `PENDING_DECISIONS.md`「收银完善」。

**为什么**：客人离店后发现多收、项目没做或不满意，只退其中一部分。反结账是整单撤回在店未结：手牌要空着、会员不能在店，离店后常常办不了，也会把没问题的项目一起撤掉。

**做法**：

| 项 | 做法（待确认） |
| --- | --- |
| 入口 | 「结账记录」里的结账单（手牌结账、桌台结账）→「退款」 |
| 退什么 | 按结账单的项目选（同名项目合并成一行，与部门营业额快照同一口径）。每项可以只退一部分数量，金额默认退这几份的实收（应收减分摊到这项的优惠、券抵扣，按份数比例算到分），可以改小、不能超过（服务端同样核对：退几份最多退「这项剩下的金额 × 份数 ÷ 剩下的份数」，分以下舍去，尾差留给最后一份；Codex 预检 `1c8b453` P2）；数量可以填 0（只退钱、不退份数，例如服务打折补偿）；同一项可以分几次退，累计不超过数量与实收。不做不对应项目的「按金额退」（退款要能落到部门） |
| 退到哪里 | 按原收款方式退，只能退现金、微信、支付宝、银行卡、其他，每种累计不超过原单这种方式收的钱：现金从选定的钱箱退（与反结账同一套：原单收款的钱箱还在班上时默认选它，否则是自己的班次）；微信、支付宝、银行卡在商户后台原路退，登记商户后台的退款单号；「其他」写明怎么退的。会员储值、团购券、优惠 / 免单、券抵扣不能部分退——只用这些付的结账单请反结账 |
| 谁能办 | 值班经理及以上（新权限「开退款单」，后台「岗位权限」可调）；结账后超过撤销时限（默认 48 小时）只有店主。写原因（至少 2 个字） |
| 与反结账 | 反结账是整单撤销、账单回到未结；退款单是结账不动、另开一张冲减。**有生效的退款单的结账单不能再反结账**（`REFUND_EXISTS`；还要退就继续开退款单） |
| 作废退款单 | 登记错了：退款的营业日当天、记退款的钱箱班次还没交班时可以作废（同一权限，写原因）；作废后班次、日结、部门都不再算这张。交班后或过了营业日不能作废，请店主处理 |
| 断网 | 与结账一样带操作编号：结果待确认时查回、原样重提或确认作废 |
| 加锁 | 经办人的班次或所选钱箱的班次（共享锁）→ 结账单一行。退款不碰账单、来访与会员；反结账同样先锁结账单再核对有没有退款单，两边不会交错 |

**进账**：

- **营业额**：冲减**退款当天**的营业额，日结在营业额下单列「退款」（净营业额 = 应收 − 反结账 − 优惠 − 券抵扣 − 退款）；按退的项目记到部门：部门参考表、看板与 ERP 营业数据的部门营业额加「退款」一列（净额 = 应收 − 优惠分摊 − 退款）。
- **收款汇总**：按收款方式单列「退款」，实收相应减少；「营业额 = 所结账单 = 结账收款」的核对把退款两边一起减。
- **交班**：退款记到办理时的班次（现金记到所选钱箱的班次）：现金退款是应有现金的减项；微信、支付宝、银行卡、其他列出退款单号，只作提醒（钱在商户后台退）。
- **对账包**：新增 `09-退款单.csv`（每项一行：退款单号、原结账单、项目、数量、金额、退款方式与退款单号、经办人、原因、作废）；异常清单列出退款单与作废的退款单。
- **不动的**：会员储值与赠金、团购券登记、技师提成（服务已经做了）、明细与账单。
- **自检**：`check` 加「退款单与结账单一致」：退款合计 = 项目合计 = 退款方式合计；每项累计不超过数量与实收，每种方式累计不超过原单；反结账过的结账单没有生效的退款单。

**打印**：「结账记录」里可以打印 80 毫米退款凭条（单号、原结账单、项目、金额、退款方式、经办人、原因）。
