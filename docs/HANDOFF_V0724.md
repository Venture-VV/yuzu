# v0.7.24 交接说明 · 会员体系 v2 第二期：本店权益自动发放

店主 2026-11-03 合并 v0.7.23 后开工（会员体系分三期，这是第二期）。设计与实现情况见 `docs/BENEFITS.md`（第 7 节是这一期的实现），默认做法见 `docs/PENDING_DECISIONS.md`「会员体系 v2」M27–M35（设计时定的）与 M36–M43（做的时候定的），都待店主确认，店主不改就按它做。

不改收款口径：充值、消费、结账、日结、交班都不变；权益发的是券（结账用券照 v0.7.20 的规矩），服务类只登记次数、不收钱。

## 1. 范围

| 块 | 做了什么 |
| --- | --- |
| 本店权益清单 | 会员文档附录三 A「汤崎洗浴与会员服务」57 项与 F 补充 2 项（共 59 项），按编号、名称、配置起点、内容与使用条件原样导入；导入后全部是草稿，文档写明暂缓的 4 项（QY-035、QY-048、QY-050、QY-057）为暂缓；编号已有的跳过。归类默认：券类 11 项（含暂缓的免费洗车）、事件礼 5 项、折扣类 4 项、制度说明 1 项、其余 38 项服务与资格类 |
| 后台「会员权益」 | 店主、店总（`benefit.publish`）：按类别分组的清单（编号、名称、起点、数量、券、本月发了多少、状态）；一键导入；编辑（起点、类别、周期、数量、各档阶数量、券模板、事件、节日日期、内容与条件，带版本号）；发布 / 暂缓；不能删除。发布要条件齐全（起点、券类与事件礼要券模板与张数、服务类设了周期要填次数）；折扣类这一期不能发布 |
| 券类 | 每天营业日开始后的自动任务给够格的会员发本期（本月、本年）还没发够的券，有效到本期最后一天；充值升档、消费升阶、保级、手动调整、上线与期初导入定档时、新会员建档时，同一事务里当场补发差额；数量按会员现在的档阶取一行、不相加；降档不收回；暂缓后不再发、已发的照常可用 |
| 事件礼 | 首笔充值（首充礼）、充值升档与消费升阶（升级礼）、到期保级与补充期内保级（保级礼）、生日月（生日礼，每年一次）、设置的节日日期（节日关怀，当天起 7 天内、每个日期一次）；每项按事件去重 |
| 服务类 | 会员详情「本月可享」列出够格的；设了次数的（每天 / 每月 / 每年）由服务的同事「登记使用」，系统数次数，到上限拒绝（`BENEFIT_LIMIT`）；不计次的也能登记留痕；登记错的作废（写原因，本人当天的自己能作废，其他的要店主或店总）；登记走「结果待确认」 |
| 会员详情「本月可享」 | 按会员现在的档阶分券类（本期发了几张、能用几张）、事件礼（什么时候发、收到过几次）、服务与资格（本期用了几次 / 上限、登记使用）、制度说明；升档以后还能享的；最近的使用登记 |
| 看板「会员体系」 | 加「本月会员权益」：已发布几项、本月发券张数与人数（每期发放、当场补发、事件礼）、登记使用次数，每项的本月数字，自动发放的运行情况 |
| 自检 | `check` 加 4 项：发放记录与发券记录一致、每期发放不超过应得、登记使用不超过次数、自动发放正常运行；共 **60 项** |
| 命令 | `import-benefits --quote` 预览、`--apply` 导入（门店环境照真实数据导入的规矩，要店主同意）；`membership-daily` 一并跑自动发放 |
| 演示数据 | `demo-prepare` 加「会员体系」块（单独一个标记，已经准备过的演示库也会补上）：三位演示会员（将到期、补充期、刚降档）、导入清单并发布 4 项、本月的券 |

## 3. 验收要点

| 编号 | 项 | 怎么验 |
| --- | --- | --- |
| B1 | 导入清单 | 店主在「管理后台 → 会员权益」点「导入 59 项」：59 项全是草稿，QY-035 / 048 / 050 / 057 是暂缓；起点按文档（如 QY-004 浴票延迟 L1·尊、QY-051 首充礼 L0·会员、P021 行李优先寄存「未配置」）；再导入编号已有的跳过（`import-benefits --quote` 预览「跳过 59 项」）。值班经理、店员没有这一页（接口 403） |
| B2 | 发布的条件 | 券类不选券模板点发布被拒「请选择发哪张券」；P021（起点未配置）被拒「请先设配置起点」；折扣类的发布按钮灰着（接口被拒「第三期」）；各档阶数量不高于起点、券每期超过 10 张、服务类设了每月不填次数，保存被拒 |
| B3 | 版本号 | 两个页面同时打开同一项，一个先保存，另一个保存被拒「刚被别人改过」并刷新成最新的；没改内容的保存不加版本号；已发布的改完要还能发布 |
| B4 | 券类当场补发 | 发布 QY-040（选券、每月 1 张，加一行「L3·初 起 2 张」）；新会员首充 1 万升到 L2：会员详情「本月可享」券类「本月发 1 / 1 张 · 能用 1 张」，「账户内券」多一张，有效到本月最后一天、来源「会员权益」；再充 2 万升到 L3：补发 1 张（本月 2 / 2） |
| B5 | 每期发放 | 发布一项 L0 起点的月度券类（或把 QY-040 起点改到 L0·会员）：一分钟内（应用的巡检）所有在册会员收到本月的券；看板「本月会员权益」的「每期发放」随之增加；冻结的会员不发。下个月第一天的发放由 `tests/benefits.test.ts` 时间快进覆盖；手工验收不能快进，记「受阻未测」 |
| B6 | 首充礼 | 发布 QY-051（选券）：新会员第一笔充值入账后「事件礼 · 首充礼 · 收到过 1 次」，再充值不再发；已经有充值或期初的会员不算首充 |
| B7 | 升级礼 | 发布 QY-052（选券）：充值升档、储值消费升阶（L1 消费到 1,500 升享阶）各发一次；同一次充值连升几档只发一份、张数按升到的档阶；店主手动调整档阶不发 |
| B8 | 生日礼、节日关怀 | 发布 QY-020（L1·初 起）：生日在本月的 L0 会员升到 L1 当场发、一年一次；已经是 L1 的会员补填本月的生日，保存后「本月可享」当场有生日礼（再改日期不重发）；发布 QY-055 并填今天或前几天的日期：一分钟内够格的会员收到、每个日期一次。保级礼由 `tests/benefits.test.ts` 时间快进覆盖，手工记「受阻未测」 |
| B9 | 服务类登记 | 把 QY-001 设为每月 2 次并发布：L2 以上会员的「本月可享」显示「本月已用 0 / 2 次」；店员点「登记使用」两次后按钮灰掉，第三次接口被拒 `BENEFIT_LIMIT`；L0 会员登记被拒「从 L2·初 起才能享」；券类、事件礼、暂缓的、没发布的不能登记 |
| B10 | 作废登记 | 店员只能作废自己今天登记的，作废别人登记的 403；店主、店总能作废任何一条；作废写原因，作废后腾出次数、列表里显示「已作废：原因」 |
| B11 | 结果待确认 | 登记使用时断网、超时或回复 500：卡片上方「登记权益使用」结果待确认，「登记使用」按钮灰掉；查回、按原内容重新提交只登记一次；确认作废后原请求晚到被拒（`OP_ABANDONED`） |
| B12 | 看板与后台数字 | 「数据看板 → 会员体系」的「本月会员权益」与后台清单每项的「本月 N 张 · N 位 / N 次」一致；后台显示最近一次自动发放的营业日与结果 |
| B13 | 与发券规则的关系 | 「券与会员权益 → 发券规则」里还有启用的升级礼（或生日礼）、会员权益的升级礼（生日礼）也发布了：后台「会员权益」顶部提示会各发一份 |
| B14 | 演示与自检 | 新建演示库 `demo-prepare` 后 `check` **60 项**全 ✓、`demo-check` 通过；看板「会员体系」的到期提醒名单有「演示会员·将到期」、补充期名单有「演示会员·补充期」，今天的状态变化有「演示会员·刚降档」降档；三位演示会员的「本月可享」有本月的项目券 |
| U1 | 从 v0.7.23 升级 | 只应用 `041`；升级前的券、发券记录（含生日礼）、运行记录照常；权益清单是空的；`check` 全 ✓ |
