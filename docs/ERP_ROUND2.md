## 2. 草稿箱（03）

### 2.1 存在哪里

草稿存在服务端（表 `erp_drafts`），按人存：换一台电脑、换浏览器、重新登录都还在；只有本人看得到、改得了。不放在浏览器本机——门店的电脑几个人共用，本机存的草稿换台电脑就没了，也分不清是谁的。

草稿不是单据：没有单号，不进审核，不占预算，能改能删。表按「哪一类单据」留了字段（`kind`），这次只接需求单（新提的与退回后修改的）；报销单、采购单等以后要草稿时接同一张表，不用再加表。

### 2.2 什么时候存

- **每 30 秒**：填单页开着时每 30 秒看一次，内容与上次存的不一样就存（不弹提示，页脚小字显示「草稿已自动保存 14:02」）。一个字都没填的空白单不存。
- **离开时**：点返回、点别的菜单离开填单页时马上存一次，右上角提示「已保存草稿」；切到别的标签页、最小化、关标签页、关浏览器、刷新时也马上存一次（用浏览器的 `keepalive` 请求，页面关了也能发完）。关掉的页面没法再提示，下次进填单页时顶部会提示有草稿。
- 图片在选的时候已经传到服务器，草稿只记是哪几张；图片还在上传的那几秒先不算进草稿，传完的下一次保存带上。
- 上一张需求单「结果待确认」时不自动存（先把那一笔查回、重提或作废）。

### 2.3 进填单页与草稿箱

- 进「提需求」页：有没提交的草稿时，顶部显示「有未完成的草稿，是否继续填写」，写着最近一份的保存时间、部门与前几行的名称；「继续填写」把这一份填回页面；「草稿箱（N）」看全部；「先不用」收起提示（草稿还在草稿箱里）。
- 第一次自动保存以后，地址栏带上这份草稿的编号：刷新页面直接回到刚才填的内容。
- 「修改需求单」页（待审核、退回后修改）也有草稿：一张需求单一份。再进修改页时提示「上次改到一半的内容还在，是否继续」，可以继续或丢掉。
- **草稿箱**：「采购需求单」页右上角与填单页都能打开。列出自己的草稿（保存时间、还有几天过期、部门、几行、前几行的名称）；「查看」展开看每一行的内容与图片；「继续填写」；「删除」（先问一句）。每人最多 20 份，满了要先删。
- **提交成功**：这份草稿在提交的同一个事务里关掉，不会留着被再提一次。需求单通过、定为不采购、撤回以后，它的修改草稿一起清掉。
- **过期**：30 天没再保存的草稿自动清理（应用每分钟的自动任务里做）；草稿箱里写着「还有 N 天过期」。

### 2.4 两个页面同时开着、迟到的请求

- 草稿带版本号：同一份草稿在另一个页面（或另一台电脑）存过以后，这边再存会被告知「这份草稿在别处改过」，这边停止自动保存，不会悄悄盖掉；可以点「载入最新的」。
- 提交成功、手动删除的草稿不是马上删掉，而是先标「已关闭」（草稿箱里看不到），第二天由自动任务清掉：这样迟到的自动保存请求（页面关了才到服务器的）不会把它又建出来。
- 每次保存带一个保存编号：没收到回复、再发一次的同一次保存只算一次。

### 2.5 接口与数据

- `GET /api/erp/requests/drafts`：自己的草稿（摘要）。`GET /api/erp/requests/drafts/:key`：一份的全部内容。
- `PUT /api/erp/requests/drafts/:key`：保存。`key` 是页面生成的草稿编号（UUID）；带 `rev`（看到的版本，第一次是 0）、`saveId`（这一次保存的编号）、`requestId`（修改哪张需求单，新提的为空）、内容。
- `POST /api/erp/requests/drafts/:key/delete`：删除（标已关闭）。
- 权限：「提需求单」（`request.create`）；模块开关跟「采购需求单」。
- 内容不按提交的规则核对（草稿可以缺这缺那），只限长度与行数（最多 50 行、每行最多 9 张图）；图片要是已经上传的需求单图片。
- 只有「部门申购」权限的账号看图片原来只能看自己上传的、本部门与自己提的需求单里的；加一条：自己草稿里的图片也能看（同一张图别人先传过时，草稿恢复也看得到）。
- 加锁：保存、删除只锁草稿一行；提交需求单（操作编号的咨询锁之后、写完需求单）与修改、审核、撤回需求单（需求单一行之后）在最后关掉草稿——没有先锁草稿再锁需求单的路径。

## 3. 部门表格导入（02）

### 3.1 流程

「提需求」页右上角两个按钮：

1. **下载模板**：一份 Excel，三个工作表——
   - 「需求表」：表头一行、不合并；橙色表头必填、灰色选填；点到单元格有填写提示；部门、物品名称、用途、采购优先级是下拉（只能选，不能自己写）。
   - 「填写说明」：每一列怎么填、必填还是选填、例子。
   - 「选项」：下拉用的部门、用途、物料名称与编号（下载时的档案）。
2. **导入表格**：选 Excel（.xlsx）或 CSV → 「预览」逐行核对 → 没有问题的话「导入」。
   - 有问题的行整行标红，问题写在最后一列（第几行、哪一列、为什么），页面上方写「有 N 行要先改好」；有一行有问题整份都不导入（不会进一半）。
   - 没问题时写明合成几张需求单；确认后一次生成，都是「待审核」，与手填的一样走审核与每日截单。

列：`序号 | 申请部门 | 物品名称 | 物料编号 | 用途 | 数量 | 单位 | 采购优先级 | 期望到货日期 | 参考单价 | 参考链接 | 产品详情 | 备注`。必填：物品名称、用途、数量。列按表头的名字认，顺序可以换，多出来的列不管。

### 3.2 核对规则

| 列 | 规则 |
| --- | --- |
| 申请部门 | 要与部门档案里的名称一样、在用。部门申购只能给员工档案里的所属部门导入：空着按自己的部门，写了别的部门报错。店主、采购可以替任何部门导入（空着按自己的所属部门，没有所属部门的要填） |
| 物品名称 / 物料编号 | 物品要在物料档案里（受管、在用）：按名称认；档案里同名的有几个时要在「物料编号」写编号。不在档案里的报错——新产品要带参考链接和图片，请在页面上填 |
| 用途 | 费用用途的固定选项之一（与页面上的下拉一样） |
| 数量 | 大于 0，最多 3 位小数 |
| 单位 | 选填，空着按物料档案的采购单位；最多 8 个字 |
| 采购优先级 | 紧急 / 普通，空着按普通 |
| 期望到货日期 | 选填，不能早于今天；Excel 的日期格式、`2026-11-20`、`2026/11/20` 都认 |
| 参考单价 | 选填，元，最多 2 位小数 |
| 参考链接 | 选填，`http` 或 `https` 开头，最多 500 个字；单元格带超链接的取链接地址 |
| 产品详情、备注 | 选填，最多 200、100 个字 |

合成需求单：按「部门 + 优先级 + 期望到货日期」合，一张最多 50 行（与页面一样），超过的按顺序拆成几张。一份文件最多 500 行。

### 3.3 重复导入

部门的常规补货常常每周用同一份表，所以同一份文件允许再导入；预览时提醒「这份文件 X 月 X 日 XX 导入过」，要勾「确认再导入一次」才能导入。（集采导入照旧：同一份文件只能导入一次。）

连点两下、断网重试不会导入两次：导入带操作编号，与手填的需求单同一类「结果待确认」（没收到结果时在页面上方查回、按原内容重新提交或作废）。

### 3.4 接口与数据

- `GET /api/erp/requests/sheet/template`、`POST /api/erp/requests/sheet/preview`、`POST /api/erp/requests/sheet/import`，都要「提需求单」。
- 导入记录记在 `purchase_request_imports`（加 `kind`：`bulk` 集采、`dept` 部门）；需求单的来源加一类 `sheet`（部门表格导入），需求单上显示「表格导入」。
- 操作编号的业务类型用「部门需求单」（`purchase_request`）：权限、作废都与手填的需求单一样，不新加类型。
- 加锁：操作编号的咨询锁（与「确认作废」串行）→ 同一份文件的咨询锁 → 写导入记录、需求单（都是新行）。

## 4. 集采模板最终版（01）

### 4.1 模板

「采购 → 集采导入」的「下载模板」就是采购组的最终版：

- 第 1 行标题「品牌新增寻款采购清单」（合并），第 2 行表头：`序号 | 是否下单 | 是否到货 | 是否退货 | 产品名称 | 用途 | 采购数量 | 备注 | 产品详情 | 参考链接渠道`，列宽、冻结窗格与最终版一样。
- 「是否下单 / 是否到货 / 是否退货」是下拉：只能选「是」「否」。
- 橙色表头必填（产品名称、采购数量），灰色选填；点到单元格有填写提示；第二个工作表「填写说明」写每一列怎么填。表头的名字、顺序都没动。

### 4.2 导入怎么认

- **表头在哪一行自动找**：前 10 行里第一行同时有「产品名称」（或「物品名称」）与「采购数量」（或「数量」）的就是表头，上面的标题行不管。
- **列按名字认**，顺序可以换；8.0.1 旧模板的列（申请部门、申请人、物品名称、单位、数量、采购优先级、期望到货日期、采购途径、供应商名称）表里有的照旧认，旧模板填的文件照样能导入。
- **申请部门**：最终版没有这一列——在导入页上选「这份清单记在哪个部门」。表里有「申请部门」列的按表里的（空着的行按页面上选的）。
- **产品名称**：必填，最多 40 个字；与物料档案名称一样的带上物料，不一样的按新产品（导入的不要求链接和图片，与 8.0.1 一样）。
- **用途**：自由填写（最终版里是「客房漱口」「淋浴间」这样的），原样记在需求行的用途上，最多 20 个字；空着的记「其他」。
- **采购数量**：必填，大于 0，最多 3 位小数；写成「19个」「2 箱」的把单位拆出来。
- **单位**：最终版没有这一列——数量里带的单位 → 表里的「单位」列 → 都没有按「个」。
- **备注、产品详情**：最多 100、200 个字。
- **参考链接渠道**：单元格带超链接的取链接地址（显示的文字是网页标题，不记）；文字本身是网址的取文字；不是网址的当作渠道——认得出是网购、自采、供应商的记成采购途径，认不出的记在产品详情后面（「渠道：……」）。
- **是否下单 / 是否到货 / 是否退货**：只能是「是」「否」或空着，别的报错。这三列是采购线下跟踪用的，系统里的下单、到货、退货由采购单与收货单自动回写，不从表里导。**标了「是」的行（线下已经下单、到货或退货）默认不导入**——导进来会进「待转采购单」，容易再下一次单；预览里这些行标「不导入」。确实要把它们也记进系统的，勾「线下已下单的也导入」。
- 表里贴的图片不导入（最终版里图片是浮在表上的，对不到行）。

其余照旧：按「部门 + 优先级 + 期望到货日期」合成需求单，直接「已通过」进「待转采购单」；同一份文件只能导入一次；一份最多 500 行；有一行有问题整份不导入。

## 5. 不做的

- 报销单、采购单、付款申请等其他单据的草稿：表留好了，这次只接需求单。
- 部门表格导入不收新产品（不在物料档案里的）：新产品要图片，表格里带不了。
- 集采表里贴的图片不导入。
- 草稿不能转给别人、不能几个人一起改。

## 6. 迁移 `130`

- `erp_drafts`：草稿（编号、哪一类单据、谁的、修改哪张单、内容、图片、摘要、版本号、最后一次保存的编号、关闭时间与原因、时间）。
- `purchase_request_imports` 加 `kind`（`bulk` / `dept`）；「同一份文件只能导入一次」的唯一约束改成只管集采（`kind = 'bulk'`）。
- `purchase_requests.source` 加 `sheet`（部门表格导入），「导入的必有导入记录」的约束跟着放宽。

只加表、加列、放宽约束；旧数据：已有的导入记录都是集采（`bulk`）。不动操作编号与「确认作废」的两条约束。
