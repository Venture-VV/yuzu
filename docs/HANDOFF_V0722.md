# v0.7.22 交接说明 · 代码整理（让项目更轻便）与会员体系 v2 设计稿

店主 2026-11-03 合并 v0.7.21 后定：**看看项目里有没有屎山代码，做些优化，让整个项目更轻便**；同时理解店主发来的《福田店与宝安店会员体系》（2026-11-02），设计怎么开发（设计稿 `docs/MEMBERSHIP.md`，这一版不写会员体系的代码）。迁移 **`039_payment_fences.sql`**（只放宽约束）。重构不改业务口径：金额、日结、交班、部门参考表、自检的结果都不变，`check` 仍 **53 项**；按普通候选版本验收（快速开发周期：CI 全绿后店主合并，验收在 main 的 v0.7.22 标签上补做）。

- **阻断项**：
  - 重构后任何金额、日结、交班表、部门参考表、对账包、`check` 的结果与 v0.7.21 不同（这一版不该改任何业务口径）。
  - 某个页面打不开、一直转圈，或断网后打开新页面时整页白屏（应显示「这一页没有加载出来」和「重新加载」）。
  - 登记付款、期初未付登记：同一笔登记成两笔；确认作废后原请求又登记上；刷新后「结果待确认」不见了；有待确认的一笔时还能另起一笔。
  - 越权：没有「登记期初未付、付款、核销与供应商退款」的人能作废付款、期初未付；没有「查看供应商货款与对账」的人能查回。
  - 导入（会员期初、手牌柜号、价目表）多导、少导或导错行；引号里的换行把一条记录拆开。
  - 两人同时保存规则，一方的修改丢了。
  - 升级后原有数据变了，或 `check` 在升级后的库上不全 ✓；演示数据命令在试用、正式环境写入了数据（与之前相同）。
