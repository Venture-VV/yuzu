## 0. 一句话

员工手机上打开 **柚子饭堂**（第一次打开，看板娘柚子会先打个招呼，然后带你登记、走一遍新手教程）：看今天吃什么、给喜欢的菜点个赞、到饭堂门口亮出 **饭卡码**、有话「跟柚子说」；**食堂负责人**用手机一扫，打卡就记进 yuzu。**厨师**在手机上发布每天的菜单。yuzu 后台（ERP「员工食堂」）管名单、打印开通卡片、看用餐记录。

## 1. 谁用、用来做什么

| 谁 | 在哪儿用 | 能做什么 |
| --- | --- | --- |
| 员工（所有人） | 手机：柚子饭堂 | 第一次打开时自己登记（用户名、手机号、密码）；今天 / 明天 / 这周的菜单；给菜点赞；亮出饭卡码；看自己这个月吃了几顿；换个头像；「跟柚子说」心愿和碎碎念 |
| 厨师（食堂部门） | 手机：柚子饭堂「厨房」 | 以上全部，加上编辑、发布菜单（复制昨天的一键带出），看每道菜收到几个赞 |
| 食堂负责人（食堂部门） | 手机：柚子饭堂「厨房」「扫码」 | 以上全部，加上扫码打卡、没手机的同事手动登记、撤销登记错的、看今天每餐多少人 |
| 管理员（店主、店总） | 电脑：yuzu → ERP →「员工食堂」 | 开关模块、选食堂部门、设开饭时间；注册二维码（开关自己注册、打印海报）；员工名单（单个加、粘贴一批加、停用、安排厨师和负责人）、打印开通卡片、重新开通；看菜单、用餐记录（筛选、撤销、导出）；「柚子信箱」看员工说的话、回信 |

- 员工账号与 yuzu 的系统账号（`staff`）**分开**：员工账号只能登录柚子饭堂，进不了管理后台，也没有任何 ERP 权限；系统账号的登录也进不了柚子饭堂。
- 员工自己登记**不要注册口令**（店主 2026-11-07）：管理员在后台打开自己登记以后，拿到员工入口地址（注册二维码、员工群里的链接）的人都能登记成普通员工；管理员可以随时关掉，名单里看得到谁是自己注册的、不认识的停用就好（第 14 节）。厨师、负责人只能由管理员在后台安排；食堂负责人在手机上只能搜名单、手动登记。

## 3. 架构

```
员工手机（浏览器，可添加到桌面）
   │ HTTPS  staff.<域名>（备案后；备案前见第 9 节）
   ▼
网关服务器上的 Caddy（与小程序同一台：只做 HTTPS 与转发）
   │ Tailscale（只放行网关服务器到门店 yuzu 的员工端口）
   ▼
门店 yuzu · 员工端口 CANTEEN_PORT
   │ 单独的 Fastify 实例：只有柚子饭堂的页面与 /api/canteen/*；没有管理后台、没有别的接口
   ▼
yuzu 数据库（名单、菜单、点赞、打卡都在这里）← 管理后台 ERP「员工食堂」直接读写
```

- **为什么不再建一个库同步**：食堂只是名单、菜单和打卡，没有必要维护两份数据和一套同步协议（还要两边分别备份、恢复时对齐版本号）。小程序已经定了「公网服务器只转发、数据只在门店」，柚子饭堂照同一个做法，部署时只是在同一台网关服务器的 Caddy 里多加一个站点。
- **员工端口的边界**：只挂柚子饭堂的静态页面和 `/api/canteen/*`；写请求核对来源（Origin 与 Host 一致）；会话 Cookie 单独一个名字（`yuzu_canteen_sid`，HttpOnly、SameSite=Strict，HTTPS 时加 Secure）；登录、开通按工号与来源 IP 限次；请求体上限 32 KB。主端口上没有 `/api/canteen/*`，员工端口上也没有 `/api/erp/*`。
- **模块开关**：ERP 注册表里加模块「员工食堂」（分组「员工服务」，**默认关**）。关着时后台接口按 ERP 规则拦截，员工端口的接口一律回「饭堂还没开张」。没设 `CANTEEN_PORT` 的实例不开员工端口，其余一切照旧。
- **门店系统连不上时**：员工照样能亮码（离线生成）、能看上次打开时的菜单；负责人扫到的码先存在手机上，显示「已记下，联网后自动补登」，恢复后按原操作编号补交（第 6 节）。

## 5. 饭卡码

- **离线生成**：登录后手机拿到一把只属于自己的码钥匙（`HMAC(CANTEEN_CODE_SECRET, 员工编号 + code_epoch)`，服务端不存、随时能算出来）。饭卡码每 **30 秒**换一次：`YZC1:<员工编号>:<时间段>:<签名>`，签名是码钥匙对时间段的 HMAC 取 8 位。手机按上次联网时记下的服务器时间差修正本机时钟。
- **服务端核验**：负责人扫到码交给 yuzu，按扫到的时间核对时间段（前 90 秒到后 30 秒内的都认）、签名、员工是否启用。签名用常量时间比较。
- **一码一用**：同一人同一餐只记一次，所以同一个码再扫只会提示「已经打过卡啦（几点几分）」，不会多记。
- **作废**：管理员停用员工、重新开通（忘了密码）时，`code_epoch` 加一、员工端会话全部删掉：旧手机上的码钥匙随之失效，马上扫不进。
- **能防到什么程度**：码不是固定的工号，截图一分半钟后就失效；转发出去的码只能用一次，本人再来就会提示已打卡。负责人看到的是姓名、工号、部门和头像，当面核对；这不是门禁闸机，挡不住有人尾随进门。

## 6. 打卡规则

- **餐次**按扫到的时间落在哪个开饭时间里：默认早餐 07:00–10:00、午餐 10:30–14:30、晚餐 16:30–20:30，夜宵 22:00–次日 01:00 默认不开（后台可改、可开，K2）。跨午夜的夜宵记在开始那天。不在开饭时间扫码，提示「现在不是开饭时间」并列出时间。
- **每人每餐一次**（K3）。重复扫码不是错误，黄色提示「已经打过卡啦」。
- **手动登记**：同事没带手机、手机没电时，负责人搜名字或工号点一下登记，记为「手动」（可写一句备注）。
- **撤销**：负责人当天可以撤销自己登记错的（写原因），管理员在后台随时可以撤销；撤销只做标记、不删记录。
- **断网补登**：负责人手机发不出去或结果不明（超时、服务器出错）时，先把这一笔（操作编号、码、扫到的时间）存在手机上并读回核对，**存不下就不发**；之后每 10 秒、以及恢复联网时按原操作编号原样补交，直到拿到明确结果。服务端按扫到的时间核验码，只收 24 小时内扫到的（K5）。补登结果在扫码页列出：成功几条、哪几条无效（例如码过期、员工已停用）。
- 同一个操作编号重复提交，返回第一次的结果（并发也只记一条）。

## 7. 菜单与点赞

- 每天每餐一份菜单，最多 30 道菜，每道菜名最多 20 个字，可选一个表情（按菜名自动带出，例如「鱼」🐟、「鸡」🍗、「面」🍜，厨师可以改）和标签：辣 🌶、素 🥬、新 ✨、招牌 ⭐；一句话备注最多 100 字。
- 厨师和负责人可以保存草稿、发布；员工只看得到已发布的。改菜单带版本号：两个人同时改，后保存的提示「菜单刚被别人改过」，看过最新的再改，不会互相覆盖；这次要存的内容放回编辑框，「用我的覆盖」存的就是它，照原来要的发布或存草稿（刷新以后才重试的也一样）。每次保存先把操作编号与内容存在手机上并读回核对（存不下就不发）；回复没收到时，刷新、关掉再开也还在，只能原样重试（同一个操作编号、同一个版本号，会拿到同一个结果），确认之前不能存别的；重试被拒时，只有能说明原来那次以后也不会生效的才放下：「菜单刚被别人改过」（版本号已经过去）、内容本身不对（原来那次是同样的内容）、这一天已经过了能改的日子（日子只会往后走）；没登录（重新登录以后再原样重试）、没权限、饭堂暂时关着、正忙都说明不了，照样留着。某一天的菜单没取到时不能保存（不会把上一份的菜存过去）；保存成功的回复回来时厨师已经换到别的日子、餐次的，只把这一笔从手机上删掉（确认了），现在这一份照常能改。
- 「复制昨天」「复制上周同一天」把那天的菜带进编辑框，改一改再发布。
- 点赞：员工给喜欢的菜点 ❤️，再点取消；厨师在厨房页看到每道菜几个赞，后台菜单页也能看到。

## 8. 开通与登录

0. **自己登记（第二期，主要的办法）**：管理员在「设置」里打开自己登记，把注册二维码发到员工群或贴在饭堂（不要注册口令）；员工扫码打开，看完开场动画，在「新同事登记」填用户名、手机号、密码就开好账号、直接进去（第 14 节）。下面后台加人、开通卡片的办法照旧能用，给没手机、不方便自己登记的同事。
1. 管理员在后台加人（单个加，或把「工号 姓名 部门」一行一个粘贴进来，先预览再加），然后**打印开通卡片**：每人一张小卡片，有「柚柚」、姓名、工号、二维码和 8 位开通码，7 天内有效（K6）。
2. 员工用手机相机扫卡片上的二维码（或在登录页点「我有开通码」手动输入），看到「欢迎你，某某」，设一个至少 6 位的密码，就进来了。
3. 登录时用户名、手机号、工号都认（K13）。之后 30 天不用再登录（用着就一直顺延，K7）；换手机、忘密码时管理员点「重新开通」打一张新卡片，旧手机上的登录和饭卡码马上失效。
4. 同一个工号连续输错 5 次密码锁 15 分钟；同一个来源 IP 10 分钟内最多试 30 次（K8）。
5. 第一次打开会教员工「添加到桌面」：iPhone 用 Safari 的分享 → 添加到主屏幕（iOS 26 的分享在地址栏旁边的「···」里），安卓用浏览器的「安装应用」；用 http 打开时说明里提示换管理员给的 https 网址再添加（http 下亮不了饭卡码、没网打不开）。在微信里打开会提示「点右上角 ··· 在浏览器打开」（微信里不能添加到桌面，扫码页也可能用不了相机）。

## 9. 上线步骤

**代码合并后、备案之前（测试环境跑通）**——只在测试服 A 的演示库（`yuzu-demo`）上开，不在门店试用库、演练库上开：

1. 演示库那台的 `.env` 叠加 `compose.canteen.yaml`，设 `CANTEEN_PORT`、`CANTEEN_CODE_SECRET`（`openssl rand -hex 32`）。
2. 在测试服 A 上用 `tailscale serve` 把员工端口发成 tailnet 内的 HTTPS 地址（带有效证书，相机和添加到桌面都能用）；参加测试的手机装 Tailscale 加入店主的 tailnet 就能打开。也可以用香港的服务器挂 Caddy 转发（不用备案，但跨境网络不保证稳定）。员工端一定要用 HTTPS 打开：用 http（例如局域网 IP）打开时亮不了饭卡码、负责人也扫不了码（浏览器只在 HTTPS 或本机 localhost 下给加密与相机），登记、登录、看菜单照常。
3. ERP「模块设置」打开「员工食堂」，「员工食堂 → 设置」选食堂部门、核对开饭时间、填员工入口地址；加几位测试员工、打印开通卡片，按第 12 节的清单在 iPhone 和安卓真机上走一遍。

**备案之后（正式）**：网关服务器的 Caddy 加一个站点 `staff.<域名>`，转发到门店 yuzu 的员工端口（经 Tailscale，规则只放行网关服务器到这个端口）；门店 yuzu 叠加 `compose.canteen.yaml`、设 `CANTEEN_COOKIE_SECURE=true` 与 `CANTEEN_TRUST_PROXY=<网关服务器的 Tailscale 地址>`，`CANTEEN_BIND` 设成门店那台的 Tailscale 地址（默认只监听本机 127.0.0.1，适合 `tailscale serve`）。部署照旧由 Codex 按 `main` 的版本标签做，开不开由店主定。

```
# 网关服务器的 Caddyfile 里加一段（示例）
staff.<域名> {
  reverse_proxy <门店 yuzu 的 Tailscale 地址>:8090
}
```

| 环境变量 | 说明 |
| --- | --- |
| `CANTEEN_PORT` | 员工端口；不设就不开（默认不开）。不能与 `PORT`、`MP_PORT` 相同 |
| `CANTEEN_HOST` | 员工端口监听的地址，默认同 `HOST` |
| `CANTEEN_CODE_SECRET` | 饭卡码的密钥，至少 32 个字符；开了员工端口就必须配。换了它所有人的饭卡码要重新打开柚子饭堂（联网一次）才能用 |
| `CANTEEN_COOKIE_SECURE` | 员工端走 HTTPS 时设 `true` |
| `CANTEEN_TRUST_PROXY` | 前面的转发服务器的地址（逗号分隔，可写网段）；限次按它转来的真实来源 IP 算。不设就不信任转发头 |

## 15. 新手教程（第二期）

登记好（或第一次登录）以后接着走，柚子在旁边说话、指着要点的地方；**要员工自己点一下才往下走**（点别处不算），右上角能跳过，「我的」里能再走一遍（K15）。要指的东西 2.5 秒还没出来（例如不是 HTTPS 打开的、这台手机亮不了饭卡码）时照常显示说话框，能「下一步」、能跳过，不会整屏挡住。

1. 首页：现在这一顿吃什么，一眼就能看到。
2. 点赞：给一道示例菜点个 ❤️ 试试（教程里的示例，不记进菜单）。
3. 点底部中间的「饭卡码」：开饭时给食堂负责人扫一下就打卡了；码 30 秒一换，截图没用，没网也能亮。
4. 点「跟柚子说」：想让柚子做的事、碎碎念都可以写在这里。
5. 点「我的」：换头像、看这个月吃了几顿，还能再看一遍开场和教程。
6. 厨师多一步「厨房」（写菜单、发布），负责人多一步「扫码」。最后柚子欢呼：开饭愉快！

## 16. 跟柚子说（第二期）

- **员工**：首页有「跟柚子说」的一栏（普通员工的底部导航也有这一项，厨师、负责人那一格是「厨房」）。选「想要柚子做的」或「碎碎念」，写最多 500 字，点「交给柚子」——信封飞进柚子的信箱。下面列着自己说过的话、柚子（管理员）看过没有、回信。每人每天最多 20 条（K16）。
- **结果待确认**：发出去没收到回复时，这一条（操作编号与内容）先存在手机上并读回核对，存不下就不发；页面上显示「这一条还没确认送到」，只能原样再发（同一个操作编号，不会存两条；联网或再打开这一页时也会自动原样再发），确认之前不能发新的。再发被拒时，只有能说明原来那次也不会生效的才放下、把内容放回输入框：内容本身不对、今天说太多了（门店系统先按操作编号找那一条，有就原样给回）；没登录（重新登录以后再发）、饭堂暂时关着等都照样留着。
- **管理员**：ERP「员工食堂 → 柚子信箱」：没看过的排前面，按种类、看过没有筛选；点「看过了」、写一句回信（最多 300 字，回信自动算看过）；导出表格。
- **回信的结果待确认**：回信带操作编号，走 ERP 的那一套（`sendErpOp` + `ErpPendingPanel`，迁移 `092` 给「确认作废」加了业务类型 `canteen_reply`）。没收到结果时记录留在这台电脑上，关掉对话框、刷新以后柚子信箱上面照样列着：能查回、按原内容重新提交（同一个编号只记一次，之后改过的回信不会被它改回去），或确认作废（原请求晚到也不会改回信）；没确认之前这一条不能再回信。
- 接口：员工端口 `GET/POST /api/canteen/feedback`；管理后台 `GET /api/erp/canteen/feedback`、`POST /api/erp/canteen/feedback/:id/read`、`POST /api/erp/canteen/feedback/:id/reply`（带 `clientKey`）、`GET /api/erp/canteen/feedback.csv`；查回、作废走 `/api/erp/ops`。
