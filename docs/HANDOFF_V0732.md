# v0.7.32 交接说明 · 付款流

店主 2026-11-06 合并 v0.7.31（#66）后开工：财务、法务审批分期（`docs/ERP_FINANCE_LEGAL_PLAN.md` 第 4.3 节）的第三期「付款流」。

- 设计稿 `docs/PAYMENTS.md`，规则没定的按默认 P1–P12（`docs/PENDING_DECISIONS.md`「付款流」，待确认）：计划金额按分取整、最后一段补齐（P1），各段的可付条件（P2），质保起算（P3），变更后多付只显示（P4），付款申请的审批链（财务 → 负责人，≥ ¥50,000 加店主，P5），提前付款多一级店主（P6），按申请付款不再审、挂合同的货款必须先提申请（P7），三单门槛 1% 且 ¥50（P8），质保金到期前 30 天提醒（P9），权限（P10），本周应付四周（P11），结项（P12）。
- 不动收款、钱包、交班与库存账。**没挂合同的采购单与付款登记与 v0.7.31 一样**（照旧可以直接登记付款、走原来的付款审批）；有两处行为变化：① 挂了合同的采购单的收货单不能再直接登记付款（要走付款申请，`PAYMENT_REQUEST_REQUIRED`）；② 挂了合同的采购单提交时不再要求询价（价格按合同的单价表，C9）。

入口：

- ERP 导航新的「财务」分组「付款」（`/erp/payments`）：五个标签页——付款申请（全部、审批中、已退回、待付款、已结束、我发起的；搜申请号、收款方、合同号、用途）、发票、三单（待处理 / 全部）、质保金、本周应付；右上角「发起付款申请」。导航上的数字 = 批了待付款的申请（登记付款的人才算）+ 到期前 30 天的质保金。
- 合同详情（`/erp/contracts/:id`，审批通过以后）：「付款计划」卡（每一段的计划、现在可付、在途申请、已付与说明，「申请付款」/「提前申请」），下面是验收登记与质量问题。
- 付款申请详情（`/erp/payments/requests/:id`）：审批进度与「审批」按钮（与审批中心同一个对话框）、撤回、改了再提交、作废、登记付款 / 登记合同付款、结束；这一段现在的情况；三单匹配与放行；按这张申请登记的付款。
- 审批中心：两种新单据（付款申请、提前付款），详情里看得到合同这一段的条件、三单、供应商往来余额；提前付款不能勾选批量。
- 应付货款：多一个「其中质保金（未到期）」卡片与表格列。采购单详情：三单匹配（采购单金额、已收货、已开票、状态）。
- 新权限「发起付款申请」（后台「岗位权限」可改：店主、店总；采购、对账付款职责）。

## 3. 验收要点

1. **升级不改数据**：在 v0.7.31 的库上升级，`check` 全 ✓（多一项 `payments`）；没挂合同的采购单、付款登记、期初未付与 v0.7.31 一样（直接登记付款照旧走付款审批）。
2. **付款计划**：新建一份采购合同（相对方从供应商档案里选，单价表每行选物料），走完审查、登记签署。合同详情的「付款计划」：预付段签署后整段可付；到货段说明「还没有生效的收货单」；验收段「还没登记验收」；质保段写明质保期到哪天。每段的计划金额按分取整、四段合计等于总价（比例除不尽时最后一个比例不为 0 的段补差额）。审批通过以前的合同详情里没有付款计划；审批通过、还没登记签署的看得到计划、不能申请（说明「签署以后才能申请付款」，接口拒绝 `CONTRACT_NOT_PAYABLE`）。
3. **付款申请与审批**：在预付段点「申请付款」，金额默认 = 这一段还能申请的，改得比计划 − 在途 − 已付大时拒绝（`REQUEST_OVER_PLAN`）；提交后审批中心出现「付款申请」，没建规则时财务 → 负责人两级（申请金额 ≥ ¥50,000 三级，最后一级店主）；审批中撤回、退回后「改了再提交」从第一级重走，没付过钱的可以作废（写原因）。新建时断网或服务器出错 → 页面上方「结果待确认」，刷新后还在；查回、按原内容重新提交只建一份，确认作废后原请求晚到也不建（`OP_ABANDONED`）。
4. **提前付款**：还没到条件的段（例如到货段）点「提前申请」，或金额超过现在可付的，要勾「提前付款」写原因，不勾拒绝（`EARLY_REQUIRED`）；审批中心是「提前付款」，财务 → 负责人 → 店主三级，不能勾选批量（接口批量同意也拒绝 `APPROVAL_NO_BATCH`）。
5. **按申请登记付款**：批完的申请是「待付款」，登记付款的人在申请上「登记付款」——不再走付款审批、登记即确认；预付段记为预付款，到货、验收、质保段核销到这份合同的采购单的收货单（选别的收货单拒绝 `ALLOCATION_NOT_IN_CONTRACT`）；金额超过申请里还没付的拒绝（`OVER_REQUEST`）。付清了变「已付清」；付一部分以后「结束」（写原因）；当月冲销这笔付款，申请回到「待付款」。没收到结果时同样「结果待确认」，重提只记一笔。
6. **挂合同的货款必须走付款申请**：在「应付货款」直接登记付款、核销到挂了合同的采购单的收货单 → 拒绝（`PAYMENT_REQUEST_REQUIRED`，提示先在「付款」里提申请）；把没带申请的预付款核销到这些收货单上同样拒绝；带申请的预付款照旧能核销。没挂合同的照旧可以直接付。
7. **到货段与三单**：开一张挂这份合同的采购单（不再要求询价）、提交、确认，按单收货一部分：到货段按已收货占合同总价的比例放开（说明里写着已到货多少）。申请到货款 → 三单不齐拒绝（`THREE_WAY_NOT_MATCHED`）；在「发票」登记发票分到这张采购单（同一供应商同一号码再登记拒绝 `INVOICE_DUPLICATE`），开票与收货差额在 1% 且 ¥50 以内即「对得上」，可以申请；差额超过的挂起，在「三单」或申请详情里写原因「放行」（记下当时三个金额），之后退货、作废发票等让金额变了，放行失效、要重新放行。采购单详情里看得到三单的状态。
8. **验收与质保**：合同详情登记验收（不合格要写怎么处理），合格后验收段可付；登记一条质量问题 → 质保段挂起（说明里写有几条未处理的）、质保金台账显示「有质量问题挂起」；标记已处理后恢复。验收、质量问题登错了作废（写原因）。质保期满（按合同的起算依据与月数）且没有未处理的问题时质保段可付；「质保金」标签页的状态（未起算 / 未到期 / 30 天内到期 / 可付 / 有质量问题挂起 / 已付清）与导航数字（到期前 30 天、含已到期没付的）。
9. **服务、租赁、其他合同**：相对方不在供应商档案里也能申请；批了以后申请上是「登记合同付款」（单号 `HF…`），不进供应商往来、应付货款里看不到；当月冲销后申请回到待付款。到货段在验收合格后整段放开。
10. **没挂合同的应付**：「发起付款申请」→「没挂合同的应付」，选供应商后列出这家没结清的收货单、期初未付；挂了合同的收货单标「从合同申请」、不能选；同一笔已经被别的没结束的申请占着时，再申请超过剩下的拒绝（`OVER_REQUESTED`）；批了以后登记付款只能核销到申请里选的货款（`ALLOCATION_NOT_REQUESTED`）。
11. **本周应付**：从本周一起四周，每周列出已批待付（按期望付款日）、可付还没申请的合同段、到期的质保金，每周与四周合计；填「可用资金」显示缺口（只在本机）；「导出」下载 CSV。周一打开「付款」页顶上提示本周应付。
12. **应付货款的质保金**：有质保段、还没到期的合同，供应商往来里「质保金（未到期）」一列显示质保段还没付的部分（不超过余额），总览多一个卡片。
13. **权限**：部门账号（只有「部门申购」）看不到「付款」（接口 403）；采购职责能发起申请、不能登记付款；对账付款能登记付款、发票、放行；负责人、成本核算能看不能改；「付款」模块关掉后页面提示没有开启、接口拒绝（`ERP_MODULE_DISABLED`）。
14. **手机**：竖屏手机的审批中心打开付款申请，详情里看得到合同这一段的条件与三单，底部「同意」「退回」可用，页面不横向滚动。
