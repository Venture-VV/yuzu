- **v0.7.8**（迁移 `027`）：部门采购需求单、采购单的图片与规格（`docs/REQUISITIONS.md`）；另修正 v0.7.7 合并时 Codex 审查的四条（本文件第 4、7、9 节，以及第 8 节的导出）。
- **v0.7.9**（迁移 `028`，需要时）：采购台账、费用报销、需求单、下单物料四个视图与导出；12 条账目自检；8–10 月旧账只读对照。

## 1. 三种单据

| 单据 | 单号 | 是什么 | 谁登记 |
| --- | --- | --- | --- |
| 备用金打款 | BY | 公司把钱打给某个部门的经办人去采购。按部门记账（D14），经办人留名，个人经手的金额可以单独查 | 对账付款、成本核算 |
| 费用报销 | BX | 一次支出登记成一张：按采购单报销（现付供应商的采购单），或按次报销。钱从哪来：**备用金**（必须选出自哪一笔打款）或**公司直付** | 成本核算 |
| 退回 / 补付 | TH / BF | 经办人把没花完的钱退回公司（退回），或者花超了由公司补给经办人（补付），记在对应的那笔打款上 | 对账付款、成本核算 |

打款、退回、补付登记即生效；登记错了由负责人冲销（写原因），不删除、不修改。

## 2. 平账

每一笔打款单独平账，只算已确认的报销：

| 栏 | 算法 |
| --- | --- |
| 打款 | 这笔打款的金额 |
| 支出 | 用这笔钱、已确认的报销合计（待确认的单列「待确认」，确认后才算进支出） |
| 应退回 | 打款 − 支出 |
| 实际退回 | 退回 − 补付 |
| 未退回 | 应退回 − 实际退回 |

- 未退回 = 0：**已平**。
- 未退回 > 0：经办人手里还有钱没退。从打款日起超过 7 天（可调，待确认）标红「超期未退」。
- 未退回 < 0：经办人垫了钱（花超了，或多退了），等公司补付，标「待补付」。

退回不能超过未退回，补付不能超过待补付。

**每日平账**：按付款日（打款日期）与部门汇总上面五栏；当天有一笔没平，整天就显示「未平」，并列出是哪几笔。也可以按经办人看（个人经手）。

## 3. 费用报销

| 项 | 做法（待确认） |
| --- | --- |
| 发票类型与税点 | 固定选项、互相校验：增值税专用发票（1%、3%、6%、9%、13%）、增值税普通发票（0、1%、3%、6%、9%、13%）、收据（0）、无票（0）。店主可在 ERP「模块设置」里改 |
| 发票号 | 专票、普票必须填发票号码；标了有发票却没有发票号的直接拦下（12 条自检的第 11 条） |
| 费用科目 | 只有办公费、固定资产、低值易耗三种（文档原话），每一行单独选 |
| 用途 | 固定选项，店主可改；默认：客用消耗、员工用品、办公、维修保养、装修改造、营销活动、餐饮原料、其他 |
| 部门、经办人 | 部门从部门档案里选（不能把几个部门拼在一起），经办人从员工里选 |
| 购买与到货数量 | 每一行都要填；不一致时必须写差异原因。按采购单报销时，购买数量取采购单，到货数量取已生效的收货（按库存单位），不能改 |
| 金额 | 每一行一个金额（实际付的，可以和采购单的价格不一样），整张单的金额是各行合计 |
| 确认 | 单笔超过 2000 元（D13，店主可在「模块设置」里改）要负责人确认，进「审批待办」；不超过的登记即确认。负责人自己登记的可以同时确认 |
| 退回与撤回 | 负责人可以退回待确认的报销（写原因），登记人重新提交或撤回 |
| 冲销 | 已确认的报销由负责人冲销（写原因）；冲销后这笔钱退回备用金的平账 |

## 4. 现付供应商与按采购单报销

原来的应付货款是给「挂账」供应商用的：收货时记应付，月结或按批次付款核销。网购、市场采购是下单时就由经办人付清的，如果收货照样记应付，同一笔钱会在应付货款和费用报销里各记一次。所以：

- 供应商档案加「**结算方式**」：**挂账**（月结或按批次结算，默认，原来的做法）/ **现付**（下单时由经办人用备用金或公司账户付清）。
- **现付供应商的收货不记应付**：收货单确认时记下当时的结算方式；货款走费用报销。改供应商的结算方式只影响之后确认的收货。
- 退给现付供应商的货也不记应付扣款。供应商退回的钱先按「冲销原报销单、按实际金额重新登记」处理；正式的供应商退款单在 RQ-002 做（Batch 4 #20、#25）。
- **按采购单报销**只能选现付的采购单（已确认或已关闭）；采购单的每一行只能报销一次，报销单撤回或冲销后可以重新报。
- **一张采购单只有一种结算方式**（v0.7.8 修正）：以第一张生效的收货记下的为准；还没收货但已按采购单报销的算现付；都没有才看供应商当前的设置。所以供应商改了结算方式之后：挂账时已收货（记了应付）的采购单不能再报销；现付时已报销的采购单，后面的收货也按现付、不记应付。同一笔货不会既在应付里付、又在报销里报。
- 挂账供应商照旧在「应付货款」里付款核销，不能按采购单报销。
- **待报销与一键转报销**（v0.7.29，`docs/ERP_PURCHASING.md` 第 3 节）：「费用报销」页顶上列出现付、已确认或已关闭、还有没报销的行的采购单；采购单详情有「报销」一栏与「转报销」。转报销打开登记页并带好没报销的行、金额、采购途径、经办人、部门、上次的用途与科目、经办人在这个部门最早没平的打款，核对后提交；上面的规则都不变。
- **采购途径**（v0.7.29）：按次报销要选在哪买的（供应商配送、批发市场、网购平台、商超门店、其他，字典在 ERP「模块设置 → 采购规则」），后四项要写说明；按采购单报销照采购单记。报销列表、详情与 CSV 都带途径。

## 6. 加锁顺序

备用金打款 → 采购单 → 报销单 / 退回补付单。登记报销先锁打款（与退回、冲销串行），按采购单报销再锁采购单（同一行不会被两张报销单同时报）。

部门备用金设置（v0.7.29）只锁 `petty_accounts` 一行、带版本号，不碰打款、报销的锁；部门备用金台账、待报销与转报销带出的默认值只读。

## 7. 自检（`check` 库存部分）

- **费用报销单与明细一致**：每张报销单的金额 = 各行合计；用备用金的报销与它的打款同一个部门；有效报销单里同一采购单行只出现一次。
- **备用金台账一致**：有效的退回 / 补付都记在有效的打款上；冲销的打款下面没有有效的报销与退回补付。
- **现付供应商的收货不记应付**：挂账的收货各有一条应付，现付的收货没有应付；同一张采购单的收货结算方式一致；报销的采购单没有挂账的收货（v0.7.8 加）。
- **部门备用金台账与平账一致**（v0.7.29）：每个部门台账的余额（打款 + 补付 − 用备用金的已确认报销 − 退回）= 这个部门各笔打款的「未退回」之和。

## 9. 断网时的登记（v0.7.8 修正）

报销、备用金打款、退回 / 补付与会员记账、前台一样（AGENTS.md）：

- 提交前把操作编号和原请求存在本机浏览器里并读回核对，**存不了就不提交**；
- 超时或断网后，记录留在本机：报销列表与登记页、备用金页顶部显示「结果待确认」，进页面先自动查回（已登记的直接打开原单据，已作废的移除）；
- 查不到时员工选「按原内容重新提交」（同一编号，服务端保证只登记一次），或「作废这笔」（服务端登记作废，原请求晚到也整笔回滚，`OP_ABANDONED`）后重新填写；有未处理的一笔时不能另起一笔；
- 作废按原业务的登记权限检查（报销：登记报销；打款、退回补付：登记打款退回），只拦同类型的原请求。
