# ERP 采购五项（v0.7.29）· 设计稿

店主 2026-11-05：「目前我获得了一些 ERP 的反馈，有 AI 改的也有人要求的……最急的是采购上的使用，请你识别真实需求的整合和拆解，只保留五个需要开发的 ERP 进销存采购供应链上的开发项，并在这次 PR 里完成。同时，规划下后面财务跟法务相关审批流程怎么开发，拍个期。」

财务、法务审批流程的分期与时间表另见 [`docs/ERP_FINANCE_LEGAL_PLAN.md`](ERP_FINANCE_LEGAL_PLAN.md)。

## 1. 反馈从哪来、怎么整合

四份材料：

| 来源 | 内容 | 性质 |
| --- | --- | --- |
| 门店同事的便签「今日工作发现问题及建议」 | 采购要记在哪买的（网购、批发市场、超市）；现付的采购单确认后报销要再填一遍；每个部门的备用金看不清还剩多少、花在哪 | 人提的，日常在用、最急 |
| 《ERP 补充方案 · 财务与供应链》 | 按行业共性补 12 个板块（F1–F6 财务、S1–S6 供应链），分四批上线，八条「好操作」规矩 | AI 整理 |
| 《ERP 待整改项清单》 | 20 项（业务流 7、合同流 6、财务流 7），P0 九项 | AI 整理 |
| 《ERP 三流合一》演示稿 | 业务流 × 合同流 × 财务流，询价比价示例、付款四段、质保金、落地顺序 | AI 整理 |

整合时先去重：三份 AI 材料讲的是同一套东西（例如「无询价记录」「无比价表」「S3 寻源与价格库」是一件事；「无补货建议」「S2 采购计划与安全库存」是一件事），合并后是约 20 件；再对照现有系统划掉已经有的（采购单的确认与改版、最近成交价比较、急采与补单、可用天数提醒、按采购单报销、每打款平账、12 条账目自检、供应商对账登记都已上线）。剩下的按「是不是采购日常在用、是不是钱漏出去的地方」排：

1. **采购途径**（便签）——现付采购说不清从哪买，报销、台账都对不上。
2. **采购单一键转报销**（便签 + F1 的「默认值带出」）——现付采购单报销要重填一遍，容易漏报、重报。
3. **部门备用金台账**（便签 + 演示稿第 12 页）——看不出每个部门手里还剩多少、每一笔花在哪，没有定额。
4. **补货建议**（清单 #6、S2）——补货靠人想，急采多、单价高。
5. **询价比价与定标**（清单 #8、#9 P0，S3，演示稿第 8 页）——价格靠印象，大额采购没有比价依据。

其余的（合同、付款节点、质保金、三单匹配、预算、发票台账、应收挂账、审批中心、供应商评分、批次效期、呆滞、盘点差异审批、数据权限隔离等）不在这一版，排进财务、法务的分期，见 `ERP_FINANCE_LEGAL_PLAN.md` 第 4 节。

## 2. ① 采购途径（迁移 `070`）

**问题**：网购、批发市场、超市买的东西，单据上只有供应商名称，看不出是在哪个平台、哪个档口买的；报销和采购台账也对不上来源。

**做什么**

- 采购途径字典放在新的「采购规则」里（ERP「模块设置 → 采购规则」改，后台规则总表可见）。默认（待确认，E1）：供应商配送、批发市场、网购平台、商超门店、其他；后四项要写「途径说明」（档口、平台与店铺、门店名、说明）。键固定、名称可改；单据存键和当时的名称。
- 供应商档案加「默认采购途径」。新建采购单按供应商带出，可改；接口不传时按供应商的默认，再按字典第一项（补单、补货建议生成的草稿也这样）。
- 采购单：采购途径 + 途径说明（最多 60 字）；草稿、退回时可改，已确认的改版时可改。
- 报销单：按采购单报销的照采购单记；按次报销的在页面上必选（接口不传记「未填」，兼容旧调用）。
- 显示与导出：采购单详情与列表、下单物料（页面与 Excel）、采购台账（逐笔与 CSV）、报销列表、详情与 CSV、部门备用金台账。

**数据**：`purchase_orders`、`expense_claims` 加 `channel`、`channel_label`、`channel_note`；`suppliers` 加 `default_channel`。只加列，旧单据为空（显示「—」）。

## 3. ② 采购单一键转报销

**问题**：现付供应商的采购单确认后，登记报销还要再选一遍采购单、部门、经办人、用途、发票，每一行再选科目；漏报、重报都靠人记。

**做什么**

- **待报销**（「费用报销」页顶上的一张卡片，写着几张、未报销多少钱；没有时不显示）：现付、已确认或已关闭、还有没报销的行的采购单。列采购单号、供应商、采购途径、下单日期、经办（采购单的编制人）、未报销金额、到货进度、已过天数，最早的在上面。
- **采购单详情**加「报销」一栏：这张单报在哪几张报销单（单号、状态、金额）；现付且有没报销的行时，有登记报销权限的人看到「转报销」。
- **转报销** = 打开登记报销页并带好（默认 E2，人只核对、改不一样的，再提交）：
  - 按采购单报销、勾上没报销的行，实付金额 = 采购单金额，采购途径照采购单；
  - 经办人 = 采购单的编制人；部门 = 关联的需求单都来自同一部门时取它，否则取经办人档案里的部门；
  - 用途、发票类型、税点 = 同一供应商上一张报销的，没有就空着让人选；
  - 每行费用科目 = 这个物料上次报销用的，没有用「低值易耗」；
  - 钱从哪来 = 经办人在这个部门有没平的打款时选「备用金」和最早的那一笔，否则「公司直付」。
- 报销的规则都不变：只有现付的能按采购单报、同一行只报一次、购买与到货数量以系统为准、超门槛要负责人确认。

**接口**：`GET /api/erp/expenses/to-claim`（待报销）、`GET /api/erp/expenses/po/:id/prefill`（带出的默认值）；采购单详情多返回 `claims`。只读，不需要迁移。

## 4. ③ 部门备用金台账（迁移 `071`）

**问题**：备用金现在按打款一笔一笔平账，能看出某一笔平没平，但看不出「这个部门手里现在有多少、这个月花了多少、每一笔花在哪」；没有定额，补多少靠估。

**做什么**

- **部门备用金设置**：每个部门可设保管人、定额（可空）、备注；带版本号，两人同时改后保存的被拒。
- **部门备用金**（「备用金」页顶上的「部门备用金」入口）：每个部门一行——定额、在手、待补付、待确认的报销、本月已确认支出、超期没平的笔数、建议补足（设了定额才算：定额 − 在手）、最近一笔的日期。
- **台账**（点开一个部门）：选日期段，期初余额 + 每一笔（打款 +、用备用金的已确认报销 −、退回 −、补付 +）+ 每笔之后的余额 + 期末余额；报销那一笔带明细（物品、数量、金额、采购途径、采购单号）；待确认的报销列在下面、不算进余额；导出 CSV。
- **口径**（E3）：余额 = 有效打款 − 用备用金的已确认报销 − 退回 + 补付 = 这个部门各笔打款的「未退回」之和（与每日平账同一口径；自检核对两边相等）。在手 = 余额为正的部分，待补付 = 为负的部分。
- **打款时提示**：设了定额的部门，打款后在手超过定额时页面提示（不拦）。

**数据**：`petty_accounts`（部门一行：保管人、定额、备注、版本、改的人与时间）。改设置只锁这一行、核对版本；不碰打款、报销的锁。权限：看要「查看费用报销、备用金」，改设置要「登记备用金打款、退回、补付」。

## 5. ④ 补货建议

**问题**：系统已经有日均用量与可用天数提醒，但没算「该补多少、跟谁买」，补货靠人想，急采多、单价高。

**做什么**（默认 E4，都在「采购规则」里可改）

- **补货建议**（「采购」页顶上的入口，写着现在有几种要补）：只看总仓的受管、在用物料（台面日耗品照常算总仓的领用）。
  - 日均用量按「可用天数的用量统计」（默认近 28 天）；
  - 在途 = 草稿、待确认、已退回修改、已确认的采购单还没收到的数量（补单除外）；
  - 触发：(结存 + 在途) ÷ 日均用量 < 提醒天数（物料设了提醒天数用物料的，没设用「补货触发天数」，默认 7 天）；近期没有用量的，按低库存提醒数量：结存 + 在途 < 提醒数量；
  - 建议量 = 补到「补货目标天数」（默认 14 天；物料的提醒天数更长时取提醒天数 + 7）× 日均用量 − 结存 − 在途，按采购单位向上取整；没有用量的补到提醒数量；
  - 单价 = 最近一次同口径成交价，没有用参考价；供应商 = 物料的默认供应商，没设的取最近一次收货的供应商，都没有的放「未定供应商」（要先选供应商）。
- 按供应商分组；每组可以改数量、去掉行，点「生成采购单草稿」用现有的新建采购单接口建一张草稿（备注「补货建议生成」），打开草稿核对后提交。已经生成的草稿算在途，不会重复建议。
- 只读计算，不需要迁移；接口 `GET /api/purchase-suggestions`。

## 6. ⑤ 询价比价与定标（迁移 `072`）

**问题**：价格靠印象，谈成多少没留底；大额采购没有比价依据，定了哪家也说不清为什么。

**做什么**

- **询价单**（「采购」页顶上的「询价比价」入口）：标题、要货日期、物料与数量（采购单位）、规格、备注。物料一经建好不改（要改就撤销重建）。
- **报价**：每家供应商一份——每行含税单价、运费、付款条件（文字，例如「月结 30 天」「预付 50%」）与账期天数、交货天数、报价有效期、备注。每份报价要报全部物料；同一张询价单一家供应商只有一份有效报价，询价单还开着时可以撤下重报（写原因）。
- **比价表**：每家的货款合计、运费、综合到价（= 货款 + 运费，E7）、按综合到价排序；每行最低价标出；每行带最近成交价与涨跌。账期、交货、售后不折算进价格，写在报价里给定标人看。
- **定标**：选一家 + 理由（必填）。有效报价至少 2 家（E6，默认 2）；只有 1 家的要标「单一来源」并写原因，由负责人（「负责人确认」权限）定标。定标后还没转采购单的可以撤销定标（写原因），回到可报价。
- **转采购单**：定标后一键生成采购单草稿（供应商、物料、数量、单价按中标的报价，规格带上，备注写询价单号与运费），采购单记下来自哪张询价单；采购单撤回后可以再转一次。
- **金额门槛**（E5）：合计 ≥ ¥5,000（默认，待确认；设 0 不要求）的采购单**第一次提交**时，必须来自已定标的询价单、供应商与中标的一致，否则拒绝（`QUOTES_REQUIRED`）。先收货后补单、急采补单、已确认后的改版不拦。
- **价格曲线**（E8）：任一物料可查近 12 个月的成交价（已生效收货的单价，按采购单位、同价格口径）与询价报价，采购单编制、询价比价页都能打开。

**数据**：`sourcing_events`（询价单）、`sourcing_lines`（物料行）、`sourcing_quotes`（报价）、`sourcing_quote_lines`（报价的每行单价）；`purchase_orders` 加 `sourcing_event_id`（同一张询价单同时只有一张没撤回的采购单，唯一索引兜底）。

**锁**：报价、撤下、定标、撤销定标、撤销询价单都先锁询价单一行；转采购单在新建采购单的事务里锁询价单一行（操作编号的咨询锁 → 询价单 → 新采购单）；采购单提交时核对询价单只读、不加锁。

## 7. 权限与入口

| 动作 | 权限 |
| --- | --- |
| 看补货建议、询价单、价格曲线 | 查看库存与物资单据（`inventory.read`） |
| 建询价单、登记与撤下报价、定标、转采购单、生成补货草稿 | 编制与提交采购单（`purchase.manage`） |
| 单一来源的定标 | 负责人确认（`inventory.approve`） |
| 看待报销 | 查看费用报销、备用金（`expense.read`） |
| 转报销（带出默认值、提交报销） | 登记费用报销（`expense.manage`） |
| 部门备用金看板与台账 | 查看费用报销、备用金（`expense.read`）；导出要「导出报销明细与每日平账」 |
| 部门备用金设置 | 登记备用金打款、退回、补付（`petty.manage`） |
| 采购规则 | 门店设置（`settings.manage`） |

新接口挂在已有的 ERP 模块下（采购：`/api/purchase-sourcing`、`/api/purchase-suggestions`、`/api/purchase-price-history`；采购规则在库存的前缀下 `/api/inventory/purchase-rules`，费用报销读途径字典也用它；费用：已有的 `/api/erp/expenses`、`/api/erp/petty` 前缀），模块关着时照旧拦下。

## 8. 验收要点

1. 采购单、报销单、下单物料、采购台账、部门台账都能看到采购途径；要写说明的途径没写会被拦。
2. 现付采购单确认后出现在「待报销」；转报销打开的页面各项都已带好，提交后采购单详情看得到这张报销，「待报销」里消失；同一行不能报两次。
3. 部门台账的期末余额 = 这个部门各笔打款「未退回」之和；退回、补付、冲销后都对得上；定额与建议补足显示正确；CSV 与页面一致。
4. 补货建议的建议量按规则算得出来（含在途与取整）；生成草稿后再看，建议量扣掉了草稿的数量。
5. 合计 ≥ ¥5,000 的采购单直接提交被拒（`QUOTES_REQUIRED`）；询价 2 家、定标、转采购单后能提交；单一来源只有负责人能定标；补单不拦。
6. `check` 全部 ✓（新增两项自检：`petty_accounts` 部门备用金台账与平账一致、`sourcing_links` 询价单与采购单的关联一致）。
