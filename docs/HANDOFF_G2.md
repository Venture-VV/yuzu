# G2 提测交接 · S2 到店与未结手牌

> 测试对象以 PR [#1](https://github.com/Venture-VV/yuzu/pull/1) 当前 head 为准（完整 SHA 写在 PR 说明与交接评论里）。修复后请在新 SHA 上复测，旧 SHA 的通过记录不能替代。

## 1. 本阶段范围

| 任务 | 交付 |
| --- | --- |
| S2.1 来访、手牌池与同行绑牌 | 手牌池（男宾 / 女宾 / 儿童分区、锁定、停用）；散客 / 会员接待；一次接待多人自动建同行组、在店客人加入 / 退出同行；受控换牌（账单跟人走、可锁定原牌）；无消费时撤销误开的牌 |
| S2.2 共同账单与挂账契约 | `bills` + `bill_lines`：项目挂账（价格快照、来源分组）、作废更正（必填原因、经办留痕）、同一操作编号只形成一组明细；预结账汇总；前台自检 |
| S2.3 前台双栏 POS 工作台 | `/frontdesk`：左手牌状态矩阵（盲打牌号、分区 / 状态筛选、联牌角标、在店时长、未结金额）+ 右小票抽屉；平板竖屏为侧滑抽屉；管理 → 手牌 |

**不在本阶段**：收款、门票 / 时长 / 大厅过夜计费、团购核销、会员卡扣款、退款、交班与双口径日结（均为 S3）。S2 任何操作都**不得**改变会员余额，也不写 `consumptions` / `ledger_entries` / `reversals`。

## 2. 数据库与边界

增量迁移 `src/server/migrations/004_frontdesk.sql`（应用启动或 `cli.js migrate` 自动执行）：

- 新表：`hand_tags`、`visit_groups`、`bills`、`visits`、`visit_tag_changes`、`visit_group_events`、`bill_lines`；
- 只改一处已有约束：`idempotency_keys.op_type` 增加 `checkin`、`bill_post`、`tag_swap`；
- 001–003 的其他表、数据、触发器不动；升级不预置任何手牌（`tests/upgrade.test.ts` 覆盖）。

不变量（数据库约束 + 自检）：

1. `visits_tag_open_uq`：同一张手牌同时最多一个在店来访；`visits_member_open_uq`：同一会员同时最多一张在店手牌。
2. `bills.amount_cents / line_count` = 该账单有效明细之和（自检 `bill_amount_vs_lines`）。
3. 明细只能「有效 → 已作废」，金额、项目、数量不可修改，不可删除；已结束的账单不能再挂账（触发器 `bill_lines_guard`）。
4. 来访与账单状态一致；在店手牌启用、未锁定、分区一致；同行组状态与在店客人一致。
5. 加锁顺序：手牌（id 升序）→ 同行组 → 来访 → 账单（S3 起再锁会员）。

## 6. G2 验收要点（对应排期表「AI验收」G2 行）

| 场景 | 建议做法 | 放行依据 |
| --- | --- | --- |
| 陌生店员完成散客 / 会员接待 | `/frontdesk` 按 F2 或点空闲牌；会员页签按手机号查找 | 发牌成功，状态板与小票同步 |
| 男女牌防呆 | 女宾行填男宾牌号、儿童行填成人牌号 | 页面拦截且按钮不可用；绕过页面直接调用 `POST /api/frontdesk/checkins` 返回 `ZONE_MISMATCH` |
| 多人同行绑牌 | 一次接待 3 人；在店客人「更多 → 与在店客人同行」；退出同行 | 同组手牌有「联 xx」角标，小票显示同组全部手牌与同行未结 |
| 项目挂账、查未结、预结账 | F4 加项目、F8 预结账（可勾选同组或任意在店手牌） | 合计与明细一致；预结账注明「不是结账单」 |
| 换牌与账单追溯 | 小票「换牌」，选丢失 / 损坏并锁定原牌 | 新牌承接全部明细；经办记录可见「A → B」；原牌锁定不能再发 |
| 授权更正 | 店员作废本人 10 分钟内的明细；作废他人或超时明细 | 前者成功且留原因与经办人；后者 403，店主可以 |
| 释放防呆 | 对有有效明细的手牌「撤销误开的牌」 | 409 `BILL_UNSETTLED`，手牌不释放 |
| 双终端并发抢占同一手牌 | 两个浏览器同时给同一张空闲牌发牌（`e2e/frontdesk.spec.ts` 已覆盖） | 只有一台成功，另一台提示已在店；库中该牌只有 1 个在店来访 |
| 并发改同一账单 | 多终端同时挂账 / 同时作废同一明细 / 挂账与撤销同时提交 | 合计 = 有效明细之和；同一明细只冲减一次；不会出现挂在已撤销账单上的明细 |
| 不改动会员钱包 | 会员接待、挂账、换牌、作废前后比较 `members` 余额与 `ledger_entries` / `consumptions` 行数 | 完全不变；会员日结 4 项自检仍全绿 |
| 重复提交 / 超时 | 同一 `clientKey` 重放；改内容重放；`GET /api/frontdesk/ops/:key` 查回 | 不重复发牌 / 挂账；改内容重放返回 `IDEMPOTENCY_CONFLICT` |
| 越权 | 后勤账号访问前台接口；店员建牌 / 解锁 | 403 |
| 多视口 | 1440×900、1280×720、1024×768、820×1180 | 牌号、金额、角标与按钮不截断，无横向滚动 |

## 9. 已知限制

- 状态板每 10 秒刷新、小票每 15 秒刷新；多终端同时操作时以服务器为准，写操作冲突会明确提示，不会静默覆盖。
- 预结账不打印小票；浏览器打印在 S4 统一处理。
- 店员登录首页仍是会员工作台（待确认第 33 项）；「前台」在导航第一位。
