## 1. 本阶段范围

| 任务 | 交付 |
| --- | --- |
| S2.1 来访、手牌池与同行绑牌 | 手牌池（男宾 / 女宾 / 儿童分区、锁定、停用）；散客 / 会员接待；一次接待多人自动建同行组、在店客人加入 / 退出同行；受控换牌（账单跟人走、可锁定原牌）；无消费时撤销误开的牌 |
| S2.2 共同账单与挂账契约 | `bills` + `bill_lines`：项目挂账（价格快照、来源分组）、作废更正（必填原因、经办留痕）、同一操作编号只形成一组明细；预结账汇总；前台自检 |
| S2.3 前台双栏 POS 工作台 | `/frontdesk`：左手牌状态矩阵（盲打牌号、分区 / 状态筛选、联牌角标、在店时长、未结金额）+ 右小票抽屉；平板竖屏为侧滑抽屉；管理 → 手牌 |

**不在本阶段**：收款、门票 / 时长 / 大厅过夜计费、团购核销、会员卡扣款、退款、交班与双口径日结（均为 S3）。S2 任何操作都**不得**改变会员余额，也不写 `consumptions` / `ledger_entries` / `reversals`。

## 2. 数据库与边界

增量迁移 `src/server/migrations/004_frontdesk.sql` 与 `005_frontdesk_g2.sql`（应用启动或 `cli.js migrate` 自动执行）：

- 新表：`hand_tags`、`visit_groups`、`bills`、`visits`、`visit_tag_changes`、`visit_group_events`、`bill_lines`；
- 只改一处已有约束：`idempotency_keys.op_type` 增加 `checkin`、`bill_post`、`tag_swap`，以及 005 的 `abandoned`（作废待确认操作的登记）；
- 001–003 的其他表、数据、触发器不动；升级不预置任何手牌（`tests/upgrade.test.ts` 覆盖）。

不变量（数据库约束 + 自检）：

1. `visits_tag_open_uq`：同一张手牌同时最多一个在店来访；`visits_member_open_uq`：同一会员同时最多一张在店手牌。
2. `bills.amount_cents / line_count` = 该账单有效明细之和（自检 `bill_amount_vs_lines`）。
3. 明细只能「有效 → 已作废」，金额、项目、数量不可修改，不可删除；已结束的账单不能再挂账（触发器 `bill_lines_guard`）。
4. 来访与账单状态一致；在店手牌启用、未锁定、分区一致；同行组状态与在店客人一致。
5. 加锁顺序：手牌（id 升序）→ 同行组 → 来访 → 账单（S3 起再锁会员）。

| 项目挂账、查未结、预结账 | F4 加项目、F8 预结账（可勾选同组或任意在店手牌） | 合计与明细一致；预结账注明「不是结账单」 |

## 10. 第 2 轮：首轮 G2 意见的修复

| # | 首轮问题 | 修复 | 回归 |
| --- | --- | --- | --- |
| 1 · P1 | 发牌与锁牌 / 停用并发时都成功，产生「在店但锁定 / 停用」的手牌 | `tags.ts` 先 `FOR UPDATE` 锁手牌行，再用**单独查询**判断在店（新语句能看到等锁期间已提交的来访）；锁定、停用、改分区共用；锁顺序不变 | `tests/frontdesk-race.test.ts`：持有账单单号计数行让发牌停在拿到手牌锁之后，锁定 / 停用 / 改分区随后到达，均返回 `TAG_IN_USE`；反向顺序发牌返回 `TAG_LOCKED`；旧代码下这些用例失败 |
| 2 · P1 | 挂账响应丢失后关闭窗口，重开丢失待确认操作并可重复挂账 | 前台接待、挂账、换牌改用本机持久保存的待确认记录（编号、对象、原请求、经办人）；关闭、刷新、切换手牌、重新登录后，对话框与页面顶部仍提示，原操作确认前同一对象不能另起一笔；顶部提醒会自动只读查回 | `e2e/frontdesk-recovery.spec.ts`：响应丢失后关闭重开、刷新后原样重提、接待响应丢失后重新登录，均只生效一次 |
| 3 · P1 | 查回「未找到」被当作「没有生效」，原请求随后仍可能提交 | 查回改为纯只读，查不到显示「暂未查到，原请求可能仍在处理」，不解锁；新增 `POST /api/frontdesk/ops/:key/abandon`：先把编号登记为 `abandoned` 并提交，原请求无论在路上还是在等锁，最后写编号时都会冲突并**整笔回滚**（返回 `OP_ABANDONED`），之后才删除本机记录、允许重新填写；原操作已生效时作废接口返回查回结果而不作废 | 后端：挂账在来访行锁上等待时查回为未找到、作废成功、放锁后原请求 409 且账单为 0、同编号重提被拒、新编号只记一笔；接待同理；不能作废会员记账编号。E2E：请求未到服务器 → 查回 → 作废 → 重新提交只有一笔 |
| 4 · P2 | 尾号匹配多张空闲牌时自动选第一张 | 只有完全相同、唯一的数字相同或唯一候选时才自动补全；多张时列出候选要求点选（接待、换牌）；状态板盲打多张候选时回车只提示，需方向键选中或点选 | E2E：尾号对上两张空闲牌时 Tab 不补全、提交按钮不可用，点选后才可发牌；状态板回车不打开 |

其他：Playwright 断言等待由 5 秒放宽到 10 秒（与后端测试同时运行时的首轮超时）；新增仓库根目录 `AGENTS.md`（环境隔离、命令、验收输出与署名约定，不含本机路径）。

**未改动但需要知道**：会员记账（充值 / 消费 / 撤销）的待确认流程里，「放弃这笔」在查不到时直接删除本机记录，理论上存在与问题 3 相同的窗口。为不改动已在试用的钱包代码，本轮未修改；建议在 S3 接通钱包桥接时一并改为服务端作废，或经店主同意后单独修复。
