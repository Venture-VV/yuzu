# v0.7.25 交接说明 · 会员体系 v2 第三期：会员折扣、邀请体验与赠送会籍

店主 2026-11-03 合并 v0.7.24 后开工（会员体系分三期，这是最后一期）。设计稿 `docs/MEMBERSHIP_P3.md`，默认做法见 `docs/PENDING_DECISIONS.md`「会员体系 v2」M44–M56（设计时定的）、M57–M62（做的时候定的）与 M63–M66（浴票延迟，店主 11-03 让 CI 恢复之前先接着开发时补上），都待店主确认，店主不改就按它做。

**会员折扣是优惠、不是收款**：营业额减少，充值、储值消费、收款的算法不变；日结、交班、看板、营业数据、对账包把它和券抵扣一样单列。涉及结账金额，按资金候选版本验收（快速开发周期：CI 全绿后店主合并，验收在 main 的 v0.7.25 标签上补做）。

## 1. 范围

| 块 | 做了什么 |
| --- | --- |
| 折扣类权益的配置 | 后台「会员权益」的折扣类可以编辑并发布：适用明细（客房房费 / 门票 / 整张账单）、起点的折扣（写「付几成」，75 = 7.5 折，10–99）、更高档阶的折扣（各档阶表）、每周几、每月几号；发布要有适用明细与折扣（数据库约束兜底）。导入清单时 QY-011 派对房及包房折扣预填「客房房费；L3·初 7.5 折、L4·初 6.5 折、L5·初 5.5 折、L6·初 5 折」，仍是草稿 |
| 结账时自动算 | 手牌结账核对时按这几位会员此刻的档阶（含体验中的临时身份，到期没处理的先按规则推算）列出能享的会员折扣，自动用省得最多的一种；只打会员本人手牌账单上的适用明细；省下的 = 合计 × (100 − 折扣) ÷ 100，对省下的金额四舍五入到分（M47）。员工选了券抵扣或「优惠 / 免单」就不用（二选一，页面写明）；没选时必须带上（`MEMBER_DISCOUNT_REQUIRED`），金额、权益与此刻算的不一致拒绝（`MEMBER_DISCOUNT_CHANGED`），与券、优惠一起提交拒绝；桌台结账不算 |
| 入账与报表 | 收款方式「会员折扣」（`member_discount`），记会员、权益与版本、折扣、适用明细；每张结账单最多一笔券抵扣或会员折扣；部门营业额快照只分摊到适用明细；退款单不能退这部分；反结账随单作废，重结按那一刻重新算；日结、交班、看板「经营总览」「营业数据」、对账包都单列「会员折扣」，净营业额 = 应收 − 优惠 − 券抵扣 − 会员折扣 − 退款 |
| 邀请体验 | 会员详情「邀请体验 / 赠送会籍」：L2 起的会员每月 1 次（撤销的不退），给对方「自己的档级 − 1」的初阶 7 天；天数、每月次数（0 = 不开放）、受邀间隔在后台「会员规则」改 |
| 赠送会籍 | 按 QY-042 会籍赠送的起点（默认 L3·尊）、周期与上限，同一事务给赠送人登记一次 QY-042 的使用（「登记使用」里不能单独登记 QY-042，这条登记也不能单独作废），对方得到低一档的初阶 1 个月 |
| 受邀人 | 按手机号找：已有会员的现在的档级要低于体验的档级、同一时间只有一个临时身份、12 个月内只能被邀请或赠送一次（撤销的不算）、不能邀请自己；还不是会员的当场建档（只问姓名，渠道默认「老带新」，与建档页一样发开卡礼） |
| 享什么 | 服务类与登记使用、结账会员折扣、VIP 柜：按自己的与临时身份的取高的；每月券类与事件礼只按自己的；不进升档、升阶、保级的判断；他店查询显示自己的档阶。前台账单、接待对话框在档阶旁标「体验 L3 观澜 · 初」 |
| 结束 | 到期（每天的到期处理里，记在结束日的下一天）；转正（自己的档级升到体验的档级或更高时，在记状态变化的同一事务里，升档与升级礼照常）；撤销（店主、店总写原因，赠送会籍一并作废那次 QY-042 的使用登记、次数腾出来） |
| 结果待确认 | 发起走「结果待确认」：超时、断网、回复 500 时卡片上方查回、按原内容重新提交（只发起一次）或确认作废（作废登记加 `member_trial`） |
| 看板与规则 | 看板「会员体系」加「邀请体验 / 赠送会籍」（体验中、7 天内到期、本月发起、到期、转正、撤销，体验中的名单）；「本月会员权益」加会员折扣的笔数、金额与会员数；后台「会员规则」加「低一档邀请体验」三项 |
| 前台接会员码 | 小程序线（PR #42）合并后主线做（MP9）：会员工作台、接待对话框、桌台的会员查找框扫到会员码由 yuzu 校验，通过就直接打开 / 选上那位会员；过期、解绑、门店没配会员码时写明原因 |
| 打印用例的时段 | 结账演示在营业日切换后 5 个半小时内灌时，开班到交班这一段按比例压进当天（顺序与金额不变），单据都落在当天，打印、日结的浏览器用例在这个时段也找得全 |
| 升级用例 | 迁移清单只在 `tests/helpers.ts` 维护一处（`migrationsFrom`），`tests/migrations-list.test.ts` 核对清单与迁移目录一致、编号不撞（两条线各加迁移时不再改同一批文件） |
| 浴票延迟（续） | QY-004 做成结账时自动算（M63–M66，迁移 `045`，设计稿第 4 节）：后台「会员权益」新类别「浴票延迟」，填起点与各档阶多给几分钟（1–240）；会员的门票在「门票跳档宽限」之上再多给这几分钟不跳档（按会员此刻的档阶，含体验中的临时身份取高的；几项取多的）。结账核对、结账、手牌详情、看板估算同一算法；结账单记下分钟数与权益，结账记录与小票写「会员浴票延迟 N 分钟」。QY-004 导入时**不预填分钟数、仍是草稿**（会员文档的起点与梯度对不上，等店主填，M50） |
| 自检 | `check` 加 3 项：会员折扣对应折扣类权益、一单一种、不与券和优惠同用；赠送会籍与 QY-042 的使用登记对得上；临时身份到期的已结束、档级够了的已转正。部门快照的优惠分摊含会员折扣。共 **63 项** |

## 3. 验收要点

| 编号 | 项 | 怎么验 |
| --- | --- | --- |
| D1 | 折扣类配置与发布 | 店主在「管理后台 → 会员权益」：QY-011 预填「客房房费 · 7.5 折起」、各档阶 6.5 / 5.5 / 5 折，仍是草稿；QY-054 会员日没填折扣，发布被拒「请填写起点的折扣」；不选适用明细发布被拒；折扣写 9 或 100 保存被拒（付几成 10–99） |
| D2 | 结账自动带上 | 发布 QY-011；L3 会员开牌、入住钟点房再退房：结账对话框自动出现「会员折扣 −¥X（会员 · L3 观澜 · 初 7.5 折 · 派对房及包房折扣（客房房费））」，X = 房费合计 × 25 ÷ 100，对省下的金额四舍五入到分（例如房费 128.10 元省 32.03 元）；门票等其他明细不打；结清后结账单与小票有「会员折扣」 |
| D3 | 取省得最多 | L4 会员与 L3 会员合并结账（各自有房费）：只用一种，取省得最多的那一种（只打那位会员本人的房费）；带省得少的提交被拒 `MEMBER_DISCOUNT_CHANGED` |
| D4 | 二选一 | 加「优惠 / 免单」或选一张券：会员折扣那一行变成「已改用券或优惠 / 免单……不用了」；去掉券或优惠恢复；接口同时带会员折扣与券或优惠被拒 |
| D5 | 必须带上 | 接口不带会员折扣、也没有券和优惠时被拒 `MEMBER_DISCOUNT_REQUIRED`；页面上不能单独去掉 |
| D6 | 账与报表 | 日结、交班表、看板「经营总览」、ERP「营业数据」、对账包「01-日结汇总」「02-结账单」单列会员折扣，净营业额减去它；部门营业额快照只分摊到客房；退款单退不了这部分；反结账后重结照样自动算 |
| D7 | 日期与档阶 | 会员日填每月几号 / 每周几，只在那几天出现；到期没处理的会员结账前先按规则处理（例如该降到 L2 的不再享 L3 起的折扣）；桌台结账不出现会员折扣 |
| T1 | 邀请体验 | L1 会员的「邀请体验」灰着（写明「L2 起」）；L4 会员邀请一位还不是会员的朋友：输入手机号显示「还不是会员：当场建档」，填姓名后确认；朋友的详情「体验中：L3 观澜 · 初（今天 至 6 天后）」，本月可享按 L3；邀请人本月不能再邀请（每月 1 次） |
| T2 | 受邀人的限制 | 档级不低于体验的、已经在体验中的、12 个月内被邀请或赠送过的（到期的也算）、自己，都不能接受，页面写明原因；撤销过的可以再被邀请 |
| T3 | 享与不享 | 体验中的会员：服务类（L2·初 起的会员专属通道）能登记；L3 起的月度券不发；前台账单标「体验」，VIP 柜按体验的档级核对；他店查询显示自己的档阶 |
