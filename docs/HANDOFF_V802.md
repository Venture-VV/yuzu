# v8.0.2 交接说明 · 采购单撤回与登记发票串行

店主 2026-11-08 合并了 8.0.1（[PR #75](https://github.com/Venture-VV/yuzu/pull/75)，合并提交 `954dab4`）。测试会话在 `a6b2b6d` 上报的 [P2](https://github.com/Venture-VV/yuzu/pull/75#issuecomment-6714489088) 合并时还没修，按快速开发周期在这一版修。8.0.1 的交接说明见 [`HANDOFF_V801.md`](HANDOFF_V801.md)。

## 1. 范围（相对 v8.0.1）

- **问题**：提交即确认的采购单「撤回」与财务「登记发票」没有在同一张采购单的锁上串行。
  - 撤回在采购单的排他锁里核对「没有发票」；
  - 登记发票读采购单的状态时却没有加锁。
  - 所以登记发票读到「已确认」以后、写入之前采购单被撤回，发票照样登记上：采购单已撤回，却挂着一张有效发票；需求行也已放回、可以再转单。
- **登记发票**：先按 id 升序对选的采购单加共享锁（`FOR KEY SHARE`，只与撤回等的排他锁冲突，两张发票之间不互相等），锁住以后再核对采购单是不是这家供应商的、还在下单状态。
  - 撤回先锁住：登记发票等撤回提交，看到「已撤回」，拒绝（422 `PO_NOT_ORDERED`）。
  - 登记发票先锁住：撤回等发票提交，看到已经有发票，拒绝（409 `PO_IN_USE`）。
- **撤回**：草稿、待确认、退回的采购单也在锁里核对没有发票、报销、三单放行。
  - 以前只核对提交即确认的单；待确认的单也能登记发票（「已下单」包括待确认），撤回以后发票同样挂在已撤回的单上（8.0.0 起就是这样）。
  - 现在有发票的单要先作废发票才能撤回，提示「发票登错了请先作废发票」；详情页的「撤回」按钮随之不显示。
- **三单放行**：锁住采购单以后也核对还在下单状态，已撤回的拒绝（422 `PO_NOT_ORDERED`）。页面上本来看不到已撤回的单，这里防的是旧页面或直接调接口。
- 按采购单报销本来就先锁采购单、再核对状态，不用改。
- **版本号** 8.0.2：`package.json`、`package-lock.json`、`Dockerfile`、`compose.yaml`、`src/server/config.ts`。

## 3. 验收要点

1. 登录页与导航栏显示 `v8.0.2` 和提交 SHA。
2. 两种交错顺序。要两个会话同时操作，人手很难卡准，用 `tests/purchasing-v801.test.ts`「采购单撤回与登记发票串行（8.0.2）」的做法：另开一个事务锁住一行，让一方停在半路。
   - 先撤回：锁住经办人一行，撤回停在写日志。这时登记发票卡在采购单的锁上；放开以后撤回成功（200）、发票拒绝（422 `PO_NOT_ORDERED`），采购单上没有有效发票。
   - 先登记发票：锁住供应商一行，发票停在写入。这时撤回卡在采购单的锁上；放开以后发票成功（201）、撤回拒绝（409 `PO_IN_USE`），采购单仍是已确认。
3. 待确认的采购单登记一张发票：详情页没有「撤回」，接口撤回 409 `PO_IN_USE`；作废发票以后可以撤回；撤回以后再登记发票、三单放行都是 422 `PO_NOT_ORDERED`。
4. 8.0.1 的撤回照旧：提交即确认、没有收货、报销、发票、三单放行的可以撤回，需求行回到待转采购单；人审批过的、收了货的不能撤回。
5. `node dist/server/cli.js check` 全 ✓。
