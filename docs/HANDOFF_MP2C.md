## 1. 范围

### 2c 线上领券（`docs/MP_COUPONS.md`，MP22、MP27）

- **后台**「微信小程序 → 领券中心」（新权限 `mp.coupon`：店主、店总）：
  - 开关（默认关）；从启用的券模板里加可领的券，按列表的先后显示；
  - 每张的领取限制：每人限领 N 张（1–99，默认 1）或不限领；可以停领、拿掉；
  - 带版本号保存，结果待确认照其他开关；
  - 每张一共领了多少、最近 7 天领了多少，最近 50 条领取记录。
- **小程序**「我的 → 领券中心」（开着、有可领的券时才显示）：
  - 列出可领的券，券面与「我的券」一样；领过几张、能不能领、为什么不能；
  - 点「领取」发到会员名下，可以直接去「我的券」；
  - 领取走「结果待确认」：先存操作编号，结果不确定时请门店系统确认作废。
- **门店系统**：
  - 领取在一个事务里：这个微信的咨询锁 → 作废登记、同一个编号 → 绑定状态共享锁 → 核对绑定版本号 → 会员一行 → 数已领 → 主线发券 → 写领取记录；
  - 限领按会员数：换绑微信不能多领，合并进来的会员卡领过的也算；
  - 领取带列表上的绑定版本号：点了领取以后才换绑的，不发券（`BIND_STALE`，与 #52 的充值建单同一个做法）。
- **网关**：`/v1/coupon-center`、`/v1/coupon-claims`、`/v1/coupon-claims/abandon`，领取与作废每个微信每分钟最多 20 次。

### 2d 原路退回（`docs/MP_RECHARGE.md` 第 9 节，MP21）

- **开关**：后台「线上充值」的设置里加「原路退回」（默认开）。门店系统的微信支付配好、开着时，主线的退储值才给选「门店系统原路退回」。关掉只影响以后的退储值。
- **门店系统每分钟**：
  - 按行号取交给门店系统的行，按行号唯一建原路退回单；商户退款单号建单时定下；
  - 申请退款：连不上、余额不够的隔一会儿用同一个单号再试；微信明确拒绝的记「没能退」；
  - 处理中的每 5 分钟查一次；退款通知（同一个 `/v1/pay/notify`）到了马上记。
- **后台「线上充值 → 原路退回」**：
  - 列出没退成的、处理中的与最近退到的；
  - 「马上再试」「重试」（关闭、没能退的先查旧单号，确认没退到才换新单号）、「已另行处理」（写怎么处理的）。
- **顺带**：退款等别的事件的通知，验过签就回收到（以前会回失败，微信重发一整天）。

## 5. 验收要点

1. **领券**：每人限领 N 张时同时点三次只出一张；不限领的一直能领；同一个编号重提返回同一张；确认作废之后晚到的原请求不发券；领到的券在会员详情里种类是「小程序领取」。
2. **领券的会员**：换绑微信不能多领；合并进来的会员卡领过的也算；合并掉的、停用的会员领不了；档级不够、模板停用或过期的领不了，原因是写给顾客看的话。
3. **点了领取以后才换绑**：带的是之前的绑定版本号，不发券。
4. **原路退回**：同一行只建一张单、只退一次；连不上、余额不够时用同一个单号再试；处理中的查得到结果；退款通知重复到只记一次。
5. **没退成的**：重试先查旧单号，没退到才换新单号；异常、关闭、没能退的可以记已另行处理；已退到、还在退的不能另行处理（没能退的先问微信）；单号变了的重试、另行处理回 409。
6. **一张一张办**：店主的操作拿着一张原路退回单时，每分钟的扫描跳过它；扫描不会拿着旧单号去申请；行号小、晚提交的行照样取到。
7. **对账**：2b 的对账一起核对 `MPRF` 开头的退款行；微信退了、门店还没记的先查一次补上；门店没有的、门店记了已退到账单里没有的标出来；商户平台手动退的不核对。
8. **开关**：关掉后主线的退储值不给选「门店系统原路退回」，已经交给门店系统的照样退完。
9. **账目**：`check` 全过；退储值的账（本金、赠金扣回、降档）都在主线，原路退回只管把钱退到。
