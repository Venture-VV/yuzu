# ERP 独立工作区（含 SCM）

店主 2026-10-30 定（见 `PENDING_DECISIONS.md`「ERP 独立工作区」与 ROADMAP 第 10 节第 8 项）：

- 财务、采购用的功能放进单独的 ERP 工作区，门店前台看不到；
- ERP 包含 SCM：供应商、采购、库存、应付货款；
- 财务、采购的同事之后会陆续提需求，所以模块按注册表配置，不写死。

**第一步 v0.7.3 已完成**（单独的 PR [PR #19](https://github.com/Venture-VV/yuzu/pull/19)，在 v0.7.2 之后）：ERP 工作区、模块注册表与模块开关、接口拦截、只读的营业数据。交接见 `docs/HANDOFF_V073.md`。

## 1. 边界

- **同一套系统、同一个数据库、同一个实例。**
  - 数据只有一份，不用两边同步。
  - 备份、数据指纹、`check` 自检照旧。
  - 以后真要单独部署，再把 ERP 拆出去：代码放在单独的目录、接口走单独的模块开关，拆的时候不用改业务逻辑。
- **门店的页面不变。** 前台、会员、餐饮、钟房、交班、流水、日结、经营看板与报表，都留在门店。
- **ERP 只读营业数据。** 日结汇总、营业收入只能看，不在 ERP 里改。
- **储值只在会员钱包。** 会员钱包是唯一的储值账本（AGENTS.md），ERP 不另建余额。
- **页面与接口地址都不变。**
  - 页面 `/inventory`、`/purchasing`、`/payables`、`/todo` 照旧，只是改在 ERP 外壳里打开；ERP 的首页是 `/erp`。
  - 接口 `/api/inventory`、`/api/purchase-orders`、`/api/payables` 照旧，测试脚本不用改；它们统一经过 ERP 的模块开关。
  - 新加的 ERP 接口放在 `/api/erp/` 下。
- **怎么进 ERP。**
  - 门店主导航里没有 ERP 的页面；有 ERP 权限的人在用户菜单（左下角头像）里点「进入 ERP」。
  - 只用 ERP 的人（只有库存、采购、货款职责）登录后直接进 ERP 的第一个模块；
  - ERP 顶栏的「返回门店」只对门店那边有页面的人显示：回到门店首页；没有会员权限的回到门店主导航里第一个能用的页面（例如开了餐饮时，管厨房的后勤进餐饮）。

## 2. 模块注册表（不写死）

每个 ERP 模块在共享的模块注册表 `src/shared/erp.ts` 里登记一条。ERP 的导航、页面拦截、接口拦截和模块开关都从这张表来，不在页面里一个个写。

| 字段 | 说明 |
| --- | --- |
| 模块编号 | 例如 `master`（主数据）、`inventory`、`purchasing`、`payables` |
| 名称、分组、图标 | ERP 导航按分组显示 |
| 页面 | 这个模块有哪些页面（路由） |
| 权限 | 看到这个模块要有哪些权限（有其中一个即可） |
| 默认开关 | 新装的门店开不开；店主在 ERP「模块设置」里改，存在设置里 |
| 依赖 | 依赖哪些模块。例如采购依赖库存（物料、供应商档案在库存里）：库存关着，采购也用不了。依赖的模块要登记在前面（按登记顺序算，`tests/erp.test.ts` 会检查） |

**页面怎么拦。** ERP 外壳按注册表里的页面前缀认出页面属于哪个模块：模块关着时提示没有开启，没有这个模块的权限时回到 ERP 首页。

**服务端怎么拦。** 按注册表里的接口前缀统一拦截（`src/server/modules/erp.ts`）：模块关着时，这个模块的接口一律返回 403 `ERP_MODULE_DISABLED`，不用每个接口自己判断。没登录的请求照常 401，不透露模块设置。CLI、自检、备份不经过接口，不受影响。

**第一批模块（v0.7.3）：**

| 模块 | 内容 | 谁看得到（有其一即可） | 依赖 |
| --- | --- | --- | --- |
| 库存 | 物料、供应商、部门档案；期初、收货、领用、退回、报损、盘点；库存报表 | 查看库存与物资单据 | — |
| 采购 | 采购单的编制、确认、修订与按单收货 | 查看库存与物资单据（物资经办要按单收货）、编制采购单、负责人确认、查看货款 | 库存 |
| 应付货款 | 应付、期初未付、付款登记与对账单 | 查看供应商货款与对账 | 库存 |
| 审批待办 | 待办汇总：负责人要确认的采购、报损、盘点调整、退货、付款、期初集中在一页 | 负责人确认 | 库存 |
| 营业数据 | 只读：每天的营业收入、收款与部门构成、日结情况（与经营总览同一口径） | ERP：看营业数据（只读），默认店主、店总 | — |

- **审批待办只是汇总页**：注册表里它没有自己的接口前缀（`apis: []`）。关掉它只是不显示「审批待办」这一页；采购单、付款、期初、报损、盘点调整、退货的确认都在各自的单据里办，属于库存、采购、应付货款模块，照常能用。要停掉确认，关掉对应的模块（测试会话复测 v0.7.3 的观察）。
- 物料、供应商、部门档案（主数据）这一步还在库存模块里：采购、货款都依赖它，单独开关没有意义，等有了单独的需求再拆。
- 库存、采购原来就在用，所以全部默认开启。店主在 ERP「模块设置」里开关；关掉的模块导航不显示、页面提示没有开启、接口拒绝，数据都保留，重新开启就恢复。
- 设置项是 `erp_modules`，只存店主改过的开关；没存的按注册表的默认。

## 3. 留给定制化的扩展点

下面这些等有了具体需求再做，不提前做：

- **数据字典**：物料分类、单位、付款条件、费用类别等，做成在 ERP 里能维护的字典，不写成代码里的固定选项。
- **自定义字段**：供应商、物料等主数据可以加门店自己的字段。字段的定义放在设置里，值存在主数据上；列表和导出都带上这些字段。
- **审批规则**：
  - 哪些单据要审批、由谁审、金额门槛是多少；
  - 店主 #18 定的门槛是 2000 元以内不用负责人确认，可以调整。
- **单据编号与打印格式。**
- **分岗**：仓库、采购、部门、财务（含成本）分开，不能兼任（店主 #17）。现在还是可以兼任的职责。

每一项都按同一个顺序做：

1. 先在 `PENDING_DECISIONS.md` 写清规则、默认值、谁能改；
2. 再开发；
3. 单独验收。

## 4. 需求怎么提

财务、采购的同事提需求时，请尽量写清楚下面几项。可以直接复制这个模板，发给店主，或者评论在开发会话当前的 PR 上：

```
【模块】例如：采购 / 应付 / 库存 / 费用报销 / 成本
【谁用】哪个岗位、几个人、在哪台设备上用
【场景】现在线下怎么做，哪一步最费事、最容易错
【单据与字段】要登记什么单据，每张单有哪些字段，哪些必填
【流程与审批】谁发起、谁审、金额门槛，审完之后怎么流转；能不能撤回 / 冲销，要不要写原因
【报表与导出】要看什么数，按什么汇总，导出成什么格式
【和门店的关系】要不要读门店的营业数据；会不会影响前台收银（一般不应影响）
【急不急】希望哪天用上；有没有月结、盘点这类固定的时间点
```

## 5. 开发与验收

- **版本与迁移号**：
  - 每批需求一个小 PR，一个版本号（切换前只加最后一位）；
  - 迁移号先在 ROADMAP 第 7 节登记，再使用。
- **怎么验收**：
  - 涉及应付、付款等钱的改动，按资金候选版本验收；
  - 不碰门店收银的模块，按普通版本验收。
- **在哪里验收**：
  - 用新建的独立演示库（`seed-inventory-demo`）；
  - 不往门店试用库、正式库写演示数据；
  - 后勤的真实试点，仍按 ROADMAP 第 10 节 Batch 4 的约定，等前台切换稳定之后再开始。
