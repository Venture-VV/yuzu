# 上线评测说明（v0.7.21 · 初期开发收口）

店主 2026-11-03 定：**初期开发到 v0.7.21 结束，准备上线让大家评测**。这份说明给参加评测的门店同事与各位 AI：在哪里评测、用什么账号、每个模块从哪里进、发现问题怎么记；哪些要真机才能测；哪些规则还是默认做法、等店主确认；初期开发之后还有哪些事。协作红线照 [AGENTS.md](../AGENTS.md)，里程碑与门禁照 [ROADMAP](ROADMAP.md)。

> 评测不是切换。评测期间正式记录仍以现行做法（旧系统、Excel、纸质单）为准；正式切换按 ROADMAP 第 3 节的 M3 演练 → M4 影子运行 → M5 切换（版本 1.0.0）走。

## 4. 怎么评测、怎么报问题

1. **按自己的岗位走一整天**：前台从开班到交班，值班经理加上授权、反结账与日结，后勤从需求单到付款。每做完一步看一眼数字对不对：余额、应收、交班实点、日结合计、库存结存。
2. **断网与超时**：故意在提交时断网或关页面。页面会进入「结果待确认」：不要重新填写，按提示「查回」，查不到时「按原内容重新提交」或「确认作废」后再填。重复记账、重复扣款、重复打印都是阻断项。
3. **不同尺寸**：门店电脑（1440×900）、小屏电脑（1280×720）、平板横屏与竖屏（iPad）、手机；看有没有横向滚动、按钮被挡、字看不清。
4. **记问题**：写清环境（演示库 / 演练库）、导航栏上的实例标识与版本 + SHA、账号与岗位、时间、一步步怎么做、看到什么、本来应该是什么，附截图。
   - 门店同事：发到店主的飞书需求文档（由 DeepSeek 整理，开发会话按优先级排进 ROADMAP）。
   - AI：评论在开发会话当前开着的 PR 上，写明测试 SHA、环境、实际范围、未测项（环境缺失记「受阻未测」，不记通过）、问题清单（P1 / P2，附复现步骤与位置）；署名照 AGENTS.md。
5. **P1（阻断）**：账错、串单、越权、数据丢失、重复扣款、破坏旧模块自检、实例标识或 SHA 显示错误。其余记 P2，或作为「需求」发飞书文档。
6. **每天收尾**：测试服上 `node dist/server/cli.js check` 全 ✓（Codex 每日巡检）；有 ✗ 当天报。

## 7. 初期开发之后（要店主先定规则或等条件，评测期间不做）

- **要店主先定规则**：按钱箱的班次模型（现在按人交班）；会员价（按等级打折）；会员等级的保级与降级、按档权益、会员价改按会员体系 v2 分三期做（v0.7.23–v0.7.25，`docs/MEMBERSHIP.md`，店主 2026-11-03；第一期 v0.7.23 已做），积分不做；充值退款（赠金怎么处理）；次卡（先问清顾客手里有没有旧次卡要核销）；会员停用、合并、换手机号的审批；客房电话预订与保留时长、押金规则（飞书文档 Q17）。
- **要等真机或现场条件**：终端设备服务 APK；业务单据（结账单、交班表、日结单）改走网口打印；断网打印队列（硬件 v0.2）；发卡、挂失等读卡业务；门锁客控、手牌柜锁控、闸机（D8 本期不做）；第二级精确定位。
- **以后看需要**：多门店；顾客端（小程序、线上点单）与支付直连；平台 API；离线队列；iPad Safari 自动化；公网访问加固（只有正式服放云端时）；旧 EBC 逐笔历史迁移（期初余额导入已有）；ERP 的数据字典、自定义字段、审批规则、成本核算、BOM、批次效期、布草洗涤、自动补货、供应商门户、电子发票。
- **切换路线**：评测与演练（M3）→ 正式服影子运行（M4，新旧双录、每晚对账）→ 切换（M5，1.0.0，营业日 06:00 冻结 EBC、当场导入余额）。后勤真实试点（G4）在前台切换稳定之后。
