# v8.1.10 交接说明 · 核库转领用、急采后补合同

主线 [PR #127](https://github.com/Venture-VV/yuzu/pull/127)。店主 2026-11-18 转来会议需求表（ERP 采购四条 P0），开发会话问了十二个问题，店主当天答复：

- 「1-4不用管，5按照建议6安好建议7不管8按照建议9按照建议后面都按照建议」；
- 「好，做完直接合并」。

这一版做两块：核库转领用（C2）、急采后补合同（C4 的后半段）。不做 2 万合同线、数量线、防拆单、合伙人特批与超限预警，现有的金额线与审批规则不动。

- 设计：`docs/ERP_V8110.md`。
- 答复与默认做法：`docs/PENDING_DECISIONS.md`「8.1.10：ERP 采购四条」CK1–CK25（CK1–CK12 是店主的答复，CK13–CK25 是细项的默认做法，待确认）。
- 迁移 `185`（核库）、`186`（急采补合同），都只加不改：
  - 加列、加表；
  - 审批动作、操作编号与「确认作废」的类型在当时的约束上追加（写法同 `162`、`183`）；
  - 需求单两个守卫函数换成新版（多了「已转领用」与「已领用的行不能改」），新表 `request_line_stock` 有自己的守卫。
- 同一个 PR 还带着：会员工作台的「发券」先锁住会员一行再核对（Codex 审查 `cf81873` 顺带发现，见 CHANGELOG）。

## 0. 升级后会看到的变化

- **采购规则**（ERP 设置 → 采购规则）多四项：提需核库（开）、核库时限（24 小时）、急采补合同金额（¥20,000）、补合同期限（15 天）。
- **需求单**：
  - 选了物料、总仓有货的需求单提交以后先是「待核库」，核完才是「待审核」；
  - 库管（物资经办）进得了「采购 → 需求单」，多一个页签「待核库」，ERP 导航「需求单」上有待核库的张数；
  - 状态筛选多「已转领用」「待核库」；
  - 需求单详情里，选了物料的行写着总仓现在有多少；核过库的写着领用、替代或转采购与领料单号。
- **岗位权限**多一项「需求单核库」（默认店主与物资经办）。
- **急采**：「采购 → 急采」多一栏「待补合同」；补单采购单详情有「补合同」；达到金额的急采补上合同之前付不了款。
- **升级时已经在待审核里的需求单**不受影响（核库状态是「不用核」），照常审核。

## 1. 范围

### 1.1 核库转领用（`docs/ERP_V8110.md` 第 2 节，迁移 `185`）

- 服务端 `src/server/modules/request-stock.ts`；领料单在 `inventory/docs.ts` 的 `createRequestIssue`（与库管平时登记领料同一条路）；页面 `features/requests/StockCheck.tsx`。
- **进待核库**（CK13）：提交、修改后再提交、主管确认、部门表格导入之后看——选了物料、总仓有货的行要核；标了急的、集采导入的、开关关着的、一行都不用核的直接待审核（「不用核库」）。
- **核库**（CK14）：库管逐行选领用（能换算的单位按这一行的单位填，可以只领一部分；换算不了的整行领用、按库存单位填）、替代（总仓有货的另一种物料，按它的库存单位填）、转采购；「核库完成」时领用的行一起开一张部门领料单，马上生效（总仓 → 申请部门的小仓，领料人写提单人），部门之后签收。
- **替代**（CK15）：提单人、这个部门的主管或店主答复。同意按提议开领料单（经办人记提议的库管）；总仓不够了或替代品停用了，这一行改成转采购、答复照样记下；不用就照原来买。
- **结果**（CK16）：全部领用的需求单变成「已转领用」，与通过、不采购、撤回一样是结束状态；还有要买的进采购审核。
- **采购那边**（CK23、CK24）：
  - 核库没完：不能通过、不能退回（`STOCK_CHECK_PENDING`），可以不采购；不在「待审核」里；
  - 领用过的需求单不能改、不能退回修改（`STOCK_ISSUED_LOCKED`）；待核库时撤回、不采购的，核库收掉；
  - 整行领用的不能转采购单、发起询价（`REQUEST_LINE_ISSUED`），部分领用的转采购单默认买剩下的；
  - 核库开的领料单冲销了，这一行照原来的数量买。
- **超时**（CK10）：每分钟的任务把超过核库时限没核完的记成「超时转采购」，把超过时限没答复的替代记成「没回，照原来买」；审批记录里记在系统账号名下。
- **可见**（CK17、CK25）：部门只在自己的需求单里看到所需物品的总仓结存；库管看全部需求单（只读）。
- **结果待确认**：核库完成、答复替代都带操作编号（业务类型 `request_stock`），页面顶上的「结果待确认」能查回、重提、确认作废。
- **流程图**：「需求审核」在核库没完时写「待核库」「待部门确认替代品」；全部领用的流程结束。

### 1.2 急采后补合同（`docs/ERP_V8110.md` 第 1 节，迁移 `186`）

- 服务端 `inventory/urgent-contract.ts`、`inventory/contract-due.ts`；页面 `purchasing/BackfillContract.tsx`、急采页「待补合同」。
- 急采生效时合计达到「急采补合同金额」的记下要补合同（生效那一刻定，以后改金额线不影响，CK18），期限按现在的「补合同期限」算（CK19）。
- 补合同只改补单采购单挂的合同，挂上不能换；付过款、在付款申请里或报销过的不能补（CK20）；能挂的合同见 CK21。
- 补上之前四处拦（`CONTRACT_REQUIRED`）：付款申请、直接登记付款、预付款核销、现付报销（CK22）。

## 4. 验收要点

1. **核库**：
   - 选了物料、总仓有货的需求单是「待核库」，标了急的、手填新品、总仓没货的是「待审核」；开关关了都是「待审核」；
   - 待核库时采购通过、退回被拦，不采购可以；部门申购核不了库；
   - 库管核库：只领一部分的，领料单上记着录入的单位（如 2 箱）、总仓少了换算后的数量、申请部门的小仓多了这么多；剩下的转采购单默认只买剩下的；
   - 全部领用的变成「已转领用」，不能再改、不能通过；
   - 替代：同意以后领料单的经办人是提议的库管；先把替代品领空再同意，这一行改成转采购、页面写原因；
   - 超时：把进待核库的时刻往前挪过核库时限，一分钟内变成「超时转采购」；
   - 领料单冲销以后，这一行在「待转采购单」里照原来的数量。
2. **急采补合同**：
   - ¥20,000 以上的急采生效后在「待补合同」里，写着期限；补合同之前付款申请、付款登记、报销都被拦；
   - 补合同只能选这家供应商、到期日不早于下单日的合同；挂上以后不能换；
   - 超期标红，照样能补。
3. **结果待确认**：断网时点「核库完成」或「同意替代」，刷新后在页面顶上查回或确认作废。
4. **三台设备**：待核库、核库对话框、替代确认、急采待补合同在四个尺寸上不横向滚动，按钮在屏幕里。
