# 8–10 月旧账只读对照（v0.7.10，飞书需求 RQ-005 收尾）

RQ-005「采购与费用闭环」分版做：v0.7.7 费用报销与备用金、v0.7.8 需求单与图片、v0.7.9 台账四视图与 12 条账目自检（都已合并），**v0.7.10 旧账只读对照（本文件）**。需求原文在店主的飞书文档 RQ-005：「11 月起新账，8–10 月旧账不导入正式账（D9），保留只读对照入口，明确标注『不进正式账』，不参与 11 月后的统计」；验收标准要求「12 条自检规则能复现账目问题清单里的差额」。

## 1. 边界

- **只读、不进正式账**：旧账导入单独的只读表（迁移 `028`），不写报销单、备用金、采购单、库存、应付，任何正式的报表、台账、平账、账目自检、`check` 都不读这些表。页面顶部常显「8–10 月旧账 · 只读对照 · 不进正式账，不参与 11 月起的统计」。
- **按原样保留**：每一行保留原表的行号、原始单元格（含公式原文），页面能对回原表；只做推定分类（标「推定」），不改原值，不做「按人记的备用金转成按部门」之类的自动映射（D14）。
- **原始文件是真实业务数据，不进 Git**：仓库里只有合成样例（`legacy-samples` 生成，结构与原表一致、内容是编的）。门店正式库导入原始文件须店主同意（与其他导入命令一样）；测试服的演练库不导入原始文件。

## 2. 四份原始文件的结构（按原表核对过）

| 文件 | 工作表 | 表头 | 说明 |
| --- | --- | --- | --- |
| 采购台账 | 第 1 张「费用报销明细表」：前两行是标题与单位，第 3 行表头 | 序号、日期、类别、数量、金额、商户、用途、是否有发票、备注 | 打款、支出、退款混在「金额」一列（负数是打款或退款）；有合并的金额格（一笔钱对几行物品）；金额有公式 |
| | 第 2 张「付款台账」：第 1 行表头 | 日期、打款金额、应退回金额、退回出纳、备注 | 每个付款日一行，日期是 Excel 日期序号；金额多为公式；末尾有「合计」行 |
| 采购物资明细表 | 「8月」「9月」「10月」三张：第 1 行标题，第 2 行表头 | 序号、购买日期、物品名、用途、金额、购买数量、到货数量、部门、发票（专票、普票）、税点、备注（办公费、固定资产、低值易耗等） | 「备注」列实际是费用科目；税点是小数（0.13 = 13%）；有合并的金额格；10 月是空表 |
| 已下单物料 | 「10月」「11月」…：第 1 行表头 | 下单时间、产品名称、图片、选款、部门、下单人、数量、金额、备注 | 图片是 WPS 的单元格图（`DISPIMG` 公式指向 `xl/cellimages.xml`），导出 Excel 就丢；「金额」是这一行的总价 |
| 品牌新增寻款采购清单 | 一张：第 1 行标题，第 2 行表头 | 序号、是否下单、是否到货、是否退货、产品名称、用途、采购数量、备注、产品详情、参考链接渠道 | 「参考链接渠道」格里是商品标题，链接在单元格的超链接里；表格后面有很多空行 |

导入**按表头名称认列**（不按位置），认不出的文件整份拒绝并说明缺哪一列。认出是哪份表之后，文件里其余写了东西的工作表也必须认得出（如某个月份表的表头改了名、多了一张手记的表），否则**整份拒绝**并写明哪张表缺哪一列，不悄悄少导入一个月；完全空白的表（WPS 默认带的 `Sheet3` 之类）跳过。

## 3. 导入（命令行，默认只预览）

```bash
node dist/server/cli.js import-legacy <文件.xlsx> --operator <店主账号>            # 预览：认出是哪份表、每张表多少行、核验结果
node dist/server/cli.js import-legacy <文件.xlsx> --operator <店主账号> --apply    # 写入只读表
node dist/server/cli.js import-legacy <文件.xlsx> --operator <店主账号> --apply --replace "<原因>"   # 换一份文件：先作废同一份表的旧导入
node dist/server/cli.js legacy-samples <目录>        # 写出四份合成样例（演示、验收用）
node dist/server/cli.js seed-legacy-demo            # 把合成样例导入演示库（试用 / 正式环境拒绝）
```

- 自动认出是哪一份表（按工作表与表头）；同一份文件（内容摘要相同）重复导入直接返回原来那次；每一份表同时只有一次有效导入，换文件要 `--replace` 写原因（旧的作废，留经办人与原因）。
- `--operator` 必须是店主账号，记为导入人；导入写审计日志。
- 只用 Node 自带的解压读 Excel（不加依赖；WPS 的样式表 openpyxl 都读不了，所以不依赖样式）：共享字符串、内联文字、公式（用文件里存的计算结果；没有结果的只算纯四则运算，算不了的保留公式原文、标「公式没有结果」；四则运算用精确的十进制算，不用二进制浮点数，`=1.005-0.01` 是 ¥1.00 而不是 ¥0.99）、数字（文件里按二进制浮点数存，按 Excel 的 15 位有效数字读成十进制，与在 Excel 里看到的一致；元换分、数量换千分之一都只在最后一步四舍五入）、合并格、Excel 日期序号与「2026-9-1」「9.1」之类的文字日期、超链接、WPS 单元格图。

## 4. 存储（迁移 `028`，只追加）

| 表 | 内容 |
| --- | --- |
| `legacy_imports` | 每次导入：哪份表、文件名、内容摘要、每张表的行数（含空行）、表内自带的合计、导入人与时间；作废时记原因与经办人 |
| `legacy_ledger_lines` | 采购台账第 1 张的每一行：行号、序号、日期、类别、数量、金额（分）与公式、商户、用途、是否有发票、备注、合并格说明 |
| `legacy_payment_days` | 付款台账每个付款日：打款、应退回、退回出纳（分）与公式、备注 |
| `legacy_material_lines` | 采购物资明细表每一行：月份表、行号、日期、物品名、用途、金额、购买 / 到货数量、部门、发票、税点、费用科目 |
| `legacy_ordered_lines` | 已下单物料每一行：下单日期、产品、图片、选款、部门、下单人、数量、金额、备注 |
| `legacy_brand_requests` | 品牌寻款清单每一行：是否下单 / 到货 / 退货、产品、用途、数量、备注、详情、链接文字与网址 |
| `legacy_images` | 已下单物料的单元格图（原图，随备份走；单张不超过 5 MB） |

除 `legacy_imports` 的作废三列外都不能改、不能删（数据库触发器）。每行另存原始单元格（JSON），页面「看原表」显示。

## 5. 页面（ERP「费用与备用金 → 旧账对照」，`/erp/legacy`）

1. **核验**：按「账目问题清单」的结构重算：总览、三套账之间的差额、每日平账（每个付款日一行：打款、当日台账支出、应退回、差额、实际退回、未退回）、字段与口径问题、12 条规则在旧账上的结果（每条点开看是哪几行）；
2. **采购台账**：原表逐行，推定的类型（支出 / 退款 / 打款 / 没有金额），问题标红；
3. **付款台账**；
4. **采购物资明细**（按月份表）；
5. **已下单物料**（带原图）；

## 6. 核验口径（与账目问题清单一致，待确认）

为了能复现核验报告里的数，口径照报告的做法定，规则写死在代码里、页面上写明：

| 事项 | 口径 |
| --- | --- |
| 采购台账算哪些行 | 从序号 1 那一行起有内容的行；表头下面、序号 1 之前的那一行（只有一个金额公式）单列「表头下的金额」，不计入各项合计 |
| 打款与退款（「金额」列的负数） | 绝对值大于 1000 元的推定为**打款**；小于 1000 元的推定为**退款**（冲减当天支出）；正好 1000 元的两类都不算，单列「无法判断」 |
| 当日台账支出 | 当天（按「日期」列）的正数支出减去退款；没写日期的行不算进任何一天 |
| 每日平账 | 打款 − 当日台账支出 − 应退回；差额绝对值不到 1 元的算「尾差」，记平 |
| 付款台账没写日期的行 | 金额照样算进打款、应退回、实际退回的合计（不能从合计里漏掉）；每日平账按日期算，这些行单列在「字段与口径问题 → 付款台账没有日期的行」，第 3 条也写明有几行没算进去 |
| 行数 | 采购物资明细表：有序号或日期的行都算一行（只有序号的行算「缺物品名、缺金额」）；品牌寻款清单：表格里的每一行都算（含空行，空行算「缺链接、缺用途、缺数量」），另列有内容的行数 |
| 合并的金额格 | 金额算在合并格的第一行；同一合并格里的其他行算「没有金额」 |
| 发票与税点 | 发票写法与税点的组合逐一列出。写法先换成新账发票字典里的类别：专票、专用发票 → 增值税专用发票；普票、普通、普通发票 → 增值税普通发票；收据；无、无票 → 无票；与字典名称完全一样的直接认。再按 ERP「模块设置」里的发票字典看税点在不在这一类允许的范围里（默认：专票 1%–13%、普票 0–13%、收据与无票只能是 0）。没填的、写法认不出的、税点不在范围里的都算对不上；收据、无票没填税点按 0 算 |
| 品牌清单的链接 | 能点开的才算有链接：单元格的超链接，或格里写的网址（整格是网址，或淘宝、京东分享文字里带的网址），只认 http / https；格里只写了商品、店铺名称的算没有链接 |
| 费用科目 | 「备注」列的写法逐一列出；新账只有办公费、固定资产、低值易耗三种，其余写法算同义不同名 |
| 部门 | 名称里有「、，,/」或换行的算「几个部门拼在一起」；带「耗材」「餐具」「运费」的算「把费用写进部门」 |

## 7. 12 条规则在旧账上

| # | 规则 | 旧账上怎么查 |
| --- | --- | --- |
| 1 | 支出必须有日期、金额、类别、部门、经办人 | 台账没有日期、没有金额、没有类别的行；明细表没有金额、没有物品名的行 |
| 2 | 打款必须能分摊到采购单 | 旧账没有采购单：推定的每一笔打款都列出 |
| 3 | 每日打款 − 支出 = 应退回 | 每个付款日的差额，不平的天数与差额最大的几天；打款为 0 但当天有支出的日子 |
| 4 | 应退回 − 实际退回 = 未退回，超 7 天预警 | 应退回与实际退回的合计与差额；记了应退回、没记实际退回的日子 |
| 5 | 发票类型与税点匹配字典 | 明细表每一行按新账的发票字典核对（见第 6 节「发票与税点」）：没填的、写法认不出的、税点不在这类发票范围里的行 |
| 6 | 费用科目只有三种 | 同义不同名的写法与行数 |
| 7 | 部门走字典、禁止拼接 | 拼在一起的部门、写进部门的费用类别 |
| 8 | 到货 ≠ 购买要写原因 | 明细表里购买数量与到货数量不同的行（旧表没有原因列） |
| 9 | 已下单未到货超期预警 | 品牌清单里「已下单」但没「到货」的行（旧表没有下单日期，分不出超没超期） |
| 10 | 同一物品同一天重复下单 | 已下单物料里同一天同名产品出现两次以上 |
| 11 | 标注有发票但实际无票 | 旧表没有发票号，核对不了，列为「无法核对」 |
| 12 | 图片与链接必填 | 品牌清单没有能点开的链接的行（只写了名称、没有网址的也算）；已下单物料没有图片的行 |

另列「三套账之间的差额」：台账推定的打款与付款台账的打款、台账净支出与付款台账打款、应退回与实际退回、8–9 月台账净支出与明细表、10 月三张表。

## 8. 同版的两项小改

- **班次跨营业日提醒**（店主 2026-11-01 同意）：本人还没交班的班次，开班时的营业日早于今天的营业日，前台工作台与交班页顶部提醒「这个班次从 X 月 X 日开到现在，请先交班」；只提醒、不拦截收款。「今天」用当班接口（页面每 30 秒轮询一次）带回的营业日，页面一直开着、过了营业日切换时间也会在 30 秒内出现。
- **日期参数的中文提示**：查询接口缺日期或日期格式不对时，提示「请填写日期」「日期格式应为 YYYY-MM-DD」，不再出现校验库默认的英文。

## 9. 合成样例与固定预期

`legacy-samples` 写出四份合成样例：结构与原表相同（标题行、表头、合并格、公式、Excel 日期序号、文字日期、合计行、超链接、WPS 单元格图、空行），内容是编的、金额是凑整的假数。导入后核验页的每一个数写在 `src/server/demo/legacy-expected.json`（测试与验收都按它核对）。
