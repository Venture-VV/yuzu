## 3. 升级要知道的

1. **已经在用点单密码的店，升级后变成「不要密码」**（EM2）。要继续用：升级后到「后台 → 电子菜单 → 设置 → 点单密码」改成「要」，平板 15 秒内跟上。测试服上如果正在评测点单密码，升级后请先改这一项。
2. **不要密码时**，拿到平板、知道一张在店手牌的号码与桌号的人就能往这张手牌上点菜（EM4）。每一单记着是哪台平板、什么时候下的；点错的照旧在前台退菜。
3. 平板升级后字与按钮直接是放大的；不喜欢可以改回「设计稿原样」。放大的倍数与文字的新位置是开发定的，请设计师过目（`docs/EMENU.md` 第 12.2 节）。

## 4. 验收要点

管家部：

1. 用 `http://<内网 IP>:<端口>` 打开「管家」：点「新增会员」1 秒内出录入窗（称呼、联系方式、备注都在）；提交后名单里马上有、「在册会员」数加一；代录预约、拍消费单、名称库同样打得开；控制台没有 `randomUUID` 的报错。

订单查询：

2. 分别输手机号后 4 位、手牌号（带字母、只输数字）、结账单号、客人称呼：都能列出对应的账单；已反结账、有退款的标得出来；退款单跟着原结账单一起列。
3. 点开一张单：逐行明细与打印的结账单一致，多出所属部门与优惠；各行优惠相加 = 这张单的优惠 + 券抵扣 + 会员折扣。
4. 导出明细 CSV：一行一个消费项目；金额列相加 = 列表里这些结账单的金额相加（退款单的行是负数）。
5. 前台店员（没有历史权限）搜昨天的单：查不到，页面写明只查当天；直接打开昨天那张单的明细接口被拒（403）。

部门项目明细：

6. 看板选「近 7 天」：每个部门各项销售金额相加 = 上面「部门构成」的数；表尾销售金额合计 = 应收、净额合计 = 净营业额（= 这 7 天日结净营业额相加）；切时间范围表跟着变；导出的 CSV 与页面一致。

平板：

7. 见 `docs/EMENU.md` 第 12.4 节的 5 条（默认放大且不要密码能下单；改成「要」与 8.0.14 一样；改成「设计稿原样」与 8.0.14 一样；放大档逐屏看不压图不出边；断网时「结果待确认」不要密码也能处理）。

回归：

8. `check` 全部 ✓；结账、反结账、退款单、日结、对账包的数字不变。

## 6. 已知的限度

- 订单查询是对结账单逐张匹配、没有另加索引（没有迁移）：门店的量够用，结账单到几十万张以后可能要加索引。
- 没有历史权限的岗位能看今天开的退款单，但它的原结账单如果是之前的单打不开（抽屉里显示服务端的提示）。
- 平板放大后，顶栏分类很多、名字很长时分类名会按最宽的名字收一点（不小于设计稿原来的大小）。
- 后台刚改「点单密码」的那几秒里，平板上正好发出去的一单会被拒绝一次（提示输入密码或不用密码），平板随后取到新的设置。
