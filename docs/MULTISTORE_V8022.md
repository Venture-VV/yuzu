# 8.0.22 设计 · 多门店、多店多仓、多公司主体（MD-A、MD-B、MD-C）

范围见 `docs/SCHEDULE_V8020.md` 第 4 节；店主 2026-11-14「全部都按照默认」已确认 MD1–MD6。店主 2026-11-15 定 8.0.22 是这一批的收尾版。AI 辅助另见 `docs/AI_V8022.md`。这一版细分出来的默认写在第 9 节（`docs/PENDING_DECISIONS.md` MD12 起），都标「待确认」。

## 0. 现状与原则

- 现状（按 `40be92f` 的代码盘点）：294 张表，没有一张带门店或主体；营业日切换时间、门店名、钱箱、打印、前台规则都是全局设置一份；单号计数器全局；日结按营业日一行；技师轮牌一条队列；底图全楼一份；库存一个总仓 + 各部门小仓。
- **原则一：只有一家店时与现在完全一样。** 现有数据全部归「本店」（迁移时建，编号 1），已有单据内容不改；本店不设任何门店上下文，所有默认值落在本店——以往的用例、演示数据、接口一条不用改。
- **原则二：第二家店的数据与本店分开。** 第二家店的员工只看到、只动到自己门店的手牌、账单、班次、日结、设备、客房、桌台、技师、空间、预约与仓库；店主可以按店看，也可以合并看。
- **原则三：全公司共用的不拆。** 会员、钱包、券、次卡、权益、价目表、会员规则、ERP 的物料与供应商、审批规则全公司一套（MD2、MD4）；钱包的每条流水记发生在哪家店，门店之间按储值消费出结算表。

## 1. 门店、主体与员工（迁移 `153`）

- `legal_entities`（公司主体）：名称（发票抬头）、税号、地址电话、开户行与账号、启用。迁移时建「本公司」（编号 1，名称取现在的门店名）。
- `stores`（门店）：编号代码（2–8 位字母数字，比如 `BA`、`FT`）、名称、所属主体、地址、电话、营业时间、启用、排序。迁移时建「本店」（编号 1，代码 `HQ`，名称取设置里的门店名）。时区照旧全系统一个（`APP_TIMEZONE`），门店档案里只显示——跨时区开店时再拆（MD12）。
- `staff_stores`（员工挂哪几家店）：迁移时现有员工全部挂本店。店主（`owner`）不用挂，所有门店都能进。
- 门店的设置（`store_settings`，门店 + 键）：第 4 节「按店」的那几项，第二家店改了存这里；本店照旧用原来的设置。
- 后台「门店与主体」分区（`settings.manage`）：门店的新建、修改、停用（本店不能停用），主体的新建、修改；员工档案里多一项「门店」（多选）。

## 2. 当前门店

- 会话多记一列当前门店（`sessions.store_id`）。登录时：只挂一家店的直接进；挂几家的（含店主）默认上次用的，第一次用挂的第一家。
- 导航栏常显当前门店名（与实例标识、版本同一行）；挂了不止一家店的人点门店名换店（`POST /api/auth/store`，只能换到自己挂着的、启用的门店），换了以后页面整个重新取数。
- `/api/auth/me` 多带 `store`（当前门店）与 `stores`（能进的门店）；登录页照旧显示门店名（取本店）。
- 平板点餐的账号、他店查询的账号同样挂门店。

## 3. 门店上下文怎么传（一处做，处处有）

- 每个请求在解析完会话以后，把当前门店放进这次请求的上下文（Node 的 `AsyncLocalStorage`）。
- **写**：`src/server/db.ts` 包住连接池的 `begin`——每个事务（含只读快照）开头在当前门店不是本店时执行一次 `set_config('yuzu.store', 门店编号, true)`；第 5 节那些表的 `store_id` 默认值取 `yuzu_store()`（没设就是本店）。这样 396 处事务、183 处只读快照里新写的单据都自动记上当前门店，不用一处处改 INSERT。每分钟的自动任务按单据原来的门店处理（见第 6 节）。
- **读**：门店维度的清单、看板、报表显式按 `store_id` 过滤（第 5 节逐项）；「合并看」只给有对应报表权限、并且挂着那几家店的人。
- **为什么不用数据库的行级安全**：部署用的数据库账号是官方镜像建的超级用户，行级安全对它不起作用；改账号要动各环境的部署，这一版不做。

## 4. 设置按店（`store_settings`）

`loadSettings` 读完全局设置以后，当前门店不是本店时用这家店的覆盖值替换下面这些键（没覆盖的照用全局的）：门店名、营业时间、营业日切换时间、开班要求、按人 / 按钱箱交班、钱箱清单、打印方式与等待时间、前台规则（自助作废、丢牌费、超时宽限）、餐饮与桌台规则、电子菜单规则、客房规则、预约规则、技师与钟房规则、实时位置与导览规则、扣料用的仓库。其余设置（钱包、会员、券、ERP、审批、付款……）全公司一份。后台的规则页在第二家店里打开时，这些项旁边写「本店单独设置」，保存进 `store_settings`。

营业日：`businessDate`、`businessDayStart` 等都经 `loadSettings` 取切换时间，因此自动按当前门店；会话里的 `today` 也按当前门店算。

## 5. 哪些表按店（迁移 `154`）

加 `store_id bigint NOT NULL DEFAULT yuzu_store()`（引用门店，现有行都是本店），读的地方按店过滤：

| 块 | 表 | 读怎么过滤 |
| --- | --- | --- |
| 手牌与前台 | `hand_tags`（代码改成「门店 + 代码」唯一）、`visit_groups`、`visits`、`bills`、`checkouts`、`refunds`、`backfill_entries`、`auth_grants` | 前台看板、手牌清单、结账记录、流水、退款、补录都只看当前门店；会员「在店」照旧全公司一个（一位会员同一时刻只能在一家店里） |
| 班次 | `shifts`（「门店 + 钱箱」同时只有一个开着的班次）、`shift_members` | 班次、交班只看当前门店；收款找经办人此刻所在的班次时只找当前门店的 |
| 日结 | `daily_settlements`（改成「门店 + 营业日」唯一，原主键换成编号） | 日结按门店算、按门店关；合并看把几家店的日结相加 |
| 钱包流水（只记不过滤） | `recharges`、`consumptions`、`reversals`、`ledger_entries`、`member_refunds`、`count_cards` | 会员在哪家店都能用、流水全公司都看得到；日结只算本店发生的；门店间储值结算表按这一列算（第 7 节） |
| 设备 | `devices`（「门店 + 编号」唯一）、`device_jobs` | 设备页、打印机清单、终端只看当前门店的；打小票只打当前门店的打印机 |
| 客房与预约 | `room_types`、`rooms`（「门店 + 房号」唯一）、`room_stays`、`bookings` | 房态、入住、预约只看当前门店 |
| 技师与钟房 | `technicians`（「门店 + 工号」唯一）、`technician_sessions` | 技师牌、轮牌、派钟只在当前门店的技师里排；轮牌锁按门店分 |
| 餐饮与桌台 | `kitchen_stations`、`dining_tables`（「门店 + 名称」唯一）、`table_sessions`、`kitchen_items`、`emenu_orders` | 点单、桌台、出品屏只看当前门店；估清（`dish_limits`）这一版全公司一份（MD13） |
| 空间与底图 | `floors`、`zones`、`spaces`（「门店 + 代码」唯一）、`space_usages`、`floorplan_batches`（每家店一份在用的底图）、`location_readers`、`current_locations`、`guide_markers` | 空间台账、底图、房态图、实时位置、对客导览都按店 |
| 审计 | `audit_logs` | 记一列门店；审计页可以按店筛 |

单号：计数器照旧全公司按「种类 + 日期」一个（第二家店的结账单接着本店的号往下排，不会撞号），不加门店段（MD14）。

## 6. 自动任务

每分钟的任务按单据自己的门店处理：会员到期、权益、生日这类全公司的照旧；预约的自动取消与爽约、扣料、平台对账、AI 小结按门店逐家跑（读出单据的 `store_id`，在那家店的上下文里处理，写出的新单据落在那家店）。

## 7. 门店之间的储值结算表

- 会员在 A 店充值、在 B 店消费储值：B 店替 A 店「花」了 A 收进来的钱。结算表按营业日区间列出每两家店之间：A 收的储值在 B 消费了多少（本金、赠金分开），差额谁欠谁。
- 只是报表（`/api/reports/store-settlement`，财务、店主看），不自动记账；两家店是同一个主体时只做参考。

## 8. 多店多仓与调拨（迁移 `155`，MD-B）

- 仓库加门店：本店现有的总仓与部门小仓都归本店；新门店建好以后自动建它的主仓（「XX 店主仓」）；部门照旧全公司一套，部门小仓按「部门 + 门店」各一个（第二家店用到哪个部门再建）。「总仓」可选：店主可以把某家店的主仓标成总仓（集采到货进这里，再调拨给各店）。
- 结存：本店主仓照旧记在物料上（原来的 `stock_milli`），别的仓记在 `warehouse_stock`；移动加权平均成本照旧全公司一个（MD15）。
- **调拨单**（新单据 `DB`）：调出仓、调入仓（不同门店的仓）、物料与数量 → 「调出」时从调出仓扣、记在途 → 「调入」时调入仓按实收数量入库，差异（短少、损坏）登记原因；在途的可以撤回。权限：库管（`stock`）。锁：调拨单一行 → 物料（id 升序）→ 两个仓的结存行，与别的库存单据同一套（物料行锁串行所有仓的收发）。
- 采购单多一项「收货门店」（默认当前门店）；按采购单收货进那家店的主仓。集采按门店分货：需求单按门店提，转采购单时同一家供应商的几家店可以合成一张、收货时按门店分别收。
- 部门领料、退料、报损、盘点照旧，只是在当前门店的仓里做。

## 9. 多公司主体（迁移 `156`，MD-C）

- 门店挂主体；合同、进项发票、付款申请与付款、开票申请、银行账户、批量付款加 `entity_id`（默认当前门店的主体），清单按主体筛；打印、导出 Word、开票申请的「销售方」取主体的抬头与税号。
- 一个主体可以有多家店；本公司（编号 1）是现有全部数据的主体。

## 10. 价目按店覆盖（迁移 `157`，MD4）

- 价目表全公司一套；门店可以对某个项目（某一档）单独定价（`service_item_store_prices`）。挂账取价时先看当前门店有没有单独的价，没有用全公司的。后台价目页在第二家店里打开时多一列「本店价」。

## 11. 报表：按店看与合并看

数据看板、日结、部门 × 项目、技师业绩、班次、每日对账包：默认看当前门店；店主（与挂着几家店、有报表权限的人）多一个「合并看」开关，按门店分列再合计。

## 12. 测试

- 原有用例全部照旧通过（只有本店）。
- 新用例建第二家店与那家店的员工：手牌、接待、结账、交班、日结、设备、客房、技师、桌台、预约、仓库各自隔开；同一位会员两家店都能用储值，流水记各自的门店，结算表对得上；调拨单调出、在途、调入、差异；主体的抬头上合同、开票申请。
- 浏览器用例：换门店以后看板、日结都换成那家店的。

## 13. 默认做法（待确认，写进 `docs/PENDING_DECISIONS.md`）

| 编号 | 事项 | 默认 |
| --- | --- | --- |
| MD12 | 时区 | 全系统一个（`APP_TIMEZONE`）；门店档案里只记不分，跨时区开店时再拆 |
| MD13 | 估清（菜卖完） | 全公司一份；两家店各自估清时再拆 |
| MD14 | 单号要不要带门店 | 不带：计数器全公司一个，第二家店接着往下排，不会撞号 |
| MD15 | 成本 | 移动加权平均全公司一个（同一物料各店一个成本） |
| MD16 | 部门小仓 | 部门全公司一套；部门小仓按「部门 + 门店」各一个，用到才建 |
| MD17 | 会员同一时刻在店 | 一位会员同一时刻只能在一家店里（与现在一样） |
| MD18 | 合并看谁能用 | 店主；以及挂着几家店、有那张报表权限的人只合并自己挂着的店 |
