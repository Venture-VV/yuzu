# 8.0.21 设计 · 财务与合同做深

排期见 `docs/SCHEDULE_V8020.md` 第 3 节（CW-A 到 CW-J）；默认做法 CW1–CW10 店主 2026-11-14「全部都按照默认」已确认，本文件里再细分出来的（CW11 起）记在 `docs/PENDING_DECISIONS.md`，店主 2026-11-14「都按默认」一并按默认确认。对外接口（支付直连、平台验券、OTA）见 `docs/INTEGRATIONS_V8021.md`。迁移 `141`–`150`（第 9 节）。

开工前读代码核对的现状：

- **进项发票台账**（8.0.3）：`supplier_invoices` 一张表管三单登记、报销关联、台账直接登记（`source three_way|expense|manual`），内容不可改、只能认证与作废；发票号码去空白、不分大小写后取咨询锁（`input_invoice_no:<号码>`），同一供应商（没有供应商的按开票方）同一号码只有一张有效的。登记全靠手填。
- **付款**：`payments`（供应商往来，按收货单 / 期初未付分摊）与 `payment_requests`（付款申请，挂合同按段、或不挂合同）、`contract_payouts`（服务、租赁合同的付款）；付款方式 `bank_transfer|wechat|alipay|cash|other`。没有「批量」与「对银行流水」的概念；供应商档案只有联系人、电话，没有银行账户。
- **回款**：`ar_collections`（协议单位回款）、`platform_settlements`（平台打款登记）、`petty_advances`（备用金打款）、报销单（公司付的没有单独的打款记录）。
- **合同**：`contracts.draft`（jsonb）存可改的内容（标题、起止、总价、四段付款、质保、验收、单价表），提交、审批、签署、用印、归档一整套；没有模板，也没有任何文档生成（只有上传扫描件）。服务端有手写的 zip 与 xlsx（`lib/xlsx.ts`），前端有 `/print/*` 打印页。
- **供应商对外**：只有对账确认链接（`recon_links`，8.0.7）：随机 24 字节令牌只存 SHA-256、14 天有效、只能回一次、公开接口按 IP 限次、`no-store`。询价报价、订单确认、发货都只能员工代录。
- **选项**：作废原因、撤销原因、移单原因是写死的快捷选项；退款、报损、取消预约、资产报废的原因是纯手填；费用科目、合同类型、盘点差异原因、团购平台在数据库里有 CHECK（进账务口径）。门店自己维护的清单只有渠道来源、耗用用途、钱箱（`settings` 里）。供应商、物料、合同没有扩展字段；会员原来的 `custom_fields` 在 8.0.4 冻结、改成标签。

## 1. 数据字典与自定义字段（CW-J，迁移 `141`）

**字典**：门店自己维护「快捷原因」类的清单，**不碰**进账务口径的分类（费用科目、合同类型、盘点差异原因、团购平台照旧写在代码与 CHECK 里）。

- 一份设置 `dictionaries`（规则锁保存，`saveRuleSetting`），按清单键存 `{ key, label, active }[]`，每份最多 30 项、只能停用不能删（停用的老数据照常显示）。
- 第一批清单：作废明细原因、撤销消费原因、移单原因、退款原因、报损原因、取消预约原因、资产报废原因。原来写死的作为默认值；原来是纯手填的，页面上多一排快捷选项，**仍然可以手填**（不改数据库，原因还是存文字）。
- 后台「规则中心 → 数据字典」一个分区（`settings.manage`）。

**自定义字段**：会员、供应商、物料、合同四类，每类最多 10 个（CW10）。

- `custom_field_defs`：`entity`（`member|supplier|material|contract`）、`key`（f1…f10，建了不改）、`label`、`type`（`text|number|date|select`）、`options`（选项类）、`list`（列表里显示）、`active`、`sort`、`version`。同一类里 `key` 唯一、启用的 `label` 不重名。
- `custom_field_values`：`entity`、`entity_id`、`field_id`、`value`（文本、数字存整数或两位小数的文本、日期 `YYYY-MM-DD`、选项存选项文字）、`updated_by/at`，主键 `(field_id, entity_id)`。**单独一张表**，不加到业务表上（合同、物料、会员都有保护触发器与版本号，扩展字段改了不应该动它们的版本）。
- 改值：详情页「其他信息」一块单独保存（`PUT /api/custom-fields/:entity/:id`，带看到的值的摘要、对不上拒绝），权限照那一类的「维护」权限（会员 `member.write`、供应商与物料 `inventory.master`、合同 `contract.manage`）。列表能按自定义字段筛选，导出带上。**不进账务口径、不参与结账与任何计算**。
- 锁：定义的新建先取「自定义字段 + 类别」的咨询锁（同一类串行，数 10 个）、修改只锁定义一行（带版本号）；值的保存只锁那一格（`(field_id, entity_id)`，`INSERT … ON CONFLICT` 之前 `FOR UPDATE`），不锁业务行。
- 会员原来冻结的 `custom_fields` 列不动。

## 2. 发票识别（CW-A，迁移 `142`）

在「发票台账 → 登记发票」与三单登记、报销登记的发票一栏，多一个「拍照 / 选文件识别」：

- **二维码优先**：增值税发票（含数电票）左上角的二维码是一串逗号分隔的字段（版本、发票种类代码、代码、号码、金额（不含税）、开票日期、校验码……）。浏览器本机解码（`BarcodeDetector`，没有时用 `jsqr`——现在只在员工食堂用，改成主程序也打包），直接带出号码、日期、不含税金额；数电票 20 位号码同样认。
- **读不到二维码再走文字识别**：沿用管家部的本机 OCR（tesseract.js，资源已经随构建带着、按需加载），按版式找「发票号码」「开票日期」「价税合计」「税额」「销售方名称 / 纳税人识别号」；PDF 先用已有的 `pdfjs-dist` 渲染第一页。识别结果只是**填进表单**，每一格标「识别」，人核对后才能保存（CW1）。
- **不传第三方**：图片不离开浏览器；保存时照旧把照片 / PDF 作为附件上传到自己的服务器。
- 台账多记一列 `entry_method`（`manual|qr|ocr`），只为统计「多少张是识别的」；内容仍然不可改。查重照旧按发票号码的锁。

## 3. 开票申请（CW-B，迁移 `143`）

给客人开票（销项）。8.0.21 做**台账与状态**，开票服务商做成适配器、先带模拟的（CW2）：

- `invoice_requests`：来源 `checkout|recharge|ar_collection`（结账单、会员充值、协议单位回款）+ 来源编号、可开金额（来源的实收，不含储值支付、券、优惠——储值在充值时开）、抬头类型（个人 / 单位）、抬头、税号、邮箱、手机、发票种类（普票 / 专票）、备注；状态 `requested|issued|rejected|voided`；开出后记发票号码、开票日期、PDF（`erp_files`）、服务商与它的单号。
- **同一笔只能开一次**：同一来源同时只有一张 `requested|issued` 的（部分唯一索引）。红冲 = 作废已开的（写原因）+ 重新申请。
- 谁做：前台（`frontdesk.checkout`）在结账记录、充值记录上「申请开票」；财务（新权限 `invoice.issue`，默认店主、有 `payable` 职责的）在 ERP「财务 → 开票」处理：登记已开（手工开好后填号码、传 PDF），或「交给服务商开」（适配器，见 `docs/INTEGRATIONS_V8021.md` 第 5 节），驳回写原因。
- 锁：申请先取操作编号的咨询锁（与「确认作废」，新业务类型 `invoice_request`）→ 来源一行（`FOR KEY SHARE`，结账单 / 充值 / 回款，锁住以后核对没反结账、没作废）→ 写申请；处理只锁申请一行（带版本号）。来源反结账、作废时**不拦**，但开了票的在开票台账上标红「来源已作废，要红冲」。

## 4. 银行账户与网银流水（CW-C，迁移 `144`）

- `bank_accounts`：本公司的银行账户（名称、开户行、账号后四位、币种固定人民币、启用）。完整账号不存（批量付款文件只需要收款方账号）。
- **导入**：网银导出的 CSV / Excel（xlsx 用已有的读法，`@shared/csv-read` 读 CSV）。内置两三家常见格式（工商、建设、招商的对账单表头）+ 一个「通用」——页面上把列对到「日期、收入、支出、余额、对方户名、对方账号、摘要、流水号」，对过一次的映射按账户记住。同一份文件（内容摘要）只导一次；每条流水按「账户 + 流水号」，没有流水号的按「账户 + 日期 + 金额 + 对方 + 余额」去重。
- `bank_statement_lines`：账户、日期、方向（收 / 付）、金额、对方户名、对方账号、摘要、银行流水号、状态 `open|matched|ignored`。只增不改（状态与勾对除外）。
- **勾对**（CW3）：一条流水可以对一笔或几笔系统里的记录（`bank_matches`：流水、对象种类、对象编号、金额、状态 `active|voided`、谁、自动还是人工）。对象：
  - 付出：供应商付款（`payments`）、合同付款（`contract_payouts`）、备用金打款（`petty_advances`）、备用金补付（`petty_settlements` 的 topup）、批量付款的一行（第 5 节）；
  - 收入：协议单位回款（`ar_collections`）、平台打款（`platform_settlements`）、备用金退回（`petty_settlements` 的 return）。
  - 自动勾对只认「金额相等、日期 ±3 天、对方户名与供应商 / 协议单位 / 平台名称一致」三样都对上、而且只有一个候选的；其余进「待勾对」，人工挑。勾对的金额合计等于流水金额才算这条对平。撤销勾对写原因。
- 待办：超过 7 天没对上的流水、超过 7 天没对上流水的付款与回款，进 ERP 待办。
- 锁：导入先取操作编号的咨询锁（新业务类型 `bank_import`）→「账户 + 文件摘要」的咨询锁 → 写导入与流水（新行）；勾对：流水一行（`FOR UPDATE`）→ 对象一行（`FOR KEY SHARE`，按种类、id 升序；锁住以后核对没作废）→ 写勾对。对象作废时不拦，勾对标红「对象已作废」。
- 页面：ERP「财务 → 银行流水」（新模块 `bank`，依赖 `payables`）：账户、导入、流水列表（按状态筛）、勾对抽屉。权限：看 `payable.read`、导入与勾对 `payable.manage`。

## 5. 批量付款文件（CW-D，迁移 `145`）

默认用网银批量转账文件，银企直连是可选的适配器（CW4）：

- 供应商档案加收款账户：户名、开户行、账号（`suppliers.bank_*`，维护照旧 `inventory.master`；账号在列表里打码）。
- `payment_batches`：批次号、付款账户（`bank_accounts`）、银行模板、状态 `draft|exported|done|voided`、合计、笔数；`payment_batch_items`：付款申请（已审批、还没付清的）、金额、收款户名、开户行、账号（**生成时抄一份**，之后改档案不影响这一批）、状态 `pending|paid|failed|removed`。同一张付款申请同时只能在一个没结束的批次里（部分唯一索引）。
- 流程：财务在「付款 → 批量付款」勾选待付的申请 → 生成批次 → 导出网银模板（内置工商、建设、招商 + 通用 CSV 四种，xlsx 或 CSV）→ 在网银里上传付款 → 回来：导入银行流水，按「金额、收款户名」自动对上每一行，对上的照「按申请登记付款」记账（方式 `bank_transfer`，参考号 = 银行流水号，`payFromRequest` 原来的锁与幂等）；对不上的手动「标记已付 / 失败」。全部有结论后批次 `done`。
- 已导出的批次不能改，只能作废重开（作废前要确认这一批还没在网银里付——页面上让人勾「我确认没有付款」）。
- 锁：生成批次先取操作编号的咨询锁（新业务类型 `payment_batch`）→ 付款申请（id 升序，`FOR NO KEY UPDATE`，核对已审批、没付清、不在别的批次）→ 写批次；记已付走 `payFromRequest` 的原锁（供应商 → 申请 → 收货单 → 期初未付），之前先锁批次一行。

## 6. 合同模板与起草（CW-E，迁移 `146`）

- `contract_templates`：名称、合同类型（采购 / 服务 / 租赁 / 其他）、**正文**（纯文本加段落，用 `{{字段}}` 占位）、**可填字段**（`[{key,label,type}]`，正文里引用；另有内置字段：供应商名称、我方名称、合同编号、起止日期、总价大小写、付款节点表、单价表、质保、验收）、**可选条款**（`[{key,title,text,default}]`，起草时勾选）、状态 `active|retired`、版本。改模板 = 停用旧版、写一份新版本（与用料一样），已经起草的合同记着用的是哪一版。
- 起草：新建合同时选模板 → 合同的 `draft` 里多 `template: {id, version, values, clauses}`；结构化的部分（四段付款、单价表、验收……）照旧在原来的表单里填，模板只管正文。
- **导出**：Word（`.docx`，服务端用已有的 zip 生成最简单的 WordprocessingML：标题、段落、付款节点与单价两张表）与 PDF（新打印页 `/print/contract/:id`，浏览器「打印 → 存为 PDF」）。导出的是**当时的草稿或生效版本**，页眉写合同编号与版本；导出后仍走现有的法务审查、签署与用印（CW5，不做在线签署）。
- 权限：模板维护 `contract.manage`；导出 `contract.read`。锁：模板的新建、改版先取「合同模板」的咨询锁，再锁旧版一行（带版本号）；导出只读。

## 7. 供应商门户（CW-F，迁移 `147`）

在对账确认链接的做法上扩成四种（CW6：不开账号、凭链接、14 天有效、可作废）：

- `supplier_links`：种类 `quote|po_confirm|delivery|recon`（`recon` 照旧用 `recon_links`，这里不搬），对象（询价单、采购单）、供应商、令牌摘要、快照、过期、作废、生成人；`supplier_link_replies`：每次回复一行（报价、确认、发货预告各自的内容 jsonb、回复人姓名、IP、时间）。
  - **报价**（询价单、开着的）：供应商在链接里按询价单的行填单价、运费、交期、付款条件、有效期 → 系统替他登记一份报价（`sourcing_quotes`，来源记「供应商链接」、经办人记生成链接的员工），已经有这家的有效报价就撤下旧的、登记新的；询价单定标或撤销以后链接失效。
  - **订单确认**（已审批的采购单）：确认能供、承诺到货日（可以改）、备注 → 记 `po_supplier_confirmations`，采购单上显示「供应商已确认，承诺 X 日到」，流程图（8.0.17）的「下单」环节用承诺日。只能确认一次，要改请采购重发链接。
  - **发货预告**（已确认的采购单）：发货日、预计到货日、各行发多少、物流单号 → 记一条，可以多次（分批发货）；收货时收货单上提示「供应商预告发了 X」。
- 公开接口 `/api/public/supplier/:token`（读）、`/reply`（写）与 `recon` 同一套：令牌只存摘要、按 IP 限次、`no-store`、模块关着 404、过期或作废 404。公开页面 `/s/:token`。
- 对外访问：正式服对公网开放前（`docs/RELEASE_V800.md` 第 2.3 节）只能在内网 / Tailscale 里用，页面上生成链接时提示这一点。
- 锁：生成先锁对象一行（询价单 / 采购单 `FOR NO KEY UPDATE`）→ 作废同种类没回的旧链接 → 写新链接；回复：链接一行（`FOR UPDATE`）→ 对象一行（与员工端同一把锁：报价走 `addQuote` 原来的锁、确认与预告锁采购单一行）→ 写回复与结果。

## 8. 权限、模块与入口

| 入口 | 位置 | 权限 |
| --- | --- | --- |
| 数据字典、自定义字段定义 | 后台「规则中心」新分区「数据字典与字段」 | `settings.manage` |
| 自定义字段的值 | 各自详情页「其他信息」 | 各类的维护权限 |
| 发票识别 | 发票台账、三单、报销登记里的发票一栏 | 照原来 |
| 开票申请 | 前台结账记录、会员充值记录；ERP「财务 → 开票」（新模块 `sales_invoices`） | 申请 `frontdesk.checkout`；处理新权限 `invoice.issue` |
| 银行流水 | ERP「财务 → 银行流水」（新模块 `bank`） | 看 `payable.read`、导入与勾对 `payable.manage` |
| 批量付款 | ERP「付款」页签 | `payable.manage` |
| 合同模板、导出 | ERP「合同」页签与合同详情 | `contract.manage` / `contract.read` |
| 供应商链接 | 询价单、采购单详情 | `purchase.manage` |

新模块默认开（功能开关默认开的约定），依赖：`sales_invoices` 不依赖别的；`bank` 依赖 `payables`。
