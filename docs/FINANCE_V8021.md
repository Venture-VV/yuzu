# 8.0.21 设计 · 财务与合同做深

排期见 `docs/SCHEDULE_V8020.md` 第 3 节（CW-A 到 CW-J）；默认做法 CW1–CW10 店主 2026-11-14「全部都按照默认」已确认，本文件里再细分出来的（CW11 起）记在 `docs/PENDING_DECISIONS.md`，店主 2026-11-14「都按默认」一并按默认确认。对外接口（支付直连、平台验券、OTA）见 `docs/INTEGRATIONS_V8021.md`。迁移 `141`–`150`（第 9 节）。

开工前读代码核对的现状：

- **进项发票台账**（8.0.3）：`supplier_invoices` 一张表管三单登记、报销关联、台账直接登记（`source three_way|expense|manual`），内容不可改、只能认证与作废；发票号码去空白、不分大小写后取咨询锁（`input_invoice_no:<号码>`），同一供应商（没有供应商的按开票方）同一号码只有一张有效的。登记全靠手填。
- **付款**：`payments`（供应商往来，按收货单 / 期初未付分摊）与 `payment_requests`（付款申请，挂合同按段、或不挂合同）、`contract_payouts`（服务、租赁合同的付款）；付款方式 `bank_transfer|wechat|alipay|cash|other`。没有「批量」与「对银行流水」的概念；供应商档案只有联系人、电话，没有银行账户。
- **回款**：`ar_collections`（协议单位回款）、`platform_settlements`（平台打款登记）、`petty_advances`（备用金打款）、报销单（公司付的没有单独的打款记录）。
- **合同**：`contracts.draft`（jsonb）存可改的内容（标题、起止、总价、四段付款、质保、验收、单价表），提交、审批、签署、用印、归档一整套；没有模板，也没有任何文档生成（只有上传扫描件）。服务端有手写的 zip 与 xlsx（`lib/xlsx.ts`），前端有 `/print/*` 打印页。
- **供应商对外**：只有对账确认链接（`recon_links`，8.0.7）：随机 24 字节令牌只存 SHA-256、14 天有效、只能回一次、公开接口按 IP 限次、`no-store`。询价报价、订单确认、发货都只能员工代录。
- **选项**：作废原因、撤销原因、移单原因是写死的快捷选项；退款、报损、取消预约、资产报废的原因是纯手填；费用科目、合同类型、盘点差异原因、团购平台在数据库里有 CHECK（进账务口径）。门店自己维护的清单只有渠道来源、耗用用途、钱箱（`settings` 里）。供应商、物料、合同没有扩展字段；会员原来的 `custom_fields` 在 8.0.4 冻结、改成标签。

## 1. 数据字典与自定义字段（CW-J，迁移 `141`）——已做

**字典（快捷原因）**：门店自己维护弹窗上那一排可点的原因，**不碰**进账务口径的分类（费用科目、合同类型、盘点差异原因、团购平台照旧写在代码与 CHECK 里）。

- 一份设置 `dictionaries`（`PUT /api/settings` 的部分保存，在设置锁里合并，只改提交的那几份），按清单键存文字数组，每份最多 30 条、每条最多 20 个字、不能重复。原因在业务表里本来就存文字，所以清单里**可以删、可以改名**：只影响以后的快捷选项，已经记下的原因原样留着；页面上照样可以手填。
- 十份：作废明细、撤销接待、换手牌、锁牌、撤销消费、转单（原来写死的照搬成默认值），退款、报损、取消预约、资产报废（原来纯手填，页面上多一排快捷原因，默认给几条常见的）。前端统一用 `useReasons(<清单键>)`（`lib/session`）与 `components/ReasonChips`；`ReasonDialog` 多一个 `reasons` 参数。
- 后台「规则中心 → 数据字典与字段」一个分区（`/admin/dictionaries/<页签>`，`settings.manage`），三个页签：快捷原因、自定义字段、按字段查。

**自定义字段**：会员、供应商、物料、合同四类，每类**启用的**最多 10 个（CW10），连停用的最多 99 个。

- `custom_field_defs`：`entity`（`member|supplier|material|contract`）、`key`（f1…f99，按建的先后取，建了不改）、`label`（最多 12 个字，启用的里面不重名）、`type`（`text|number|date|select`，建了不改）、`options`（选项类，最多 20 个）、`in_list`（列表里显示）、`active`、`sort`、`version`。触发器兜底：不能删，类别、编号、类型不能改。
- `custom_field_values`：`(field_id, entity_id)` 一格，`value`（文字；数字规范成整数或两位小数的文字；日期 `YYYY-MM-DD`；选项存选项文字），`updated_by/at`。**单独一张表**，不加到业务表上（合同、物料、会员都有保护触发器与版本号，扩展字段改了不应该动它们）。清空就删掉那一格（改动都记审计 `custom_field_value`）。
- 改值：详情页「其他信息」一块单独保存（`GET/PUT /api/custom-fields/:entity/:id`，带看到的值的摘要，对不上拒绝 `FIELDS_CHANGED`）。读照那一类的查看权限（会员 `member.read`；供应商 `inventory.read` 或 `contract.read`；物料 `inventory.read`；合同 `contract.read`），改照维护权限（会员 `member.write`、供应商与物料 `inventory.master`、合同 `contract.manage`）。只提交改了的格；没改的老值（例如选项删了以后的老选项）不再校验。会员在会员工作台的详情，供应商、物料在 ERP 库存「档案」的弹窗里，合同在合同详情页。取不回来（也没有上一次的）时这一块写明「其他信息加载失败」、可以重试，不当成没建字段整块藏起来（Codex 审查 `26fe580` 后补）；还在取时不占位，没有启用的字段时整块不显示。
- 列表：「列表里显示」的字段在会员工作台的会员列表、物料与供应商档案、合同列表的那一行下面显示「字段：值」（`GET /api/custom-fields/:entity/values?ids=`，一个列表取一次）。
- 按字段查：后台「按字段查」选一类、一个字段，文字类按包含查、其余按等于，空着就列出填了的；导出 CSV（记审计）。除了 `settings.manage` 还要能看那一类。
- **不进账务口径、不参与结账与任何计算。**
- 锁：定义的写入（新建、修改、停用 / 启用）先取「自定义字段 + 类别」的咨询锁（同一类串行，数启用的个数、取编号），修改再锁定义一行（带版本号，对不上拒绝 `FIELD_CHANGED`）；值的保存先取「自定义字段值 + 类别 + 对象」的咨询锁（同一个对象的保存串行、核对摘要），不锁业务行（只读地核对对象存在）。
- 会员原来冻结的 `custom_fields` 列（8.0.4 起转成标签）不动。

## 2. 发票识别（CW-A，迁移 `142`）——已做

在「发票台账 → 登记发票」、付款页三单的「登记发票」、报销登记的发票一栏，多一个「拍照 / 选文件识别」（`features/invoices/InvoiceScan`），全在浏览器本机做（`features/invoices/invoice-scan`）：

- **PDF**（数电票多是 PDF）：用 `pdfjs-dist` 取第一页的文字（PDF 里本来就是文字，不用识别），再把这一页画成图找二维码。
- **二维码优先**：增值税发票（含数电票）左上角的二维码是逗号分隔的字段（版本 01、票种代码、发票代码、发票号码、不含税金额、开票日期、校验码……）。先用浏览器自带的 `BarcodeDetector`，没有时用 `jsqr`（员工食堂的扫码也用它）；整张找不到再放大左上角、右上角找。带出号码（老票 8 位、数电票 20 位）、开票日、不含税金额，票种代码推出专票 / 普票（`@shared/invoice-recognize` 的 `parseInvoiceQr`）。二维码里没有税额：有 PDF 文字的用文字里的价税合计与税额；没有的，发票类型只有一档税率就直接算，几档的等人选了税率再按不含税金额算价税合计。
- **读不到二维码、也没有 PDF 文字，才走文字识别**：沿用管家部的本机 OCR（tesseract.js，`/concierge/ocr/` 下的资源随构建带着、按需加载，`receipt-ocr` 导出 `loadLocalTesseract`），按版式找「发票号码」「开票日期」「（小写）价税合计」「合计 金额 税额」、第二个「名称」「纳税人识别号」（销售方）（`parseInvoiceText`）。
- 识别结果只是**填进表单**，带出来的每一格标「识别」，表单底下要勾「已对照票面核对过识别出来的内容」才能提交（CW1）。开票方名称与档案里的供应商同名的直接选上；老票的发票代码写进备注。报销页的票面价税合计只用来对照报销合计，不一致时提示。
- **不传第三方**：图片、PDF 不离开浏览器；附件照旧在登记以后上传到自己的服务器。
- 台账多记一列 `entry_method`（`manual|qr|ocr`），登记时写定（保护触发器照旧，建了不改），台账那一行标「二维码识别 / 文字识别」，页面上数「有效的 N 张里 M 张是识别登记的」。三个入口的请求各多一个字段（台账、三单 `entryMethod`，报销 `invoiceEntryMethod`），**手填的不放进原请求摘要**，升级前就在「结果待确认」里的原请求照样对得上。查重照旧按发票号码的锁。

## 3. 开票申请（CW-B，迁移 `143`）——已做

给客人开票（销项）。8.0.21 做**台账与状态**，开票服务商做成适配器、先带模拟的（CW2、CW22）：

- `invoice_requests`：来源 `checkout|recharge|ar_collection`（结账单、会员充值、协议单位回款）+ 来源编号与单号、开票金额、抬头类型（个人 / 单位）、抬头、税号、邮箱、手机、发票种类（普票 / 专票；个人只能普票、专票要税号）、备注；状态 `requested|issued|rejected|voided`；开出后记发票号码、开票日期、PDF（`erp_files` 新类别 `sales_invoice`）、开票途径（`manual` 手工登记 / 服务商名，`mock` 为模拟）与服务商单号。申请号 `KP<日期>-<序号>`。申请的内容建了不改（触发器只放行处理的那几列）。
- **可开金额（CW13）**：结账单只算现金类收款（微信、支付宝、现金、银行卡、其他），去掉储值、券、优惠、会员折扣、次卡、挂账，减掉已生效的退款单；会员充值按实收（赠金不开）；协议单位按回款。反结账、冲销了的为 0。开票金额不能超过可开金额，可以少开。
- **同一笔只能开一次**：同一来源同时只有一张申请中 / 已开的（部分唯一索引）。驳回的、作废的不占；红冲 = 作废已开的（写原因）+ 重新申请。
- 谁做：前台在「结账记录」里打开一张单点「开票」（`frontdesk.checkout`）、会员详情的充值记录那一行点「开票」（`recharge.create`）、ERP「应收与挂账」回款那一行点「开票」（`ar.manage`）；有「开票」的都能申请。财务（新权限 `invoice.issue`，默认店主与有「对账付款」职责的，CW14）在 ERP「财务 → 开票」（新模块 `salesInvoices`，默认开，不依赖库存）处理：登记已开（手工开好后填号码、可传 PDF）、「交给服务商开」（适配器，`docs/INTEGRATIONS_V8021.md` 第 5 节；没接时这个按钮不出现）、驳回、作废。页签：申请中、已开、要红冲、全部。
- 来源反结账、冲销**不拦**；已开的在开票页标红「来源已作废，要红冲」，「要红冲」页签数得出来（CW15）。（「要红冲」在库里先筛再取最近的 500 张，Codex 审查 `beabd59` 后补）
- 锁：申请先取操作编号的咨询锁（与「确认作废」串行，新业务类型 `invoice_request`，查回、确认作废走全店那一套）→ 来源一行（`FOR KEY SHARE`，结账单 / 充值 / 回款，锁住以后核对没反结账、没冲销）→ 写申请；处理只锁申请一行（带版本号，对不上拒绝 `INVOICE_REQUEST_CHANGED`）。**交给服务商开**：先在锁里把申请记成「发送中」（`issued_via = sending`，同一张不会同时发两次），事务外调服务商（记一行对外调用），再锁申请一行写结果；服务商明确失败的改回申请中；结果没回来的（进程中断）由财务确认服务商没开出后「改回申请中」（写原因）。发送中的不能登记、驳回、作废。

## 4. 银行账户与网银流水（CW-C，迁移 `144`）——已做

- `bank_accounts`：本公司的银行账户（名称、开户行、账号后四位、网银格式 `icbc|ccb|cmb|generic`、启用）。完整账号不存（CW16）。还记着这个账户导入时列怎么对（`column_map`）。
- **导入**：网银导出的 CSV（页面先按 UTF-8 读、乱码再按 GBK 读）或 Excel（`lib/sheet-read`）。按同义词认列（`@shared/bank` 的 `detectColumns`：日期、收入 / 支出（或交易金额 + 借贷标志、或负数为支出）、余额、对方户名、对方账号、摘要、流水号；工商、建设、招商常见的表头都在同义词里），认不准的在预览里逐列改，导入后按账户记住。表头可以不在第一行（前 30 行里找）；合计行、没有日期的行跳过，日期认不出的行列出来不进库。同一个账户同一份文件（内容摘要）只导一次；每条流水有流水号的按「流水号」、没有的按「日期 + 方向 + 金额 + 对方 + 余额 + 摘要」去重。
- `bank_statement_lines`：账户、日期、方向（收 / 付）、金额、余额、对方户名、对方账号、摘要、银行流水号、状态 `open|matched|ignored`（「不用对」要写原因，如利息、手续费）。内容只增不改（触发器）。
- **勾对**（CW3，`bank_matches`）：一条流水对一笔或几笔系统里的记录（勾对的金额等于记录的金额）。对象：付出——供应商付款、合同付款、备用金打款、备用金补付（第 5 节起还有批量付款的一行）；收入——协议单位回款、平台打款、备用金退回。现金付的不参与。
  - 导入时自动勾对：只认「金额相等、日期前后 3 天、对方户名对得上（相等，或长名称互相包含）」三样都对上、**而且只有一个候选**的。批量付款的一行只认**从这个账户导出的批次**——别的账户的流水同户名、同金额、同一天也不对上；抽屉里不列，手工勾对拒绝（`MATCH_ACCOUNT_MISMATCH`）（Codex 审查 `26fe580` 后补）。
  - 其余在流水抽屉里挑：前后 30 天、金额不超过还差的、还没对过的记录，金额正好相等的排在前面；合计等于流水金额才算这条对平，少了的显示「还差」。撤销勾对写原因。同一笔记录同时只对一条流水（部分唯一索引）。
  - 对象后来作废了不拦，流水上标红「对象已作废」。
- 待办（CW17）：超过 7 天没对上的流水；超过 7 天没对上流水的付款与回款（**从有流水的那天起算**，以前的不算）——页面上方提示，ERP 导航「银行流水」带数字。
- 锁：导入先取操作编号的咨询锁（新业务类型 `bank_import`）→「账户 + 文件摘要」的咨询锁 → 写导入与流水（新行）→ 自动勾对（对象 `FOR KEY SHARE`）；人工勾对：流水一行（`FOR UPDATE`，带版本号）→ 对象（`FOR KEY SHARE`，按种类、id 升序；锁住以后核对没作废、没对过）→ 写勾对；撤销：流水一行 → 勾对一行。
- 页面：ERP「财务 → 银行流水」（新模块 `bank`，依赖 `payables`）：账户、导入、流水（没对上 / 对平了 / 不用对 / 全部，按账户、户名、摘要、流水号、金额搜）、勾对抽屉。权限：看 `payable.read`、维护账户、导入与勾对 `payable.manage`。

- 合计行：日期那一格不是日期、这一行写着合计 / 总计 / 小计的才跳过；有日期的一笔（摘要里写「合计支付」之类）照常认（Codex 审查 `ee51abe` 后补）。
- Excel 对账单里存成序号的日期按**对上的那一列**换成日期（按同义词认的、手动对的、这个账户记住的都算；原来只认固定的几个表头），渠道订单表的入住、离店同样（Codex 审查 `55ccc5e` 后补）。

## 5. 批量付款文件（CW-D，迁移 `145`）——已做

默认用网银批量转账文件，银企直连是可选的适配器（CW4；8.0.21 不做直连按钮，等银行开通联调）：

- 供应商档案加收款账户：户名、开户行、账号（`suppliers.bank_payee/bank_name/bank_account`，维护照旧 `inventory.master`）。**完整账号不发到页面**：列表只给后四位，档案弹窗里账号框空着、提示尾号，要改就整个重填（空着 = 不改）。
- `payment_batches`：批次号 `PL<日期>-<序号>`、付款账户（`bank_accounts`，模板跟账户的网银格式走）、状态 `draft|exported|done|voided`、合计、笔数；`payment_batch_items`：付款申请（已审批、还没付清的）、金额（申请还没付的部分）、收款户名、开户行、账号（**生成时抄一份**，触发器兜底不能改，之后改档案不影响这一批）、用途「付款申请 <号>」、状态 `pending|paid|failed|removed`、记已付时用的操作编号（生成时定下）。同一张付款申请同时只能在一个没结束的批次里（`active` 的部分唯一索引）。
- 流程：「付款 → 批量付款」页签勾选待付的申请（收款账户不全的不能勾）→ 生成批次 → 导出网银模板（工商、建设、招商常见的列 + 通用 CSV，CW19；**按门店实际网银的导入模板核对后再用**）→ 在网银里上传付款 → 回来：「银行流水」导入对账单，按「金额 + 收款户名」自动对上每一行（批量付款的一行是流水的勾对对象之一），对上的照「按申请登记付款」记账（方式 `bank_transfer`，凭据写批次号与银行流水号；没挂合同的核销到申请里选的那几笔，挂了合同的记预付款、之后按收货核销；服务、租赁合同登记合同付款）；对不上的手工「标记已付」（填付款日、流水号）或「失败」（写原因，申请回到待付款）。全部有结论后批次 `done`。这样记出来的付款在银行页不再算「没对上流水」（它那一行已经对上了）。
- 导出以后不能改，只能作废重开：作废要勾「我确认这一批没有在网银里付款」，有记了已付的不能作废。
- 锁：生成先取操作编号的咨询锁（新业务类型 `payment_batch`）→ 付款申请（id 升序，`FOR NO KEY UPDATE`，锁住以后核对已审批、没付清、不在别的没结束的批次、收款账户齐全）→ 写批次与明细；导出、作废只锁批次一行（带版本号）；记已付：批次一行 → 明细一行（先记下付款日与流水号，之后重来都按这一次的，原请求的摘要对得上）→ 事务外调 `payFromRequest` / `payoutFromRequest`（明细自己的操作编号，原来的锁与幂等：供应商 → 申请 → 收货单 → 期初未付）→ 再锁批次、明细写结果。
- **收款账户的双人复核**（CW28，Codex 安全审查 `354e34c` 后补，迁移 `151`）：收款户名、开户行、账号只由应付岗（`payable.manage`）在供应商的「收款账户」里改（`PUT /api/inventory/suppliers/:id/bank`），采购（`inventory.master`）存供应商档案时带了不一样的收款账户拒绝 `SUPPLIER_BANK_SEPARATE`；店主以外的人改了是「待复核」，要另一位应付或店主带上看到的后四位与这一行的版本（`rowVersion`，行的 `xmin`，改了任何一项都会变）复核（`POST …/bank/verify`；改的本人复核 403；看完以后又被改过的——哪怕换成同样后四位的账号、只改了户名或开户行——`SUPPLIER_BANK_CHANGED`，Codex 审查 `ee51abe` 后补），店主改的直接算复核过；批量付款的候选里没复核的不能勾（`BATCH_BANK_UNVERIFIED`），生成批次时只抄已复核的（核对以后到抄之间刚被改掉的整批拒绝）；账户三项不管从哪儿变了，触发器把复核清空。锁：改账户、复核只锁供应商一行（`FOR NO KEY UPDATE`）。
- 流水对上批量付款的一行、记了账以后，那笔付款被冲销（或合同付款被冲销）：流水那一行标「对象已失效」，与直接对上付款的一样（Codex 审查 `55ccc5e` 后补）。
- **批次占着申请**（Codex 审查 `beabd59` 后补）：申请进了一批没结束的批量付款以后，只有那一行自己（用它的操作编号）能登记付款；单独登记付款、作废、结束都拒绝（`REQUEST_IN_BATCH`，等那一批记已付、标失败或作废）。**导出前再核对**：每一行的申请还是待付款、没付的还够这一行；没挂合同的，申请里选的货款还能核销这么多（有人不走申请直接登记付款核销掉了的就不够）——对不上的不导出（`BATCH_STALE`），作废重开。**不走申请的付款登记、它的确认与退回再提交、供应商往来核销**，核销到的收货单 / 期初未付正被没结束的批次里的申请占着的，也拒绝（`TARGET_IN_BATCH`，测试会话在 `ee51abe` 上报的 P1：导出以后另行付掉一部分，文件里还是原金额）；**下载文件前**再核对一次，对不上的不给下载（这一行标失败或作废这一批后重新生成）。
- 记已付做到一半（付款已经按这一行自己的操作编号 `pay_client_key` 记上、这一行还没标已付）：再记一次时先按这个操作编号找回那笔付款（按申请登记的付款或合同付款），不再按现在的余额重算核销；银行流水对批量付款的一行时与别的对象一样只在给的日期范围里找（按批次导出的那天）。（Codex 审查 `354e34c` 后补）
- 导入对账单的原样重提（同一个操作编号）也把自动对上的批量付款行接着记账：上一次导入提交了、记账没做完进程就停了的，重提时补上——只挑还没结论的行，各行用自己固定的付款编号，不会记两次（Codex 审查 `e64932b` 后补：原来重提跳过记账，流水显示对平了、申请却还是待付款）。

## 6. 合同模板与起草（CW-E，迁移 `146`）——已做

- `contract_templates`：编号 `HT-<序号>`、版本、名称、合同类型（采购 / 服务 / 租赁 / 其他）、**正文**（纯文本，空一行分段，`# ` 开头的一行是小标题，用 `{{字段}}` 占位）、**可填字段**（`[{key,label,type,required}]`，文字 / 数字 / 日期，必填的没填不能提交审查 `CONTRACT_INCOMPLETE`）、**可选条款**（`[{key,title,text,default}]`，起草时勾选，导出时接在正文后面的「补充条款」）、状态 `active|retired`。内置字段从合同带出：我方、相对方、合同编号、合同名称、起止日期、总价、总价大写（人民币大写）、税率、付款节点（表）、单价表（表）、质保、验收方式、验收签字人、不合格处理。可填字段不能与内置字段重名（新建、改版都拦）；渲染时内置字段以合同本身为准，模板值里有同名的也盖不掉（Codex 审查 `354e34c` 后补）。没选模板时请求里不带 `template`（或带 `null`），原请求摘要与升级前一样。
- 改模板 = 停用旧版、写一份新版本（同一编号只有一版在用；触发器兜底：不删、版本内容不改、停用的不能再启用）。已经起草的合同记着 `template: {id, code, version, name, values, clauses}`，模板改版、停用都不影响；编辑这种合同时下拉里照样有那一版（标「已停用」）。
- 起草：合同表单多一节「合同正文（模板）」——选模板、填字段、勾条款；结构化的部分（四段付款、单价表、验收……）照旧在原来的表单里填，模板只管正文。模板与合同类型不一致时提示，不拦。
- **导出**：合同详情「导出 Word」（`.docx`，服务端生成最简单的 WordprocessingML：标题、段落、付款节点与单价两张表，页眉写门店、合同编号与版本）与「打印 / PDF」（打印页 `/print/contract/:id`，A4，浏览器「打印 → 存为 PDF」）。导出的是**当时的草稿或生效版本**（起草中的页眉写「草稿」）；没用模板的合同导出合同要素与两张表。导出记审计（`contract_template`）。导出后仍走现有的法务审查、签署与用印（CW5，不做在线签署）。
- 维护：ERP「合同」页「合同模板」——列表、新建、改（存成新版）、显示停用的旧版、每版有几份合同在用。
- 权限：模板维护 `contract.manage`；看模板与导出 `contract.read`。锁：新建先取「合同模板」的咨询锁（编号在锁里取）；改版、停用先取「合同模板 + 编号」的咨询锁、再锁那一版一行；导出只读。

## 7. 供应商门户（CW-F，迁移 `147`）——已做

在对账确认链接的做法上扩成三种（CW6：不开账号、凭链接、有效天数与对账确认链接同一项设置（默认 14 天）、可作废）：

- `supplier_links`：种类 `quote|po_confirm|delivery`（对账确认照旧用 `recon_links`，这里不搬）、对象（询价单或采购单）、供应商、令牌摘要、快照（供应商看到的单号、物料行、采购单的单价与合计）、过期、作废、生成人；只能作废一次，别的不能改。重发时同一对象、同一家、同种类还在用的旧链接自动作废。`supplier_link_replies`：每次回复一行（内容 jsonb、回复人姓名、IP、时间、页面生成的操作编号 `client_key` 唯一——没收到结果再点一次只记一次，内容不同的拒绝），只追加。
  - **报价**（询价单、询价中）：在询价单详情「请供应商在线报价」里选一家、生成链接。供应商在链接里按询价单的行填含税单价、运费、交期、付款条件、有效期、姓名 → 系统替他登记一份报价（`sourcing_quotes.via_link_id` 记链接，经办人记生成链接的员工，比价表里标「供应商链接」）；这家已经有有效报价（员工登记的或上一次链接里报的）就撤下旧的（原因「供应商通过报价链接重新报价」）、登记新的。询价单定标或撤销以后链接里显示「询价已经结束」，不能再报，也不能再发。
  - **订单确认**（已确认、没关闭的采购单，先收货后补的单不发）：采购单详情「供应商确认与发货」里发链接。供应商确认能供、写承诺到货日（不早于今天）、备注 → 记 `po_supplier_confirmations`（一张采购单只认第一次，确认以后不再发确认链接）；采购单上显示「供应商已确认，承诺 X 到」，流程图（8.0.17）的到货环节按承诺日算超期。
  - **发货预告**（供应商已确认的采购单）：发货日、预计到货日（不早于发货日）、各行这一批发多少（不超过下单数量）、物流单号 → 每次记一条，可以分批；采购单详情列出各批，按单收货时收货单上提示「供应商预告了 N 批发货」。
- 公开接口 `/api/public/supplier/:token`（读）、`/reply`（写）与对账确认同一套：令牌只存摘要、同一来源地址 10 分钟里试错最多 30 次、`no-store`、采购模块关着 404、过期或作废 404。公开页面 `/s/:token`（手机上也能填）。员工端接口：`/api/purchase-sourcing/:id/supplier-links`、`/api/purchase-orders/:id/supplier-links`、`/api/purchase-orders/:id/supplier-portal`、`/api/purchase-supplier-links/:id/void`（发、作废要「编制与提交采购单」，看要「查看库存与物资单据」）。
- 对外访问：正式服对公网开放前（`docs/RELEASE_V800.md` 第 2.3 节）只能在内网 / Tailscale 里用，生成链接时页面上提示这一点。
- **按采购单的版次认**（Codex 审查 `beabd59` 后补，迁移 `152`）：采购单链接的快照里记着发链接时的版次；采购单改版（可能换了供应商）时，发出去的确认、发货预告链接一起作废；版次或供应商对不上的链接打开是「这张采购单改过了」、不能回复。订单确认改成「一张采购单的一个版次」一次（`po_supplier_confirmations.po_revision`，与采购单一起唯一）：改版前的确认留着，但确认状态、流程图的承诺到货日、发货预告都只认当前版次的，改版、重新确认以后可以再发确认链接。
- 锁（没有反过来的路径）：生成先锁对象一行（询价单 / 采购单 `FOR NO KEY UPDATE`）→ 作废旧链接 → 写新链接；回复先不加锁读出链接对应的对象，再锁对象一行（询价单 `FOR UPDATE`，与员工登记报价、定标同一把；采购单 `FOR NO KEY UPDATE`）→ 链接一行（`FOR UPDATE`，锁住以后再核对没作废、没过期）→ 写回复与结果（报价走与员工登记同一个 `insertQuoteLocked`）；作废只锁链接一行。
