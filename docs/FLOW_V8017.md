# ERP 流程图 · 采购从提需求到付款（8.0.17）

店主 2026-11-13：「erp 那边想做流程图，让审批更简单直观，可以参考钉钉或者飞书，一起在 8.0.17 做了吧。」附了一张《浴族 · 采购审批流程（横版）》：按金额分成流程 A（免比价）与流程 B（必须比价 + 审批），每个环节一个圆点——做完的打绿勾、正在等的橙点并写等了多久、没到的灰着、超期或卡住的红底标出来。

这一版做两件事：**采购的流程图**（照店主那张图），和**所有单据的审批进度改成同一套图样**（钉钉、飞书审批详情里那种一级一级的时间线）。默认做法记在 `PENDING_DECISIONS.md`「8.0.17 ERP 流程图」（LC1–LC10，待确认）。

## 1. 一条总规矩：图是算出来的，不是填出来的

流程图**只读**：每个环节的状态都从现有的单据推出来（需求单、询价单、采购单、审批单、收货单、付款与报销），没有新的表、没有新的审批环节、不改任何规则。单据往前走一步，图自己跟着变；图上不能点「通过」，要办事点环节跳到那张单据上办（权限照旧）。

这样做的原因：流程图要是另存一份状态，迟早与单据对不上；从单据算，图上是什么，单据就是什么。

## 2. 两条流程与分流

| | 流程 A · 免比价 | 流程 B · 比价 + 审批 |
| --- | --- | --- |
| 什么时候走 | 合计小于「询价门槛」，也没有发起询价 | 合计达到「询价门槛」，或已经发起了询价 |
| 环节 | 部门提需求 → 需求审核 →（采购单审批）→ 采购下单 → 到货验收 → 入库 → 财务付款 | 部门提需求 → 需求审核 → 询价比价 → 比价定标 → 采购单审批 → 下单中标方 → 到货验收 → 入库 → 财务付款 |

- **分流的金额读「采购 → 采购规则」里的询价门槛与最少报价家数**（现在是 ¥5,000、2 家），不在流程图里另设一个数。店主图上写的是 ¥1,000：在采购规则里把询价门槛改成 1000 即可，图与提交采购单时的拦截一起变（LC2）。门槛设成 0（不要求询价）时都走流程 A。
- **金额用哪个**：有采购单的用采购单合计；只有需求单时按各行「参考价 × 数量」估，图上写明是估的；一行参考价都没填的先按流程 A 画，注明「金额未定，下单时合计达到门槛要先询价」（LC3）。
- 流程 A 里的「采购单审批」只在这张采购单确实要人审时才出现（需求单转的采购单按采购规则「提交即确认」时没有这一环）。
- 没有需求单、采购直接建的采购单：从「采购下单」（或询价）开始画，前面没有「部门提需求」。

## 3. 每个环节怎么算

| 环节 | 谁 | 做完 | 正在等（橙点） | 卡住（红） |
| --- | --- | --- | --- | --- |
| 部门提需求 | 部门 · 提的人 | 需求单已提交（写提交时间） | — | — |
| 需求审核 | 审核需求单的人 | 已通过（谁、什么时候） | 待审核；截单后提交的写「明天起可审核」 | 已退回（写原因，等部门改）；等了超过「环节超期天数」 |
| 询价比价 | 采购 | 有效报价够家数，或已定标 | 询价中：已收几家 / 要几家；还没发起的写「待发起询价」 | 等了超过天数，写还缺几家 |
| 比价定标 | 采购 / 负责人 | 已定标（中标供应商、谁定的；单一来源会注明） | 报价已齐、待定标 | 等了超过天数 |
| 采购单审批 | 审批链当前这一级 | 已确认（谁、什么时候） | 草稿待提交；待审批（第几级、等谁） | 已退回修改（写原因）；审批中心标了超时；等了超过天数 |
| 采购下单 / 下单中标方 | 采购 → 供应商 | 采购单已确认（单号、日期） | 已通过的需求还没转采购单 | 等了超过天数 |
| 到货验收 | 仓库 | 已到齐，或采购单关闭且到过货 | 供应商送货中；部分到货（几行到了）；有收货单在等确认时写单号 | 过了预计到货日（没填的按「下单后几天算超期」），写超期几天 |
| 入库 | 仓库 / 负责人 | 到齐并且收货单都已确认生效 | 有收货单登记了、还没确认 | 等了超过天数 |
| 财务付款 | 财务 | 挂账：这张单的应付付清；现付：都报销完 | 到货以后：已付多少、未付多少；现付的写还有几行没报销 | 不标超期（付款期限在「付款 → 本周应付」里看，LC7） |

- 「到货验收」对应收货单**登记**，「入库」对应收货单**确认生效**（库存这时才加，LC8）。
- 超期两个口径：到货按采购单的预计到货日，没填的按采购规则里已有的「下单后几天没到货算超期」；其余环节按新加的一项采购规则「一个环节等了几天标红」（默认 2 天，LC4）。审批环节另外认审批中心自己的超时。
- 一张需求单拆成几张采购单、或几张需求单并成一张采购单时，合在一个环节里写「2 / 3 张采购单已到货」「3 张需求单」；点环节去到没做完的那一张（LC9）。
- 流程结束的几种：全部做完；需求单被定为「不采购」或撤回；采购单关闭。结束的图上写明，不再标等待。

图上的「部门确认（部门主管）」这一环系统里现在没有（需求单只有一道审核）。加一道部门主管确认是新的审批规则，不在「只读的图」的范围里，单独请店主定（LC1）。

## 4. 放在哪

1. **采购 → 流程进度**（新页，`/purchasing/flow`）：进行中的每一条画一张卡（照店主那张图：标题行写流程 A / B 与金额，下面一排环节）。顶上写现在的分流规则；可以按「全部 / 卡住或超期 / 待审核 / 询价中 / 待审批 / 待到货 / 待入库 / 待付款」筛。已经全部做完的不列。
2. **单据详情顶上**：需求单、询价单、采购单打开就是这条流程走到哪了；点别的环节跳到对应的单据。
3. **审批中心**：采购单的审批详情里带这条流程——审的人看得到这张单前面走过什么、后面还有什么。
4. **审批进度（所有单据）**：采购单、收货等库存单据、报销、付款、付款申请、合同里原来的「审批进度」改成一条竖着的时间线：每一级一个圆点（已同意绿勾、审批中橙点带等了多久、未到灰、退回红），下面是谁同意或退回、什么时候、写了什么意见。内容与原来一样，只是换了图样。

宽屏横排（像店主那张图），窄屏、抽屉里自动改成竖排。

## 5. 谁看得到

- 有「查看库存」权限的（采购、仓库、财务、负责人）：流程进度页与各处的流程图都看得到，带金额。
- 只有需求单权限的部门同事：只在**自己看得到的需求单**里看到流程图（需求走到哪了），**不显示金额与付款数**，下游环节只写状态、不能点进采购单（LC6）。
- 审批中心里按原来「谁能审」的规矩。

## 6. 取数与性能

- 一个只读接口：`GET /api/erp/purchase-flow?kind=request|po|sourcing&id=`（一条）与 `GET /api/erp/purchase-flows`（进行中的，最多 60 条）。都在只读快照里取，不加锁、不写任何东西。
- 采购单的到货、已付、未付直接用采购单详情的同一个取数函数，数字与采购单页一模一样。
- 环节怎么算写成一个不碰数据库的函数（`src/shared/purchase-flow.ts`），前后端共用，单元用例逐种情形核对。
- 进行中的列表按「没结束的需求单 + 没结束的采购单（近 120 天）」取，同一条不重复列（需求已经全部转成采购单的，由采购单那张卡代表）。门店的量级（同时几十条）下够用；量大了再做分页（已知的限度）。

## 7. 不做的

- 不在图上办事（通过、退回、定标都在原来的页面）。
- 不加「部门主管确认」「固定付款日（15 / 30 号）」这类新规则（LC1、LC7）。
- 报销、合同、付款申请各自的整条流程图这一版不画（它们的审批进度已经换成时间线）；采购这条先做，好用再照样加。
