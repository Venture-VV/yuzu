## 0. 升级后会看到的变化

- **老一些的浏览器上，侧栏能单独滑了**（店主 2026-11-16 报「侧边栏经常会划不动，就是右边滑着然后左边超了」）：门店、后台、ERP 都一样。整页不再跟着内容滚，右边滚动时左边侧栏原地不动。新版浏览器上本来就正常，看不出变化。
- **UI 工作台打开时**，「原样 / 放大」总是和平板现在的设置一致（后台「电子菜单 → 设置」）；之前有时开在「原样」。

## 1. 范围

1. **侧栏划不动**：门店、后台、ERP 的整屏版面用 `h-dvh`（`100dvh`，随地址栏伸缩的屏幕高度）定高。Chrome 108、Safari 15.4 以前的浏览器不认识 `dvh`——没法更新内核的安卓平板自带浏览器、内核偏老的国产浏览器常见——把这条当没写，版面没了高度，变成整页跟着内容滚：侧栏被撑得和内容一样长（后台约 2,100～2,400px）、自己没东西可滑，右边一滚、左边跟着跑出屏幕。
   - 修法：`scripts/dvh-fallback.ts`（PostCSS 插件，主系统与员工食堂的 Vite 配置都接上）。打包时给每条用到 `dvh` / `svh` / `lvh`（`dvw`……）的规则，紧跟着补一块 `@supports not (height: 1dvh) { 同一个选择器 { 换成 vh / vw } }`，只有不认识 `dvh` 的浏览器用它。
   - 不写成同一条规则里的两条声明（`height:100vh;height:100dvh`）：Vite 8 默认用 Lightning CSS 压缩、目标浏览器是 Chrome 111 / Safari 16.4 以上，会把前一条当多余的删掉（实测）；单独的 `@supports` 不删。
   - 平面图画布的最大高度原来写在行内样式里（打包管不到），改成类名，一并有了后备。
   - 写法约定记进 `AGENTS.md`「屏幕高度（8.1.4）」：照常写 `h-dvh` 这类类名，行内样式里不写 `dvh`。
2. **工作台开在哪一档**：工作台第一次取到草稿时按菜单里的平板设置定「原样 / 放大」，可菜单那时不一定回来了——草稿先回来就一直停在「原样」。现在平板菜单要等菜单回来（取不回来也算回来了）再开（`StudioPage.tsx`）。这是 8.1.3 合并后第一次跑 CI 时 `e2e/studio.spec.ts` 时过时不过的根因。

## 3. 已执行的验证

- **侧栏**：
  - 新版 Chrome（Playwright 自带）上复现不出来：侧栏与右边内容各自能滑，滚轮与真实的触摸序列（按下、移动、抬起）都试过。
  - 模拟不认识 `dvh` 的浏览器（把样式表里的 `dvh` 改成不认识的单位，与老浏览器一样整条声明作废）：修之前整页在滚（平板横屏 1024×768 门店页整页 1,579px 高）、侧栏自己滚 0px、右边滚 800px 侧栏顶边到 -748px；修之后整页一屏高、侧栏原地不动、后台侧栏能单独滑 700 多像素。新版浏览器里的各项数字与修之前一样。
  - 打包产物里每条用到 `dvh` 的规则后面都有给老浏览器的那一块（主系统、管家部、员工食堂的样式表）。
- **工作台**：本地给草稿请求、菜单请求分别加 1.5 秒延迟复现，修之前报错与 CI 一样（应为 `big`、实际 `design`）、反过来开在「原样」；修之后三种先后顺序都过。
- **用例**：新加 `tests/dvh-fallback.test.ts`（4 条：补在哪、`@layer` / `@media` 里补在原处、自定义属性与关键帧不补、跑两遍不重复、Lightning CSS 按 Vite 默认目标压缩后那一块还在）；`e2e/viewports.spec.ts` 新加「不认识 dvh 的老浏览器」（门店电脑、平板横屏、小屏电脑过；平板竖屏与手机不显示侧栏、跳过）；`e2e/studio.spec.ts` 打开工作台后先核对开在平板设置的那一档。
- **CI**：`bc9655b`（#119 合并前的最后一个提交）上 11 项全绿；版本号那个 PR 的 CI 见 PR。
- 类型检查、`npm run check:code`、`npm run format:check`、构建都过。

## 4. 验收要点

1. **出过问题的那台设备**（平板或电脑）：更新到 8.1.4 以后，在门店首页、后台、ERP 里往下滑右边的内容，左边侧栏不动；手指在侧栏上滑，侧栏自己滚（后台的分区多，一屏放不下）。还划不动的话，记下设备型号、浏览器与版本（浏览器的「关于」里）报在 PR 上。
2. **新版浏览器**：门店、后台、ERP 的侧栏、右边内容与 8.1.3 一样；平面图（后台「空间台账 → 底图」与前台房态图）画布高度不超过一屏。
3. **没有真机时的模拟**：跑 `e2e/viewports.spec.ts` 的「不认识 dvh 的老浏览器」；或在浏览器开发者工具里拦下样式表、把 `dvh` 改掉再看。
4. **UI 工作台**：设计师打开平板菜单的工作台，工具栏「原样 / 放大」与后台「电子菜单 → 设置」里平板的字号档一致；多开几次都一样。

## 5. 已知的限度

- 修的是「不认识 `dvh`」这一种老浏览器。更老的（不认识 `@layer`，Chrome 99、Safari 15.4 以前）整套样式都会失效，不在这一版的范围内；真遇到时请报设备与浏览器版本。
- 真机（门店那台设备）上还没看过，靠模拟核对。
