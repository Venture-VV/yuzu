# 底图转换（RQ-004 第二段，v0.7.15）

飞书需求 RQ-004「系统内平面图」分四段：① 空间台账（v0.7.14）→ ② **底图转换**（这一版）→ ③ 房态图（含第一级实时位置）→ ④ 对客导览与图纸治理。迁移 `033_floorplans.sql`。入口：后台「空间台账 → 底图」。默认做法（待确认）见 `docs/PENDING_DECISIONS.md`「底图转换」，验收要点见 `docs/HANDOFF_V0715.md`。

真实图纸只在开发环境里解析，不进仓库；测试与验收用合成样例（`docs/data/floorplan-sample.dxf`、`floorplan-sample-v2.dxf`）。

## 2. 用编码图实测（开发环境，图纸不进仓库）

需求文档附件「会所 1-3 层编码图.dwg」（约 13 MB），用这一版的命令行 `floorplan-convert` 走完整链路（单独的转换进程）：

| 项 | 结果 |
| --- | --- |
| 读图 | LibreDWG（WebAssembly 版，`@mlightcad/libredwg-web` 0.8.1）22 秒；图元 47,504 个、图层 367 个，展开块参照 9,568 个后得到 293,554 条线、8,479 个文字；LibreDWG 报非致命错误码 64（个别数值超出范围，已忽略） |
| 转换 | 约 4 秒；转换进程内存峰值约 1.3 GB；全程约 27 秒（需求 30 分钟） |
| 楼层 | 三层平面在同一张图里横向排开，按墙线的空隙自动分出 3 块；楼层按房号的楼层位与图上的标题定：L1「一层」、L2「二层」、L3「三层」 |
| 房号 | 95 个编码都在「W-区域文字」图层：L3 90 个、L2 5 个、L1 没有（只出底图） |
| 房间轮廓 | **95 个全部配上轮廓**（封门洞半径 0.6 米一轮就分开）：SPA、踩背房 6–33 ㎡，客房约 21 ㎡，派对房 34–77 ㎡；没有例外 |
| 底图体积 | L1 84 KB、L2 168 KB、L3 208 KB（上限 1 MB） |

开工时的原型只用了墙、柱、门窗几类图层，有 5 个例外（G301 连到走廊；G306、G307、G308 与 G305 连成一片；P201 连到走廊）；把完成面、门套、门的「未开虚线」、扶手等加进围合后都分开了。例外的处理流程照样保留给以后的新图纸。

## 3. 转换链路

代码在 `src/server/floorplan/`：`read-dwg.ts`、`read-dxf.ts`、`read-pdf.ts` 读图 → `model.ts` 中性图元 → `convert.ts` 转换 → `worker.ts` 转换进程 → `run.ts` 起进程。

1. **读图**：DWG 用 LibreDWG 的 WebAssembly 版（版本固定 0.8.1），ASCII DXF 自带解析（设计方另存的 DXF、测试与验收用的合成图纸；二进制 DXF 不收）。展开块参照（最多 6 层），块里画在 0 层的随块参照的图层，去掉外部参照绑定后的图层前缀（`…$0$`），多段线的凸度折成圆弧，镜像（拉伸方向 -Z）的图元翻过来，文字按对齐方式取位置；填充、标注等不转换，只计数。LibreDWG 报致命错误（错误码 ≥ 128）或读不出图元的，记「读不了这个文件」与错误码；非致命的错误码在报告里提示。
   **矢量 PDF**用 pdf.js（`pdfjs-dist` 的 legacy 版，版本固定 6.4.299，只在转换进程里加载，不画图、不需要 canvas）：每页的路径（描边与填充都当轮廓，曲线折成纸上约 1 毫米一段，只做裁剪的路径不要）与文字（基线起点、字高按文字矩阵、旋转按文字方向）；图片、渐变只计数。尺寸按图纸比例 1:N 从纸上的点换成实际毫米：N 先用上传时填的（命令行 `--scale`；v0.7.19 起填的优先，原来是图上的优先，待确认），没填按图上的比例文字（「1:100」「比例 1：150」「SCALE 1:200」，取出现最多的），都没有拒绝；填的与图上写的不同时，转换报告提示「PDF 上写的比例是 1:…，按上传时填的 1:… 换算」。按页面显示的方向（含旋转、裁剪框），y 朝上；每页一块图形，页与页横向隔开 50 米以上，按空隙分楼层时自然分开，页上的楼层标题给这一层定楼层；整个落在页面外的线与文字不要。图层：带可选内容组（CAD 导出时的图层）的按组的名字（白名单照用），不在组里的线算「PDF-墙」、文字算「PDF-区域文字」。没有矢量线条（扫描件）、没有文字（文字转成了曲线，认不出房号）的直接拒绝。
2. **图层白名单**（按名字认，转换报告列出每个图层的用途与图元数）：

   | 用途 | 认法 |
   | --- | --- |
   | 剔除 | 家具、洁具、植物、设备、顶面 / 天花、灯、机电（EQUIP、VPIPE、WIRE）、消火栓、卷帘、疏散、窗帘、尺寸 / 标注 / DIM、填充 / HATCH、英文 / TEXT、轴号、看线、地坪 / 地材、分界线、标识、高差、立面、大样、修改云线、RC-*、AA-* |
   | 只参与围合 | 完成面、门套、门的「未开虚线」、FINISH |
   | 画进底图并参与围合 | 墙、柱、隔断（墙）；门；窗、幕墙、Curt（窗）；楼梯、扶手、电梯（楼梯电梯） |
   | 房间名与房号 | 「区域文字」 |
   | 没用到 | 其余（包括 0 层） |

3. **分楼层**：结构线的中心点按空隙（≥ 20 米）先横向、再纵向切块，至少 10 条结构线；楼层号先看图上的楼层标题（「一层」「2F」「L3」，图框横向范围内、上下 20 米内；按距离从近到远分配，一个标题只给一块），没有标题再取块里房号的楼层位多数——个别房号换了楼层（楼层位对不上）不会让整层认错，只列为提示。没认出楼层的大块（≥ 50 条结构线）在报告里提示，零星的图例、大样不报。房号文字不在任何一层图框里的、楼层位与所在楼层不符的，列为提示。
4. **围合房间**：每层按 50 毫米一格画结构线，算每格到最近结构线的距离。离线不到 R 的格先当作封住（宽不到 2R 的门洞都封上了），从房号文字的中心点（按对齐方式与字宽估算；压在墙上时往外找 2 米内最近的空地）向外漫水，得到房间的「芯」：
   - 一块芯里有两个以上编码（门洞太宽、隔墙不在结构图层上）→ 「几个编码连成一片」；
   - 芯大于 400 ㎡、碰到图框边、或里面有「走道 / 走廊 / 过道 / 通道 / 大厅 / 大堂 / 门厅 / 电梯厅 / 前厅 / 休息厅 / 休息区 / 等候区」的文字 →「连到走廊或图外」；
   - 这两种在这块里把 R 依次加到 0.8、1.0 米重试；连到走廊的，加大 R 后走廊那边还得单独在（没有编码、仍连到走廊或图外），才算真的分开——走道比 2R 还窄、整个消失了，分不清房间到哪为止，按例外列出；
   - 所有的芯（房间与走廊等）同时往外长回最多 2R，长到结构线为止，门洞两边各分一半；沿格子边描外轮廓，按 60 毫米简化。面积按轮廓算（含门洞的一半，门的开启扇形算走道的，不扣柱子）。
5. **例外**：连到走廊或图外 / 几个编码连成一片 / 文字附近找不到空地 / 编码重复（同一个编码在两处），预览里逐条写处理办法（请设计方补墙线、改门洞、移文字）。启用后例外的编码在房态图上只显示位置点。
6. **底图**：每层一份 SVG，本地坐标 10 毫米一单位、原点在图框左上角、y 向下（直接当 SVG 坐标）；结构线按墙、门、窗、楼梯电梯分组，线宽不随缩放；保留不带编码的区域文字（走道、布草间……），编码由预览与房态图在轮廓那一层画。超过 1 MB 时容差与取整依次放大（120、240 毫米）再出，仍超过的提示。
7. **可重跑**：同样的图纸与参数得到同样的结果。同一份图纸（文件摘要）、同一版转换程序只转换一次，重传回到原来那一批（v0.7.19 起 PDF 还按上传时填的比例：改了比例重新转换）；新图纸转出新的一批，与在用的那一批比对。

## 4. 批次、预览与启用

| 项 | 做法 |
| --- | --- |
| 上传 | 「空间台账 → 底图」选 DWG 或 DXF（≤ 30 MB），可以写备注。图纸文件本身不保存，只记文件名、大小、摘要。同时只转换一份；转换在单独的进程里跑，限时 15 分钟，应用重启时没转完的记失败（重新上传即可） |
| 批次状态 | 转换中 → 待启用 / 转换失败；待启用 → 在用；在用 → 已换下（启用了别的一批）。只有一批在用；转换结果只追加，不能改、不能删 |
| 预览 | 楼层切换，底图 + 房间轮廓（点房间看编码、原文、面积），放大缩小；例外清单与处理办法；与空间台账比对；与在用的那一批比对；转换报告（图层清单与用途、提示、读图与转换用时、内存峰值） |
| 与空间台账比对 | 以台账为准，不按图纸改台账（D6）：图上有、台账没有（或已停用）；台账（图上这几层、在用）有、图上没有；编码相同、楼层不同；图上的原文与台账的「编码图原始标注」不同；对上的个数 |
| 与在用的那一批比对 | 房间增减；编码变更（新编码的轮廓盖住旧编码的文字，或两处文字相距不到 1.5 米）；同一个编码换了楼层；位置挪了 2 米以上。位置都换回图纸坐标再比（两批的图框可能不同） |
| 启用 | 店主、店总（与空间台账同一组权限）；确认框写明有几个例外；原来在用的换下。请求带上页面看到的在用批次，与服务端当时在用的对不上（超时后迟到的请求、另一个标签页、两人同时操作）就拒绝 `FLOORPLAN_STALE`，不会把后来启用的那批换下；这一批已经在用时再发一次不报错。结果不明时页面刷新后按最新状态再决定 |
| 给第三段 | `GET /api/floorplans/active`：在用那一批的楼层与房间（按编码对上台账的空间：`spaceId`、显示名）；`GET /api/floorplans/<批次>/floors/<楼层>/svg`：每层底图，在用的那批前台客房岗位也能看，其余只有后台能看；SVG 带 `Content-Security-Policy: default-src 'none'` |
| 导出 | `spaces.geojson`：每个编码一个要素，配上轮廓的是多边形、例外是文字所在的点；坐标是各层本地坐标（不是经纬度） |
| 自检 | `check` 加一项「底图批次与房间轮廓一致」：在用的批次有底图，房间的位置与轮廓都在图框内（比 v0.7.14 多一项） |
| 加锁 | 启用先取「底图」咨询锁（全部串行），再锁批次（id 升序）；上传靠唯一索引（同一份文件、同时只转换一份）兜底 |

## 5. 命令行

```bash
node dist/server/cli.js floorplan-convert <图纸.dwg|.dxf|.pdf> [--out 目录] [--scale 100]   # 不碰数据库：每层 SVG、spaces.geojson、report.json
node dist/server/cli.js floorplan-sample <文件.dxf|.pdf>                                  # 写出合成样例图纸（第一版；.pdf 写 PDF 版，1:100）
```

这两个命令不连数据库，不需要 `DATABASE_URL`。`floorplan-convert` 与后台走同一个转换进程，适合在测试服上量用时与内存、在本机核对图层归类（`report.json` 列出每个图层的用途与图元数，PDF 另有页数、换算比例与比例来源 `pdf`），或在不想写进系统时先看结果。PDF 会打出页数与换算用的比例（给了 `--scale` 按它换算，与图上写的不同时一并打出；没给按图上的比例文字）。PDF 样例的预期在 `src/server/demo/floorplan-expected.json` 的 `pdf`（与 DXF 第一版只差 W306，原因写在那里的说明里）。

## 6. 部署与授权

- 转换进程的入口打包成 `dist/server/floorplan-worker.js`，应用与命令行起子进程跑它（只带运行需要的环境变量，不带数据库地址）；开发与测试直接用 tsx 跑源码。
- 读编码图那样大的 DWG 时，服务器要有约 1.5 GB 空闲内存、持续半分钟左右；内存不够时转换失败、写明原因，不影响前台。门店 Mac mini 上 Docker Desktop 的内存上限（设置 → Resources）要在平时用量之外留出这 1.5 GB；`compose.yaml` 没有给应用容器设内存上限。
- `pdfjs-dist`（读 PDF）是 Apache-2.0，版本固定 6.4.299；它的可选依赖 `@napi-rs/canvas`（画图用，这里用不到，装不上也能读）在 `package.json` 的 overrides 里固定为 1.0.11。
- `@mlightcad/libredwg-web` 是 GPL-3.0：只在店主自己的服务器上的转换进程里运行，不对外分发软件，不涉及 GPL 的分发义务；版本在 `package.json` 里固定为 0.8.1，升级要重新用编码图实测。以后要对外分发系统，或开源库读不了新图纸，再按需求文档评估 ODA 商业授权。

## 7. 不在本段

- 房态图（按楼层渲染、颜色表示状态、点房间开房查房）与第一级实时位置：第三段，读 `/api/floorplans/active`。
- 对客导览（区域色块、中英双语、图标）与图纸入库治理的完整流程（来源、版本、日期登记，旧底图留档回溯，保存原图纸）：第四段，v0.7.19 做，见 `docs/FLOORPLAN_FINISH.md`。本段只留转换批次与差异报告。
- 品牌平面图 PDF 的文字抽取（对客名称）：品牌名已按 v0.7.14 进别名表、要现场核对后录入，不从 PDF 自动改别名（品牌图上没有编码、坐标系不同，v0.7.19 也不做）。验收标准里的「或 PDF」：转换程序能读矢量 PDF（命令行 `floorplan-convert`，见第 3、5 节），v0.7.19 起后台也收 PDF（上传时可填图纸比例，见 `docs/FLOORPLAN_FINISH.md` 第 3 节）。
- 例外房间的手工画轮廓：本段不做，按例外清单请设计方改图后重传；第三段房态图上例外的编码显示位置点。v0.7.19 加后台补画轮廓（按批次存）。
