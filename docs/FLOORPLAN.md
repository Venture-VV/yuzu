## 2. 这一段交付什么

1. **转换链路**：读 DWG（LibreDWG，固定版本）→ 图元（图层、类型、几何、文字，展开块参照）→ 按图层白名单过滤 → 按楼层切开 → 简化（合并路径、坐标取整、去掉过短的线段）→ 每层一份 SVG 底图。
2. **空间轮廓与配对**：每层的房间轮廓（闭合多段线，或由墙线围合出的面），房号文字点落进轮廓自动配对；输出 `spaces.geojson`（每个轮廓带配到的编码）。
3. **例外与差异报告**：文字没落进任何轮廓、一个轮廓里有两个编码、台账里有但图上没有、图上有但台账里没有、编码相同但楼层不同；与当前台账比对的「房间增减、编码变更」清单。人工只核对这些。
4. **入库**：转换结果（底图、轮廓、报告）作为一个「转换批次」存进系统，按楼层留历史，不覆盖旧的；店主或店总在后台看预览与报告后「启用」这一批，第三段房态图用启用的那一批。
5. **可重跑**：同一份 DWG、同一份白名单，重跑结果相同（按文件摘要识别）；换新版 DWG 重跑，30 分钟内出新底图与差异报告。

## 3. 待用编码图跑通后定稿的

- LibreDWG 的版本与部署方式：在应用镜像里固定版本编译，还是单独的转换镜像（后台上传 DWG 后由服务端调用）；
- 编码图里结构层、门、楼梯电梯、房号文字所在的图层名（白名单初值），xref 前缀怎么处理；
- 三层在同一张图里怎么分楼层（按图框范围或楼层标题，第一次人工框定、之后沿用）；
- 房间轮廓的来源：图里有没有成形的房间边界（闭合多段线、填充边界），还是要由墙线围合；
- 坐标单位与比例、底图体积（目标单层 ≤ 1 MB）与转换耗时。

## 4. 不在本段

- 房态图（按楼层渲染、颜色表示状态、点房间开房查房）与第一级实时位置：第三段。
- 对客导览（区域色块、中英双语、图标）与图纸入库治理的完整流程（来源、版本、日期登记，旧底图留档回溯）：第四段。本段只留转换批次与差异报告，第四段在此基础上做。
- 品牌平面图 PDF 的文字抽取（对客名称）：品牌名已按 v0.7.14 进别名表、要现场核对后录入，本段不从 PDF 自动改别名。
