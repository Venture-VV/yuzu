# v0.7.2 交接说明 · S5 餐饮第一步：出品档口、点单、厨房出品屏、估清

ROADMAP 第 10 节 S5 的第一步（G5 第一部分）。**餐饮功能默认关闭**：升级后不开启时，主导航没有「餐饮」，前台挂账、结账、交班、日结、对账包与升级前完全一样。开启后，点单就是给客人挂账（与前台挂账同一条路径 `postCharges`，同一套「结果待确认」），退菜就是作废明细（`voidLine`）——这些在前台挂账的资金路径上，按 T0 验收；出品单、估清只记出品状态与份数，不动钱。桌台与不洗浴客人的独立结账是第二步（要改结账模型）。

规则按洗浴中心、汤泉餐厅的常见做法先定默认、标「待确认」，见 `docs/PENDING_DECISIONS.md`「餐饮第一步」。版本号按店主 2026-10-30 的规则只加最后一位。

## 1. 范围

| 项 | 内容 |

## 2. 迁移与数据

- 迁移 `022_dining.sql`：新表 `kitchen_stations`（出品档口）、`dish_limits`（估清，每道菜一行：营业日、剩余份数 ≥ 0）、`kitchen_items`（出品单，每条餐饮明细一行，`bill_line_id` 唯一）；`service_items.station_id`。只加不改：已有项目没有档口，已有明细没有出品单。
- 出品单保护触发器 `yuzu_kitchen_item_guard()`：不能删除；明细、菜品、档口、份数、口味备注、下单人与时间不可改；状态只能前进一步或撤回一步，任何状态都可以因退菜改为已退（终态，之后不能再改）；催单次数只增不减。状态与各时间字段由 `kitchen_items_state_check` 约束保证一致。
- 新设置项 `dining_rules` 有代码默认值，迁移不写入。
- 挂账请求的明细多了可选的 `note`（口味备注）：不带时与升级前的请求完全相同（幂等摘要不变），升级前留下的「结果待确认」照常查回、重提。功能关闭或菜不进厨房时带备注拒绝（`DISH_NOTE_NOT_ALLOWED`）。
- 演示数据没有改（`src/server/seed*.ts` 归测试会话）：演示库里没有档口，菜都不进厨房。E2E 自建「E2E 热菜」「E2E 水吧」两个档口与「E2E 宫保鸡丁」「E2E 柠檬茶」两道菜，结束时关闭餐饮功能、取消估清。需要演示餐饮时测试会话可以补到演示数据里（建议另起固定预期）。前台、结账演示的固定预期只在自检项清单末尾加了 `kitchen_items`（因为自检多了一项）。
- 加锁顺序（AGENTS.md 已更新）：来访 → 账单 → 明细 →（技师队列 → 钟单 → 技师状态）→ 估清（按项目 id 升序）→ 出品单。厨房屏的开始做、出餐、上菜、撤回只锁出品单一行；设估清只锁估清一行；都不反向加锁。

## 4. 验收要点

| # | 操作 | 预期 |
| --- | --- | --- |
| D1 | 升级后不开启餐饮，照常接待、挂账、结账、反结账、交班、日结 | 与 v0.7.1 一致：挂账记在「门票与洗浴项目」、不进厨房；主导航没有「餐饮」，打开 `/dining` 提示没有开启；直接调点单接口拒绝（`DISH_NOT_KITCHEN`）、挂账带口味备注拒绝（`DISH_NOTE_NOT_ALLOWED`）；`check` 全 ✓（多一项「出品单与餐饮明细一致」） |
| D2 | 后台「餐饮」：店总建档口、把菜挂到档口；店总改餐饮规则；店主开启 | 店总能建档口与挂菜，改规则 403；档口重名拒绝（`STATION_NAME_TAKEN`）；需要技师的项目挂档口拒绝（`ITEM_NEEDS_TECHNICIAN`）；规则总表有「餐饮」一组；审计有记录；开启后主导航出现「餐饮」 |
| D3 | 点单：输入不在店的手牌；再输入在店客人的手牌，点两道菜（一道写「少辣」），下单 | 不在店的提示核对牌号；下单后账单「餐饮」分组多两条明细，显示「待做」与口味备注；厨房屏出现这两道菜，同一个出品单号（`CD` 开头）；点单页只能点进厨房的菜 |
| D4 | 点单时断网 / 超时（或拦截响应） | 进入「结果待确认」：查回、按原内容重新提交（同一编号只生效一次）、确认作废；同一编号改了口味备注重提按不同请求拒绝；顶部提醒「去处理」到前台也能处理 |
| D5 | 厨房屏：开始做 → 出餐 → 上菜；撤回；连点两下「撤回」 | 列随之移动；撤回只退一步，第二下提示状态刚变了（`DISH_CHANGED`）；下单超过 15 分钟没出餐标红；催单后标出次数；按档口筛选后刷新页面仍是同一档口 |
| D6 | 权限：后勤点单；客户经理打开厨房屏；在「岗位权限」去掉值班经理的「厨房出品屏」后让他开始做、出餐、上菜、撤回 | 后勤点单 403、能用厨房屏与估清；客户经理 403；值班经理只能上菜与撤回上菜（`KITCHEN_ONLY`），不能设估清 |
| D7 | 估清：某道菜限量 2 份，两台各点 1 份；再点 1 份；退掉 1 份；设估清；取消估清 | 剩余依次 1、0；超过剩余整笔拒绝（「今天只剩 N 份」/「已估清」），账单不变；退菜后加回；估清后点单页不能点；取消后不限量；两台同时点最后一份只有一台成功 |
| D8 | 退菜：点单页「退菜」（写原因）；前台作废另一道餐饮明细；超过自己作废时限或别人挂的明细 | 明细作废（留痕）、账单合计减少；厨房屏显示「已退」；估清加回；作废规则与前台一致（超时或别人挂的要店主） |
| D9 | 前台「加项目」点一道进厨房的菜；按纸质单补录一道菜 | 前台点的同样进厨房（没有口味备注）；补录的直接记为已上菜，不扣估清 |
| D10 | 有菜还没上时结账；结账后看厨房屏；反结账 | 结账核对列出没上的菜（只提醒，不拦）；结账后厨房屏这道菜标「客人已结账」；日结、交班、对账包金额与前台挂账同口径（餐饮明细计入「餐饮」部门）；反结账照常 |
| D11 | 数据库兜底（只在演示库）：直接改出品单的份数、把状态乱跳、删除出品单 | 都被触发器拒绝；`check` 全 ✓ |
| D12 | 5 种尺寸打开点单、厨房出品、估清、后台「餐饮」；开启技师与餐饮后看主导航 | 没有横向滚动；手机上点单的菜名单独一行；1280×720 下 13 个导航入口都在 |
