# v0.7.2 交接说明 · S5 餐饮：出品档口、点单、厨房出品屏、估清；桌台与不洗浴客人单独结账

ROADMAP 第 10 节 S5 的两步（G5），店主 2026-10-30 定并入同一个 PR，餐饮一次验完。

**餐饮功能默认关闭**。升级后不开启时：

- 主导航没有「餐饮」；
- 前台挂账、结账、交班、日结、对账包与升级前完全一样。

**第一步：点单、厨房出品屏、估清。**

- 点单就是给客人挂账，与前台挂账同一条路径（`postCharges`），同一套「结果待确认」；
- 退菜就是作废明细（`voidLine`）；
- 这两项在前台挂账的资金路径上，按 T0 验收；
- 出品单、估清只记出品状态与份数，不动钱。

**第二步：桌台与不洗浴客人单独结账。**

- 不洗浴的客人在桌台上开台、点单，用一张结账单结清（可以合并几桌）。
- 改了结账单的数据结构：结账账单可以没有来访与门票，改记开台与人数。
- 收款与手牌结账用同一套处理：服务端与页面上的收款部分都抽成了公共部分，手牌结账的行为不变。
- 桌台结账、反结账按**资金候选版本**验收。

另外修正了 v0.7.1 验收的 P2（只收扫码的单也能选退款钱箱，见 T15）。

规则按洗浴中心、汤泉餐厅的常见做法先定默认、标「待确认」，见 `docs/PENDING_DECISIONS.md`「餐饮第一步」「餐饮第二步」。版本号按店主 2026-10-30 的规则只加最后一位。

## 2. 迁移与数据

- 迁移 `022_dining.sql`：新表 `kitchen_stations`（出品档口）、`dish_limits`（估清，每道菜一行：营业日、剩余份数 ≥ 0）、`kitchen_items`（出品单，每条餐饮明细一行，`bill_line_id` 唯一）；`service_items.station_id`。只加不改：已有项目没有档口，已有明细没有出品单。
- 出品单保护触发器 `yuzu_kitchen_item_guard()`：不能删除；明细、菜品、档口、份数、口味备注、下单人与时间不可改；状态只能前进一步或撤回一步，任何状态都可以因退菜改为已退（终态，之后不能再改）；催单次数只增不减。状态与各时间字段由 `kitchen_items_state_check` 约束保证一致。
- 新设置项 `dining_rules` 有代码默认值，迁移不写入。
- 挂账请求的明细多了可选的 `note`（口味备注）：不带时与升级前的请求完全相同（幂等摘要不变），升级前留下的「结果待确认」照常查回、重提。功能关闭或菜不进厨房时带备注拒绝（`DISH_NOTE_NOT_ALLOWED`）。
- 演示数据没有改（`src/server/seed*.ts` 归测试会话）：演示库里没有档口，菜都不进厨房。E2E 自建「E2E 热菜」「E2E 水吧」两个档口与「E2E 宫保鸡丁」「E2E 柠檬茶」两道菜，结束时关闭餐饮功能、取消估清。需要演示餐饮时测试会话可以补到演示数据里（建议另起固定预期）。前台、结账演示的固定预期只在自检项清单末尾加了 `kitchen_items`（因为自检多了一项）。
- 加锁顺序（AGENTS.md 已更新）：来访 → 账单 → 明细 →（技师队列 → 钟单 → 技师状态）→ 估清（按项目 id 升序）→ 出品单。厨房屏的开始做、出餐、上菜、撤回只锁出品单一行；设估清只锁估清一行；都不反向加锁。
- **迁移 `023_dining_tables.sql`（第二步）**：
  - 新表：
    - `dining_tables`（桌台，不能删除）；
    - `table_sessions`（开台，一桌一张账单，`bills.kind = 'table'`）：部分唯一索引保证一张桌同时只有一个未结的开台；保护触发器规定不能删、开台信息不可改，结束后只有反结账的事务能改回未结；
    - `table_session_moves`（转台记录，只追加）。
  - `checkout_bills`：
    - `visit_id` 与门票四列改为可空，加 `table_session_id`、`guests`（默认 1）；
    - 约束 `checkout_bills_owner_check`：要么是来访账单（门票齐全、1 人），要么是桌台账单（门票为空）。
  - `kitchen_items`：`visit_id` 改为可空，加 `table_session_id`，约束恰好属于其中一个。
  - 幂等与作废登记：加 `table_open`、`table_post`、`table_checkout`。
  - **只加表、加列、放宽约束，不改已有数据**：已有的结账账单都是来访账单，人数按 1。
- 第二步的加锁顺序：班次（共享）→ 桌台（id 升序，开台、转台、反结账才锁）→ 开台（id 升序）→ 账单 → 明细 → 估清 → 出品单 → 会员。
- 演示数据仍没有改。E2E 另建四张桌台：`E2E-A1`、`E2E-A2`、`E2E-B1`、`E2E-B2`，区域「E2E 大厅」，排序 9000 以后。开始时会收掉上次中断留下的开台，结束时撤台并关闭餐饮功能。
