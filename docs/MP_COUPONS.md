# 小程序第二期 2c：线上领券（设计稿与实现；小程序线，2026-11-04）

店主 2026-11-04 定（MP22）：只领店主设为「小程序可领」的券模板；每个模板的领取限制是选项——**不限领 / 每人限领 N 张**，默认每人限领 1 张，上线后店主再配置；其余照券模板的规则。本稿写怎么领、记在哪、要主线加的发券入口、小程序线要做的、怎么测。这一步不动钱，按普通功能验收；和 2a 一样，对顾客开放要等 yuzu 正式切换（ROADMAP 第 3 节 M5）。

## 1. 顾客怎么用

1. 「我的」→「领券中心」（后台开着、有可领的券时才显示）：列出可领的券。每张写：
   - 名称、券的内容（模板的摘要，例如「代金券 ¥30.00 · 满 ¥50.00 可用」）、有效期；
   - 领取限制：「每人限领 1 张，已领 0 张」或「不限领」。
2. 点「领取」→ 门店系统发券到这位会员名下 →「领到了」，在「我的券」里能看到，到前台结账时照常用。
3. 领不了的写原因：已经领满、会员已冻结、这张券只给某几档的会员、券已经停领或过期。

## 2. 规则

| 项 | 做法 |
| --- | --- |
| 可领的券 | 后台「微信小程序 → 领券中心」：从启用的券模板里加，按列表的先后给顾客看。每个设领取限制：不限领，或每人限领 N 张（1–99，默认 1）。可以随时停领，已经领到的不受影响；最多放 30 张 |
| 券本身 | 走主线券模块发券（第 3 节）：有效期、门槛、范围、限定等级都照模板；一次领一张 |
| 限领按会员算 | 按会员数，不按微信：换绑一个微信也不能多领。合并掉的会员卡不能领 |
| 不限领 | 每点一次领一张，没有上限（网关照样限流：每个微信每分钟最多 20 次）。只给多领也不要紧的券用，后台在选项旁写明 |
| 并发与重提 | 每次点「领取」带操作编号：同一个编号重提返回同一张券；结果不确定时与绑定、建单一样请门店系统「确认作废」。同一位会员同时点两次：先锁会员一行再数已领，领取记录按（券模板、会员、第几张）唯一兜底，限领 N 张时第 N + 1 张领不出来 |
| 点了领取之后才换绑 | 领取带上领券中心列表里的绑定状态版本号（与充值建单一样）：之后解绑、换绑过的，门店系统拒绝（`BIND_STALE`），不会把券发给换绑以后的会员；顾客回到领券中心重新领 |
| 记录 | 小程序线自己的领取记录（只追加）：哪张券模板、哪位会员、哪个微信（绑定记录）、第几张、发券记录与券、时间。主线的发券记录种类是「小程序领取」，经办人是系统账号「小程序」 |
| 列表里不显示的 | 停领的；券模板停用、固定有效期已过的（谁都领不了）。档级不够、已经领满的照样列出、写原因 |

## 3. 要主线加的（按 MP8：小程序线写需求，由主线做）

1. **发券入口** `issueMpClaimCoupon(tx, { templateId, memberId, claimId, at })`：在小程序线自己的事务里调用，与领取记录一起提交：
   - 发券记录的种类加一类「小程序领取」（`mp_claim`，主线的迁移给 `coupon_issues` 的种类约束加上它）；经办人是系统账号「小程序」（2a 已有，`system.mp`）；去重键 `mp_claim:<claimId>`，同一个领取记录只发一次；
   - 模板停用、过期、这位会员的档不在模板的限定等级里：拒绝（抛 `AppError`，调用方的事务跟着回滚，顾客看到原因）；
   - 加锁照现有的发券：会员一行之后对模板加共享锁（调用方先锁好会员一行）；
   - 返回发出去的券（券码、有效期）。
2. **显示**：会员详情的券、发券记录里「小程序领取」照常显示。

## 4. 小程序线要做的

| 部分 | 内容 |
| --- | --- |
| 设置（不另建表） | 领券中心的设置放在 `settings` 的 `mp_coupon_rules`：开关、可领的券（券模板、`per_member` 每人限领 N 张或 `unlimited` 不限领、可领还是停领，按列表的先后显示）、版本号。与 2a 的线上充值设置一样用 `saveRuleSetting` 保存：带打开时的版本号，对不上拒绝；只核对这次新加的券模板是启用的 |
| 迁移 `048`（ROADMAP 第 7 节已登记） | 领取记录 `mp_coupon_claims`（只追加；（券模板、会员、第几张）唯一，操作编号唯一，发券记录与券各自唯一）；`mp_op_fences` 加一类 `mp_coupon`。只建自己的表，主线的 `049` 先跑后跑都行 |
| 门店系统（`src/server/modules/mp/coupon-center.ts`） | 领券中心的列表（这位会员已领几张、能不能领、为什么不能；能不能领用主线的只读判断 `mpClaimEligibility`）；领取：这个微信的咨询锁（`mp_coupon:<openid>`）→ 作废登记、同一个编号 → 这个微信绑定状态的共享锁（解绑拿排他的）→ 有效绑定 → 会员一行 → 数已领（连同合并进来的会员卡）→ 主线发券 `issueMpClaimCoupon`（拒绝时整个回滚）→ 写领取记录，同一个事务；确认作废（与领取取同一把咨询锁） |
| 接口 | 小程序端口 `GET /api/mp/coupon-center`、`POST /api/mp/coupon-claims`（新领 201、重提 200）、`POST /api/mp/coupon-claims/abandon`；员工端口 `GET /api/admin/mp/coupons`、`PUT /api/admin/mp/coupons/rules`（`mp.coupon`） |
| 网关 | `/v1/coupon-center`、`/v1/coupon-claims`、`/v1/coupon-claims/abandon` 带会话转发；领取与确认作废每个微信每分钟最多 20 次 |
| 后台「微信小程序 → 领券中心」 | 开关、加券、领取限制、停领、先后、拿掉（带版本号，结果待确认照其他开关）；每张一共领了多少、最近 7 天领了多少；最近 50 条领取记录。权限 `mp.coupon`（MP27：店主、店总） |
| 小程序 | 「我的 → 领券中心」（开着、有可领的券时才显示）：可领的券（券面与「我的券」一样）、领取、结果待确认；领到后可以直接去「我的券」 |
| 券面（「我的券」与领券中心共用，RQ-014） | 大字：代金券写金额、折扣券写几折、兑换券写「兑换」、买一赠一券（主线 8.0.4 的 `bogo`）写「买一赠一」（放不下一行的小一号）；下面是门店系统的一句话说明里其余的部分（「买 X 送 Y 1 份 · 最多抵 ¥Z」）。认不得的种类大字写「券」、说明整句照写。已发的买一赠一券的说明里「买的项目」由主线 #80（8.0.5）补上，补上之前写「指定项目」 |
| 测试 | `tests/mp-coupon-center.test.ts`：限领 N 张（同时点三次只出一张、第 N + 1 张拒绝）、不限领、同一个编号重提（同时重提也只发一张）、确认作废之后晚到的原请求不发券、换绑微信不能多领、合并进来的会员卡领过的也算、冻结与合并的会员、档级不够、模板停用、停领与关掉、只追加；`tests/gateway.test.ts` 转发与限流；`miniprogram/tests/coupon-center.test.ts` 列表的字与结果待确认 |

## 5. 前提与合并顺序

主线的发券入口（第 3 节）在主线 #51（v0.7.27，迁移 `049`）里，#51 先合并，2c 再合并（小程序线把 main 合进来、CI 全绿后交店主）。
主线的接口：`issueMpClaimCoupon(tx, deps, { templateId, memberId, claimId, at? })`，小程序线拿领取的操作编号当 `claimId`（去重键 `mp_claim:<编号>`）；只读判断 `mpClaimEligibility(db, deps, { templateId, memberId, at? })`。
