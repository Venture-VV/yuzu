# 小程序第二期 2c：线上领券（设计稿；小程序线，2026-11-04）

店主 2026-11-04 定（MP22）：只领店主设为「小程序可领」的券模板；每个模板的领取限制是选项——**不限领 / 每人限领 N 张**，默认每人限领 1 张，上线后店主再配置；其余照券模板的规则。本稿写怎么领、记在哪、要主线加的发券入口、小程序线要做的、怎么测。这一步不动钱，按普通功能验收；和 2a 一样，对顾客开放要等 yuzu 正式切换（ROADMAP 第 3 节 M5）。

## 1. 顾客怎么用

1. 「我的」→「领券中心」（后台开着、有可领的券时才显示）：列出可领的券。每张写：
   - 名称、券的内容（模板的摘要，例如「代金券 ¥30.00 · 满 ¥50.00 可用」）、有效期；
   - 领取限制：「每人限领 1 张，已领 0 张」或「不限领」。
2. 点「领取」→ 门店系统发券到这位会员名下 →「领到了」，在「我的券」里能看到，到前台结账时照常用。
3. 领不了的写原因：已经领满、会员已冻结、这张券只给某几档的会员、券已经停领或过期。

## 2. 规则

| 项 | 做法 |
| --- | --- |
| 可领的券 | 后台「微信小程序 → 领券中心」：从启用的券模板里勾选。每个设领取限制：不限领，或每人限领 N 张（1–99，默认 1）。可以随时停领，已经领到的不受影响 |
| 券本身 | 走主线券模块发券（第 3 节）：有效期、门槛、范围、限定等级都照模板；一次领一张 |
| 限领按会员算 | 按会员数，不按微信：换绑一个微信也不能多领。合并掉的会员卡不能领 |
| 不限领 | 每点一次领一张，没有上限（网关照样限流：每个微信每分钟最多 20 次）。只给多领也不要紧的券用，后台在选项旁写明 |
| 并发与重提 | 每次点「领取」带操作编号：同一个编号重提返回同一张券；结果不确定时与绑定、建单一样请门店系统「确认作废」。同一位会员同时点两次：领取记录按（这张可领的券、会员、第几张）唯一，限领 N 张时第 N + 1 张领不出来 |
| 记录 | 小程序线自己的领取记录（只追加）：哪张可领的券、哪位会员、哪个微信、第几张、发券记录、时间。主线的发券记录种类是「小程序领取」，经办人是系统账号「小程序」 |

## 3. 要主线加的（按 MP8：小程序线写需求，由主线做）

1. **发券入口** `issueMpClaimCoupon(tx, { templateId, memberId, claimId, at })`：在小程序线自己的事务里调用，与领取记录一起提交：
   - 发券记录的种类加一类「小程序领取」（`mp_claim`，主线的迁移给 `coupon_issues` 的种类约束加上它）；经办人是系统账号「小程序」（2a 已有，`system.mp`）；去重键 `mp_claim:<claimId>`，同一个领取记录只发一次；
   - 模板停用、过期、这位会员的档不在模板的限定等级里：拒绝（抛 `AppError`，调用方的事务跟着回滚，顾客看到原因）；
   - 加锁照现有的发券：会员一行之后对模板加共享锁（调用方先锁好会员一行）；
   - 返回发出去的券（券码、有效期）。
2. **显示**：会员详情的券、发券记录里「小程序领取」照常显示。

## 4. 小程序线要做的

| 部分 | 内容 |
| --- | --- |
| 迁移 `048`（待在 ROADMAP 第 7 节登记，与主线核对） | 可领的券 `mp_coupon_offers`（券模板、领取限制、N、开关、排序、版本号）；领取记录 `mp_coupon_claims`（只追加；按（可领的券、会员、第几张）唯一，操作编号唯一）；`mp_op_fences` 加一类 `mp_coupon` |
| 门店系统 | 可领的券（含这位会员已领几张、能不能领、为什么不能）、领取（这个微信的咨询锁 → 作废登记、同一个编号 → 会员一行 → 数已领 → 写领取记录 → 主线发券，同一个事务）、确认作废 |
| 网关 | `/v1/coupon-offers`、`/v1/coupon-claims`（含确认作废）带会话转发；限流 |
| 后台「微信小程序 → 领券中心」 | 勾选券模板、设领取限制、停领、排序（带版本号）；每张可领的券领了多少、最近的领取记录。权限照 MP27 |
| 小程序 | 「我的 → 领券中心」：可领的券、领取、结果待确认；领到后去「我的券」 |
| 测试 | 限领 N 张（并发两次只出一张、第 N + 1 张拒绝）、不限领、同一个编号重提、确认作废之后晚到的原请求不发券、模板停用或过期、限定等级不够、冻结与合并的会员、换绑微信不能多领 |
