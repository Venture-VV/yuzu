## 3. 验收要点

1. **采购途径**（`tests/erp-purchasing.test.ts` ①、`e2e/erp-purchasing.spec.ts` ①）：
   - 规则默认五个途径，可改名、可加，键重复拒绝；
   - 供应商的默认途径带进新建的采购单，选的就是这家的默认途径时说明选填；改选别的要写说明的途径（批发市场、网购平台、商超门店、其他）不写说明，页面提示、接口拒绝 `CHANNEL_NOTE_REQUIRED`；按次报销必须选途径；
   - 按次报销选途径，按采购单报销照采购单；采购单详情与列表、下单物料（页面与 Excel）、采购台账（逐笔与 CSV）、报销列表、详情与 CSV 都带途径。
2. **采购单一键转报销**（②）：
   - 现付供应商的采购单确认后出现在「费用报销」页的「待报销的现付采购单」；
   - 「转报销」打开的登记页各项都带好（没报销的行、金额、途径、经办人、部门、上次的用途与科目、最早没平的打款），核对后提交；
   - 提交后采购单详情的「报销」一栏看得到这张报销单，「待报销」里不再出现；同一行不能报两次。
3. **部门备用金台账**（③）：
   - 各部门的定额、在手、待补付、待确认的报销、本月支出、超期没平、建议补足（定额 − 在手）；
   - 台账选日期段：期初 + 每一笔 + 每笔之后的余额 = 期末；报销那一笔带明细与途径；待确认的报销列在下面、不算进余额；CSV 与页面一致；
   - 退回、补付、冲销后，期末余额 = 这个部门各笔打款的「未退回」之和（`check` 的 `petty_accounts`）；
   - 两人同时改同一个部门的设置，后保存的被拒；设了定额的部门打款后在手超过定额时有提示（不拦）。
4. **补货建议**（④）：
   - 建议量按规则算得出来：(结存 + 在途) 能用的天数少于提醒天数才建议，补到目标天数，按采购单位向上取整；没有用量的按低库存提醒数量；
   - 按供应商分组；没有供应商的组先选供应商才能生成；
   - 「生成采购单草稿」后打开草稿核对；回到补货建议，这些物料的建议量已扣掉草稿的数量（草稿算在途）。
5. **询价比价与定标**（⑤）：
   - 合计 ≥ ¥5,000 的采购单直接提交被拒 `QUOTES_REQUIRED`（可以存草稿）；补单、已确认后的改版、演示数据不拦；门槛设 0 不要求；
   - 询价单 → 两家报价 → 比价表（综合到价 = 货款 + 运费并排名、每行最低价标出、最近成交价与涨跌）→ 定标（理由必填）→ 转采购单草稿（按中标价、记下询价单）→ 提交过门槛；
   - 有效报价不到 2 家：采购不能定标，负责人标「单一来源」并写清原因（至少 4 个字）可以；
   - 转出的草稿改了供应商，过门槛时提交被拒；采购单撤回后可以撤销定标、撤销询价单；
   - 价格曲线带近 12 个月的成交价与报价（撤销的询价单不算）。
6. **自检**：`check` 全 ✓（含新增的 `petty_accounts`、`sourcing_links`）。
7. **升级**：在 v0.7.28（或 main 上最近的版本标签）建的库上升级到这个 SHA，`check` 全 ✓；旧采购单、旧报销单的途径显示「—」，照常可以提交、报销。

## 6. 已知问题（11-05 发现，v0.7.30 修）

- **询价门槛没接上需求单和补货建议**：
  - 从需求单下的采购单，合计到询价门槛（默认 ¥5,000）时，提交被拒 `QUOTES_REQUIRED`；
  - 去询价、定标后转出的采购单，不带需求单的关联，需求单一直显示「未下单」，到货后也不变；
  - 补货建议生成的草稿过了门槛也提交不了，只能手工再建询价单，原来的草稿还算在途。
- 计划的修法：需求单、补货建议可以一键发起询价（物料与数量带过去），定标转采购单时把需求单的关联一起带上。
- 修好之前：门店要用询价，先在「模块设置 → 采购规则」里把询价门槛设 0。验收时这一条按已知问题记，不用另报。
