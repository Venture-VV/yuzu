# 8.1.16 技师：钟房搜索与筛选、排位播报、技师管理

《浴族系统需求汇总》技师 1–3（`docs/YUZU_REQ_V8115.md` 第 3 节 E 块）。草稿在 8.1.15 里做，店主 2026-11-20 定随 8.1.16 发；迁移 `191_technician_admin.sql`，默认做法的编号 JS（第 10 节，都待店主确认）。

## 1. 做了什么

- **钟房搜索与筛选**（技师 1，第 2 节）：搜索框、状态 / 类型 / 项目三样叠加的筛选、按状态排。
- **排位播报**（技师 2，第 3 节）：派钟时自动叫一次号，钟房的轮钟排队、技师卡片上另有「叫号」（手动叫号）；排位播报条（8.2.0 起在单独的「技师 → 排位播报」页，`docs/YUZU_REQ_V820.md` 第 4 节）——音量、一键静音（静音时整条变红、写明「已静音」与没念的条数）、重播上一条、试音；几台终端同时开着钟房时，只有登记成「主播报终端」的那一台念，别的终端写明是哪一台在念、可以明确接管。
- **技师管理**（技师 3，第 4 节）：门店主导航「技师」组里的「技师管理」（`/technicians`），四个页签：
  - 技师名册：工号、名字与花名、类型、等级、可做项目、组别、入职时间、状态（今天的班、排休、休假也写着）；搜索同钟房；新建、编辑（与后台「技师 → 技师名册」共用一个对话框）；类型清单在这里改。
  - 技师组别：分组、组长（组员之一）；一位技师一个组。
  - 技师班次：班次（名字、起止时间，可以跨到第二天）、一周一屏的排班表（点格子排）、临时调班（改今天已经排了的、两人对调，要写原因），改动记录只追加。
  - 休假名册：申请（钟房的岗位替技师提）、批准 / 驳回、撤回（待审批的）、销假（已批准的）；批了的那几天自动不进排位。
- 与钟房实时联动：钟房每 10 秒取一次看板，技师管理每 20 秒、保存以后马上刷新钟房、后台名册与前台选技师；休假单批了含今天的，同一个事务里把这位技师今天的上牌状态改成休假。

## 2. 钟房的搜索与筛选

- 顶上一个搜索框——姓名、工号、花名，或姓名、花名的拼音首字母（打「zxm」找到「张小明」）；状态（原来就有）、技师类型、可做的项目三样筛选可以叠加，类型、项目各自可以多选；现在生效的条件列成一排，能一项项去掉，也能一键「清空」；排序「按排位」（默认，与轮钟队列一致）或「按状态」（空闲、上钟、已派待上、休息、休假、停牌、未上牌）。有条件或按状态排时下面列技师卡片，全去掉回到原来的钟房看板。条件只在这台终端的页面上，不存、不影响别人。
- 类型、项目两排平时收着（点「类型 / 项目」展开，选了的时候一直开着），不占看板的地方；状态的筛选带各状态的人数（在职的）。
- 搜索用的拼音首字母在 `@shared/pinyin-initials`（不带字库，用运行环境自带的拼音排序：Node 与各家浏览器都有）；筛选、排序是 `@shared/clockroom` 的 `filterBoardTechnicians`、`sortBoardTechnicians`，技师管理的名册搜索用同一个 `matchesTechnician`。

## 3. 排位播报

- **叫号记录**：派钟时在派钟的事务里自动记一条（念派钟之前的排位号），手动叫号另记一条（念这位技师手上那一张钟单的房间，待上钟的优先；没有钟单就只念排位；停牌、休假、没上牌的不能叫），都只追加。念的一句在记的时候就定好：「请 3 号排位，18 号 小雅，到 A201 观澜房」——有花名念花名，没有念名字；不在轮钟队列里的不念排位号；不知道房间的念「准备上钟」。交给朗读引擎时三位以上的数字一位一位念（房号「201」念「二零一」），页面上照原样显示。
- **只有主播报终端念**：哪个浏览器在念记在服务端（`technician_announcer`）；别的终端写明「××（谁 几点起）在念，本机不出声」，点「由本机接管播报」明确接管（记审计）；只有它自己能「不由本机播报」。那台终端开着钟房每半分钟报到一次，超过一分半钟没报到，别的终端上提示「可能关掉了」，不自动转移。
- **什么念、什么不念**：页面刚打开时已经有的叫号不补念；只念之后新来的、并且是一分半钟以内的（页面在后台停了一阵再回来，不把旧的都念一遍）；静音期间的不补念，只记条数。
- **这台终端的音量、静音**记在本机浏览器（不同步到别的终端）；浏览器要先点过一下页面才肯出声——点「由本机播报」「取消静音」「试音」都算，刷新以后没点过的，条上提示点一下。没有中文声音的设备也试着念（提示试音听一下）；连朗读接口都没有的写明换一台终端。
- 语音用浏览器自带的朗读（Web Speech API，`lib/speech.ts`），不连外部服务；浏览器用例把它换成记录调用的假实现（`e2e/technician-admin.spec.ts`），不真的出声。

## 4. 技师管理的规矩

- **名册**：新建、编辑走原来的名册接口（`/api/admin/technicians`，要「维护技师名册」），多了花名、类型、入职日期（不带的——后台原来的卡片——新建为空、修改不动）；类型要在清单里（清单里去掉了、这位原来就是这一类的照旧留着）；工号保存后不变；离职的停用、不删除。
- **类型清单**：至少留一个、不重复、每个最多 12 字、最多 20 个；去掉一个类型不影响已经设成它的技师。
- **组别**：组员整份保存——名单里的归到这个组（原来在别的组的挪过来；他原来是那个组的组长的，那个组没有组长了），不在名单里、原来在这个组的退出；组长算组员；停用的组不留组员与组长；只能选在职的技师。
- **班次与排班**：班次重名、起止相同的拒绝；排班整批提交、没变的跳过；过去的不能改；最远排到 92 天以后、一次最多看 31 天；今天已经排了的格子不能在「排班」里改，要走「临时调班」写原因；对调两个人这一天的班也要写原因；停用的技师、班次不能再排（已经排了的照旧显示）。页面上「按上一周排」只填这一周里还没排、不早于今天的格子。
- **休假**：开始日期不能早于今天、最远 92 天以后开始、一张最多 31 天；同一位技师日期重叠（待审批、已批准的）的拒绝；同一个操作编号重提返回第一次建的那一张；批准、驳回、销假要「维护技师名册」，驳回、销假要写原因；待审批的钟房的岗位就能撤回；已经休完的不能再批、不能再销。
- **权限**：看技师管理要「维护技师名册」或钟房（`technician.dispatch`）权限；只有钟房权限的只能看、能替技师申请与撤回休假（页面顶上写明）；改名册、组别、班次、排班与审批休假要「维护技师名册」。手动叫号、登记主播报终端要钟房权限。规则、提成、哪些项目需要技师仍在「后台 → 技师」。
- 技师功能没开时，技师管理与钟房一样写明「技师功能没有开启」。

## 5. 钟房：休假单、排班与排位

- **休假单在读的时候算**：钟房看板、排位、派钟、上牌都按「这个营业日在已批准的休假里」把人当成休假（`technician-day.ts` 的 `approvedLeavesOn`），不靠定时任务——休假从今天开始的，不用谁去点就已经是休假。
- 休假单里的技师：不进排位、不能派钟、不能叫号；钟房不能给他上牌，也不能在钟房「取消休假」，写明「到技师管理销假」；停牌、复牌照旧。
- 批准含今天的休假：这位技师在钟上、或有派了没上的钟的拒绝（`TECHNICIAN_BUSY`，先下钟或转钟）；当天记着在岗、休息的改成休假（算离店，实时位置跟着走）。销假含今天的：当天记着休假的回到未上牌，之后照常上牌。都记进钟房日志。
- 钟房自己点的当天「休假」（没有休假单）照旧：上牌即取消。
- 排班表上今天排休的，「全部上牌」跳过（要上可以单独点上牌）；排班不拦派钟、不自动上下牌。
- 看板上的技师多了组别、今天的班（或排休）、休假单；钟房的轮钟排队与技师卡片上写着。

## 7. 接口

| 接口                                                     | 权限                         | 说明                                                                                       |
| -------------------------------------------------------- | ---------------------------- | ------------------------------------------------------------------------------------------ |
| `GET /api/technician-admin`                              | 名册或钟房                   | 总览：名册（含组别、今天的班与休假）、组别、班次、类型清单、项目分类、待审批几张、能不能改 |
| `PUT /api/technician-admin/kinds`                        | 维护名册                     | 类型清单（规则锁）                                                                         |
| `POST /api/technician-admin/groups`、`PUT …/groups/:id`  | 维护名册                     | 新建、修改组别（名称、组长、组员、排序、备注、在用）                                       |
| `POST /api/technician-admin/shifts`、`PUT …/shifts/:id`  | 维护名册                     | 新建、修改班次                                                                             |
| `GET /api/technician-admin/schedule?from=&days=`         | 名册或钟房                   | 排班表：格子、这几天的休假、最近 50 条改动                                                 |
| `PUT /api/technician-admin/schedule?from=&days=`         | 维护名册                     | 排班（整批格子），返回那几天的排班表                                                       |
| `POST /api/technician-admin/schedule/adjust?from=&days=` | 维护名册                     | 临时调班（改一格，或与另一位对调），要原因                                                 |
| `GET /api/technician-admin/leaves?status=`               | 名册或钟房                   | 休假单（待审批的在前，最多 300 张）                                                        |
| `POST /api/technician-admin/leaves`                      | 名册或钟房                   | 申请，带 `clientKey`                                                                       |
| `POST /api/technician-admin/leaves/:id/decide`           | 维护名册                     | 批准 / 驳回（已经是这个结果的原样返回）                                                    |
| `POST /api/technician-admin/leaves/:id/cancel`           | 名册或钟房（销假要维护名册） | 撤回待审批的、销假已批准的（已经取消的原样返回）                                           |
| `POST /api/clockroom/calls`                              | 钟房                         | 手动叫号：`technicianId`、`sessionId`（可选）                                              |
| `POST /api/clockroom/announcer`                          | 钟房                         | 主播报终端：`claim`（由本机播报 / 接管）、`release`、`heartbeat`（报到）                   |

钟房看板 `GET /api/clockroom` 多了 `kinds`、`categories`、`calls`（最近 10 分钟、最多 30 条）、`announcer`，技师多了花名、类型、组别、今天的班与排休、休假单。名册接口 `POST / PUT /api/admin/technicians` 多收 `nickname`、`kind`、`hiredOn`。

审计动作：`technician_group`、`technician_shift`、`technician_schedule`、`technician_leave`（`detail.action`：申请、批准、驳回、撤回、销假）、`clock_announcer`（接管、放下）。

## 8. 加锁

写在 `docs/LOCKING.md` 第 1 节「技师管理与叫号（8.1.16）」：组别、班次、排班先取「技师管理」咨询锁；休假申请锁技师一行；休假的批准、驳回、撤回、销假与钟房的休假、停牌同一个顺序（技师队列 → 技师一行 → 休假单 → 技师状态）；叫号只插一行；主播报终端只锁登记表自己那一行。两组锁之间没有反过来的路径。

| JS11 | 排班管不管排位                       | 只管显示与「全部上牌」（今天排休的跳过）；不拦上牌、不拦派钟，不按班次自动上下牌                                                                                                                       |
| JS12 | 休假的申请与审批                     | 钟房的岗位替技师申请、能撤回待审批的；批准、驳回、销假要「维护技师名册」，驳回、销假写原因；一张最多 31 天，开始日期不早于今天、最远 92 天以后；日期重叠的不能再申请；没有半天、按小时的假，没有额度   |
| JS13 | 批了的休假怎么生效                   | 读看板时算（不靠定时任务）：那几天不进排位、不能派钟、不能叫号，钟房不能上牌、不能取消休假，先到技师管理销假；批准含今天的，这位在钟上或有派了没上的钟时不能批                                         |
| JS14 | 钟房当天点的「休假」                 | 照旧：只管当天、上牌即取消，与休假单无关                                                                                                                                                               |
| JS15 | 谁能进技师管理                       | 有「维护技师名册」或钟房权限的；只有钟房权限的只能看、能替技师申请与撤回休假；规则与提成仍在后台                                                                                                       |
| JS16 | 技师管理的保存要不要进「结果待确认」 | 不进：组别、班次、排班、类型清单是整份保存的管理动作（重名、没变化、状态由服务端核对），不带操作编号；休假申请带操作编号（重提返回同一张），批准、驳回、撤回、销假按休假单现在的状态核对、重提不重复记 |
| JS17 | 叫号记录                             | 只追加；看板带最近 10 分钟、最多 30 条；派钟、手动叫号都记经办人                                                                                                                                       |
| JS18 | 离职日期                             | 停用时记下（没记过的记当前营业日），重新启用清掉；入职日期选填                                                                                                                                         |

## 11. 没做的

- 叫号的音色、语速不能选（语速固定，声音按浏览器里的中文声音挑）；不接外部的语音服务、不接门店广播。
- 休假没有半天、按小时，没有年假额度与扣减；排班不管派钟，不按班次自动上下牌；组别不参与轮钟。
- 主播报终端离线不自动转给别的终端（只提示）。
- 技师管理的保存不进门店的「结果待确认」（JS16）。
