## v8.0.22 · 多门店、多店多仓与调拨、多公司主体、价目按店、AI 辅助（这一批的收尾版）

排期 `docs/SCHEDULE_V8020.md` 第 4 节，设计 `docs/MULTISTORE_V8022.md`、`docs/AI_V8022.md`，交接 `docs/HANDOFF_V8022.md`；迁移 `153`–`158`。**只有一家店、没配模型服务时与 8.0.21 一样。**

- **多门店**（MD-A，迁移 `153`、`154`）：后台「人员与行政 → 门店与主体」建门店与公司主体，员工档案挂门店（可以多家）；能进几家店的人左侧导航换店（只能换到自己挂着的、启用的门店）。手牌、接待、账单、结账、退款、补录、班次、日结、设备与打印、客房、预约、技师与钟房、桌台与出品、电子菜单点单、空间与底图、实时位置、导览、审计都按店分（同号同名各店一份）；营业日切换、钱箱、打印、前台 / 餐饮 / 客房 / 预约 / 技师规则可以按店单独设。会员、储值、券全公司通用，流水记发生门店；门店之间的储值结算表（开卡店按第一笔充值，MD19）。看板与报表默认看当前门店，店主与挂着几家店的人可以「合并看」；每日对账包 `daily-recon --store <代码>`。
- **多店多仓与调拨**（MD-B，迁移 `155`）：新门店自动有主仓；部门小仓按「部门 + 门店」；扣料默认从这家店的主仓扣。ERP「库存 → 调拨」：调出马上扣、在途，调入按实收（短少、损坏写原因），在途的可以撤回；走全店的操作编号与「确认作废」。采购收货照旧进总仓、再调拨到各店（MD20）。
- **多公司主体**（MD-C，迁移 `156`）：合同、进项发票、付款申请与付款、合同付款、开票申请、银行账户、批量付款记公司主体（默认当前门店的主体，现有的都是本公司）；合同台账按主体筛，有几个主体时合同的「我方」用主体名称；批量付款一批只付一个主体的款。
- **价目按店**（迁移 `157`）：价目表全公司一套，第二家店可以对某个项目的某一档单独定价（「价目与套餐 → 本店价」），挂账、点单按本店价。
- **AI 辅助**（MD-D，迁移 `158`）：只读、只出文字，发出去的只有汇总数与打码后的文字（会员姓名只留姓、手机号只留前三后四、证件号去掉）。
  - 每天的经营小结：每家店营业日切换以后自动生成前一天的一份（几家店时另有全公司的），在数据看板「经营总览」顶上、ERP 首页一行；开着推送、配了群机器人时推企业微信；失败的隔 5 分钟再试、最多 3 次，也可以「重新生成」。没配模型服务时只记当天的数字。
  - 问数：数据看板「问数」页签，用一句话问经营数据；模型只能挑服务端的只读报表（按问的人的权限、能进的门店，日期最多 92 天），答案注明用了哪张报表、哪个日期范围；没收到结果原样再发不会多问一次；每人每天最多 50 次（MD10）。
  - 合同条款提示：合同表单上「AI 看一下条款」，按条列出缺了的条款、与正文对不上的地方、要留意的风险，可以逐条「知道了」。
  - 员工写的自由文字里的会员身份按会员档案认（姓名 1–32 字、会员号、手机号，空格与符号的变形也认；测试会话在 `80284a9`、`e25d122` 报的 P1）：问数的问题里有的直接拦下、什么都不发（问数本来就查不了某一位会员）；合同正文与备注里的打码以后再发；取不出档案就不发。
  - 后台「对外接口」多一行 AI 辅助与开关（默认开）；模型服务用 Claude（官方 SDK），密钥只认 `YUZU_AI_API_KEY`（`YUZU_AI_BASE_URL`、`YUZU_AI_MODEL` 选填）；`INTEGRATIONS_MOCK=true` 的开发、测试实例按数字套固定模板，不出网。正式服在大陆怎么连等店主定（MD8）。
- **收尾**：`docs/ROADMAP.md` 第 12 节逐条核对——店主 11-14 排的这一批（8.0.20–8.0.22）全部做完，剩下的都是要外部账号、真机或店主定的；排期、评测说明、交接写到做完的状态。新的待确认：MD19（结算表的开卡店）、MD20（采购收货进总仓再调拨）、MD21（出品档口全公司一套）。
- **用例**：新加 `stores-frontdesk`、`stores-modules`、`stores-transfers`、`stores-entities`、`ai`，浏览器 `e2e/v8022.spec.ts`；升级用例的旧结构补了门店列（154 起收款按门店找班次）。

## v8.0.21 · 财务与合同做深（数据字典、发票识别与开票、网银流水与批量付款、合同模板、供应商门户）· 对外接口（扫码收款、平台验券、OTA 渠道订单，模拟实现）

排期 `docs/SCHEDULE_V8020.md` 第 3 节，迁移 `141`–`152`。先收 8.0.20 留下来的：

- **进厨房的买一赠一**：出品时扣料开关关着（或那时还没设用料）、结账前才打开 / 设上的，原来结账时按「现在有用料」不记赠品出库、出品时又没记扣料，赠的那一件一次都没扣——改成进厨房、已出品的看出品时记没记过扣料（合并前 Codex 审查 `7dbc313`）。
- **数据字典与字段**（CW-J，迁移 `141`，`docs/FINANCE_V8021.md` 第 1 节）：后台「规则中心 → 数据字典与字段」。
  - 快捷原因：作废明细、撤销接待、换手牌、锁牌、撤销消费、转单原来写死的那一排原因可以改了；退款、报损、取消预约、资产报废原来只能手填，现在也有一排快捷原因。原因照旧存文字、照样可以手填；删掉、改名只影响以后的快捷选项。
  - 自定义字段：会员、供应商、物料、合同各自最多 10 个启用的字段（文字、数字、日期、选项），在详情的「其他信息」里填、单独保存，不动业务单据本身；勾了「列表里显示」的在列表那一行下面显示；「按字段查」可以查、可以导出。只是记录，不参与任何计算。
- **发票识别**（CW-A，迁移 `142`，`docs/FINANCE_V8021.md` 第 2 节）：发票台账、三单、报销登记发票时可以「拍照 / 选文件识别」——PDF 直接读文字，图片先找二维码，读不到再用本机文字识别；带出号码、开票日、类型、金额，标「识别」，要勾「已核对」才能保存。全在这台设备上识别，不传给别人。台账记下每张是手填还是识别的，页面上数得出来。
- **开票申请**（CW-B，迁移 `143`，`docs/FINANCE_V8021.md` 第 3 节）：前台在结账记录、会员充值记录上，财务在协议单位回款上点「开票」；可开金额只算实收（储值在充值时开、挂账按回款开，退款要减掉）。ERP 多一个「财务 → 开票」（新权限「开票」，默认店主与对账付款）：登记已开（填号码、传 PDF）、交给开票服务商开（适配器，先只有模拟的）、驳回、作废红冲；同一笔只能开一次，来源反结账了的标「要红冲」。
- **银行流水**（CW-C，迁移 `144`，`docs/FINANCE_V8021.md` 第 4 节）：ERP「财务 → 银行流水」。本公司的账户只记后四位；导入网银导出的对账单（CSV / Excel，自动认列、认不准的在预览里改，同一份文件只导一次、流水不重复记）；导入时自动对上金额、日期、户名都对得上且只有一个候选的付款或回款，其余在抽屉里挑；利息、手续费标「不用对」。超过 7 天没对上的进待办。
- **批量付款**（CW-D，迁移 `145`，`docs/FINANCE_V8021.md` 第 5 节）：供应商档案加收款户名、开户行、账号（页面上只看得到后四位）。「付款 → 批量付款」勾选批了待付的申请生成一批，导出网银模板（工商、建设、招商、通用 CSV），网银付完回来导入对账单，金额与户名对上的自动照「按申请登记付款」记账；对不上的手工标已付或失败。导出以后不能改，只能作废重开（要确认没在网银里付）。
- **合同模板与导出**（CW-E，迁移 `146`，`docs/FINANCE_V8021.md` 第 6 节）：ERP「合同 → 合同模板」维护合同正文模板（`{{字段}}` 占位、可填字段、可选条款；改模板存成新的一版，已经起草的合同记着用的那一版）。起草合同时选模板、填字段、勾条款，必填字段没填不能提交审查；合同详情可以「导出 Word」（.docx）或「打印 / PDF」，正文按模板排好，付款节点与单价表自动带进去，页眉写合同编号与版本。
- **供应商门户**（CW-F，迁移 `147`，`docs/FINANCE_V8021.md` 第 7 节）：不开账号、凭链接（默认 14 天有效，可作废、重发）。询价单上「请供应商在线报价」生成报价链接，供应商在手机上按行填单价、付款条件，报价直接进比价（标「供应商链接」，再报一次替换上一次的）；已确认的采购单发「订单确认」链接，供应商写承诺到货日，采购单与流程图按承诺日；之后发「发货预告」链接，供应商分批报发了什么、物流单号，采购单上列出、按单收货时提示。正式服对公网开放前只能在内网 / Tailscale 里打开。
- **用例**：补货方式的浏览器用例连建三样物料时尾号不再取随机两位（撞号 `CODE_EXISTS` 红过一次 CI）。
- **扫码收款**（CW-G，迁移 `148`，`docs/INTEGRATIONS_V8021.md` 第 2 节；8.0.21 只有模拟实现，正式的等商户号联调）：结账、充值的「微信 / 支付宝」旁边多一个「扫码收款」——扫客人的付款码，到账以后这一笔自动填好、锁定（参考号是支付方单号），照常结账、充值；要输密码的每 3 秒查一次，超过 5 分钟没结果的自动撤单；结果不确定的按编号查回或确认作废。收了钱没入账的（结账被拒、关了页面）前台顶上提示，可以挂到下一次结账、充值，或原路退回；交班前要处理完。反结账解开用过的那一笔（不自动退钱）；退款单上扫码收的那部分默认「原路退回」。手选微信 / 支付宝、手输金额的做法照旧。
- **平台验券**（CW-H，迁移 `149`，`docs/INTEGRATIONS_V8021.md` 第 3 节；8.0.21 只有模拟实现，正式的等平台应用联调）：结账的团购券那一行选美团、抖音，填（或扫）券码后点「验券」——先看平台说的项目、面值，确认后在平台核销，这一行自动填好、锁定。验过没结账的前台顶上提示，可以挂到下一次结账，或撤销核销（平台不让撤的转成一条平台核销补录）；反结账以后验过的券回到「没用」。每天 06:10（后台可改）自动按平台对前一天的核销明细，「平台核销补录 → 验券对账」看差异、标已处理。平台不通时照旧手输。
- **OTA 渠道订单**（CW-I，迁移 `150`，`docs/INTEGRATIONS_V8021.md` 第 4 节）：后台「客房 → 渠道」加渠道（携程、美团酒店、飞猪……）、佣金比例、渠道房型对照本店房型；前台「预约 → 渠道订单」导入渠道后台导出的订单表（CSV / Excel），新订单建客房预约（来源「渠道」，几间几张，房量不够照样建、标超订），对照不上的补了对照重试；再导一次：渠道取消的取消预约、改了日期的改时间、间数变了多退少补，已经到店的只提醒。预付的订单结账时收款区默认带一行团购券（券码 = 订单号）。渠道对账按入住月份算订单数、间夜、金额、佣金、净额，可导出。房量房价不推给渠道。
