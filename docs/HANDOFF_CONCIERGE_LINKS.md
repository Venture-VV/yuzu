# 管家服务同源联动交接（PR #99）

## 范围与边界

店主2026-11-13确认，前台办理会员，管家面向服务；现行身份资料、档阶、本金与可用赠金统一从原生会员系统读取。管家编号000001起只标识服务档案，历史人工核对、消费凭证和服务记录保留。需求与授权见 CONCIERGE_LINKS.md、PENDING_DECISIONS.md GJ12–GJ18、ROADMAP 的迁移136预留。

- 新服务档案必须选择系统会员；不批量复制全店会员，也不建立第二套会员身份。旧未关联档案兼容，明确待关联。
- 自动同步使用现有3秒版本轮询；查找列表5秒更新及focus/online唤醒。业务资料不从管家反写。无网络时不能提供新的实时数据。
- 管家职责可读有限系统会员摘要及余额，无原生钱包写权限、原生全档案权限或员工管理权限；经理纠错关联要原因、版本号，已有正式单据引用仍受保护。
- 档阶用原生projectedGrade和规则名称只读推算；可用赠金扣除到期批次，不在管家读请求里执行赠金清算或改档。
- 合并链按最终会员显示，保留原native_member_id和历史服务编码；金额、人数去重，不自动搬移或合并历史服务档案。
- 历史小票搜索同时匹配现行主会员资料及原快照/接待称呼。导出明确分开当前系统余额和人工核对依据。
- 资源沿用spaces/floors/zones、dining_tables、rooms/room_types。分类→区域/规格→具体资源，区域请求可先保存，不独占整个规格组。稳定资源ID识别改名及room/space挂接后的协调冲突。
- 这是管家协调安排；不会代替原生预约、开台、开房、派钟的真实占用流程。已有前台预约与结账关联继续复用原流程权限及单据核验。
