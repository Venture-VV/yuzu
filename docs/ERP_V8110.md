# 8.1.10 ERP 采购：核库转领用、急采后补合同

> 发版时是 **8.1.13**：同一天工程治理一期（PR #128）、二期（PR #129）、三期（PR #130）先后合进 `main`，用了 8.1.10、8.1.11、8.1.12，版本号按合并先后取下一个。文件名照旧。

来源：店主 2026-11-18 转来的会议需求表（四条 P0，原文见 `docs/PENDING_DECISIONS.md`「8.1.10：ERP 采购四条」），以及同一天对开发会话十二个问题的答复（CK1–CK12）。

这一版做两块：

- 核库转领用：C2，对应 CK8–CK10。
- 急采后补合同：C4 的后半段，对应 CK5、CK6。

两块新加的线都做成「采购规则」里能改的设置（CK12）。

不做：

- 2 万合同线、数量线、防拆单（CK3、CK4）；
- 合伙人特批与超限预警（CK7）；
- 现有的金额线与审批规则都不动（CK2、CK11）。

细项的默认做法是 CK13–CK25，店主 2026-11-19 答复「CK13到CK25都按默认就行」，都按默认定了。

## 1. 急采后补合同

### 1.1 哪些急采要补合同

- 急采收货单（`inv_docs.urgent`）在仓库确认生效时，合计达到「急采补合同金额」就记下要补合同（`inv_docs.needs_contract`，迁移 `186`）。
  - 这个金额是采购规则的新项，默认 ¥20,000，即会上暂定的 2 万；设 0 表示不要求。
  - 要不要补在生效那一刻定下，以后改金额线不影响已经生效的单子（CK18）。
- 期限从急采生效那天算，「补合同期限」天以内（采购规则新项，默认 15 天）。期限按现在的设置算：改了天数，还没补的单子跟着变。超期的标红，照样能补；补上之前不能付款（CK19）。

### 1.2 怎么补

- 先补采购单，用原来的「补采购单」。补出来的采购单原来什么都不能改；8.1.10 起多一个「补合同」，只改挂的合同，别的照旧不能改。
- 由采购（「采购单 · 新建与修改」权限）在补单采购单上点「补合同」，选这家供应商的采购合同：
  - 已签署或已归档；
  - 到期日不早于下单日，开始日可以晚于下单日（补签的合同）；
  - 年度框架合同同样能挂（CK5）；
  - 这些条件见 CK21。
- 单价、数量与新建采购单挂合同时一样核对：超出合同价或合同剩余量的，要写说明，至少 2 个字。
- 挂上以后不能换、不能取消，免得绕开合同付款（CK20）。
- 已经付过款、在付款申请里或报销过的补单采购单不能再补合同，免得合同的付款计划漏算已经付的钱（CK20）。
- 挂上以后，这张采购单的货款照合同走：从合同的付款计划里按付款节点申请。这与平时挂合同的采购单一样，代码不另改。
- 加锁顺序：
  1. 供应商一行（`FOR NO KEY UPDATE`，与付款登记、付款申请同一把）；
  2. 采购单一行（`FOR UPDATE`）；
  3. 合同、付款与报销记录只读，不加锁。
- 幂等：用同一份合同重提，照原样返回；采购单已经挂了别的合同的，拒绝（`PO_CONTRACT_SET`）。

### 1.3 合同没补上不能付款

要补合同的急采收货单，在补单采购单挂上合同之前（还没补采购单的也算），下面几处都拦（`CONTRACT_REQUIRED`）：

- 付款申请（应付货款来源）不能选它；
- 直接登记付款、预付款核销不能核销到它；
- 现付供应商按采购单报销时，不能报它的补单采购单（CK22）。

### 1.4 待补合同清单

- 「采购 → 急采」页加筛选「待补合同」：列出要补合同、还没补上的急采，写着还剩几天或超期几天，超期的标红。
- 急采收货单详情里写「要补合同 · 还剩 N 天」，补单采购单详情里有「补合同」按钮。
- ERP 导航「采购」上的待办数加上待补合同的张数，采购负责追。

## 2. 核库转领用

### 2.1 什么时候核库（CK13）

- 需求单提交时（要部门主管确认的，在主管确认以后）系统看每一行：选了物料、总仓现在有结存的行要核库。
  - 只要有一行要核库，这张需求单就进「待核库」。
  - 一行都没有的（全是手填的新品，或总仓都没有）直接进采购审核，CK8 说的「手填的新品不核库」就是这一条。
- 下面三种不核库，直接进采购审核：
  - 标了「急」的需求单（CK10）；
  - 集采导入的需求单（导入即通过）；
  - 「提需核库」开关关着时。
- 退回修改后重新提交的，照上面重新看一遍。已经领用的行不能再改，由数据库守卫兜底。

### 2.2 库管核库（CK14）

- 新权限「核库」（`request.stock`），默认给店主与「物资经办」（库管）。库管因此能进「采购 → 需求单」，多一个页签「待核库」；全部需求单都看得到、只读（CK25）。
- ERP 导航「需求单」上的待办数给库管算待核库的张数。
- 每一行显示申请数量和总仓结存，结存换算到需求单这一行的单位。库管逐行选：
  - **领用**：从总仓领 N，N 不超过申请数量，也不超过结存。可以只领一部分，剩下的转采购。
    - 需求单这一行的单位是物料的库存单位或采购单位时，按这个单位填，系统换算。
    - 是别的单位时只能整行领用，库管按库存单位填实际领的数量。
  - **替代**：提议换一种总仓有结存的物料，按它的库存单位写数量，等部门确认（2.3）。
  - **转采购**：这一行全部转采购。
- 点「核库完成」时，领用的行一起开一张部门领料单：
  - 从总仓出到申请部门的小仓，领料人写申请人，备注写需求单号；
  - 马上生效，与库管平时登记领料一样；部门之后签收。
- 没有替代的，这张需求单核库完成：
  - 全部领用了的，状态变成「已转领用」（CK16），不再进采购；
  - 还有要买的，进采购审核。
- 加锁顺序：
  1. 操作编号的咨询锁（与「确认作废」串行，业务类型 `request_stock`）；
  2. 需求单一行（`FOR UPDATE`）；
  3. 领料单照库存单据原来的锁：物料按 id 升序，再锁部门小仓。
- 没有反过来先锁物料、再锁需求单的路径。
- 核库完成与答复替代都带操作编号（业务类型 `request_stock`）：原样重提照旧返回，内容不同拒绝；没收到结果的走「结果待确认」，查回或确认作废。两个人同时核同一张，只有一个成，另一个是 `STOCK_CHECK_CLOSED`。

### 2.3 部门确认替代（CK15）

- 申请人、这个部门的主管或店主在需求单上看到「库管提议用 B 替代 A × N」，选「同意」或「不用，照原来买」。
- 同意：按库管提议开领料单，经办人记提议的库管，马上生效。总仓不够了（或替代品停用了），这一行改成转采购，答复照样记下，页面上写明原因。
- 不同意：这一行转采购。
- 每一行都答完，需求单核库完成，后面同 2.2。
- 加锁顺序与 2.2 相同，业务类型 `request_stock`。

### 2.4 超时（CK10）

- 进「待核库」超过「核库时限」（默认 24 小时）还没核完的，每分钟的任务记成「超时转采购」：没核的行都转采购，进采购审核。
- 替代提议发出后超过核库时限部门还没回的，记成「没回，照原来买」，这一行转采购。
- 任务一张需求单一个事务，只锁那张需求单一行，锁住以后再核对一次。审批记录里这一笔记在系统账号名下。

### 2.5 部门看得到的库存（CK9、CK17）

- 不放开总仓。需求单详情里，选了物料的行显示总仓现在的结存，只限这几样，换算到这一行的单位。
- 部门别的人照旧看不到总仓的列表。

### 2.6 采购那边

- 「待核库」「待部门确认替代」的需求单不能审核通过、不能退回（`STOCK_CHECK_PENDING`），可以定为不采购；也不出现在「待审核」里，状态筛选多一项「待核库」。
- 已经有行领用的需求单不能改、不能退回修改（`STOCK_ISSUED_LOCKED`），剩下的通过或定为不采购（CK23）。
- 待核库时撤回、定为不采购的，核库收掉：待核库的记成不用核，没答复的替代记成没回。
- 全部领用的行不出现在「待转采购」里，也不能转采购单、发起询价（`REQUEST_LINE_ISSUED`）。部分领用的行转采购单、询价单时，数量默认剩下的。
- 核库开的领料单冲销了的，这一行不再算领用，照原来的数量买（CK24）。
- 需求单进度：整行领用的标「已领用」，部分领用的写「已领 N，剩下的转采购」。导出多一列「已领用数量」。
- 采购流程图不另加环节：核库没完时「需求审核」写「待核库」或「待部门确认替代品」，全部领用的流程结束（「需求从库存领用，不再采购」）。

## 3. 设置（CK12）

「ERP 设置 → 采购规则」里新加四项，都能改，先试行一个月：

| 设置 | 默认 | 范围 |
| --- | --- | --- |
| 提需核库 | 开 | 开 / 关 |
| 核库时限 | 24 小时 | 1–168 小时 |
| 急采补合同金额 | ¥20,000 | 0（不要求）– ¥1,000,000 |
| 补合同期限 | 15 天 | 1–90 天 |

## 4. 迁移

- `185`（核库）：
  - `purchase_requests` 加核库状态、进入待核库的时刻、核库人与时刻；
  - 状态加 `issued`（已转领用），需求单守卫把它当作结束状态；
  - 新表 `request_line_stock`，记每一行的核库结果：领用、替代、转采购，领料单，替代的答复；
  - 已经领用的行不能再改或删除（守卫）；
  - 操作编号与「确认作废」在当时的约束上追加 `request_stock`。
- `186`（急采补合同）：
  - `inv_docs` 加 `needs_contract`；
  - `purchase_orders` 加补合同的人与时刻。
