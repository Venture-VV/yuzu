# v8.0.21 交接说明 · 财务与合同做深 · 对外接口（模拟实现）

店主 2026-11-14 排期的三版里的第二版（`docs/SCHEDULE_V8020.md` 第 3 节）。设计 `docs/FINANCE_V8021.md`（财务与合同）、`docs/INTEGRATIONS_V8021.md`（对外接口）；默认做法 CW1–CW27 在 `docs/PENDING_DECISIONS.md`「8.0.20–8.0.22」，店主同日「都按默认」确认。迁移 `141`–`152`。

## 0. 升级后马上会看到的变化（请先读）

- **对外接口这一版只有接口与模拟实现**（CW22）：扫码收款、平台验券、开票服务商在正式服、测试服上是「没配置」，页面上不出现「扫码收款」「验券」按钮，照旧手选微信 / 支付宝、手输团购券码——**和升级前一样**。模拟只许在开发、测试实例里打开（`INTEGRATIONS_MOCK=true`，实例不是 prod / shadow / test，和任何正式密钥同时配置时拒绝启动）。正式实现等店主拿到商户号、平台应用、服务商账号联调时做。
- 后台「场地、设备与线上」多一个分区「对外接口」，「营业项目 → 客房」多一个页签「渠道」，前台「预约」页右上多一个「预约 | 渠道订单」切换，「平台核销补录」多一个页签「验券对账」，ERP「财务」多「开票」「银行流水」，「付款」多「批量付款」页签，「合同」页多「合同模板」按钮。
- 交班多一道核对：这个班次有扫码收了钱没入账、还在支付中的不能交（只有开了扫码收款才可能有）。
- 新权限「开票」（`invoice.issue`，默认店主与有「应付」职责的）。

## 2. 迁移、演示数据与固定预期

- 迁移 `141`–`150` 都是加表、加列、放宽约束，不改已有数据。给「确认作废」加的业务类型（`invoice_request`、`bank_import`、`payment_batch`、`pay_terminal`、`platform_verify`、`ota_import`）与预约来源加的 `ota` 都是在当时的约束上追加（不照名单重建），与客户部的 `162` 等别的分支谁先跑都成立。
- **演示数据没有预置这一版的东西**：对外接口都是模拟的、财务的几样要现造单据才有意义，固定预期与 8.0.20 一样；浏览器用例都自己造数据（可重复执行）。
- 迁移 `151`（Codex 安全审查 `354e34c` 后补）：供应商收款账户的改动人、复核人与时刻，触发器在账户三项变了时清空复核。

- 主线下一个迁移号从 `153` 起（8.0.22，到 `160`）。

## 4. 验收要点

1. **数据字典**：后台加一条锁牌原因 → 前台锁牌弹窗里有；建一个会员字段 → 详情填、列表看、按字段查。
2. **发票识别**：合成一张带二维码的发票图，识别带出号码、金额，核对后登记，台账标「二维码识别」。
3. **开票**：结账记录里申请 → ERP「开票」登记已开 → 前台看得到号码；反结账以后台账标红。
4. **银行流水**：新增账户、导入一份工商格式的 CSV（自动认列）、结息标「不用对」、同一份文件再导被拦；付款、回款按金额与户名自动对上。
5. **批量付款**：供应商的「收款账户」由对账付款（qianfen）填 →「待复核」、本人复核不了、采购改档案改不了它 → 店主复核（再打开只看到后四位）→ 勾选付款申请生成批次 → 导出 → 导入含这几笔的流水 → 批次自动记已付、付款申请付清。
6. **合同模板**：建模板（必填字段、可选条款）→ 起草选它 → 不填必填字段提交审查被拦 → 打印页按模板排版、导出 Word 打得开。
7. **供应商门户**：询价单发报价链接 → 用没登录的浏览器打开、报价 → 比价里标「供应商链接」；采购单发订单确认 → 供应商写承诺到货日 → 采购单上看得到、流程图按承诺日算；发货预告报一批 → 采购单与按单收货时看得到。
8. **扫码收款 / 平台验券 / 渠道订单**：在带 `INTEGRATIONS_MOCK=true` 的独立演示库上按第 1 节走一遍（模拟按尾号给结果，见 `docs/INTEGRATIONS_V8021.md` 第 2、3 节）；在不带的库上确认按钮都不出现、照旧手选手输。
9. **对外接口页**：模式、门店开关、最近的调用（付款码只留后四位，不出现任何密钥的值）。
10. 全程 `node dist/server/cli.js check` 全部 ✓。

## 5. 做过的反向验证

- 同一笔扫码收款登记到两张结账单 → 第二张 `PAY_TX_USED`；金额、方式对不上 → `PAY_TX_MISMATCH`；退过款的再入账 → `PAY_TX_REFUNDED`；交班时有没入账的 → `PAY_UNSETTLED`。
- 手输一张已经验过券的团购券 → `COUPON_VERIFIED`；补录一张验过还没用的 → 拦下；同一张再验 → 拦下。
- 请求没到时确认作废，原请求晚到：扫码收款、验券都 `OP_ABANDONED`。
- 供应商门户：同一个提交编号内容不同 → `IDEMPOTENCY_CONFLICT`；作废、过期的链接 404；采购模块关了 404。
- OTA：同一份文件导第二次 → `OTA_FILE_DUP`；渠道改了日期 / 间数 / 取消，预约跟着改；已经到店的只提醒。
- 合并前 Codex 审查后补的（`354e34c` 到 `e64932b` 几轮）：采购改供应商档案带不一样的收款账户 → `SUPPLIER_BANK_SEPARATE`，对账付款改了以后本人复核 → 403、批量付款勾不上 → `BATCH_BANK_UNVERIFIED`；申请在批次里单独付款 / 作废 → `REQUEST_IN_BATCH`，批次占着的货款再用付款登记 / 核销去付（导出前后都一样）→ `TARGET_IN_BATCH`，库里绕开拦截记一笔再导出、再下载 → `BATCH_STALE`；记已付做到一半再记 → 找回原来那笔；验券撤销占住时结账 → `VERIFICATION_CANCELLING`；OTA 导入断在中间原样重提 → 接着做完，两间的预付订单分开结账 → 各用各的券；采购单改版以后旧链接 → 404，新供应商可以重新确认；渠道订单导入的请求断掉 → 刷新页面「结果待确认」还在、按原内容重新提交建好，超过 64 KB 的订单表能导，订单改到约满的日子标超订、只改金额不清；另一个账户的流水不对这一批 → `MATCH_ACCOUNT_MISMATCH`，详情「其他信息」取不回来 → 加载失败可重试，选好文件换渠道 → 按新渠道重新预览；供应商发货预告的回复丢了 → 刷新后「上次提交没收到结果」、按原内容重新提交只记一批，验券对账重跑没成功 → 原来的差异还在，渠道订单 / 对账取不回来 → 加载失败可重试；开票申请以后结账单退了款 → 登记已开 / 交给服务商开是 `SOURCE_CHANGED`、驳回重申，开票以后退了款 → 进「要红冲」；网银导入预览先后乱了 → 只用最后一次的；前台顶上「收了钱没入账」「验过没结账的券」取不回来 → 写明查不到、可以重试；渠道订单重试时中间被另一次导入改过 → `OTA_ORDER_CHANGED`，批量付款的付款账户取不回来 → 加载失败可重试；没有流水号、打给不同账号的两笔流水 → 两笔都记，采购单「供应商确认与发货」取不回来 → 加载失败可重试；借贷标志写「借方」的流水 → 记成付出，认不出的标志 → 记成问题，合同模板取不回来 → 加载失败可重试；一间预付订单用完以后加成两间 → 新的一间只带剩下的，「验券对账」取不回来 → 加载失败可重试，2 万多字的合同模板 → 存得进去；今天验券、明天结账 → 两天对账都没有差异，「合同模板」管理弹窗取不回来 → 加载失败可重试。

## 6. 已知的限度

- **OTA 预付订单的那一行团购券**：设计写的是「不超过房费」，做出来是「不超过应收」（房费没有单独的口径；收银员可以改金额）。
- OTA 的预计到店固定为入住日 14:00；渠道的手机号多是虚拟号，不是 11 位手机号的不记在预约上。
- 平台验券的模拟对账单只记在应用进程里（重启就没了）；正式的平台对账单由平台给。
- 扫码收款的模拟状态同样只在进程里：应用重启以后还在「支付中」的模拟交易查不到，5 分钟后撤单。
- 银企直连、OTA 直连拉单这一版都没有（只有文件）；后台「对外接口」上固定显示「没配置」并写明怎么用。
