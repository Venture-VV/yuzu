## 1. 三级结构

| 层 | 字段 | 说明 |
| --- | --- | --- |
| 楼层 | 编码（`L1`–`L3`）、名称、排序 | 只增不删，可停用 |
| 区域 | 楼层、中文名、英文名、排序、备注 | 来自「楼层区域清单」（导览图与品牌平面图，共 32 个）；公区（大堂、男汤、休息大厅……）只建区域、不建房间 |
| 空间（房间） | **编码**（唯一，建好后不能改）、楼层、区域（可空）、业态、容量（人，可空）、面积（㎡，两位小数，可空）、显示名、英文名、可售、核对状态、编码图原始标注、备注、在用 | 编码图的 95 个房间；`id` 自增，业务（客房等）引用 `id` |

- **业态**：SPA、按摩、踩背、头疗、足浴、投影足浴、客房、娱乐室、派对房、宠物轰趴房；可在台账里加新的（文字，最多 8 个字）。
- **核对状态**：已核对 / 推断（图上没有直接写明，按就近标签或品牌图推断）/ 待现场核对（例如客房的品牌房号对应）。导入时按备注标出，店主或店长现场核对后改成「已核对」（写说明、留经办人）。台账页能只看没核对的。
- **可售**：默认是；不可售的（暂停、改造）在房态与选房时不出现（第三段用）。
- **编码规则**：区域字母 + 楼层 + 两位序号（如 S301），同一编码不跨楼层；**缺号保持缺失**（M304、M314、M324，S304、S314、S324、S334，G304，C304，P204），系统不补号、不按规律生成房间。

## 2. 别名

- 一个空间可以有多个别名：品牌名（如「客房 C5」）、编码图原始标注（如「足浴 C301 2人间」）、旧名。对客显示用显示名（通常是品牌名），内部用编码。
- 别名只追加：改名时加新的、旧的停用（留着可以搜），不删不覆盖。别名可以重复——品牌图上 4 间都叫「客房 C5」——搜索时都列出来，选房、房态时显示「编码 · 显示名」区分（见第 6 节）；同一个空间不会有两条一样的在用别名。

## 3. 导入与导出

- **导入**（后台「空间台账 → 导入」）：CSV（自动识别 UTF-8 / GBK）或 Excel；两种文件——空间清单（列：楼层、区域字母、编码、业态、容量(人)、建议显示名、面积、编码图原始标注、备注；可多一列「区域」）与区域清单（楼层、区域名(中文)、区域名(英文)、备注），与需求文档附件的草稿列名一致。先预览逐行校验，再写入；有错误的整份不写；**编码已存在的不覆盖**，预览里列出与台账不同的字段（差异报告，第四段的图纸治理在此基础上做）；同一个文件只能写入一次。导入的「编码图原始标注」同时记为别名。备注里有「推断」的行导入为「推断」，其余为「已核对」——草稿里的推断（M310–M318 踩背、F312–F316 足浴 4 人间）会标出来。
- **导出**：空间清单 CSV（楼层、区域、编码、业态、容量、面积、显示名、英文名、别名、可售、核对状态、备注），给设计方、店主核对用。
- **写入带操作编号**、提交前存本机（与费用报销、批量导入一样的「结果待确认」）。

## 4. 客房挂接空间台账（RQ-003 剩余项）

- `rooms` 加 `space_id`（唯一，一个空间最多挂一间客房房间）。后台「客房 → 房间」：给每间房选一个空间（只列业态「客房」、在用、还没挂的空间），**不自动匹配**；挂上后房号显示空间编码（`room_no` 同步成编码），房态、入住单、结账单显示「编码 · 显示名」。
- 台账里已经有「客房」业态的空间时，新建客房房间必须选空间（房号不再手工录入）；台账还没导入时照旧手工录入（升级后的过渡），自检会列出还没挂接的房间。
- 挂接后的房间不能改房号；换挂另一个空间、取消挂接要写原因（例如现场核对后发现挂错了），留经办人；有在住客人时不能换挂。
- 7 间客房的品牌房号（C3、C4、C5×4、C6）与编码的对应**要现场按门牌核对后**再录入别名，系统不按图纸坐标推断。

## 5. 页面

- 后台新分区「空间台账」（店主、店长；与「客房」同一组权限）：楼层与区域、空间清单（按楼层 / 区域 / 业态 / 核对状态筛选，搜编码或别名）、空间详情（编辑、别名、核对、停用）、导入、导出。
- 后台「客房 → 房间」：挂接空间。
- 只读接口给以后的房态图、对客导览用：楼层 → 区域 → 空间的树，带别名与状态。

## 6. 默认做法（待确认，见 PENDING_DECISIONS）

- 编码建好后不能改（写错了停用、再新建正确的）；停用的空间不能挂客房、以后不在房态图出现。
- 品牌名可以重复（4 间「客房 C5」），对客显示「客房 C5」、内部和选房时显示「G305 · 客房 C5」。
- 二层约 10 间「包房」没有编码，不建空间（只建「餐饮包房」区域），等店主定是不是要进台账、用什么编码。
- 谁能改：店主、店长（后台「客房」同一组权限：经营规则设置、价目与套餐）。

## 7. 迁移 `032`（只加不改）

- 新表 `floors`、`zones`、`spaces`、`space_aliases`（只追加，停用一次）、`space_imports`（导入记录，文件摘要唯一）；空间的核对记录写在操作审计里。
- `rooms` 加 `space_id`（唯一，外键到 `spaces`）。
- 操作编号与作废登记认新类型「空间台账导入」。
- 预置 L1、L2、L3 三个楼层（名称「一层」「二层」「三层」）；不预置区域与空间（门店环境导入真实台账须店主同意；演示库由测试会话按需加合成数据）。

## 8. 锁顺序

- 导入：按文件摘要加咨询锁 → 楼层（id 升序）→ 区域 → 空间（新建）。编辑空间只锁空间一行；加别名锁空间一行。
- 客房挂接：房间 → 空间（与客房的「房间 → 入住单」同一个方向；挂接时核对没有在住的入住单）。

## 9. 自检（`check`）

- 空间编码唯一（大小写不敏感）、区域与空间在同一楼层；
- 挂接的客房：空间业态是「客房」、在用，房号 = 空间编码，一个空间只挂一间；没挂接的房间数写在说明里（不算不一致）。

## 10. 不在本段

- 底图转换（DWG → 简化 SVG + 轮廓）、房态图（点房间开房查房）、对客导览、图纸入库与差异报告的完整流程：第二到第四段。
- 实时位置（刷卡点与业务动作推导「客人在哪个区」「技师在哪间房」）：等第三段房态图一起做，数据结构那时留好。
