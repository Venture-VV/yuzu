飞书需求 RQ-004「系统内平面图」分四段：① 空间台账 → ② 底图转换（自建 DWG 解析出简化 SVG）→ ③ 房态图 → ④ 对客导览与图纸治理；实时位置只做第一级（业务推导，D17、D24）。店主 2026-11-01 定 v0.7.13 之后开工，这一版做**第一段：空间台账**，并把客房的房间挂到台账上（RQ-003 剩余的一项）。迁移 `032`（ROADMAP 第 7 节已登记）。默认做法记在 `PENDING_DECISIONS.md`「空间台账」（待确认）。

已定的前提（飞书文档）：

| 决策 | 内容 |
| --- | --- |
| D1 | 系统基线是会所 1 至 3 层（L1–L3），汤崎负 3 层至 5 层不做 |
| D6 方案 A | 编码图的编码（如 G305）是系统房号主键；品牌平面图的名称（如「客房 C5」）是显示名 / 对客名，两套对应关系进别名表；缺号保持缺失，不自行补号 |

## 1. 三级结构

| 层 | 字段 | 说明 |
| --- | --- | --- |
| 楼层 | 编码（`L1`–`L3`）、名称、排序 | 只增不删，可停用 |
| 区域 | 楼层、中文名、英文名、排序、备注 | 来自「楼层区域清单」（导览图与品牌平面图，共 32 个）；公区（大堂、男汤、休息大厅……）只建区域、不建房间 |
| 空间（房间） | **编码**（唯一，建好后不能改）、楼层、区域（可空）、业态、容量（人，可空）、面积（㎡，两位小数，可空）、显示名、英文名、可售、核对状态、编码图原始标注、备注、在用 | 编码图的 95 个房间；`id` 自增，业务（客房等）引用 `id` |

- **业态**：SPA、按摩、踩背、头疗、足浴、投影足浴、客房、娱乐室、派对房、宠物轰趴房；可在台账里加新的（文字，最多 8 个字）。
- **核对状态**：已核对 / 推断（图上没有直接写明，按就近标签或品牌图推断）/ 待现场核对（例如客房的品牌房号对应）。导入时按备注标出：备注里有「推断」「推测」「近邻标签」的为推断（附件草稿里 F312–F316 写「按品牌平面图『足浴4人间』推断」、M310–M318 写「近邻标签 踩背1/2人间」，共 12 间），有「现场核对」「待核对」的为待现场核对；文件里有「核对状态」列时以它为准。店主或店总现场核对后改成「已核对」（写说明、留经办人）。台账页能只看没核对的。
- **可售**：默认是；不可售的（暂停、改造）在房态与选房时不出现（第三段用）。
- **编码规则**：区域字母 + 楼层 + 两位序号（如 S301），大写字母开头、最多 8 位（客房挂接后房号就是编码，房号最多 8 位），同一编码不跨楼层；**缺号保持缺失**（M304、M314、M324，S304、S314、S324、S334，G304，C304，P204），系统不补号、不按规律生成房间。

## 2. 别名

- 一个空间可以有多个别名：品牌名（如「客房 C5」）、编码图原始标注（如「足浴 C301 2人间」）、旧名。对客显示用显示名（通常是品牌名），内部用编码。
- 别名只追加：改名时加新的、旧的停用（留着可以搜），不删不覆盖。别名可以重复——品牌图上 4 间都叫「客房 C5」——搜索时都列出来，选房、房态时显示「编码 · 显示名」区分（见第 6 节）；同一个空间不会有两条一样的在用别名。

## 3. 导入与导出

- **导入**（后台「空间台账 → 导入」）：CSV（自动识别 UTF-8 / GBK）或 Excel；两种文件——空间清单（列：楼层、区域字母、编码、业态、容量(人)、建议显示名、面积、编码图原始标注、备注；可选「区域」「英文名」「可售」「核对状态」）与区域清单（楼层、区域名(中文)、区域名(英文)、备注），与需求文档附件的草稿列名一致（全角括号、「容量」「显示名」「面积(㎡)」这些写法也认）。先预览逐行校验，再写入；有错误的整份不写；**编码（区域名）已存在的不覆盖**，预览里列出与台账不同的字段（差异报告，第四段的图纸治理在此基础上做），文件里全是已有的整份拒绝；同一个文件只能写入一次。面积写「120m²」「95㎡」「70」都行；区域字母要与编码的首字母一致。导入的「编码图原始标注」同时记为别名。核对状态按上面第 1 节的规则标出——草稿里的推断（M310–M318 踩背、F312–F316 足浴 4 人间）会标出来。附件草稿没有「区域」列：导入后在「空间」里按楼层、业态筛出来，勾选后「设区域」一次设好（空间要在区域那一层）。
- 附件草稿两份文件在开发环境预览（不写入）：区域清单 32 行、空间清单 95 行，都没有问题，推断 12 间。
- **导出**：空间清单 CSV（楼层、区域、编码、业态、容量、面积、显示名、英文名、别名、可售、核对状态、备注），给设计方、店主核对用。
- **写入带操作编号**、提交前存本机（与费用报销、ERP 批量导入一样的「结果待确认」，业务类型「空间台账导入」）：断网或超时后在页面上方查回、按原内容重新提交（同一编号只写一次）或确认作废（原请求晚到也不写）。

## 4. 客房挂接空间台账（RQ-003 剩余项）

- `rooms` 加 `space_id`（唯一，一个空间最多挂一间客房房间）。后台「客房 → 房间」：给每间房选一个空间（只列业态「客房」、在用、还没挂的空间），**不自动匹配**；挂上后房号就是空间编码（`room_no` 同步成编码，挂着时不能另改）。房态看板的房间格子在房号下面显示空间的显示名，入住对话框标题显示「编码 · 显示名」；房费明细名里的房号就是编码。
- 台账里已经有在用的「客房」业态空间时，新建客房房间必须选空间（房号不再手工录入）；台账还没导入时照旧手工录入（升级后的过渡）；已有的房间不强制挂接，后台「客房」提示还有几间没挂接，自检的说明里写出数目。
- 第一次挂接不用写原因；换挂另一个空间、取消挂接要写原因（例如现场核对后发现挂错了），记在操作审计里、留经办人；**有在住客人时不能挂接、换挂或取消挂接**（房费明细上的房号要与入住时一致）。挂着房间的空间不能停用、不能改成别的业态（先取消挂接）。
- 7 间客房的品牌房号（C3、C4、C5×4、C6）与编码的对应**要现场按门牌核对后**再录入别名，系统不按图纸坐标推断。

## 5. 页面

- 后台新分区「空间台账」（店主、店总；与「客房」同一组权限），分「空间」「楼层与区域」「导入」三页：
  - 上方汇总：在用的空间、区域、楼层数，客房与已挂接的间数；还没核对的、客房还没有品牌名的分别提醒（点一下只看它们）；「导出空间清单」。
  - 空间：按楼层 / 区域 / 业态 / 核对状态筛选，搜编码、显示名或别名，可显示停用的；勾选后批量设区域；「新建空间」；空间详情（编辑、核对、别名、停用）。
  - 楼层与区域：按楼层列出区域，新建、编辑、停用（里面没有在用的空间、区域时才能停用）。
  - 导入：区域清单 / 空间清单、下载模板、预览（新建几个、已在台账里几个、推断几个，问题清单与差异表）、写入、导入记录。
- 后台「客房 → 房间」：挂接空间。
- 只读接口给以后的房态图、对客导览用：楼层 → 区域 → 空间的树，带别名与状态。

## 6. 默认做法（待确认，见 PENDING_DECISIONS）

- 编码建好后不能改（写错了停用、再新建正确的）；停用的空间不能挂客房、以后不在房态图出现。
- 品牌名可以重复（4 间「客房 C5」），对客显示「客房 C5」、内部和选房时显示「G305 · 客房 C5」。
- 二层约 10 间「包房」没有编码，不建空间（只建「餐饮包房」区域），等店主定是不是要进台账、用什么编码。
- 谁能改：店主、店总（后台「客房」同一组权限：经营规则设置、价目与套餐）。

## 7. 迁移 `032`（只加不改）

- 新表 `floors`、`zones`、`spaces`、`space_aliases`（只追加，停用一次）、`space_imports`（导入记录，文件摘要唯一）；空间的核对记录写在操作审计里。
- `rooms` 加 `space_id`（唯一，外键到 `spaces`）。
- 操作编号与作废登记认新类型「空间台账导入」（`space_import`）；同一迁移还加了「撤销对账登记」（`supplier_recon_void`，v0.7.13 审查的修正）。
- 预置 L1、L2、L3 三个楼层（名称「一层」「二层」「三层」）；不预置区域与空间（门店环境导入真实台账须店主同意；演示库由测试会话按需加合成数据）。

## 8. 锁顺序

- 台账的写入（导入，楼层、区域、空间、别名的新建与修改）都先取「空间台账」咨询锁，全部串行；不用表锁（v0.7.14 审查：导入的表锁与编辑的行锁会互相等成死锁）。等锁超过 5 秒按「空间台账正在被其他终端操作」拒绝。
- 之后：编辑空间：空间一行 → 楼层、区域一行（共享锁，确认在用、在同一层）；加别名、停用别名：空间一行 → 别名一行；批量设区域：空间（id 升序）→ 区域一行（共享锁）。
- **版本号**：楼层、区域、空间各有版本号，修改（空间的编辑、核对、设区域）各加 1。页面提交读到的版本号，对不上就拒绝（`FLOOR_STALE` / `ZONE_STALE` / `SPACE_STALE`）：超时后迟到的旧请求、别人同时的修改都不会悄悄覆盖新的修改；原样重提时如果第一次其实已经生效，同样被拒绝，刷新就能看到改好了。新建靠编码（区域名）唯一防重复，别名靠「同一空间在用的别名不重复」防重复；导入走「结果待确认」。
- 客房挂接：房间 → 空间（与客房的「房间 → 入住单」同一个方向；挂接时核对没有在住的入住单）。停用空间、改业态时锁空间一行再查有没有挂着房间，两边串行。

## 9. 自检（`check`）

- 「空间台账编码唯一、区域与楼层一致」：空间编码唯一（大小写不敏感）、区域与空间在同一楼层、在用的空间不在停用的楼层；
- 「客房房间与空间台账挂接一致」：挂接的客房的空间业态是「客房」、在用，房号 = 空间编码，一个空间只挂一间；没挂接的启用房间数写在说明里（不算不一致）。

## 10. 不在本段

- 底图转换（DWG → 简化 SVG + 轮廓）、房态图（点房间开房查房）、对客导览、图纸入库与差异报告的完整流程：第二到第四段。
- 实时位置（刷卡点与业务动作推导「客人在哪个区」「技师在哪间房」）：等第三段房态图一起做，数据结构那时留好。

## 11. 接口（v0.7.14）

| 接口 | 用途 | 权限 |
| --- | --- | --- |
| `GET /api/admin/spaces` | 台账：楼层、区域、空间（含别名、挂着的客房房间）、业态、汇总 | 店主、店总 |
| `POST /api/admin/spaces`、`PUT /api/admin/spaces/:id` | 新建、编辑（编码只在新建时填） | 同上 |
| `POST /api/admin/spaces/:id/verify` | 改核对状态（`status`、`note` 至少 2 个字） | 同上 |
| `POST /api/admin/spaces/:id/aliases`、`POST /api/admin/spaces/:id/aliases/:aliasId/retire` | 加别名、停用别名 | 同上 |
| `POST /api/admin/spaces/bulk-zone` | 批量设区域（`spaceIds`、`zoneId` 或 null） | 同上 |
| `POST/PUT /api/admin/spaces/floors[/:id]`、`POST/PUT /api/admin/spaces/zones[/:id]` | 楼层、区域 | 同上 |
| `POST /api/admin/spaces/imports/preview`、`POST /api/admin/spaces/imports`、`GET /api/admin/spaces/imports` | 导入预览、写入（`clientKey`）、导入记录；结果待确认用 `/api/erp/ops/:key?type=space_import` 查回或作废 | 同上 |
| `GET /api/admin/spaces/export` | 导出空间清单 CSV | 同上 |
| `GET /api/spaces/tree` | 只读的楼层 → 区域 → 空间树（只含在用的） | 店主、店总、前台客房、客房服务员、收银 |
| `POST/PUT /api/admin/rooms/rooms[/:id]` | 房间多了 `spaceId`（不带 = 不改挂接，null = 不挂）与 `linkReason` | 能管理价目的岗位 |
