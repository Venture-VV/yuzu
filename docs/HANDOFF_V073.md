# v0.7.3 交接说明 · ERP 独立工作区第一步

店主 2026-10-30 定，见 ROADMAP 第 10 节第 8 项、`docs/ERP.md`、`docs/PENDING_DECISIONS.md`「ERP 独立工作区」。定了三点：

- **独立的 ERP 工作区**：同一套系统、同一个数据库，单独的入口和导航，门店主导航里看不到 ERP 的页面；
- **门店的财务页面留在门店**：流水、日结、交班、看板不动，ERP 只读营业数据；
- **先后**：先做完 v0.7.2（[PR #18](https://github.com/Venture-VV/yuzu/pull/18)），ERP 单独开 PR。

v0.7.2 已合并到 `main`（`733a388`），这个 PR 的目标分支是 `main`，只显示 v0.7.3 的改动。

**没有迁移，不改任何业务数据。** 库存、采购、货款的单据、流程、接口与权限规则完全不变，只是换了地方打开。新增的只有：

- 设置项 `erp_modules`（店主的模块开关）；
- 一个只读的营业数据接口；
- 一项新权限「ERP：看营业数据（只读）」；
- 前端静态资源构建时预压缩（brotli / gzip），服务端按浏览器支持直接发（测试服首次打开慢）。

不碰收银与储值，按普通版本验收。

## 1. 范围

| 项 | 内容 |
| --- | --- |
| ERP 外壳 | 首页 `/erp`；顶栏常显实例标识与「版本 + SHA」；导航分供应链 / 财务 / 设置；窄屏改为顶部横排的模块标签。库存、采购、货款、待办的页面地址不变，改在 ERP 外壳里打开 |
| 门店主导航 | 去掉库存、采购、货款、待办四项。有 ERP 权限的人在用户菜单（左下角头像）里点「进入 ERP」。只用 ERP 的人登录后直接进 ERP 的第一个模块 |
| 模块注册表 | `src/shared/erp.ts`：库存、采购、应付货款、审批待办、营业数据五个模块，各自登记页面与接口前缀、权限、默认开关、依赖（采购、货款、待办依赖库存） |
| 模块设置（店主） | 开关模块。关掉的模块：导航不显示，页面提示没有开启，接口一律 403 `ERP_MODULE_DISABLED`。依赖的模块关着时，这个模块也用不了。数据保留，改动记审计 |
| 营业数据（只读） | 任选时段的净营业额、应收与优惠、结账客人与结账单、客单价、充值实收；每天的明细与日结情况；收款与部门构成。与经营总览同一口径 |
| 新权限 | 「ERP：看营业数据（只读）」（`erp.revenue`）：默认店主、店总，库存职责不带。岗位权限页的库存采购一组改名为 ERP |
| 其他 | 物资经办在 ERP 导航里能看到「采购」（看采购单、按单收货）；后台经营规则里的库存规则在库存模块关闭时不显示 |

## 2. 迁移与数据

- 没有迁移。
- 设置项 `erp_modules` 只存店主改过的开关，没存的按注册表默认：五个模块全部开启。升级后与 v0.7.2 一样都能用。
- 演示数据没有改。E2E 结束时把模块开关恢复为全部开启。
- `check`、`fingerprint`、备份核验、对账包不经过接口，不受模块开关影响。

## 4. 验收要点

| # | 操作 | 预期 |
| --- | --- | --- |
| E1 | 升级 v0.7.2 → 本 SHA，店主登录 | 没有迁移；门店主导航没有库存、采购、货款、待办；用户菜单有「进入 ERP」；ERP 首页列出五个模块；库存、采购、货款、待办里的单据与 v0.7.2 一致；`check` 全 ✓ |
| E2 | 物资经办、采购经办、对账付款、负责人（后勤岗位，只有职责）分别登录 | 直接进 ERP 的第一个能用的模块；没有门店主导航；餐饮功能关闭时也没有「返回门店」（开启时后勤能用厨房出品屏，才有「返回门店」，点了直接进餐饮的厨房出品屏，不会被送回 ERP）；各自只看到有权限的模块（物资经办：库存、采购；采购经办、对账付款：库存、采购、应付货款；负责人：库存、采购、应付货款、审批待办）；直接打开 `/ledger`、`/settlement`、`/shift`、`/frontdesk` 回到 ERP 的第一个模块，不停在只有外壳的页面 |
| E3 | 店总、值班经理、店员、客户经理登录 | 店总能进 ERP（营业数据）；值班经理、店员的用户菜单里没有「进入 ERP」，直接打开 `/erp` 回到门店首页；直接调 `/api/erp/modules` 403；客户经理直接打开 `/frontdesk` 回到会员工作台 |
| E4 | 店主在「模块设置」关掉「采购」 | 导航不显示采购；打开 `/purchasing` 提示没有开启；`/api/purchase-orders` 返回 403 `ERP_MODULE_DISABLED`；库存、货款照常；重新开启后恢复，单据都在 |
| E5 | 关掉「库存」 | 库存、采购、应付货款、审批待办都用不了：导航不显示，接口拒绝（读写都拦）；营业数据照常；模块设置里写明依赖库存；后台经营规则不显示库存规则；重新开启全部恢复 |
| E6 | 店总改模块开关；直接调接口提交不认识的模块 | 店总 403（只有店主能改）；不认识的模块 400；店主的改动在审计里有记录（`settings_updated`，`erp_modules`） |
| E7 | 营业数据：选近 7 天、本月；与看板「经营总览」对比；确认一天的日结后再看 | 净营业额、客人、充值、收款构成、部门构成与经营总览一致；确认过日结的营业日显示「已日结」与确认人；结束日期晚于今天拒绝 |
| E8 | 权限：店员、对账付款职责的员工调 `/api/erp/revenue`；店主在「岗位权限」给值班经理加「ERP：看营业数据」 | 前两者 403（库存职责不带全店财务查看）；加权限后值班经理能进 ERP，只看到营业数据 |
| E9 | 没登录直接调 `/api/inventory/materials`（模块关着时） | 401，不透露模块设置 |
| E10 | 五种尺寸打开 ERP 首页、库存、采购、应付货款、审批待办、营业数据、模块设置 | 没有横向滚动；窄屏模块标签可横向滑动；实例标识常显 |
| E11 | v0.7.2 的库存、采购、货款流程（`e2e/inventory.spec.ts`）与回归 | 全部照常，只是导航在 ERP 里 |
| E12 | 静态资源压缩：`curl -sI -H 'Accept-Encoding: br, gzip' <地址>/assets/<主脚本>.js`；同一地址不带 `Accept-Encoding`；Docker 镜像里列出 `/app/dist/client/assets`；新开浏览器（清缓存）首次打开登录页 | 第一次返回 `content-encoding: br`，`content-type` 仍是 JavaScript，`cache-control` 一年不变，有 `vary: accept-encoding` 与 `nosniff`；不带时发原文件；镜像里每个脚本、样式都有 `.br` 与 `.gz`；首次打开下载量约为原来的四分之一（实际快多少取决于网络，测试服上请与 v0.7.2 对比记下） |
| E13 | 技师功能关闭时打开看板；直接打开 `/dashboard/technicians`；开启技师功能后再看 | 关闭时没有「技师业绩」页签，地址回到看板；开启后照常显示，数据不变；后台「技师」两种情况都在 |
