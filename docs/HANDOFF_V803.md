## 1. 范围（相对 v8.0.2）

### 1.1 费用预算（BI01–BI06）

- **在哪**：ERP「费用与备用金」→「费用预算」（`/erp/expenses/budgets`）。
  - 按月看「部门 × 费用科目」的额度、已占用（审批中的另列）与红黄绿灯。
  - 新权限「设定费用预算」（`budget.manage`）默认只有店主，在这一页改额度。
- **额度**：从某个月起生效、之后每月沿用，直到下一次修改。
  - 清空 = 从这个月起不控制；没设过的格子不控制，所以升级以后在店主设额度之前，报销的行为不变。
  - 保存时核对页面看到的额度，别人刚改过拒绝（`BUDGET_CHANGED`）。
- **占用**：这个部门、费用日期在这个月、待确认 / 已退回 / 已确认的报销明细金额。撤回、冲销的不算。
- **黄灯**：达到额度的 80%（费用报销规则里可以改，50–100）；超过 100% 红灯。
- **登记报销页**：带出这个部门这个月各科目的额度、已占用、这张报完剩多少 / 超了多少；底部提示改成「超预算，提交后走『超预算报销』审批」。
- **超预算的报销**：
  - 不拦登记，但要走审批中心的「超预算报销」：店主建了规则的按规则；没有规则时在原来的审批链后面加一级店主（最多三级）。
  - 报销单上记登记时（或退回后重新提交时）的核对结果，列表与详情标「超预算」，详情写明超了哪个科目、超了多少。
  - 超预算报销不能批量同意。
- **顺带修的问题**：门槛以内、但命中了审批规则的报销，登记时会报错（报销单的守护不让改「要不要审批」）。这一版放开了这一项与超预算核对两项，只在待确认、退回时随提交更新。

### 1.2 进项发票台账（BI07–BI12）

- **在哪**：ERP 财务里新的「发票台账」模块（`/erp/invoices`）。默认开，依赖库存模块；能看货款或费用报销的人能看。
- **台账里的发票**有三个来源：三单匹配登记的供应商发票、报销单上的专票与普票、在台账里直接登记的。
- **视图**：全部有效、待认证、认证将到期（含已过期）、已认证、不用认证、异常票、已作废；可以按来源、开票日、号码或开票方筛，可以导出。
- **认证**：
  - 专票登记时「待认证」，普票「不用认证」。哪类要认证在费用报销规则里勾。
  - 标已认证要填所属期（不能晚于本月），可以勾一批一次标（一次最多 200 张）；单张可以改回待认证。改认证状态带版本号，别人刚改过拒绝（`CERT_CHANGED`）。
  - 认证期限 = 开票日 + 360 天（规则里可以改，0 = 不设）。到期前 7 天（可改）进待办，ERP 导航「发票台账」上显示张数，有过期的标红。
- **异常票**只标记、不拦：重号、税额不符（与按税率算的差超过 ¥1，可改）、税率不符、超过认证期限、与报销金额不符、开票方未填。
- **台账直接登记**：选发票类型（规则里要填号码的类型），供应商或开票方二选一。
  - 同一开票方同一号码不能登记两次（`INVOICE_DUPLICATE`）。
  - 没收到结果时记在页面上方的「结果待确认」里（与付款页登记发票同一类业务 `supplier_invoice`）。
- **照片**：图片或 PDF，最多 9 份，不能删。
- **作废**：挂在有效报销单上的不能作废（`INVOICE_IN_CLAIM`）。三单匹配的发票作废照旧要「登记期初未付、付款、核销与供应商退款」权限。
- **报销与发票**：登记报销选了专票、普票时，按号码在台账里找。
  - 有就关联；好几张要在登记页选（`INVOICE_AMBIGUOUS`）。
  - 挂在别的有效报销单上的拦（`INVOICE_ALREADY_CLAIMED`）；在三单匹配里分到采购单的拦（`INVOICE_IN_PAYABLES`）。
  - 没有的自动登记进台账：开票方、开票日、税额可以在登记页填，不填的开票方记未填、开票日按支出日期、税额按税点算。按采购单报销的开票方是采购单的供应商。
  - 报销详情里能点到台账的那张发票。
- **付款页登记发票**加「发票类型」（默认专票）。税率不在这类发票的税点里的只提示，台账里标「税率不符」。
- **新权限**「管理进项发票」（`invoice.manage`）：默认店主与财务（对账付款、成本核算职责）。
- **费用报销规则**（ERP「模块设置」）加：预算黄灯百分比、认证期限天数、提前提醒天数、税额容差、每类发票「要认证」。旧页面保存不传这几项时保留原值。

### 1.3 测试会话在 `1a1069a` 上报的 P2（已修）

- **问题**（[评论](https://github.com/Venture-VV/yuzu/pull/77#issuecomment-6720040961)）：台账列表先按开票日取最新 1000 张、再在内存里筛「认证将到期」「异常票」。旧的逾期票排在 1000 张以后就查不到，导航上却有提醒。
- **修法**：
  - 两个视图的条件都放进 SQL，先筛再取前 1000 张。异常票的 SQL 条件与逐张算的异常标记同一口径，用例逐张比对。
  - 上方「待认证」「将到期」「异常票」的数字在 SQL 里按全部有效发票数，原来最多数 10 万张。
  - 列表超过 1000 张时多返回 `truncated`，页面写明「只列出最新的」。
  - 导出不受 1000 张的限制，最多 5 万张；原来导出也只有 1000 张。
- **用例**：`tests/budget-invoices.test.ts` 最后一条：1000 张今天的待认证票 + 1 张 403 天前的待认证票。
  - 修之前「将到期」返回空，与测试会话的复现一致；修之后列出旧票，数量与导航待办一致。
  - 同一条里核对 SQL 筛出的异常票、将到期票与逐张算的完全一致。

### 1.4 Codex 自动审查（`c2c4a12`）的两条 P2（已修）

- **改额度时被刷新盖掉别人的修改**：原来保存时拿刷新后的额度比对、当作「看到的额度」送去核对。
  - 改的过程中页面刷新过（切回窗口时自动刷新），没动过的格子也会被当成改了，把别人刚改的额度悄悄改回去；冲突提示以后再保存也不再核对。
  - 现在按点「改额度」那一刻的额度做底：改的过程中按它显示、比对与核对，只送自己改了的格子；别人改过同一格时提示、退出编辑，按最新的额度重新改。
  - 浏览器用例 `e2e/budget-invoices.spec.ts` 第 ①b 步：在修之前的页面上失败，运费从别人改的 300 被改回 200；修之后通过。
- **登记发票的发票类型走了费用报销的接口**：费用报销模块关着时，「登记发票」的发票类型是空的、提交不了；只有「管理进项发票」没有「查看费用报销」的账号也一样。
  - 现在走台账自己的 `/api/erp/invoices/meta`：要填号码的发票类型、要不要认证、在用的供应商。
  - 用例 `tests/budget-invoices.test.ts`「费用报销模块关着也能登记」。

### 1.5 Codex 自动审查（`84f5fe5`）的三条 P2（已修）

- **同一张发票既报销、又走货款**：先报销、开票方写的就是某家供应商的名称（没挂供应商），之后在付款页按三单登记同一张，原来照样登记上。
  - 现在三单登记在号码锁里核对：同一供应商的、或开票方名称就是这家供应商的（不分大小写、去空白），已报销的拦（`INVOICE_ALREADY_CLAIMED`），没报销的拦（`INVOICE_DUPLICATE`，登错了先作废原来那张）。
  - 开票方没填的同号发票仍只标「重号」「开票方未填」，由财务核对。
- **发票照片走了采购模块的图片接口**：采购模块关着、或只有「管理进项发票」的账号，传得上去、看不了。现在照片与 PDF 都经台账自己的 `/api/erp/invoices/attachments/:id/download` 给（照片直接显示）。
- **详情开着时别人改了认证**：页面刷新拿到新版本号，保存时却用旧表单加新版本号，把别人的修改盖掉。现在按打开时的版本核对，对不上提示，并按最新的认证状态重新填。浏览器用例第 ⑥ 步在修之前的页面上失败。
- 用例：
  - `tests/budget-invoices.test.ts`：反向的三单登记、采购模块关着看照片，修之前都失败；
  - `e2e/budget-invoices.spec.ts`：第 ⑥ 步。

## 3. 验收要点

1. 登录页与导航栏显示 `v8.0.3` 和提交 SHA；`node dist/server/cli.js check` 全 ✓（自检里多了「进项发票台账」一项）。
2. **预算**：店主在「费用预算」给一个部门的办公费设 ¥100。
   - 登记报销（这个部门，办公费 ¥150）时，页面显示超出 ¥50、底部提示走「超预算报销」。
   - 不再登记即确认：进审批中心，类型「超预算报销」（没有规则时一级店主）；负责人批不了，店主在审批中心或报销详情里同意才生效。店主自己登记的也一样要同意一次（「同时以负责人身份确认」只在超过确认门槛时出现）。
   - 报销单标「超预算」，详情写明超了多少。
   - 撤回以后已占用回落；把额度调高再重新提交，不再超预算。
3. **黄灯**：已占用达到 80% 的格子黄灯；规则里改成 90% 以后变回绿灯。
4. **报销进台账**：登记报销选专票、填一个新号码，提交后台账里有这张（来源「报销」、待认证）。
   - 再用同一个号码登记报销：拦，「已在报销单 … 里」。
   - 撤回第一张以后可以再报，关联回原来那张。
5. **台账登记与关联**：在台账里直接登记一张普票（不用认证）。登记报销填同一号码、同一开票方时，页面提示「台账里已有」，提交后关联它；金额不一样的在台账里标「与报销金额不符」。
6. **认证**：
   - 待认证里勾几张，一次标已认证、填所属期；
   - 单张改回待认证；
   - 两个人同时改同一张：后保存的提示别人刚改过。
7. **将到期与异常**：规则里把认证期限改成 5 天，今天以前开的专票进「认证将到期」，ERP 导航显示张数；改回 360。异常票视图里能看到各类异常。
8. **P2 回归**：在独立库里造 1000 张今天的待认证票 + 1 张一年多以前的待认证票，「认证将到期」能看到旧票，张数与导航一致；「全部有效」写明只列出最新的；导出里有那张旧票。
9. **作废**：挂在有效报销单上的发票不能作废，撤回报销以后可以。三单的发票，没有货款权限的作废不了。
10. **付款页登记发票**：选普票时进台账是「不用认证」；税率填一个这类发票没有的，只提示、照常登记，台账里标「税率不符」。
11. **权限**：采购经办能看台账（有「查看供应商货款与对账」「查看费用报销、备用金与每日平账」），但不能登记、标认证、作废；成本核算能登记、标认证、作废（报销来源的）。
12. **两人同时改额度**：A 点「改额度」，B 改了另一格并保存；A 切走再切回页面（自动刷新）后改自己的格子、保存：B 改的那格保持 B 的值。B 改的是同一格时，A 保存提示「别人刚改过」、退出编辑。
13. **费用报销模块关着**：发票台账照常，「登记发票」能选发票类型、能登记。
14. **先报销、后三单**：登记报销选专票，开票方填某家供应商的名称；再到付款页按三单登记同一号码：拦，「已在报销单 … 里报销」。台账里直接登记的同一张，三单登记也拦，作废原来那张以后可以。
15. **采购模块关着**：发票详情里的照片照常显示。
16. **两人同时改认证**：A 打开一张发票的详情，B 改了它的认证；A 切走再切回页面后保存：提示「认证刚被别人改过」，表单换成最新的认证状态，B 的修改还在。
