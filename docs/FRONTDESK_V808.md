## 1. 钟房

### 1.1 护理项目能派钟（A01）

**现状**：钟房「派钟」只列后台「技师」里勾了「需要技师」的项目；店里的护理项目（演示数据里的搓背、精油按摩、足疗，汤崎价目表的「面部护理 · 茱莉蔻系列」与「玫瑰抗衰护理」）都没勾，所以：
- 前台点护理项目挂成普通项目，不建钟单，钟房看不到；
- 钟房「派钟」列表里没有这些项目；
- 就算勾上了，前台选「暂不指定技师」挂的那一条，钟房也没有地方给它补派技师——钟房的「派钟」是另挂一笔，会重复收费。

（需求里说的「无对应服务项」不是系统的原话，最接近的是派钟对话框的「没有需要技师的项目」。）

**改法**：
1. **护理类项目都设为需要技师**：升级时（迁移 `107`）把类别或名称含「护理」、还没勾的项目设为「需要技师」（F1）。之后新建项目时，类别或名称含「护理」的默认勾上。后台「技师 → 需要技师的项目」加「按类别全选」。店主可以在那里取消个别项目。
2. **钟房「待派钟」**：前台挂了需要技师的项目、选了「交给钟房派钟」（原来叫「暂不指定技师」）的明细，列在钟房的「待派钟」里：手牌、客人、项目、钟数、价格档、谁什么时候点的。
   - 点「派钟」：选技师、点钟 / 轮钟、马上上钟、房间，与派钟对话框一样（轮钟按排队规则，跳过第一位要写原因）。
   - **不再挂一笔**：只把技师记到这条明细上并建钟单。明细保护触发器只放开一种变化：「需要技师、还没有技师的有效明细补记一次技师与钟单」（迁移 `107`）。金额、价格档不变。
   - 价格跟技师等级时，只列价格档与这条明细一样的技师；要换价格档的请前台作废重点。
   - 提成、今日钟数按明细上的技师算，补记的一样算。
   - 同一条明细两个人同时派：先到的派上，后到的提示「已经派给 X 号了」；超时重点同一位技师照样成功（不重复建钟单）。
3. **前台**：「必须选技师」关掉时，选技师的地方多一个「交给钟房派钟」。开着时照旧必须当场选（F2）。
4. **防止重复收费**：在钟房「派钟」（新挂一笔）时，如果这位客人前台已经点了同一个项目、还在「待派钟」，对话框提示去「待派钟」里派，并给出一键切过去的按钮。

**验收**：后台把一个护理项目勾上（或升级后自动勾上）；前台关掉「必须选技师」、点这个项目选「交给钟房派钟」；钟房「待派钟」出现这一条，派给一位技师并马上上钟；钟房看板有这张钟单、技师在钟上、今日钟数加一；账单只有一条、金额不变，明细上显示技师；再点「派钟」同一条提示已派。

### 1.2 技师按状态筛选；休假、停牌（B01）

**现状**：技师当天的状态只有「在岗（上牌）/ 休息 / 未上牌」，在不在钟上由钟单推出来；没有「休假」「停牌」。钟房页面固定分块（轮钟排队、休息中、未上牌、上钟中、待上钟），没有筛选。

**改法**：
- **休假**（F3）：未上牌、休息的技师可以设为「休假」（当天，写不写原因都行）。休假的不在轮钟队列里，点钟、轮钟都不能派，「全部上牌」跳过他；给他上牌就取消休假。第二天自动回到「未上牌」。
- **停牌**（F4）：停牌要写原因，一直停到「复牌」，跨营业日。
  - 在钟上或已派了钟的不能停牌。
  - 停牌时如果在岗或休息，先下牌。
  - 停牌的不能上牌，也不能派钟，「全部上牌」跳过他。
  - 复牌以后是「未上牌」，要上牌才进队列。
  - 迁移 `107`：技师加停牌的时间、原因、经办人三列；技师状态加 `leave`；钟房日志加「休假」「停牌」「复牌」三类。
  - 休假、停牌、复牌在对话框里确认，带操作编号、走「结果待确认」（合并前 Codex 审查 `e2cb70d`，迁移 `110`）：回复丢了时先查回或确认作废，处理完之前这位技师不能另做停牌、复牌、休假、上牌等；原样重提只生效一次，确认作废的原请求迟到也不生效。
- **钟房页面**加一排筛选（带人数）：全部 / 空闲待钟 / 上钟中 / 已派待上 / 休息 / 休假 / 停牌 / 未上牌。
  - 选「全部」时页面照旧。
  - 选别的就只列这一类技师，每张卡片带这个状态下能做的操作（上牌、休息、休假、停牌、复牌、上钟、下钟……）。
  - 空闲待钟 = 在岗、手上没有钟。
  - 上钟中 = 正在钟上。
  - 已派待上 = 派了钟还没上钟。
- **派钟对话框**的技师列表也能按状态筛（点钟、轮钟都能用）：全部 / 空闲待钟 / 上钟中 / 休息。休假、停牌、未上牌的不能派，不列。
- 停牌、复牌、休假记进钟房日志。

**验收**：设一位休假、一位停牌（写原因）；钟房筛选「休假」「停牌」各只列出这一位；「全部上牌」不给他们上牌；派钟对话框里没有他们；复牌以后在「未上牌」里，上牌后进队列。

### 1.3 快捷转钟（B05）

**现状**：没有转钟。客人要换技师只能先退钟（作废明细，技师回原位，上了钟的算被退一次），再重新派钟（另挂一笔）。

**改法**：
- 待上钟、上钟中的钟单加「转钟」：选另一位技师（点钟 / 轮钟；轮钟按排队规则，跳过第一位要写原因；原技师不算在里面），写转钟原因。
- 一个事务里完成：
  - 原钟单的明细作废，原因「转钟：…」。
  - 给新技师挂同项目、同价格档、同钟数、同单价的明细，账单金额不变；挂账人、挂账时间、营业日照原来那一笔（之后作废照原来的核对，不能借转钟绕过更正权限）。
  - 建新钟单：原来在钟上的，转过去马上上钟；原来待上钟的，转过去也待上钟。房间照旧。
  - 原技师按退钟 / 取消派钟的规则回到原位（F5：上了钟的算被退一次）。
  - 钟房日志两边都记「转钟」：原技师记「转给 X 号」，新技师记「从 X 号转来」。
- 新技师的价格档要与原明细一样（价格跟技师等级时），不一样的不列；要换档的照旧退钟、重新派钟。
- 转钟带操作编号，超时、断网走「结果待确认」，与派钟一样。
- 权限：钟房派钟 + 前台挂账（与派钟相同）。金额不变，不受「本人 15 分钟内」的更正限制（F5）。

**验收**：派一钟给 A、上钟，点「转钟」转给 B；账单作废一条、新增一条、合计不变；A 回到排队、被退次数加一；B 在钟上、房间照旧；钟房日志两条「转钟」。

## 2. 收银：营业额流水实时刷新（A02）

**现状**（不是服务端的缓存，数据每次都现算）：
- 结账成功后，前台只刷新了交班和前台看板。日结、流水、结账记录、退款记录、工作台「今日」、数据看板都没刷新，要离开页面再进来。
- 这些页面开着时不定时刷新（交班页只有当前班次的卡片 30 秒刷新），别的电脑结的账要等切换窗口才出来。
- 页面上的「今天」用的是登录时的营业日，过了营业日切换时间还在查前一天。
- 结账记录没有合计，对不上日结时不好查。
- 「先开班」关掉、没人开班时收的款不在任何班次里，交班合计与日结差这一块，但页面上看不出来。

**改法**：
- 收款、反结账、退款、退储值、充值、桌台结账、退房结算之后，统一刷新日结、交班、流水、结账记录、退款记录、工作台「今日」、数据看板、ERP 营业数据（同一台电脑马上刷新）。
- 这些页面开着时每 15 秒自动取一次（F6），页面上写「每 15 秒自动刷新」，另有「刷新」按钮。别的电脑结的账 15 秒内出现。
- 「今天」跟着服务端的营业日走：过了切换时间自动换到新的一天；手动选了别的日期的不动。
- 结账记录上方加合计：笔数、结账合计、反结账、退款、净额，口径与日结的营业额相同（服务端用日结的同一个函数算）。
- 交班页、日结页：当天有不在任何班次的收款时，列出笔数与金额，提示「这几笔收款时没有开班，不在交班合计里」。

**验收**：开着日结页与交班页，在另一个窗口结一笔账，15 秒内两页自动出现；同一个窗口结账后，打开的结账记录马上有这一笔；结账记录合计与日结营业额一致；跨过营业日切换时间后页面自动到新的一天。

## 3. 派对房、宠物轰趴房（A03）

**现状**：
- 空间台账的业态已经有「派对房」「宠物轰趴房」「娱乐室」。
- 经营规则「派对房计费」按业态设计费：计费项目的每小时价、最少多少分钟、多少分钟一档、开台费。结束时按用了多久挂房费。
- 问题有三处：
  - **开单只能在平面图上点**。没有启用底图的门店找不到开单的地方，只有派对房预约到店时会自动开单。
  - **账单上的名称是计费项目的名字**。几种房共用一个计费项目时，账单上看不出是派对房还是宠物轰趴房，也看不出是哪一间。
  - **营业额按部门统计时按计费项目的类别算**，两种房共用一个项目就分不开。

**改法**：
- **客房页加「派对房」板块**（客房 / 平面图 / 派对房），不需要底图：
  - 列出「开单即占用」的业态下在用、可售的房间：空闲 / 使用中、手牌、人数、开单时间、已用多久、按现在结束的预计房费。
  - 「开单」：手牌、人数、备注，与平面图上的一样，同一间同时只能开一张。
  - 「结束计费」「撤单」。
  - 按业态分组显示，派对房、宠物轰趴房各一组。
- **没设计费的业态**（F7）：开单时提示「宠物轰趴房还没有设定计费，结束时不收房费（后台 → 经营规则 → 派对房计费）」。照样能开（不收房费的娱乐室也用这个）。
- **账单名称带房型和房间**：「宠物轰趴房 X202 房费（每 30 分钟）」「宠物轰趴房 X202 开台费」（最多 48 字）。
- **统计按房间的业态**：结账时营业额按部门的快照，派对房的房费、开台费按房间的业态记（「派对房」「宠物轰趴房」分开）。迁移 `108` 改快照函数，只影响之后的结账（F8）。
- 计费方式不变：按设定的每小时价，按档计费，计入结账当天的营业额。

**验收**：后台给「宠物轰趴房」设计费（每小时 ¥200、最少 60 分钟、30 分钟一档、开台费 ¥100）；客房页「派对房」里给 X202（宠物轰趴房）开单，用 70 分钟后结束；账单出现「宠物轰趴房 X202 房费（每 30 分钟）」×3 与「宠物轰趴房 X202 开台费」；结账后日结部门参考表有「宠物轰趴房」。

## 4. 预约到店一键开单 / 派钟（A04）

**现状**：
- 到店只填手牌。只有派对房预约会自动开使用单。
- 技师预约、客房预约到店后只给「去钟房派钟」「去客房开房」两个链接：什么都不带，派钟对话框、入住对话框都要从头填。
- 预约与之后派的钟、开的房没有关联，同一张预约能派好几次钟、入住好几次。
- 客房预约点了到店，房型的名额就放出来了，可客人这时还没入住。

**改法**：
- **到店**：照旧填手牌。这位会员此刻有在店手牌的，自动带出（可改）。
- **技师预约**：
  - 点完到店，直接打开钟房「派钟」，带上手牌、项目、技师：约了技师按点钟，没约按轮钟（F9）。
  - 派完记到这张预约上（钟单记预约编号，迁移 `109`）。
  - 一张预约同时只能有一张没取消的钟单：已派的再派，提示「这张预约已经派过钟（ZD…）」；派的钟取消了可以再派。
- **客房预约**：
  - 点完到店，打开客房页，标出这个房型的空闲房，点一间就打开入住，带上手牌、人数。
  - 入住记到这张预约上（入住单记预约编号，迁移 `109`），同一张预约只能入住一次（撤销的入住不算）。
  - 不走「去开房」、直接在客房页入住的，自动记到这位客人已到店、还没入住的客房预约：先挑这间房的房型，没有同房型的再挑最早的一张（换了房型入住）（Codex 审查 `f14210c`）。
  - 已到店、还没入住的客房预约照样占着房型名额，到入住为止；客人没入住就离店了（到店时的手牌结账或撤销）不再占（Codex 审查 `fb67dca`）。
- **派对房预约**：照旧到店即开单。
- **预约列表**：
  - 已到店的显示「已派钟 ZD…」「已入住 KF…」「已开单 SY…」。
  - 还没派、没入住的显示「去派钟」「去开房」，点了带着信息过去。
- 状态照旧：到店那一刻改「已到店」。

**验收**：
- 建一张技师预约（约 A 技师），客人接待后点到店（手牌自动带出），直接到派钟，手牌、项目、A、点钟都已选好，派完预约显示「已派钟」；再点「去派钟」提示已派过。
- 客房预约到店后到客房页，点一间同房型的空房入住，手牌已带好；再入住一次被拒绝。

## 5. 餐饮

### 5.1 桌台点单下架（A05）

**现状**：
- 点单页有「手牌客人 / 桌台」两种。桌台点单不用手牌：开台、点菜、在餐饮页现结。
- 「桌台」页签有开台、点单、结账、转台、撤台。
- 桌台档案还给小程序扫码点餐用作送餐位置（扫码点餐挂在会员的手牌上，不用桌台账单）。

**改法**：
- 餐饮设置加「桌台点单」开关，**默认关**（F10，店主「下架」）。关着时：
  - 点单页只有手牌下单，没有「桌台」。
  - 服务端拒绝开台、给桌台加菜（`TABLES_DISABLED`）。
  - 已经开着的桌台照常：查看、结账、退菜、撤台、转台都行，只是不能再加菜。
  - 「桌台」页签改叫「桌台账单」，只列还开着的桌台与历史，没有「开台」。
  - 历史桌台单照旧能在结账记录里查、能反结账。
- 桌台档案照旧（小程序扫码点餐的送餐位置）。
- 店主以后要恢复，在餐饮设置里打开即可。

**验收**：点单页没有「桌台」，只能输手牌；升级前开着的桌台在「桌台账单」里能结账；调接口开台被拒绝；打开开关后恢复原样。

### 5.2 退菜、改单按金额分级（B02）

**现状**：
- 没有审批流程。退菜（作废明细）的门槛只有两种：自己点的 15 分钟内能退；其余要有「前台更正」权限（值班经理、店总、店主），只能经理用自己的账号来退。
- 「改单」就是退掉重点。
- 结过账的要反结账，或开退款单。

**改法**（F11）：
- **小额直接退**：单条金额不超过「小额退菜上限」（默认 ¥50，餐饮设置里改，0 为不分级）的菜，能下单的员工就能退（与下单同一套权限：要「前台挂账」，桌台上的还要「点单」；只有「点单」的岗位本来就不能下单，点单页不显示「退菜」「改」，Codex 审查 `f14210c`）。原因必填，不受「本人 15 分钟内」的限制，记下「小额直接退」。
- **大额、整单**：
  - 超过上限的照旧：本人 15 分钟内，或经理用自己的账号退。
  - 新加「当场授权」：值班经理及以上在退菜弹窗里输自己的账号密码批准。授权人在弹窗里看到菜名、数量、金额与原因。授权绑定这一条明细与金额，5 分钟内有效、只能用一次，与优惠授权一样（迁移 `109`：授权用途加 `line_void`）。当场授权只用于餐饮的菜：别的明细（浴资、技师、客房、其他）申请不了，带着授权也照原来的更正流程（Codex 审查 `d034bc6`）。
- **改单**：点单页的菜加「改」：退掉这道（按上面的分级）并把它放回购物车，改数量或换菜再下单。
- **退菜记录**：餐饮页加「退菜记录」，按日期列出退的菜、手牌 / 桌台、数量、金额、原因、谁退的、怎么批的（小额直接退 / 本人 15 分钟内 / 经理 / 当场授权 + 授权人），合计，可导出。经理、店主每天看一眼，这就是「留痕」。
- 结过账的照旧走反结账或退款单（不变）。

**验收**：¥28 的果汁，服务员（没有更正权限、点了超过 15 分钟）写原因直接退掉；¥168 的菜服务员退被拒，请值班经理当场授权（输账号密码，弹窗里看得到金额与原因）后退掉；退菜记录里两条，批的方式分别是「小额直接退」「当场授权（某某）」。

### 5.3 下单页显示余量（B03）

**现状**：
- 点单页已经给限量的菜显示「剩 N」；估清的（0）置灰、不能点；购物车超过余量不能提交；下单、退菜后马上加减。
- 别的终端的菜单 30 秒才刷新一次。
- 前台「加项目」里的菜不显示余量。
- 「余量」是厨房在「估清」里设的今天还能卖几份。没设的不限量，与库存（ERP）没有关联。

**改法**：
- 点单页的菜单 10 秒刷新一次（F12）。
- 下单时余量不够照旧整单拒绝，并马上刷新菜单。
- 前台「加项目」里进厨房的菜也显示「剩 N」，估清的置灰、不能点。
- 菜单上写明「剩 N = 厨房估清设的今天还能卖的份数，没写的不限量」。

**验收**：厨房把一道菜估清设成 2；一台电脑点 1 份，另一台的点单页 10 秒内变成「剩 1」；再点 1 份变「已估清」、置灰。

### 5.4 餐饮台账按时间、分类导出（B06）

**现状**：没有餐饮专门的台账。日结能导出当天全部，经营总览能按日期看分类但不能导出。

**改法**：
- 餐饮页加「台账」：选起止日期（营业日，一次最多 92 天，F13）、菜品分类（多选，空为全部）、状态（有效 / 已退 / 全部）。
- 按点单时间列出每道菜：营业日、时间、手牌或桌台、菜名、分类、数量、单价、金额、状态（有效 / 已退及原因）、出品状态、谁点的。
- 上方合计：份数、金额（只算有效的）、退菜金额。
- 「导出」按同样的条件导出 CSV。导出的文件只有所选范围，最后一行是合计，与页面上的合计一样。
- 数据来自账单明细里的餐饮明细（手牌、桌台、小程序扫码点餐都在）。
- 权限：餐饮点单或日结。

**验收**：选一天、只选「饮品」，台账只列饮品，合计与逐行相加一致；导出的 CSV 行数、合计与页面一致。

### 5.5 厨房、水吧出品流程（A06，待现场调研）

## 6. 客房

### 6.1 改房态要确认、可备注、能回退（B04）

**现状**：
- 点房间打开「改房态」，预选另一种房态，点「保存」就生效，没有二次确认。
- 只有改「维修」要写原因。
- 改动只记在审计日志里（店主、店总能看），房间上看不到改过什么，也不能撤回。
- 两个人同时改，后提交的直接盖掉前一个。

**改法**：
- 改房态分两步：
  - 先选新的房态。
  - 再弹确认：「W301：待打扫 → 已打扫（空闲）」，可写备注（改「维修」必须写原因，F14）。
- 提交时带上看到的房态，房态刚被别人改过就拒绝（`HOUSEKEEPING_CHANGED`），请刷新。确认后看板马上更新。
- **房态记录**（迁移 `108`，`room_housekeeping_events`）：每次改动记一条：谁、什么时候、从哪到哪、备注、是不是撤回。入住、退房、换房、撤销入住自动改的也记。
- **撤回上一次修改**：最近一次是手动改的、之后房态没再变过的，可以撤回到上一个房态（记一条撤回记录）。照样按改房态的规则核对，例如有人住着不能改成维修。
- 房间详情（第 6.2 节）里能看到房态记录与备注。

**验收**：把 W302 从待打扫改成已打扫：先弹确认，写备注「已检查」；看板马上变；点「撤回」回到待打扫；房间详情里有两条记录。两个窗口同时改，后一个提示已被改过。

### 6.2 房间详情汇总（B07）

**现状**：
- 没有房间的历史。
- 入住单详情只看一次入住：房费、押金、换房。
- 技师服务、餐饮挂在客人的账单上，要到前台按手牌查。
- 平面图上只看得到现在的状态。

**改法**：
- 客房页点房间 → 「房间详情」，选日期范围（默认近 7 天，最多 92 天，F15），按时间倒序列出：
  - **入住**：入住、换进 / 换出、退房、撤销，带入住单号、客人、手牌；
  - **房费**：房费、钟点房分段，作废的标出来；
  - **押金**：收押金、退押金；
  - **住客在住期间的消费**：技师服务（项目、技师、钟数、钟单号）、餐饮、其他消费。来自入住那位客人的账单里，住进这间到离开这间之间挂的明细；
  - **房态记录**：第 6.1 节。
- 能按类别筛：全部 / 入住 / 房费 / 服务 / 餐饮 / 其他 / 房态。每条带单号、金额、状态。
- 数据都现从原单据查，不另存，与单据一致。只读，权限与客房看板相同。

**验收**：W301 入住、点一钟足疗、点一份简餐、结账退房；房间详情按时间列出入住、房费、足疗（技师、钟单号）、简餐、退房、自动改待打扫，金额与账单一致。

## 8. 加锁顺序（写进 AGENTS.md）

- **钟房补派**（待派钟）：来访 → 账单 → 这条明细（`FOR UPDATE`）→ 技师队列 → 房间（共享锁）→ 技师状态 → 技师预约咨询锁 → 建钟单、写明细的技师。与派钟相同，只是不新增明细。
- **转钟**：来访 → 账单 → 原钟单的明细（`FOR UPDATE`，id 升序）→ 技师队列 → 原钟单 → 原钟单的房间（共享锁）→ 技师状态 → 技师预约咨询锁 → 新钟单、新明细。
- **休假、停牌、复牌**：技师队列 → 技师一行 → 技师状态（与上牌、下牌同一把队列锁）。
- **预约派钟、预约入住**：都不锁预约单，只读核对已到店、到店手牌一致；靠钟单、入住单上预约编号的部分唯一索引兜底。不会与预约改动反向加锁。
- **改房态、撤回**：房间一行 → 写房态记录。入住、退房、换房自动改房态的照旧在各自的锁里，最后写房态记录。
- **小额退菜、当场授权退菜**：与退菜相同（来访 / 桌台 → 账单 → 明细 → 出品单 → 估清），授权在同一事务里核销。
- **派对房板块**：只读。开单、结束、撤单照旧。
- **台账、退菜记录、房间详情、结账记录合计**：都只读。
