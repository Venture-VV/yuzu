# 8.1.9 · 全局签赠（签赠券、授权人、签赠台账）

店主 2026-11-18 转来《管家部＋客户部初次需求更改》：「请帮我把这一个需求也加到 8.1.9 版本里面一起发布」。原文要点：

1. 后台新增「签赠功能配置」入口、「签赠知识库」录入端口：
   - 统一录入、维护所有可赠送的项目、规则、权益内容；
   - 全板块通用，不分板块单独配置；
   - 打通所有业务端口，各板块都能用。
2. 前台核销签赠权益（按摩、项目、服务）时，要选：
   - 对应的签赠券类型；
   - 对应的赠送人 / 授权人。
   - 核销要留痕，每一笔可追溯来源。
3. 管家部、客户部两个面板都加「签赠台账」：
   - 明细：项目、时间、券种、赠送人、使用状态、核销记录；
   - 按授权人：总赠送、已使用、未使用、作废；
   - 个人：每个人名下累计使用了多少；
   - 占比：人员、板块、券种。

默认做法见 `docs/PENDING_DECISIONS.md`「8.1.9 签赠」SZ1–SZ8，都待店主确认。迁移 `184`，登记在 `docs/ROADMAP.md` 第 7 节。

## 1. 现状

- 系统里没有「签赠」。现在送东西有三种办法：
  - 结账时的「优惠 / 免单」：要当场授权，记了授权人和原因；但它是整张结账单的一个金额，不知道送的是哪一样，也没有券种。
  - 券（`docs/COUPONS.md`）：
    - 兑换券能送一个项目或票种，代金券能送一个金额以内的；
    - 发券记谁发的、为什么，结账时按明细抵扣；
    - 有可用、已用、作废、过期，反结账会退回；
    - 但没有授权人，也分不出哪些是签赠。
  - 会员权益的「登记使用」：只数次数，不进账单。
- 按摩等服务派钟时就挂上账单。账单明细不能是 0 元，所以「送」只能在结账时抵掉。

所以签赠做在券上：抵扣、日结、营销成本的口径都不用变，只补授权人、渠道、知识库和台账。

## 2. 做法

### 2.1 口径

- **签赠券类型**：券模板里标了「签赠」的那一类，种类只有两样：
  - 兑换券：送一个价目项目或票种，例如「按摩 60 分钟」「浴资门票」；
  - 代金券：送一个金额以内的，例如「餐饮 ¥88」。
- 每个类型另有知识库里的内容：
  - **板块**（浴区、技师、餐饮、客房、其他，可在配置里改）；
  - **权益内容**（送什么、包含什么）；
  - **规则说明**（谁能送、送给谁、有什么限制）。
- 全公司一套，与券模板一样不分门店。发过券以后，送什么、有效期不能改（与券一样）；名称、板块、内容、规则、停用随时能改。
- **签赠**：给一位会员发签赠券。
  - 一次 1–10 张；
  - 必选**授权人**、**发放渠道**（管家部、客户部、前台、其他），必写事由；
  - 非会员先建档（SZ4）。
- **核销**：前台结账时在「券抵扣」里选这位客人的签赠券。
  - 列表上券名旁标「签赠 · 板块」，后面写授权人、渠道、事由；选了哪一张就是哪种券、谁授权的；
  - 收款明细的备注写「签赠·券名（券码，授权 某某）」，结账记录、小票上看得出是谁授权送的；
  - 与券一样：一张结账单最多一张券、不与优惠 / 免单同用（SZ5）；
  - 反结账退回。
- **状态**：未使用、已使用、已作废、已过期，与券一样。

### 2.2 后台「签赠」分区（会员与营销组）

分区要「维护签赠」（`/admin/gifts`，页签写进地址）。页签的顺序与别的分区一样：规则在前，再是清单、台账。

| 页签 | 内容 |
| --- | --- |
| 配置 | 开关（默认开）、板块与发放渠道的选项、签赠总则（全店通用的说明，发放弹窗顶上显示） |
| 知识库 | 签赠券类型：新建、修改（发过以后送什么、有效期锁住）、停用；每个类型发了、用了、没用、作废、过期几张 |
| 台账 | 与管家部、客户部的签赠台账同一份 |

普通券的「券模板」列表里看不到签赠券类型，券模板的接口也改不了它（`GIFT_TEMPLATE`）。

### 2.3 发放

- 在管家部、客户部的「签赠台账」与后台台账上点「签赠发放」：
  1. 找会员（手机号、卡号、姓名；没有「查找与查看会员」的人看到的手机号打码）；
  2. 选签赠券类型（下面显示它的权益内容、规则说明）、张数、授权人、渠道（默认是当前面板的部门），写事由。
- 带操作编号：没收到结果时弹窗里说明，关掉以后在台账上方的「结果待确认」里查回、按原内容重提或确认作废。
- **授权人**只能选有「签赠授权」权限的在职员工（SZ3）：
  - 默认店主、店总、值班经理、管家部主管；
  - 后台「岗位权限」里可以加；
  - 只选、不输密码。
- 普通发券、发券规则、无记名、批量发券、会员权益都不能选签赠券类型，只能经「签赠发放」发（SZ7）。数据库触发器兜底：签赠券类型的发券记录一定有授权人和渠道，别的券一定没有。

### 2.4 台账（管家部、客户部、后台三处同一份）

筛选：发放日期、渠道、券种、授权人、状态。

- **数**：发出、已使用、未使用、已作废、已过期、抵扣合计。
- **明细**：每一张签赠券（最近 1000 张；统计是全部，导出一次最多 20000 张、超过整份拒绝），含
  - 券码、券种、板块、会员（手机号按权限打码）、授权人、经办、渠道、事由、发放时间；
  - 状态，核销的结账单号、时间、经办与抵扣金额，作废原因；
  - 没用的（含已过期的）能作废：要「作废券」或「维护签赠」，写原因。
- **按授权人**：发了几张、已使用、未使用、已作废、已过期。
- **按个人**：每位会员名下发了几张、用了几张、抵了多少，从多到少（前 50 位）。
- **占比**（各取前 8 项，其余并成「其他」）：
  - 已使用的张数按人员（授权人）、按板块、按券种；
  - 发出的张数按渠道。
- **导出**（CSV）：要「维护签赠」「管家部导出」或「客户部管理」；只看台账的人不能导整份名单。一次最多 20000 张，超过整份拒绝（`EXPORT_TOO_LARGE`，请缩短日期范围或加筛选），不截掉一部分（与零采备用金的导出一样）。
- 窄屏（商米 V3）明细是卡片，两个日期各占一行。

### 2.5 权限（默认，后台「岗位权限」可调）

| 权限 | 默认 |
| --- | --- |
| 看签赠台账 `gift.read` | 店主、店总、客户经理；管家、管家部主管（职责） |
| 发放签赠 `gift.issue` | 店主、店总、值班经理、客户经理；管家、管家部主管 |
| 签赠授权（能被选作授权人）`gift.authorize` | 店主、店总、值班经理；管家部主管 |
| 维护签赠（知识库、配置）`gift.manage` | 店主、店总 |

- 作废签赠券：与券一样要「作废券」权限，或者有「维护签赠」。
- 管家部的「签赠台账」在顶栏（`/concierge/gifts`），客户部的在页签里（`/customer?tab=gifts`），分别跟着「管家部查看」「客户部查看」显示；台账接口认 `gift.read`、`gift.manage`、`concierge.read`、`customer.read`。

### 2.6 数据（迁移 `184_gifts.sql`）

- `coupon_templates` 加：
  - `gift`（是不是签赠券类型）；
  - `gift_segment`（板块）、`gift_content`（权益内容）、`gift_rules`（规则说明）。
  - 签赠的只能是兑换券或代金券、板块必填。
- `coupon_issues` 加 `authorized_by`（授权人）、`gift_channel`（渠道）。
  - 两个一起有或一起没有；
  - 有的只能是人工发券（`manual`）。
  - 发券记录只追加，与原来一样。
- 触发器：
  - 签赠券类型的发券记录必须有授权人与渠道；
  - 不是签赠的必须没有；
  - 发过券的模板不能改签赠标记。
- 操作编号与「确认作废」加 `gift_type`（新建签赠券类型）、`gift_issue`（签赠发放），在当时的约束上追加。
- 配置存在 `settings` 的 `gift_rules`，全公司一份。

### 2.7 加锁与幂等

- **新建类型**：与新建券模板同一条路（操作编号的咨询锁与「确认作废」串行），业务类型 `gift_type`。
- **改说明**：只锁那一个模板一行、带版本号。
- **发放**：与人工发券同一套：
  - 操作编号 `gift_issue` 与「确认作废」串行；
  - 会员一行（`FOR UPDATE`，与停用、合并串行；锁住以后再核对没被合并、没停用）→ 模板（共享锁），与小程序领取同一个顺序（Codex 审查 `cf81873`：不锁会员时，合并能在发放读完会员之后、写券之前提交，券就发到合并掉的会员名下）；
  - 授权人在锁外核对：在职、有「签赠授权」；
  - 发券记录的操作编号唯一兜底。
- **核销、反结账、作废**：都是券原来的锁，不另加。
- **台账**：只读快照，不加锁。

## 3. 三台设备

- 后台「签赠」三个页签、管家部与客户部的台账、发放弹窗，在三个尺寸上不横向滚动：
  - 商米 D3 Pro：1920 × 1080、1280 × 720；
  - 商米 V3：360 × 800；
  - 小米平板：1355 × 903。
- 台账在窄屏改成卡片；明细表格只在宽屏出现。

## 4. 用例

- `tests/gifts.test.ts`：
  - 建类型（知识库内容、发过以后不能改送什么）；
  - 发放（必选授权人、授权人要有权限、渠道、事由）；
  - 普通发券与规则不能用签赠类型，触发器兜底；
  - 结账核销后台账是已使用、反结账退回、作废；
  - 按授权人 / 个人 / 占比的数；
  - 结果待确认；
  - 手机号打码；
  - 开关关了不能发。
- 浏览器 `e2e/gifts.spec.ts`：店主在后台建签赠类型 → 管家部发放给一位会员 → 前台结账选这张签赠券 → 客户部台账里看到已使用与授权人统计。
