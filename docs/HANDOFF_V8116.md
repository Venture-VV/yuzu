## 0. 升级后会看到的变化

- **主导航**分七组：前台、餐饮、房态、技师、会员、财务、设置。1440 宽起默认展开成侧栏；1280×720、平板、手机默认收成一列业务域图标，当前组的入口列在下面，别的组点开弹出。原来一排图标里的入口都还在，只是放进了对应的组。
- **房态中心**（「房态」组）：按房型分页签加总览，各状态数量可点筛选；卡片点开登记（挂账 + 派钟 + 占房一步）、续钟、换房、退房、并房、维修、标待清、清洁完成、历史。原「客房」页并进来，`/rooms` 跳过去；派对房看板没有了，看各派对房的房型页签。
- **钟房**多了搜索框（姓名、工号、花名、拼音首字母）、类型与可做项目的叠加筛选、按状态排；顶上一条播报条（音量、静音、重播、试音、接管主播报、手动叫号）。
- **技师管理**（「技师」组）：名册、组别、班次与排班、休假四个页签；批了的休假当天不进排位。
- **新建会员**先选电子卡 / 实体卡 / 匿名卡；实体卡收押金（进交班现金与日结）；匿名卡可以不填手机号。会员详情多卡类型、推荐人、偏好、会员卡与押金、退卡。后台「会员体系 → 渠道与标签」里的「建档表单」配选填项的显隐与必填。
- **菜品管理**：上下架、改价、编辑别的终端刚改过的会提示「刚刚被改过……请刷新后再操作」；断网时进「结果待确认」。

## 5. 没做完的与风险

- **12px 只做了一部分**：ERP、流水、日结、看板、食堂、巡场、工作台、导览、客户部、管家部已改；前台、餐饮、钟房、客房、会员、后台与公共部件留到下一版（需求汇总「整体」里按钮、表格、弹窗、空态、出错统一也还没做）。
- **JS16** 见上（与 8.1.15 菜品 P1 同一类问题，没做）。
- **首屏主包**：别的模块直接引 `TagCardInput` 会把前台的共用代码挤进主包（实测超过 900 KB 上限），房态中心经 `VisitDialogs.tsx` 的 `InStoreTagInput` 转一手；以后别处要用也照这样。
- `e2e/room-center.spec.ts` 的流程那条在本机连跑时有过一次原因不明的超时，加了 `actionTimeout`，再出现会报出卡在哪一步。
- `demo-showcase` 只在演示库跑，这一版改了它，没在本机跑过（CI 的演示数据那一组会跑）。
- 读卡器、语音播报没有真机验过（用例里是模拟的键盘式读卡器与假的 `speechSynthesis`）。
- 菜品导入的「结果待确认」要把整份文件存进本机，很大的表格可能存不下（会提示没有提交）。

## 6. 验收要点

1. **导航**：七组都在；1920×1080 展开成侧栏；1280×720、平板、手机收成图标列，当前组的入口在下面、别的组点开弹出；1280×720 上七个业务域不用滚动。
2. **房态中心**：后台配好房型 → 总览与各页签的数量对得上；点「待清」只看待清；技师服务房登记一位会员（刷卡或手输）→ 发卡台上这张牌有挂账、钟房有派钟、房间在用；续钟加收、换房（单与计时不变）、退房（先看结账预览）、维修（原因与时间）、清洁完成、历史都有；断网时做一样动作 → 进「结果待确认」→ 查回 / 原样重提 / 确认作废。
3. **客房**：`/rooms` 跳到房态中心的客房页签；入住、续住、押金、退房、夜审与以前一样。
4. **餐饮只填房号**：登记在技师服务房里的客人能按房号点单。
5. **钟房**：搜索（拼音首字母、花名）、叠加筛选、按状态排；两台终端只有主播报那台念；静音时页面写明；手动叫号、重播。
6. **技师管理**：新建技师（花名、类型、入职日期）、组别与组长、排班与临时调班（要原因）、休假批了当天不进排位、销假回来。
7. **会员**：三种卡各建一位；实体卡收押金 → 交班的现金与日结里有、储值余额不动；退卡全额退；匿名卡不填手机号能建、页面写「未留手机号」；后台建档表单改了显隐与必填，建档页跟着变。
8. **菜品**：断网点上架 → 待确认 → 刷新还在 → 确认作废 → 恢复网络后原请求被拒；另一台改过这道菜，这一台改价被拒、提示刷新。
9. **刷卡**：芯片号绑在 A002、手牌池有 A001 时，在牌号框里刷卡选中的是 A002。
10. **账**：`check` 全部 ✓；交班、日结、对账包里会员卡押金一行对得上。
11. **三台设备**：房态中心、钟房、技师管理、新建会员、会员详情在 1920×1080、1280×720、360×800、1355×903 上不横向滚动。
