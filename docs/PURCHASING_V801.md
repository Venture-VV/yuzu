## 05 急采收拢到供应链、按金额分级审批（P0）

**原文**：收回其他部门的急采、补单入口，急采统一收拢到供应链采购模块；急采按金额分级审批，可以选审批人——5000 元以内审批人 A，30000 元以内审批人 B。

**谁能登记**：

- 只有「编制与提交采购单」的（采购经办）和店主，入口在「采购 → 急采」。
- 部门小仓、仓库不再能登记急采、补采购单，接口也拒绝。
- 部门小仓里照样看得到给本部门买的急采，只能看。

**流程**：

1. 采购登记急采：给哪个部门、供应商、明细与金额、经手人。
2. 提交进审批中心，单据类型「急采」，审批人同意。
3. 仓库到部门验收（与现在一样，不能是登记的人），进部门小仓。
4. 采购补采购单：按急采的数量与价格生成，提交即确认（急采已经按金额审过，采购单与急采逐行对得上，见补单的核对）。

**分级审批（CG05）**：

- 合计 ≤ ¥5,000 由审批人 A 审，≤ ¥30,000 由审批人 B 审。
- 每一档在「采购规则」里指定 1–5 个人，或签；没指定的由负责人审。
- 超过最高一档（¥30,000）不能走急采，要开采购单。
- 登记的人不能审自己的急采。
- 审批中心里另建了「急采」的审批规则时，按规则走（规则优先）。

**急采上限**：原来库存规则里的「急采上限」（#19，¥2,000）改成分级的最高一档，默认 ¥30,000。

**升级时还没走完的急采**：

- 部门登记的草稿、已退回的：由采购接手修改或撤回，部门不能再改。
- 已提交、待验收的：当作已审批，照旧由仓库验收。
- 已生效、还没补单的：由采购补单。

3 天没补单的照旧进负责人待办（A10）。

## 04 简化审批链路（P0）

**原文**：部门提交需求后直接推送供应链，供应链审批通过即可开展采购。

- 部门提交需求单，由供应链（有「审核需求单」的采购）一级审核，通过即可下单。现在就是这样，不改。
- **需求单转的采购单（CG04）**：每一行都来自已通过的需求单的，提交即确认，不再走「负责人确认」的默认规则。
  - 有自己加的行的照旧走默认规则。
  - 「采购规则」里可以关。
  - 店主在审批中心为采购单建了规则的，仍照规则走。
  - 询价门槛、合同核对照旧。
- **撤回**：提交即确认、没经过人审批的采购单（需求单转的、没超过免确认门槛的），还没有收货、报销、发票、三单放行时，
  经办人（或能确认采购单的人）可以撤回，需求行回到待转采购单（与以前待确认时撤回一样）；人审批过的照旧只能「关闭」。
  8.0.2 起，待确认、退回的采购单有发票、报销或三单放行的也不能撤回（发票登错了先作废发票）；登记发票与撤回在采购单的行锁上串行
  （测试会话在 a6b2b6d 上报的 P2：登记发票读到「已确认」以后、写入之前被撤回，发票照样登记上）。

## 02 需求单的采购优先级（P0）

**原文**：部门提交采购需求单时增加采购优先级，紧急标红点，普通标绿色；审批列表自动排序，红点优先，再按交期紧迫程度排，方便先处理急单。

- 需求单加「采购优先级」：紧急（红点）、普通（绿点），默认普通。提单时选，退回后可以改。
- **排序（CG02）**，用于需求单「待审核」与审批中心顶部的「需求单待审核」：
  1. 紧急在前；
  2. 期望到货日期早的在前，没填的排后；
  3. 提交早的在前。
- 列表、详情、待转采购单的行都显示红点或绿点。

## 01 模块归属重构（P0）

**原文**：把原来放在财务板块、归属采购业务的配置，迁到采购组模块，权责对齐。

**采购规则挪进「采购」模块**：从 ERP「模块设置」挪到「采购 → 采购规则」。包括：

- 采购途径；
- 询价门槛与最少报价家数；
- 补货天数；
- 截单时间（03）；
- 急采分级审批（05）；
- 需求单转的采购单免二次审批（04）；
- 「下单后几天没到货算超期」：从财务的「费用报销规则」挪过来；采购规则里还没存过的，沿用原来费用报销规则里的值。

**新权限「维护采购规则」（`purchase.rules`，CG01）**：

- 默认只有店主。
- 店主可以在岗位权限里下放给采购主管。原来采购规则只有店主能改，也下放不了（`settings.manage` 是锁定的权限）。
- 有查看库存的人都能看采购规则。

**留在财务的**：「费用报销规则」照旧留在 ERP「模块设置」——确认门槛、平账超期、用途、发票类型。

**导航**：采购组的页面都在「供应链 → 采购」里：急采、集采导入、供应商比价、采购规则。

## 08 采购途径固定三类、签约供应商（P0，需迁移）

**原文**：采购渠道固定分三类——网购、自采（现采 / 零采）、供应商；供应商分签约、未签约，签约的可以上传合同 PDF。

**采购途径**：

- 固定三类：网购、自采（现采 / 零采）、供应商；名称不能改，也不能加。
- 网购、自采要写在哪买（平台与店铺、市场或门店），供应商不用。

**旧数据（CG08）**：已经生效的单据只追加、不改历史，记的还是当时的途径名称。按三类统计、筛选时，旧的途径这样对应：

| 旧途径 | 算作 |
| --- | --- |
| 供应商配送 | 供应商 |
| 网购平台 | 网购 |
| 批发市场、商超门店、其他、自己加的途径 | 自采 |

供应商档案里旧的默认途径按同样的对应显示和带出，下次保存档案时存成三类之一。

**签约供应商**：

- 供应商档案加「签约 / 未签约」，默认未签约。
- 签约的可以上传合同 PDF：
  - 每份不超过 10 MB，可以传多份；
  - 存在数据库里，随备份走；
  - 撤下的保留记录。
- 合同模块里的合同照旧。

**用在哪些单据**：采购单、急采补的采购单、按次报销、集采导入的需求行。

## 03 每日截单（P1）

**原文**：需求单全天可以提交，可以自定义每日截单时间；截单后照常提交、推送供应链，但当日审批通道锁定，不能审核通过。

- 「采购规则」加「每日截单」，默认关着（升级后审核照旧），在「采购 → 采购规则」里打开，截单时间默认 17:00（CG03）。
- **截单后提交的**：截单时间以后（含）提交、或退回后再提交的需求单，照常推给供应链，但当天不能审核通过，页面显示「截单后提交，明天起可审核」；第二天 0 点（门店时区）起才能通过。退回、定为不采购不受限。
- 截单前提交的照常审。
- 每张单提交时就算出「最早可以通过的日期」，之后改截单时间不影响已经提交的单；把截单关掉以后，之前截单后提交的当天也能通过（按现在的规则）。
- 急采不受截单限制。

## 11 收货联动报销（P1）

**原文**：确认收货时可以上传图片、附件，单据自动推送到财务待报销，打通采购收货到财务报账。

**收货附件（CG11）**：

- 按采购单收货、急采验收时可以挂照片（货物、送货单、小票）和 PDF。
- 每张收货单最多 9 份。
- 生效后还能补传，不能删。

**推送到财务**：

- 现付供应商的采购单，收货生效后在财务「待报销」里标「已收货」，带上收货单与附件数。
- 转报销时，报销单上看得到这些收货单与附件。
- ERP 导航「费用与备用金」显示已收货、待报销的数量。
- 挂账（月结、按批次）的照旧走应付货款。

## 06 集采模板与一键导入（P1）

**原文**：统一集采标准模板，在采购页面增加集采表格的上传、识别导入。

**入口**：「采购 → 集采导入」。

- 下载标准模板，列与采购组的「集采需求表」一样：序号、申请部门、申请人、物品名称、单位、数量、采购优先级、期望到货日期、采购途径、供应商名称、备注。
- 上传 Excel 或 CSV → 预览：逐行核对部门、物品、单位、数量、优先级、日期、途径、供应商，有错的行写明原因。
- 确认后导入。

**导入出来的需求单（CG06）**：

- 按「部门 + 优先级 + 期望到货日期」合成需求单，直接是「已通过」（导入的就是供应链），进「待转采购单」。
- 申请人写在行上。
- 物品名称与物料档案的名称一样的带上物料；不一样的按新产品，导入的不要求链接和图片。
- 采购途径、供应商（按名称找）记在行上，转采购单时按供应商分组。
- 同一份文件不能导入两次。

**权限**：审核需求单的（采购）。

## 07 供应商比价看板（P2）

**原文**：同品类商品，对比不同供应商的价格波动、货品品质、耗用数据。

**入口**：「采购 → 供应商比价」。按品类或物料、时间段（默认近 90 天，CG07），每个物料 × 供应商一行：

- **价格**：采购次数、数量、最近单价、平均 / 最低 / 最高单价、比上一个同样长的时段涨跌了多少。
- **品质**：退供应商的数量与退货率、合同验收登记的质量问题数。
- **耗用**：这段时间这个物料的领用与耗用数量。

只读，不改数据。

**入口**：「库存 → 赠品台账」。

## Z4 登录按来源 IP 限次（店主 11-07：按默认）

- **按来源 IP**：同一来源 IP 10 分钟内登录失败 30 次，这个地址拦 15 分钟，任何账号都登不了。
- **按账号 + 来源**：同一账号在同一来源 15 分钟内错 5 次，这个账号在这个地址锁 5 分钟，别的地址照常。原来只按账号计，放到公网后别人能反复把店主账号锁住。
- 登录与「当场授权」共用计数；登录成功清掉这个账号在这个地址的计数。
- 来源地址按 `TRUST_PROXY` 算（8.0.0）。

## 锁

- **截单**：需求单审核照旧只锁需求单一行，在锁里核对最早可通过日期。
- **急采**：登记、修改、提交照旧锁单据一行；提交时开审批单，与其他物资单据一样：单据 → 审批单一行。同意、退回先锁单据一行，再锁审批单。验收照旧锁单据一行，之后照旧锁物料、部门小仓。
- **需求单转的采购单免二次审批**：在采购单的锁里读关联的需求行，不加锁。
- **采购单撤回**：照旧只锁采购单一行（排他），在锁里只读地核对没有收货、报销、发票、三单放行（8.0.2 起待确认、退回的也核对），提交即确认的还要没经过人审批（审批单）。登记发票先按 id 升序对选的采购单加共享锁（`FOR KEY SHARE`），锁住以后再核对状态；三单放行锁住采购单以后也核对状态（8.0.2）。按采购单报销本来就先锁采购单、再核对状态。
- **集采导入**：先取操作编号的咨询锁（与「确认作废」串行），再取同一份文件（内容摘要）的咨询锁，文件摘要的唯一索引兜底；写导入记录与需求单（先按已提交写单与行，再改成已通过），不锁已有的单据。
- **供应商合同 PDF**：上传只按内容存文件（唯一索引去重），再锁供应商一行写挂接；撤下只锁那一条。
- **收货附件**：先按内容存图片 / PDF（唯一索引去重，不加锁），再锁收货单一行（`FOR NO KEY UPDATE`），核对状态与份数上限后再写。
- **供应商比价看板**：只读，不加锁。
- **赠品**：登记先取操作编号的咨询锁（与「确认作废」串行）；作废只锁那一条。
