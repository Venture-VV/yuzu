店主 2026-11-03 合并 v0.7.22 后开工。按设计稿 `docs/MEMBERSHIP.md`（第 14 节是这一期的实现情况）与 `docs/PENDING_DECISIONS.md`「会员体系 v2」的默认做法（M1–M13 店主没有改；做的时候定的细节 M14–M26，待确认）做第一期：L0–L6 七档、初享尊三阶，**升档、赠金、升阶、保级、补充期、降档都由系统自动完成，每次变化留一条记录**；会员详情、前台、充值页、数据看板、管理后台都看得见；另一家店开放只读的会员查询。迁移 **`040_membership_v2.sql`**；`check` **53 → 56 项**。充值的赠金与最低充值变了，**涉及收款口径，按资金候选版本验收**（快速开发周期：CI 全绿后店主合并，验收在 main 的 v0.7.23 标签上补做）。

- **阻断项**：
  - 账错：充值的本金、赠金与预览不一致；赠金不是「本笔实收 × 充值后所在档的比例」（分以下舍去）；页面上的赠金与入账不一致却入了账；不到最低的充值入了账。
  - 档阶错：滚动 365 天累计够门槛却没升档、或没够却升了；储值消费到 30% / 60% 没升阶；补充期内到 60% 没保级；阶位在同一周期里降了；状态变化记录与会员当前档阶对不上（`check` 会报）。
  - 越权：前台店员、值班经理能改会员规则或手动调整档阶；没有手填赠金权限的人改了赠金；「他店查询」账号看到余额、流水，或打开了会员、前台、ERP 的任何页面与接口；看板「会员体系」对前台店员、值班经理开放。
  - VIP 柜：等级够的会员用不了该用的柜，或等级不够的会员用上了（默认 L0–L3 → 1 级、L4 → 2 级、L5 → 4 级、L6 → 5 级）。
  - 升级：从 v0.7.22 升级后原有余额、流水、日结、交班变了；`check` 不全 ✓；上线定档做了两次或没做；券模板、发券规则的等级换算错了。
  - 演示数据命令在试用、正式环境写入了数据（与之前相同）。

## 1. 范围

| 项 | 内容 |
| --- | --- |
| 数据 | `members` 加档级 `grade`（0–6）、阶位 `tier`（0 初、1 享、2 尊；L0 为空）、周期起止、补充期、版本号；状态变化记录 `member_grade_events`（只追加：上线定档、期初导入定档、充值升档、消费升阶、到期保级、进入补充期、补充期内保级、降档、手动调整）；每天到期处理的运行记录 `membership_job_runs`；设置 `membership_rules`（会员规则）、`membership_live`（上线定档做过的标记） |
| 充值 | 同一事务里：先把到期没处理的处理掉；按滚动 365 天累计充值（本系统的充值实收，含本笔）升档（可连跳，进初阶，周期从今天起）；赠金按充值后所在档的比例；首充 / 续充最低（默认都是 5,000 元）。页面上的赠金与入账不一致拒绝（`BONUS_CHANGED`），不到最低拒绝（`RECHARGE_BELOW_MIN`）；套餐只当金额快捷按钮；手填赠金要「手填赠金」权限、单独勾选确认 |

| 每天的到期处理 | 应用每分钟巡检，每个营业日第一次巡检时逐位处理（一位一个事务、只锁会员一行）：≥ 60% 保级（保持尊阶）、30%–60% 进 90 天补充期、不到 30% 降一档进尊阶（L1 降到 L0）；补充期满不到 60% 降一档。日期按规则推算，漏跑补跑结果一样；命令 `membership-daily` 手动补跑 |

| 期初导入定档 | （原排第三期，提前）期初导入的同一事务里同样定档，记「期初导入定档」、经办人是导入人；作废期初不降档 |
| VIP 柜、券 | 发牌、换牌按档级查「会员规则」里的 VIP 柜对照；原来的「VIP 等级口径、门槛、名称」停用；前台接口 `/api/frontdesk/members/:id/level` → `/grade`；券模板的适用等级、发券规则的等级换算成 L0–L6 |
| 页面 | 会员详情等级卡（阶梯、两条进度、下一档、状态变化记录、店主的「调整档阶」）；会员详情、账单、会员一览的档阶；充值页的升档与赠金预览；「数据看板 → 会员体系」；「管理后台 → 会员规则」；「他店查询」账号的「会员查询」页 |
| 他店查询 | 新岗位「他店查询」（只有一个权限、不能兼任别的岗位）：按完整的 11 位手机号或会员号查档阶、会籍到期日、补充期、账户状态；姓名、手机号遮一部分，不含余额与流水；每次查询记审计 |
| 手动调整 | 店主写原因调到任意档阶；先处理到期，带版本号（`GRADE_CHANGED`），周期从当天起；走「结果待确认」（提交前存在本机，超时、断网、回复 500 时等级卡上方查回、原样重提或确认作废，作废后原请求晚到也不生效） |
| 自检 | 加 3 项：档阶 = 最后一条状态变化、状态变化前后相接、每天的到期处理正常且没有过期没处理的会员 |

**这一版不做**（第二、三期）：本店权益清单、每月权益券、事件礼（首充 / 升档 / 升阶 / 保级 / 节日 / 到店挑战；升级礼、生日礼沿用 v0.7.20 的发券规则）、本月可享（v0.7.24，迁移 `041`）；会员日、同行、包房房费折扣，邀请体验与赠送会籍（v0.7.25，`042`）。**演示库里的会员都是今天定档、今天升档**，到期提醒、补充期名单是空的：到期、补充期、降档靠自动化用例（时间快进）核对；带到期、补充期的演示会员排在 v0.7.24 与权益的演示数据一起做。
