# 加锁顺序（按模块）

写事务之前先读**总则**和自己模块那一节；新模块、新的写入路径把顺序加进对应的一节（没有合适的就新开一节），不要写回 `AGENTS.md`。
这里的每一条都是从 `AGENTS.md`「开发约定」原来那一行（4.6 万字节）里原样搬来的（工程治理一期，`docs/GOVERNANCE.md`），只按模块分了节、长句按分号拆成子项，文字没有改。
条目里的「同上第 N 节」指同一节里上一条引用的那份文档。

## 总则

- 写操作带操作编号（幂等键），服务端行锁 + 数据库约束兜底；按固定顺序加锁，各模块的顺序见下面各节。
- 收款（充值、结账、反结账、退款单、退储值，以及客房的收退押金、退房）在锁业务行之前先对经办人未交班的班次加共享锁，交班只对班次加排他锁、不锁业务行；收款开始时所在的班次在入账前已交班则整笔拒绝（`SHIFT_CLOSED`）。
- 两条路径会锁同一批行时，顺序必须一致；新路径先看有没有「反过来的路径」。只读地核对、不加锁的地方照各节写明的做。
- 相关的通用规则（事务里不等外部调用、事务里的查询都要 `await`、结果待确认）在 `AGENTS.md`「开发约定」。

## 1. 前台、收银与在店服务

- 前台：手牌 → 同行组 → 来访 → 账单 → 会员；
- 挂技师项目、钟房在账单之后依次锁明细 → 技师队列 → 钟单 → 技师状态，再到会员；
- 餐饮点单、退菜在这之后依次锁沽清 → 出品单，厨房出品屏只锁出品单一行、设沽清只锁沽清一行；
- 桌台：桌台（id 升序，开台、转台、反结账才锁）→ 开台（id 升序）→ 账单 → 明细 → 沽清 → 出品单 → 会员；
- 客房：房间（id 升序）→ 入住单（id 升序）→ 来访 → 账单 → 明细；
- 转单：两位客人的来访（id 升序）→ 账单（id 升序）→ 明细（id 升序）；
- 派对房等的使用单（v0.7.19）：开单：来访（共享锁）→ 空间一行（`FOR NO KEY UPDATE`，与空间台账停用、改业态串行）→ 当前位置，结束、撤单只锁使用单一行 → 当前位置，结账、撤销来访在各自已有的锁之后锁这几位客人开着的使用单（id 升序）、再清位置；
- 退款单（v0.7.20）：班次（与收款同一条）→ 结账单一行（与反结账串行：反结账锁结账单后核对没有生效的退款单），作废退款单：退款单记到的班次（共享锁，须还没交班）→ 结账单 → 退款单；
- 派对房计费：结束计费的使用单先锁来访 → 账单，再锁使用单一行 → 当前位置（与结账同一个顺序）；不计费的照旧只锁使用单一行。
- 预约：新建先取时段的锁——技师预约全部串行（一把咨询锁）、派对房锁空间一行（`FOR NO KEY UPDATE`）、客房锁房型一行（`FOR NO KEY UPDATE`）；
  - 小程序新建先取 claimKey 的咨询锁、再锁会员一行（同一位会员「同时几个」串行），再取时段的锁；
  - 确认、改时间、取消、爽约、到店先锁预约一行，改时间再取时段的锁，派对房到店之后照开单的顺序（来访共享锁 → 空间一行 → 当前位置）；
  - 每分钟的自动取消、记爽约一张一个事务、只锁那张预约单；
  - 前台派钟、挂技师项目建钟单、加钟在技师队列锁之后取同一把「技师预约」咨询锁，核对这位技师这一钟计划的时段里还占着时段的预约（与预约新建、改时间串行）。
- 业务单据打到小票机（v0.7.28）：先在只读快照里排好单据内容（不加业务锁）→ 操作编号的咨询锁（与「确认作废」串行）→ 打印机一行；断网打印队列补打：打印机一行（共享锁，与修改、停用串行）→ 把它等恢复的任务改回排队；取消只锁任务一行。
- 按钱箱交班（v0.7.28）：收款照旧在锁业务行之前对经办人此刻所在的班次加共享锁（经当班成员 `shift_members` 找）；
  - 加入钱箱：班次一行（共享锁，与交班串行）→ 写当班成员；
  - 离开钱箱：只锁本人那条当班成员；
  - 交班照旧只对班次加排他锁，在上面的人一起离开（触发器改当班成员）；
  - 开班靠「一位员工同时只在一个班次上」「一个钱箱一个开着的班次」两个唯一索引兜底。
- 前台整改（8.0.8，`docs/FRONTDESK_V808.md` 第 8 节）：钟房补派（前台已点、还没派技师的明细）：来访 → 账单 → 这条明细（`FOR UPDATE`）→ 技师队列 → 房间（共享锁）→ 技师状态 → 技师预约咨询锁 → 建钟单、在明细上记技师（与派钟相同，只是不新增明细；同一条只能补一次，明细保护触发器放行一次），转钟：来访 → 账单 → 原钟单的明细（`FOR UPDATE`）→ 技师队列 → 原钟单（锁住以后再核对状态）→ 房间（共享锁）→ 技师状态 → 技师预约咨询锁 → 新钟单、新明细，同一张钟单只能转出一次靠部分唯一索引兜底；

  - 桌台点单下架只在开台、加菜时读餐饮规则、不加锁；
  - 改房态、撤回：房间一行 → 写房态记录（撤回靠 `reverts_id` 的唯一索引兜底，带上看到的房态、对不上拒绝），退房、换房、撤销入住自动改成待打扫的照旧在各自的锁里（入住单之后）锁房间一行再写房态记录；
  - 派对房看板、餐饮台账、退菜记录、房间详情、结账记录合计都只读。
- 前台风控（8.1.15，`docs/FRONTDESK_RISK_V8115.md` 第 5 节）：接待发牌在手牌之前先锁这几位会员当天待到店的技师、客房预约（id 升序，`FOR UPDATE`；预约的确认、到店、取消都是先锁预约一行，方向一致；锁的那一句带上全部候选条件——本店、这几位会员、这个营业日、待确认 / 已确认、不是派对房，等锁的行锁到以后按最新一版重新核对，等锁期间被取消、到店、改到别的营业日的都不锁、不动），之后照旧手牌 → 同行组 → 来访 → 账单 → 会员（共享锁），锁住会员以后再查黑名单，授权凭据最后加锁并核销，写完来访把锁住的预约标到店；

  - 手牌绑 / 解绑芯片号：只锁那一张手牌（`FOR UPDATE`，与发牌、换牌锁手牌串行），同一门店一个芯片号只绑一张牌靠唯一索引兜底；

## 5. 空间、底图、位置与设备

- 空间台账：所有写入（导入，楼层、区域、空间、别名的新建与修改）先取台账咨询锁、全部串行，不用表锁，之后编辑空间：空间一行 → 楼层、区域一行（共享锁），别名：空间 → 别名，批量设区域：空间（id 升序）→ 区域（共享锁），修改带版本号、对不上拒绝；
- 客房房间挂接空间：房间 → 空间，不取台账锁；
- 底图：启用先取底图咨询锁、再锁批次（id 升序），上传只靠唯一索引（同一份图纸、同时只转换一份）兜底；
- 钟单记服务的房间（房态图）：派钟在技师队列之后、建钟单之前给房间（空间一行）加共享锁，换房间：钟单一行 → 房间（共享锁），空间台账停用空间、改业态时空间一行（排他）之后只查里面没结束的钟单、不锁钟单；
- 实时位置：位置写在业务事务的最后（业务行都锁好之后），只锁每个人的当前位置一行（同一事务里先客人：来访 id 升序，再技师：id 升序），之后不再等其他业务锁（位置表因此不用外键引用业务表：外键检查会给来访、技师、空间等行加共享锁），写不进去用存档点回滚、业务照常；
- 刷卡上报先取操作编号的咨询锁（与确认作废串行），再只锁当前位置一行（读来访、技师不加锁），刷卡点修改只锁刷卡点一行、带版本号；
- 设备（v0.7.21）：登记、打印任务先取操作编号的咨询锁（与「确认作废」串行），修改、停用、建打印任务再锁设备一行（修改带版本号；修改、停用在同一事务把这台排着还没发的任务记失败）；
  - 领取打印任务：设备一行（共享锁）→ 任务，打印在事务外发送、之后只改任务一行；
  - 按采购清单导入先取导入咨询锁；
  - 心跳与状态只锁一台设备一行（心跳按探测前的版本写回，版本变了作废）；
  - 终端上报：终端一行 → 挂在它下面的设备（id 升序），事件靠编号的唯一约束去重；
  - 都不等业务锁。
