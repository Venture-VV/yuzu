# 上线前全流程试跑清单（8.0.7）

店主 D-1（上线前一天）在**演练库**上照着走一遍 ERP 的主流程：需求 → 比价 → 合同 → 收货 → 领用与耗用 → 报销 → 付款 → 对账确认 → 平账。每一步写了在哪个页面、谁来做、做完看什么。同一条路由 `tests/erp-full-flow.test.ts` 在 CI 里自动走（数字与这里一样），这里是给人照着点的版本。

## 0. 准备

- **在哪里跑**：测试服的演练库（实例标识「测试服·不作数」）或新建的演示库。**不在正式服、门店试用库上跑**。演练库不执行任何 seed 命令，下面用到的供应商、物料都在页面上新建，名字前加「试跑」，跑完不用删（演练库不记真实业务）。
- **版本**：登录页、导航栏显示 `v8.0.7` 与提交 SHA（部署用 main 上的版本标签）。
- **跑之前**：在服务器上执行 `node dist/server/cli.js check`，全部 ✓；记下 `node dist/server/cli.js fingerprint` 的摘要（可选，跑完以后对照能看出改了什么）。
- **账号**（按岗位分开登录，模拟真实分工；同一个人兼几个岗位也行，但审批不能审自己提交的）：

  | 岗位 | 职责（员工档案里勾） | 这次做什么 |
  | --- | --- | --- |
  | 部门申购（浴区） | 部门申购，所属部门：浴区 | 提需求单、部门签收、登记耗用 |
  | 采购经办 | 采购经办 | 审核需求、询价比价、起草合同、采购单、付款申请 |
  | 物资经办（仓库） | 物资经办 | 收货、领料到部门 |
  | 对账付款（财务） | 对账付款 | 合同与付款申请的财务这一级、登记发票、登记付款、对账确认链接 |
  | 法务 | 法务 | 合同审查的法务这一级（审查清单） |
  | 库存采购负责人 | 库存采购负责人 | 供应商准入、合同与付款申请的负责人这一级、现付采购单的确认 |
  | 成本核算 | 成本核算 | 备用金打款、报销、退回结余 |

- **ERP 模块**（ERP「模块设置」）：库存、采购、采购需求单、本部门小仓、应付货款、审批中心、合同、付款、费用与备用金、发票台账都开着（默认就是开的）。

## 1. 供应商准入（负责人）

1. 采购经办在 ERP「库存 → 物料与档案」新建供应商「试跑精油供应商」（挂账结算）。列表里显示「待准入」。
2. 在供应商档案的「准入与证照」里上传营业执照（号码、有效期至一年以后，拍照或 PDF）。
3. 负责人点「准入」，写「证照齐全」。**看**：状态变「已准入」，写着谁、什么时候准入的。
4. 同一页新建物料「试跑护理精油」：库存单位「瓶」、采购单位「箱」、1 箱 = 10 瓶，打开「效期管理」、保质期 365 天。

## 2. 需求（部门申购 → 采购经办）

1. 浴区账号在 ERP「采购需求单」提一张需求单：试跑护理精油 3 箱，用途「客用消耗」。**看**：状态「待审核」。
2. 采购经办在「采购需求单」里打开它、点「通过」。**看**：状态「已通过」，这一行进「待转采购单」。

## 3. 比价（采购经办）

1. 「采购 → 询价比价」→「新建询价单」，带上刚才的需求行（3 箱），标题「护理精油 3 箱」。**看**：需求单这一行显示「询价中」。
2. 「登记报价」两次：试跑精油供应商 ¥120 / 箱；另一家（比如种子里的供应商）¥135 / 箱。
3. 「定标」选试跑精油供应商，理由「单价低、证照齐全」。**看**：询价单「已定标」。

## 4. 合同（采购经办 → 财务 → 法务 → 负责人）

1. ERP「合同」→ 新建采购合同：对方试跑精油供应商，合同金额 ¥360，单价表一行（试跑护理精油 ¥120 / 箱，3 箱），付款节点：预付 0%、到货 100%（「到货、发票齐后付清」）、验收 0%、质保 0%；验收一节可以选「验收标准」模板（第 2.5 节）。
2. 「提交审查」。审批中心里依次：财务（对账付款）同意 → 法务按审查清单逐条「通过」后同意 → 负责人同意。**看**：合同「审批通过（待签署）」。
3. 「签署」：签署日期今天，我方、对方签字人。**看**：合同「已签署」，详情里的「付款计划」四段，到货段写「还没有生效的收货单」。
4. 回到询价单点「转采购单」：采购单带着需求行。编辑采购单，「合同」选这份合同，保存后提交。**看**：采购单「已确认」（行都来自审核过的需求单，提交即确认，CG04）；采购单上显示合同号，没有「超出合同」；需求单显示「已下单」和采购单号。

## 5. 收货（物资经办）

1. ERP「库存」→ 新建收货单，选这张采购单：实收、验收都是 30 瓶；这是管效期的物料，填批号「试跑-B01」、到期日（20 天后，用来看临期提醒）。「一起验收的采购」不用选（CG10）。
2. 提交。**看**：收货单「已生效」，金额 ¥360；采购单的到货情况「已到齐」。
3. 库存「呆滞与临期」→ 临期批次里有「试跑-B01」，还剩 30 瓶、20 天后到期；ERP 导航「库存」上的数字加了 1。

## 6. 领用与耗用（物资经办 → 部门申购）

1. 物资经办新建领料单「从总仓领料」：领到浴区，领料人写名字，10 瓶。**看**：领料单「已生效」，总仓剩 20 瓶。
2. 浴区账号进 ERP「本部门小仓」，在「待签收」里点「部门签收」（可以写一句备注）。
3. 浴区账号登记耗用：4 瓶，用途选「客用消耗」（经办人默认自己），说明「贵宾区补充」。**看**：浴区小仓剩 6 瓶；「耗用记录」里有这一条（用途、经办人）；能按用途筛、导出。
4. 「呆滞与临期」里那一批变成还剩 20 瓶（领走的先从这一批出）。

## 7. 报销（成本核算）

模拟一笔零星的现付采购：备用金先打给经办人，向网店买，收货后按采购单报销，结余退回。

1. 采购经办把一家供应商改成「现付」（或新建一家现付的「试跑网店」）；新建物料「试跑一次性拖鞋」（双 / 包，1 包 = 50 双）。
2. 成本核算在 ERP「费用与备用金 → 备用金与每日平账」登记打款：浴区、经办人自己、¥500、微信、凭证「转账尾号 ××××」。
3. 采购经办下现付采购单：试跑一次性拖鞋 3 包 × ¥150 = ¥450，提交；负责人确认。
4. 物资经办按采购单收货 150 双。**看**：「应付货款」里这家现付供应商没有多出这张收货单（现付不记应付）。
5. 成本核算「费用报销」→ 新建，按采购单报销：选这张采购单，带出拖鞋这一行（数量、¥450），用途「客用消耗」，付款来源「备用金」选刚才那笔打款，发票类型「收据」。**看**：报销单「已确认」（¥2,000 以内不用负责人确认）。
6. 「备用金与每日平账」里给这笔打款登记「退回」¥50（现金当面点清）。**看**：这笔打款「已结清」，未退回 ¥0；每日平账今天这一行：打款 − 报销 = 应退，应退 − 已退 = 0。

## 8. 付款（对账付款 → 采购经办 → 财务、负责人 → 对账付款）

1. 对账付款在 ERP「付款 → 发票」登记发票：试跑精油供应商，发票号码随便一个，¥360，分到那张采购单。**看**：「三单」里这张采购单「对得上」。
2. 采购经办打开合同详情的「付款计划」：到货段可付 ¥360。点「发起付款申请」：到货段 ¥360，期望付款日今天，用途「到货款」。**看**：申请「审批中」，两级（财务 → 负责人）。
3. 审批中心：财务同意 → 负责人同意。**看**：申请「待付款」；对账付款的 ERP 导航「付款」上的数字加 1。
4. 对账付款在申请详情里「登记付款」：¥360、银行转账、凭证「流水尾号 ××××」，核销到那张收货单。**看**：申请「已付清」；合同的到货段「付清」；「应付货款」里这家供应商余额 ¥0。

## 9. 对账确认（对账付款 → 供应商）

1. 「应付货款」→ 这家供应商 →「登记已对账」，按批次勾这张收货单。
2. 在这条对账登记上点「生成确认链接」，复制链接（只显示这一次）。
3. 用手机或无痕窗口（不登录）打开链接：看到对账单（收货 ¥360、付款 ¥360），点「确认无误」，留姓名。**看**：再打开显示已回复、不能再回。
4. 回到门店这边：对账登记显示供应商的回复「已确认无误」、谁、什么时候。

## 10. 平账与收尾

1. **应付**：这家供应商余额 ¥0，没有没付的收货单。
2. **备用金**：打款已结清；每日平账今天这一行对得上。
3. **需求单**：这一行显示采购单号（已下单、已到货），部门申购自己也看得到。
4. **合同**：付款计划里到货段「付清」。
5. **自检**：服务器上 `node dist/server/cli.js check` 全部 ✓（库存、采购、需求单、询价、合同、付款、发票台账、费用与备用金、应收与挂账……）。有 ✗ 的截图发给开发会话，不要手工改库。
6. 有时间再走两段（各自独立）：
   - **挂账**：ERP「应收与挂账」建协议单位（额度 ¥1,000）→ 前台结账选「挂账」¥600 → 日结里算营业额、不算实收 → ERP 登记回款 ¥600 核销 → 账龄里这家清了。
   - **资产**：拿第 5 步那张收货单的一行「转资产建卡」→ 打印标签 → 开一次扫码盘点、扫一张、结束 → 没扫到的列在盘亏里（只记录，不改卡片）。

## 11. 发现问题怎么报

在测试服或演示库上截图，写清第几步、哪个账号、看到的和应该看到的，发到主线开着的 PR 上（报告第一行写版本与完整 SHA，见 `AGENTS.md`）。账错、串单、越权、数据丢失、重复扣款、自检不过是阻断项。
