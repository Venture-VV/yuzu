# 付款流（v0.7.32）

财务、法务审批分期的第三期（`docs/ERP_FINANCE_LEGAL_PLAN.md` 第 4.3 节）：合同签了以后，钱按合同的付款节点、在条件满足时、经过审批再付出去，付之前采购单、收货单、发票三单对得上；质保金单独看；每周知道接下来四周要付多少。

规则没定的按第 9 节的默认 P1–P12 做（`PENDING_DECISIONS.md`「付款流」，待确认）。

## 1. 范围

| 块 | 内容 |
| --- | --- |
| 付款计划 | 按合同（生效的那一版）的付款节点算出每一段的计划金额、可付金额、已申请、已付；每段写明「为什么现在能付 / 还不能付」（第 2 节） |
| 验收登记、质量问题登记 | 合同详情里登记验收（合格 / 不合格）与质量问题（未处理 / 已处理）；验收合格放开验收段，质保期满且没有未处理的质量问题放开质保段（第 2 节） |
| 付款申请 | 选合同的某一段或没挂合同的应付发起；走审批中心（单据类型「付款申请」，提前付款是「提前付款」）；批了以后出纳按申请登记付款，不再审一次（第 3 节） |
| 三单匹配 | 登记发票（发票号、开票方、金额、税额，分到哪几张采购单）；按采购单比对收货金额与发票金额，差异超过门槛的挂起、财务看过写原因才放行；付款申请要三单对得上（第 4 节） |
| 质保金台账 | 一合同一条：金额、起算日、到期日、状态；到期前 30 天进待办；没付清的合同显示「未结项」（第 5 节） |
| 本周应付 | 未来四周每周要付的钱（已批待付、可付未申请、到期的质保金）与资金缺口，能导出；每周一进待办（第 6 节） |

不做：银行付款接口（出纳照旧线下转账、回来登记付款）；发票的认证状态、到期提醒、异常票标记（v0.7.33 发票台账）；企业微信推送（以后接，先进 ERP 待办）。

## 2. 付款计划

付款计划不另存一张表，每次按合同生效的那一版现算，变更单生效（合同升版）以后自然按新的一版算。

**每一段的计划金额**：合同总价 × 这一段的比例，按分取整；最后一个比例不为 0 的那一段补齐差额，四段合计正好等于总价（P1）。

**可付金额与条件**（P2）：

| 段 | 什么时候能付 | 能付多少 |
| --- | --- | --- |
| 预付 | 合同已签署（或已归档） | 整段 |
| 到货 | 采购合同：挂这份合同的采购单有生效的收货单；服务、租赁、其他合同没有收货单，登记验收合格后放开 | 采购合同按到货比例放开：到货段金额 × min(1, 已生效的收货金额（减去生效的退货）÷ 合同总价)；其他合同验收合格后整段 |
| 验收 | 最近一条生效的验收登记是「合格」 | 整段 |
| 质保 | 质保期满，且没有未处理的质量问题 | 整段 |

质保期的起算按合同的「起算依据」（P3）：验收合格日（最近一条合格验收的验收日）；最后一次到货日（这份合同最后一张生效收货单的日期）；签订日。期限按合同写的月数（0 个月 = 起算当天就满）。

每一段显示：计划金额、可付金额、已申请（审批中的、批了没付的）、已付，以及说明，例如「还没登记验收」「已到货 ¥36,000 / 合同 ¥60,000，到货段放开 60%」「质保期到 2027-11-30，还有 23 天」「有 1 条未处理的质量问题」「已付 ¥18,000，超过这一段（变更后）的计划金额 ¥15,000」。

**已申请、已付**算在付款申请选的那一段上；变更单生效以后照旧算在原来那一段，计划金额变小、已付超过计划的，显示超出（不追回、不报错，P4）。

**验收登记**（新）：合同已签署 / 已归档以后，维护合同的人登记验收：验收日（不晚于今天）、结果（合格 / 不合格）、签字人（默认带合同验收条款里写的签字人）、说明（不合格时必填，写怎么处理）。登记以后不能改，登错了作废（写原因）；以最近一条没作废的登记为准。

**质量问题登记**（新）：合同已签署以后登记：发现日、问题描述；处理完以后标记「已处理」（处理日、处理结果）。有未处理的质量问题时质保段不可付；问题登错了可以作废（写原因）。

## 3. 付款申请

**谁发起**（P10）：采购、对账付款职责（店主、店总也可以）。

**从哪里发起**：

1. **合同的某一段**：合同详情的付款计划里每一段有「申请付款」，金额默认 = 可付金额 − 已申请 − 已付，可以改小；不能超过这一段的计划金额 − 已申请 − 已付。
2. **没挂合同的应付**：在付款申请里选供应商，再选这家没结清的收货单、期初未付（与付款登记的核销一样）和各自金额。挂了合同的采购单的收货单不能从这里选（要从合同那一段申请）。

还填：期望付款日、用途说明；合同那一段还不可付、或申请金额超过可付金额的，要勾「提前付款」并写原因（第 3.2 节）。

### 3.1 审批

提交即走审批中心（P5）：

- 单据类型「付款申请」，金额 = 申请金额，部门 = 采购单或合同的部门；没有规则命中时 财务 → 负责人，申请金额 ≥ ¥50,000 的再加一级店主。
- 「提前付款」是单独的单据类型，没有规则命中时 财务 → 负责人 → 店主（比照常的多一级）；店主可以在「审批规则」里按金额另定。
- 财务那一级的详情里看得到：合同与这一段的条件、三单的金额与状态（第 4 节）、这家供应商的往来余额。

申请可以撤回（审批中）、退回后改了再提交；没付过钱的可以作废（写原因）。

### 3.2 提前付款

这一段还没到条件（例如货没到要先付到货款、验收前要付验收款）也能申请，但要勾「提前付款」、写原因，按「提前付款」的审批链多审一级（P6）。批了以后与平常一样付。

### 3.3 批了以后：出纳登记付款

批完的申请是「待付款」。登记付款的人（对账付款职责）在申请里点「登记付款」：走现有的付款登记（付款日、方式、凭据、核销到哪几张收货单 / 期初未付，或者记为预付款），带着申请号，**不再走付款的审批**（申请已经批过，P7）；金额不超过申请里还没付的部分。

- 合同的预付段：登记为预付款（核销合计可以是 0），之后在供应商往来里像现在一样把预付款核销到收货单上。
- 合同的到货、验收、质保段：核销到挂这份合同的采购单的收货单上；也可以部分记为预付款（写明用途）。
- 没挂合同的申请：核销到申请里选的那几张收货单 / 期初未付。

付清了申请变「已付」；付了一部分、剩下的不付了，在申请里「结束」（写原因）。

**挂合同的货款必须走付款申请**：直接登记付款（不带申请）时选到挂了合同的采购单的收货单，拒绝并提示先提付款申请（`PAYMENT_REQUEST_REQUIRED`，P7）；没带申请的预付款也不能核销到这些收货单上（同样拒绝），带申请的预付款照旧核销。没挂合同的照旧可以直接登记付款（走原来的付款审批），也可以先提申请。

## 4. 三单匹配

**发票登记**（新，v0.7.33 再扩成完整的发票台账）：对账付款的人登记供应商开来的发票：发票号码、开票方（供应商）、开票日、价税合计、税额、税率，以及分到哪几张采购单、各分多少（合计等于价税合计）。同一供应商同一发票号码只能登记一次；登错了作废（写原因）。

**按采购单比对**（P8）：

- 采购单金额：采购单行的合计；
- 已收货金额：这张采购单生效的收货单金额，减去生效的退货；
- 已开票金额：分到这张采购单、没作废的发票金额。

已开票与已收货的差异在门槛内（差额 ≤ 已收货金额的 1%，并且 ≤ ¥50），且已收货没有超过采购单金额（同一个门槛），算「对得上」；否则「挂起」。还没开票、还没收货的是「不齐」。

**挂起的处理**：财务（对账付款）在采购单或付款申请里看三个金额，写原因「确认放行」；确认时记下当时的三个金额，之后收货、退货或发票变了要重新确认。

**付款申请要三单齐全**：申请合同的到货、验收、质保段时，这份合同下有收货的每一张采购单都要「对得上」或「已确认放行」；没挂合同的申请，选的收货单所属的采购单同样要求。预付段（货还没到）不要求；服务、租赁、其他合同没有采购单，不要求（v0.7.33 发票台账接上以后再要求有发票）。提交时不齐或挂起的拒绝（`THREE_WAY_NOT_MATCHED`），审批中再变了的（例如发票作废），财务那一级看得到、可以退回。

## 5. 质保金台账

ERP「付款」里的「质保金」：一份有质保段（比例 > 0）的合同一条：

- 质保金额（质保段的计划金额）、起算日（第 2 节的起算依据；还没验收的显示「未起算」）、到期日、已付；
- 状态：未起算 / 未到期 / 30 天内到期 / 可付 / 有质量问题挂起 / 已付清；
- 到期前 30 天（含已到期没付的）进 ERP 待办，导航「付款」上显示件数（P9）。

**不混应付余额**：供应商往来与应付总览里，没到期的质保金单独一列「质保金（未到期）」，「现在该付」不含它。

**没付清不结项**：合同详情显示付款计划的完成情况，四段都付清（或「结束」了）才算「已结项」；台账能筛「未结项」。

## 6. 本周应付

ERP「付款」里的「本周应付」：从本周一起四周，每周列出：

- 已批待付的付款申请（按期望付款日）；
- 可付还没申请的合同段（算在本周）；
- 那一周到期的质保金。

每周合计与四周合计；页面上填「可用资金」算出缺口（只在本机，不存）；导出 CSV。每周一（门店时区）ERP 待办里出现「本周应付 ¥… / … 笔」。

## 7. 权限（P10）

| 权限 | 默认 |
| --- | --- |
| 查看付款计划、付款申请、发票、三单与质保金 | 能看货款的人（「查看货款与对账」：店主；采购、对账付款、负责人、成本核算职责）|
| 发起付款申请 | 店主、店总；采购、对账付款职责 |
| 审批 | 审批中心照旧（按规则；「审批中心：审批」） |
| 按申请登记付款、登记发票、确认三单放行 | 「登记付款」的人（店主；对账付款职责） |
| 验收登记、质量问题登记 | 「维护合同」的人 |

## 8. 锁与并发

- 付款申请：新建先取操作编号的咨询锁（与「确认作废」串行）→ 合同一行（共享锁，读付款计划时合同不在改）→ 写申请；同一合同同一段的「已申请 + 已付」不超过计划金额，在合同一行的锁里核对。修改、提交、撤回、作废、结束只锁申请一行（带版本号），提交、撤回之后锁申请的审批单一行；同意、退回在申请一行之后锁审批单一行（与审批中心一样）。
- 按申请登记付款：供应商一行（与现在的付款一样）→ 付款申请一行 → 收货单（id 升序）→ 期初未付（id 升序）；申请一行锁住以后核对「已付 + 本次 ≤ 申请金额」。
- 验收、质量问题登记：只锁合同一行。
- 发票：新建先取操作编号的咨询锁，再锁供应商一行；作废只锁发票一行。三单放行：只锁采购单一行，记下当时的三个金额。
- 本周应付、付款计划、质保金台账都只读。

## 10. 实现要点

- 迁移 `080`：付款申请（`payment_requests`：申请号 `FS…`、供应商、合同与段（可空）、金额、是否提前与原因、期望付款日、用途、状态、版本号、操作编号与原请求摘要；没挂合同的申请选的收货单 / 期初未付 `payment_request_targets`）；付款登记加 `payment_request_id`；验收登记 `contract_acceptances`、质量问题 `contract_quality_issues`（都只追加 + 作废 / 处理标记）；审批中心的单据类型加「付款申请」「提前付款」；「确认作废」的业务类型加「付款申请」。
- 迁移 `081`：发票 `supplier_invoices` 与分到采购单的金额 `supplier_invoice_lines`（只追加 + 作废）；三单放行 `po_match_releases`（记下放行时的三个金额与原因）。
- 服务端：`src/server/modules/payments/`（付款计划的计算、付款申请、按申请登记付款、验收与质量问题、发票与三单、质保金台账、本周应付、自检）；审批中心加两种单据（规则命中、默认链、详情要点）；付款登记接上申请、挂合同的货款拦截。
- 页面：ERP 新的「付款」：付款申请（列表、新建、详情与登记付款）、发票、质保金、本周应付；合同详情加付款计划、验收与质量问题；采购单详情加三单；审批中心的卡片与详情。
- 自检加 `payments`：付款申请的已付 = 带着申请号的生效付款合计且不超过申请金额；合同每段的已申请 + 已付不超过计划金额（变更后超出的除外，单列）；挂合同的货款没有不带申请的付款；发票分到采购单的金额合计 = 价税合计。
