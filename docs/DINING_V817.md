# 8.1.7 餐饮分区与点菜单（店主 2026-11-18）

店主转来两项需求：

1. 一份文件《餐饮点单面板新增二级菜单 + 全模块分类改造》，原话：「请帮我根据这个文件直接更改餐饮界面的排版」。
2. 后来追加一句：「请再帮我新增一项餐饮部的功能就是小票可视化，帮我参照市面上海底捞的点餐模板，就是这桌点完单之后可以查看餐饮的点菜单可视化，同时上面显示上或没上菜」。

需求文件的四条原文：

1. 点单下单后弹出二级选择菜单，3 个入口：【餐厅｜水吧｜果吧】，选中后进入对应点单页面。
   餐厅的分类为餐饮、酒水；水吧的分类为手作饮料、糖水、调酒；果吧不再细分二级分类。
2. 桌台模块新增分区分类：散桌、景观包厢、休闲水吧区、休息果吧区，单独点开后展示详情。
3. 厨房出品分类：保留现有逻辑不变。
4. 新增【果吧】相关分类，三处同步增加：沽清列表、台账、退菜记录。

没写细的地方按下面的默认做法做，记在 `docs/PENDING_DECISIONS.md`「8.1.7」CF1–CF9，等店主确认。

## 1. 点单分类：单独一套，不动价目表的分类

- **点单分类是单独的一套。** 三处入口（餐厅、水吧、果吧）和它们下面的小分类固定为需求里写的这几个（`src/shared/dining.ts` 的 `DINING_OUTLETS`）：
  - 餐厅：餐饮、酒水；
  - 水吧：手作饮料、糖水、调酒；
  - 果吧：不分小分类。
- **不改价目表的分类。** 价目表的「分类」还管着日结与经营总览的「部门」、券的适用范围和会员折扣；把菜改成「手作饮料」「调酒」这些名字，会让报表的部门和券跟着变。所以点单分类另记，价目表的分类照旧。
- **存在哪里。** 迁移 `181` 给 `service_items` 加两列：
  - `dining_outlet`：`restaurant` / `water` / `fruit`，空为还没设；
  - `dining_group`：小分类，果吧为空。

  数据库只核对入口是这三个之一、小分类不超过 8 个字；入口与小分类配不配得上由接口核对。

- **还没设的菜按默认归类**（`diningSlotOf`，前后端同一个函数，页面上标「默认」），从上往下第一条对上的：
  1. 价目分类正好叫酒水、手作饮料、糖水、调酒的，归到对应的那一处、那一类。「餐饮」不算：店里的菜价目分类多半都写「餐饮」（演示数据也是），它是统称，要往下看出品档口。
  2. 价目分类带「果吧」→ 果吧；带「调酒」「鸡尾酒」→ 水吧 · 调酒；带「糖水」→ 水吧 · 糖水；带「酒」→ 餐厅 · 酒水。
  3. 看出品档口的名字：带「果吧」的归果吧，带「水吧」的归水吧 · 手作饮料。
  4. 价目分类带「饮品」「饮料」而不在水吧做的，多是瓶装的 → 餐厅 · 酒水（只看这两个词：「餐饮」里也有个「饮」字）。
  5. 其余归餐厅 · 餐饮。
- **后台设置。** 后台「餐饮 → 出品档口与菜品」每道菜在出品档口旁边多一个「点单分类」下拉；每个价目分类那一组可以「整类设为…」。与出品档口同一个保存按钮、同一个接口（`PUT /api/admin/dining/items`，多带 `slot`，不带不改）。

## 2. 点单页：先选入口，再按小分类点

- 点单页的菜单区先弹出三个大入口：餐厅、水吧、果吧。每个入口写着它的小分类和现在有几道菜，有估清的标出来。
- 点一个入口，就进这一处的点单页：
  - 上面一排「餐厅｜水吧｜果吧」可以直接换另一处，不用再回入口页；
  - 下面是小分类标签（全部、餐饮、酒水……），选「全部」时菜按小分类分段排；
  - 果吧没有小分类标签，直接列出果吧的菜。
- **下单成功以后回到三个入口**（下一单再选）。从桌台详情点「点单」进来，也是先选入口。
- **不做遮住整页的弹窗**：找客人、换桌、催单、上菜、退菜都在同一页，弹窗挡住它们反而碍事。三个入口是在菜单区里弹出来的，带同样的进场动效。
- 菜篮可以混点几处的菜，一起下单。出品照旧按每道菜的出品档口送到对应的厨房屏，第 4 节不动。

## 3. 桌台：四个分区，点开看这个区的详情

- 四个分区：散桌、景观包厢、休闲水吧区、休息果吧区（`TABLE_ZONES`）。用桌台原有的「区域」一列，不加迁移。
- **后台。** 建桌、改桌时「区域」从四个分区里选，也可以「不分区」。原来写了别的区域的（例如大厅、包间）照旧显示，在下拉里标「原区域」，改了以后就不再出现。接口照旧接受 12 个字以内的任何区域，原有数据与用例不受影响。
- **桌台页上面一排分区卡片**（全部 + 四个分区；还有不在四个分区里的桌时多一张「其他区域」），每张写着：
  - 桌数；
  - 用餐中几桌、几人；
  - 待上菜几份；
  - 消费合计。
- 点一张分区卡片，下面只列这个区的桌（明细格子与原来一样，点空桌开台、点用餐中的桌看明细）。卡片下方再写一行这个区的详情：空闲几桌、用餐中几桌、几人、待上菜、合计。
- 选了哪个区记在地址里（`?zone=景观包厢`），刷新还在。「全部」按分区分段列出。

## 4. 厨房出品：不动

厨房出品屏照旧按出品档口分。

## 5. 沽清列表、台账、退菜记录：按点单分类，含果吧

- **沽清列表**（厨房的「估清」页）：
  - 按点单分类分组：餐厅 → 餐饮、酒水；水吧 → 手作饮料、糖水、调酒；果吧；
  - 上面一排「全部｜餐厅｜水吧｜果吧」可以筛；
  - 每道菜旁边仍写出品档口。
- **台账**：
  - 「分类」一列改成点单分类，例如「餐厅 · 酒水」「果吧」；
  - 按「全部｜餐厅｜水吧｜果吧」筛，选了一处以后还能按它的小分类筛；
  - 导出用同样的条件，多一列「价目分类」，方便和日结的部门对账；
  - 原来按价目分类筛的接口参数（`categories`）照旧能用。
- **退菜记录**：
  - 加一列「分类」（点单分类）；
  - 同样按「全部｜餐厅｜水吧｜果吧」与小分类筛；
  - 导出带分类，也按同样的条件。
- **按哪份分类算。** 台账与退菜记录用菜现在的点单分类，这和原来的价目分类一样，也不是下单时的快照：后台改了某道菜的分类，查以前的日子也按新分类。

## 6. 点菜单（小票可视化）

- **样式。** 参照常见火锅店点餐小票的样子，不用对方的名字和标志。一张竖长的小票纸，从上到下依次是：
  1. **抬头**：门店名、「点菜单」、桌号与分区（手牌客人写手牌号与称呼），人数，开台（到店）时间；
  2. **上菜进度**：一条进度条，「已上 x 份 / 共 y 份」，还有未上、已退几份；
  3. **每次下单一段**：写着第几次下单、时间、点单人。每道菜一行，依次是菜名、口味备注、份数、金额；右边一个状态章：已上、未上、制作中、已出餐、已退（已退的菜名划掉，不算金额）；
  4. **底部合计**：只算有效的份数与金额。
- **可以只看未上的菜**：小票上方有一个开关。
- **刷新。** 点菜单开着时每 10 秒刷新一次：数据放在 React Query 里，定时刷新走共用的 `useLivePoll`（8.1.3，`AGENTS.md`「定时取数」）——页面在后台、连不上服务器时不取，回到页面、网络恢复时马上取；关上就不取。
- **入口**：
  - 桌台详情的「点菜单」；
  - 点单页右边「还没上的菜」旁边的「点菜单」（手牌客人、桌台都有）；
  - 下单成功的提示里写着「右边『点菜单』里看上菜进度」，指向上面那一个。
- **怎么算已上。**
  - 出品单是「已上菜」的算已上；
  - 后台关了「出餐后还要服务员点上菜」时，「已出餐」也算已上；
  - 没进厨房的餐饮明细（没有出品单）算已上；
  - 退了的菜单独计数，不算进已上、未上。
- **接口**：`GET /api/dining/receipt?session=<开台>` 或 `?visit=<来访>`，只读。权限与桌台详情、点单相同（「餐饮点单」或「结账」）。已经结账的桌、离店的客人接口照样返回（只读）；页面上的入口跟着开着的桌、在店的客人。

## 7. 不在这一版

- 点菜单打到小票机：现有的业务单据打印（v0.7.28）可以接，等店主要。
- 点单分类的入口与小分类做成后台可改：现在固定为需求里写的这几个，要增减改代码（CF1）。
- 平板电子菜单（`/emenu`）的分类：照旧按后台「电子菜单」里排的分类，不跟点单分类走。
