# S7 客房（v0.7.4）

店主 2026-10-31 选定：v0.7.4 做一个完整模块 S7 客房（ROADMAP 第 10 节第 3 项）。规则先按洗浴中心客房、酒店的常见做法定默认、标「待确认」，见 `PENDING_DECISIONS.md`「客房」。**客房功能默认关闭**，店主在后台开启；关闭时前台、结账、交班、日结与升级前完全一样。按资金候选版本验收（押金与收款）。

## 1. 范围

| 部分 | 内容 |
| --- | --- |
| 后台「客房」 | 客房规则（店主）：开关、退房时间、加收一晚的时刻、钟点房宽限、押金默认金额。房型与房价、房间（能管理价目的岗位） |
| 客房页 | 房态看板（按楼层排成格子：空闲、在住、待打扫、维修）；入住、续住、换房、收退押金、退房、退房结账、撤销入住、打扫 / 维修、夜审 |
| 两种住客 | **洗浴客人**：入住时输入在店手牌，房费挂在手牌账单上，离店时随手牌一起结。**只住房的客人**：单独开一张客房账单（`bills.kind = 'room'`），在客房页退房结账 |
| 押金 | 押金台账（只追加）：收、退、抵扣；押金是负债，不算营业额；现金押金计入交班应有现金 |
| 报表与自检 | 看板「客房」、交班表与日结单列押金、对账包「07-客房与押金」、自检三项 |

不在这一版（店主定规则后再做）：房价含洗浴门票（住客票）、预订、按日期浮动的房价、会员房价、钟点房封顶转全天、迷你吧与客房挂账、打扫排班、门锁 / 房卡对接。

## 2. 房态

- 每间房有一个打扫状态：已打扫（空闲）、待打扫、维修（要写原因）。
- 「在住」不单独存：有未退房的入住单就是在住；一间房同时最多一个在住单（部分唯一索引兜底）。
- 退房、换房、撤销入住后，原房间变「待打扫」；打扫完点「已打扫」。
- 只有空闲（已打扫、没有在住单）的启用房间能入住、能换进来。

## 3. 房费

房费按入住时的房价计（之后改房型的价格不影响已入住的），每一笔房费都是账单上的一条明细（来源「客房」，部门「客房」），并在 `room_stay_charges` 记下是哪一晚 / 哪一段，**同一晚、同一段只挂一次**（唯一索引兜底）。

**全天房**（房价是每晚的价格）：

- 入住时挂第一晚（入住的营业日）。
- 夜审：给在住、入住营业日早于今天的全天房挂今晚。夜审只能在今天「加收一晚的时刻」（默认 18:00）之后做：这时还在住的客人，按退房规则本来就要付今晚。
- 退房时（时刻 T，营业日 C）应付的晚数：
  - 从入住营业日到 C 的前一天，每晚一次（至少一晚）；
  - T 过了 C 当天的退房时间（默认 12:00）、还没到加收一晚的时刻（默认 18:00）：再加收半天（房价的一半，按分取整）；
  - T 过了加收一晚的时刻：C 这一晚也要付。
  - 已经挂过的不重复挂，少挂的（例如漏做夜审）在退房时补上。作废过的房费不再补（作废是前台有意的更正）。

**钟点房**（房价是每段的价格，每段时长按房型，默认 3 小时）：

- 入住时挂第一段；续住加一段，马上挂上。
- 退房时超过已付时段加宽限（默认 15 分钟），按段补齐。

## 4. 押金

- **收**：入住时或在住期间。收款方式：现金、微信、支付宝、银行卡、其他（写备注）；储值、团购券不能当押金。
- **退**：在住期间可以退一部分；退房时余下的全部退回。按原收款方式原路退：现金从经办人当班的钱箱退，扫码、银行卡记为「原路退回」提醒。
- **抵扣**：只住房的客人退房结账时，押金先抵扣应收（收款方式「押金抵扣」，先用非现金收的部分），余下的原路退回。洗浴客人退房时押金全部退回，房费随手牌结账。
- **账**：
  - 押金台账只追加，每笔收、退、抵扣（以及反结账时的恢复）各记一行，带收款方式；
  - 每种收款方式的余额 = 收 − 退 − 抵扣 + 恢复，不能为负；
  - 退房、撤销入住之后余额为 0（自检核对）。
- **班次**：收、退都要经办人先开班（与充值、结账相同的班次协议），记在经办人当班的班次。现金押金计入交班应有现金；交班表单列「押金：收 / 退」。
- **营业额**：收押金不是营业额。抵扣的部分随结账单计入营业额（收款构成里是「押金抵扣」，不是现金），日结单列押金的收、退、抵扣与在住押金余额。

## 5. 退房与结账

- **洗浴客人退房**（客房页「退房」）：按第 3 节补齐房费、押金全部原路退回、房间变待打扫。房费留在手牌账单上，客人离店时随手牌一起结。手牌结账时还有在住的客房，拒绝并提示先退房。
- **只住房的客人退房结账**（客房页「退房结账」，要「结账收款」权限）：
  - 结账核对列出房费（含退房时要补的）与应收合计；
  - 收款与手牌、桌台结账相同（组合收款、团购券、优惠当场授权、先开班），另加「押金抵扣」；
  - 结清后入住单记为已结账、房间变待打扫，押金余下的原路退回（同一事务、同一班次）。
- **反结账**（前台「结账记录」，与手牌、桌台相同）：
  - 入住单恢复为在住；房间此刻已有人住时不能反结账；
  - 押金抵扣恢复为押金；退房时退回的押金不恢复（已经退给客人）。

## 6. 夜审

- 客房页「夜审」：给在住的全天房挂当晚房费，同一晚不会重复挂；可以重复做（只补没挂的）。
- 夜审报告：在住的入住单、今晚挂的房费、押金余额、各房态间数，记下谁做的、什么时候做的。
- 漏做的不要紧：退房时会把少挂的补上；看板提示「今晚还没夜审」。

## 7. 权限

| 权限 | 默认岗位 |
| --- | --- |
| 客房：入住、续住、换房、退房、押金、夜审（`room.operate`） | 店主、店总、值班经理、店员 |
| 客房：打扫、维修（`room.housekeep`） | 店主、店总、值班经理、店员、后勤 |
| 只住房的客人退房结账 | 「结账收款」（`frontdesk.checkout`） |
| 客房规则 | 店主（`settings.manage`） |
| 房型、房间 | 能管理价目的岗位（`catalog.manage`） |

## 8. 数据（迁移 `024_rooms.sql`）

| 表 | 内容 |
| --- | --- |
| `room_types` | 房型：名称、全天房 / 钟点房、房价（分）、钟点房每段分钟；停用不删除 |
| `rooms` | 房间：房号、楼层、房型、打扫状态与维修原因；停用不删除 |
| `room_stays` | 入住单：房间、入住时的房型与房价、账单（手牌账单或客房账单）、来访（洗浴客人）、住客称呼与人数、会员、预计离店、状态（在住、已退房、已结账、已撤销）、操作编号 |
| `room_stay_charges` | 每一笔房费：哪一晚（全天房）/ 第几段（钟点房）/ 半天加收，对应的账单明细；同一晚、同一段唯一 |
| `room_moves` | 换房记录（只追加） |
| `room_deposits` | 押金台账（只追加）：收、退、抵扣、恢复，收款方式、班次、结账单、经办人 |
| `room_audits` | 夜审记录：营业日、谁做的、挂了几晚多少钱 |

另外：账单类型加「客房」（`bills.kind = 'room'`）；结账单所结的账单可以是入住单（`checkout_bills.room_stay_id`）；收款方式加「押金抵扣」（`checkout_payments.method = 'deposit'`）；幂等与作废登记加客房的业务类型。只加表、加列、放宽约束，不改已有数据。

## 9. 自检

- **押金台账**：每个入住单、每种收款方式的押金余额不为负；已退房、已结账、已撤销的入住单余额为 0；押金抵扣与结账单的「押金抵扣」收款一致。
- **房态与在住单**：在住单的房间是启用的；一间房最多一个在住单；入住单的账单与来访状态一致（洗浴客人的手牌在店，只住房的客人的客房账单未结）。
- **房费不重复**：每个入住单每一晚、每一段最多一笔有效房费；每笔房费都对应一条客房明细。

## 10. 页面与接口

| 页面 | 接口 |
| --- | --- |
| 后台「客房」：客房规则（店主）、房型与房价、房间 | `GET /api/admin/rooms`；`PUT /api/admin/rooms/rules`；`POST/PUT /api/admin/rooms/types[/:id]`；`POST/PUT /api/admin/rooms/rooms[/:id]` |
| 客房页：房态看板、夜审提醒 | `GET /api/rooms`（房态、在住单摘要、今天的夜审情况、各房态间数） |
| 入住 | `POST /api/rooms/checkin`（操作编号；带 `expectedRate` 核对房价；可带押金） |
| 入住单：房费、押金、换房记录 | `GET /api/rooms/stays/:id` |
| 续住、改登记、换房、撤销入住 | `POST /api/rooms/stays/:id/extend`（操作编号）；`PUT /api/rooms/stays/:id`；`POST /api/rooms/stays/:id/move`、`/cancel` |
| 收押金、退押金 | `POST /api/rooms/stays/:id/deposits`、`/refunds`（操作编号，先开班） |
| 作废只住房客人的房费 | `POST /api/rooms/lines/:lineId/void` |
| 洗浴客人退房 | `GET /api/rooms/stays/:id/checkout-preview`（要补的房费、押金）；`POST /api/rooms/stays/:id/close`（操作编号，带 `expectedDue` 核对） |
| 只住房的客人退房结账（可合并几间房） | `GET /api/rooms/checkout-preview?ids=1,2`（每间房的明细、要补的房费、押金、登记会员的余额）；`POST /api/rooms/checkout`（操作编号，带 `expectedTotal` 核对；收款可含 `{ method: 'deposit', amount }`） |
| 改房态（打扫、维修） | `PUT /api/rooms/:id/housekeeping` |
| 夜审 | `POST /api/rooms/audit`（返回夜审报告） |
| 看板「客房」 | `GET /api/reports/rooms?from=&to=` |
| 反结账 | 前台 `POST /api/frontdesk/checkouts/:id/void`（与手牌、桌台结账相同） |

带操作编号的六种（入住、续住、收押金、退押金、退房、退房结账）与前台一样有「结果待确认」：查回走 `GET /api/frontdesk/ops/:key`，确认作废走 `POST /api/frontdesk/ops/:key/abandon`（按业务类型检查权限）。
