## 0. 一句话

员工手机上的 **柚子饭堂** 加一个 **工作台**：员工能用的应用都放在这里，按部门、角色显示。第一个应用是 **巡场**——安保部门的人巡到哪里，就扫那里贴的场所二维码打卡；店总（以及店主指定的人）在手机上、在 yuzu 后台都能看每天的巡场清单。后台的 ERP 里原来的「员工服务」分组改名 **员工工作台**，就是员工端应用的中台：**员工食堂**、**安保巡场**各是一个应用，能单独开关；以后加应用照样在注册表里加一条。

## 1. 需求对照（店主原话 → 做法）

| 店主说的 | 做法 |
| --- | --- |

## 2. 架构：员工端是柚子饭堂，中台是 ERP「员工工作台」

- **不另起一个后台**：ERP 本来就是按注册表管模块的工作区（导航、页面拦截、接口拦截、店主的模块开关都按 `src/shared/erp.ts` 的注册表来，AGENTS.md）。把原来的「员工服务」分组改名「员工工作台」，里面两个应用：
  - **员工食堂**（原来的，不变）；
  - **安保巡场**（新）：模块键 `patrol`，**默认关**，**依赖员工食堂**——员工端口、员工账号、员工名单都在员工食堂里，员工食堂关着时巡场也用不了。
- **员工端口照旧一个**（`CANTEEN_PORT`）：巡场的员工端接口 `/api/canteen/patrol/*` 挂在员工端口上；安保巡场模块关着时这些接口回「巡场还没开」。后台接口 `/api/erp/patrol/*` 只在主端口上。
- **员工账号照旧**：用柚子饭堂的员工账号（`canteen_employees`），部门就是员工名单里的部门（`departments` 表）。员工账号进不了管理后台（`docs/CANTEEN.md` 第 1 节），巡场也一样。
- 以后的员工端应用（排班、请假、报修、公告……）照这个样子：注册表加一个模块、员工端工作台加一个入口、后台加一页，员工端接口挂在员工端口上。

## 3. 员工端（柚子饭堂，手机）

### 3.1 工作台

- 底部导航：有工作台应用的人（巡场部门的人、手机上能看巡场记录的人），第四个入口换成 **工作台**；别的人照旧（厨房 / 跟柚子说），不受影响。
- 工作台页按格子列出这个人能用的应用：
  - **巡场**（巡场部门的人）；
  - **巡场记录**（后台指定的人）；
  - 原来柚子饭堂的：**厨房**（厨师、负责人）、**扫码**（食堂负责人）、**柚子信箱**（食堂负责人）、**跟柚子说**（所有人）。
- 首页也有一张巡场卡片（巡场部门的人写「巡场打卡」，只看记录的人写「巡场记录」），一点就到。
- 能用哪些应用由门店系统在「我是谁」里一起告诉手机（`CanteenMe.apps`），离线时用上次的；后台改了部门、改了能看记录的人，员工下次打开（或 5 分钟内自动刷新）就跟着变；接口每次都按名单当场核对，手机上显示的入口只是方便。

### 3.2 巡场（安保部门）

- 大按钮 **扫码打卡**：打开相机扫场所二维码。https 打开时网页里取景；店里局域网用 http 打开时改用「拍一张扫码」（与食堂负责人扫码同一个做法，`docs/CANTEEN.md` 第 17 节）。
- **直接扫也行**：用手机相机或微信扫一扫贴着的码，打开的就是柚子饭堂的巡场页、自动打卡（码里是「员工入口地址 + 场所码」）。没登录的先登录，登录好接着打卡。
- 打卡结果大字显示：「✓ 北门停车场」「22:15 打卡成功 · 今天这里第 N 次」，响一声；刚打过的（2 分钟内同一个人同一个码，XC5）提示「刚打过卡」，不重复记。
- **断网也能扫**（XC7）：扫到的先记在手机上（读回核对，存不下就不发），再交给门店系统；没收到明确结果的留着，每 10 秒、联网时按原来的操作编号原样补交。页面上显示「还有 N 笔等联网补交」。只收 24 小时内扫到的。
- 下面列 **今天的巡场**：每个场所今天几点、谁巡过；还没人巡的排在前面、标出来（XC6）；标题旁写我今天巡了几次、还有几处没人巡。

### 3.3 巡场记录（后台指定的人，XC2）

- 按天看（前一天 / 后一天，最多看 92 天前）：每个场所这一天谁几点巡过、一共几次；没人巡的标出来；按人筛。
- 只能看，不能改。

## 4. 后台（ERP「员工工作台 → 安保巡场」）

| 页 | 内容 |
| --- | --- |
| 今天 | 今天（营业日，XC4）每个场所：巡了几次、第一次与最后一次、谁巡的；**还没人巡的场所**排在前面、标红；今天巡场的人与次数。可以换日期看前几天 |
| 巡场记录 | 按营业日起止（最多 92 天）、场所、巡场的人筛选；每条：营业日、扫到的时间、场所、人（工号、姓名、部门）、怎么扫的（工作台扫码 / 直接扫 / 拍照）、离线补登的标出来；合计条数；**导出 CSV**（与页面同一个查询）；测试或扫错的可以作废（写原因，XC10） |
| 场所与二维码 | 列表：名称、位置说明、状态、今天巡了几次；新增、改名称与位置、调顺序、停用 / 启用（XC9）、**换码**（XC8）；**打印二维码**：勾选几个或全部，A4 上一页 6 张，每张印场所名称、位置说明与二维码（员工入口地址没填时提示先去「员工食堂 → 设置」填） |
| 设置 | **巡场部门**（多选，XC1）、**手机上能看巡场记录的人**（从员工名单里挑，XC2）；保存带版本号，两个人同时改提示刷新 |

权限（XC3）：**安保巡场：看记录**（`patrol.read`：今天、巡场记录、导出）与 **安保巡场：场所与设置**（`patrol.manage`：场所、换码、打印、设置、作废记录），默认店主、店总；店主可以在「岗位权限」里给别的岗位。

## 5. 数据（迁移 `111_patrol.sql`，只建自己的表、放宽一条约束）

| 表 | 内容 |
| --- | --- |
| `patrol_points` | 场所：名称（1–20 字，没停用的不重名）、位置说明（最多 40 字）、场所码（12 位，随机，唯一）、是否启用、排序、版本号、新建时的操作编号（唯一）、谁什么时候建的、改的 |
| `patrol_checkins` | 打卡：场所、员工（引用 `canteen_employees`）与当时的工号 / 姓名 / 部门（快照）、扫到的时间（手机按服务器时间差修正）与入库时间、营业日、怎么扫的（`scan` 工作台扫码 / `link` 直接扫开的 / `photo` 拍照）、操作编号（唯一）；作废留原因与经办人。保护触发器：打卡记录不能删、不能改，只能作废一次 |

设置存在 `settings` 的 `patrol` 一项：巡场部门、手机上能看记录的人、版本号 `rev`（规则锁，`lib/rule-settings`）。「确认作废」（`op_fences`）加业务类型 `patrol_point`（新建场所的「结果待确认」，与 ERP 其他单据一样，`sendErpOp`）。不改任何已有的表。

## 6. 规则（默认 XC1–XC12，见 `PENDING_DECISIONS.md`「8.0.9」）

摘要：巡场部门在后台选（XC1）；手机上看记录的人在后台指定（XC2）；后台权限默认店主、店总（XC3）；按营业日算（XC4）；同一个人 2 分钟内重复扫同一个码只记一次（XC5）；这一版不规定巡几次、几点巡，只标出没人巡的场所（XC6）；断网先记手机、24 小时内补交（XC7）；能换码（XC8）；停用的场所扫了提示停用（XC9）；后台能作废记录（XC10）；这一版不做异常上报（XC11）；场所名称最多 20 字、不重名（XC12）。

## 7. 锁与幂等（写进 AGENTS.md）

- **打卡**：员工一行（共享锁，与停用、重新开通串行，同食堂打卡）→「员工 + 场所」的咨询锁（2 分钟内去重时串行）→ 场所一行（共享锁，与停用、换码串行）→ 写打卡；同一个操作编号靠唯一约束兜底（原样重提返回第一次的结果）。
- **场所**：新建先取操作编号的咨询锁（与「确认作废」串行），名称靠部分唯一索引兜底；修改、停用 / 启用、换码只锁场所一行（带版本号，对不上拒绝）。
- **作废打卡**只锁那一条。**设置**走规则锁、带版本号。
- 今天、巡场记录、导出、员工端的今天与记录都只读。

## 8. 能防到什么程度

- **码不给员工端**：员工端拿不到任何场所码（场所列表只有名称），只能扫贴着的码；码只在后台（`patrol.manage`）看得到、打印。
- **要本人登录**：打卡记在登录的员工名下，接口每次核对他在不在巡场部门、账号有没有停用。
- **挡不住的**：有人把码拍下来，在别处扫照片——这是纸质二维码巡更的共同短板。办法：码被拍走、怀疑被复制时「换码」重贴；后台看「怎么扫的」「离线补登」「时间间隔」（几十秒内连扫相隔很远的场所就可疑）。要更严格可以以后换 NFC 贴片或定位，不在这一版（XC11 附注）。

## 9. 这一版不做

异常上报（拍照、备注）；规定巡更路线、频次与漏巡提醒；巡场排班；NFC / 蓝牙 / 定位打卡；员工端改场所、换码；与门禁、监控联动。以后要做时再排。

## 10. 验收要点

1. ERP「模块设置」里「员工工作台」分组下有「员工食堂」「安保巡场」；只开安保巡场、员工食堂关着时提示要先开员工食堂。
2. 「设置」选巡场部门「安保部」、指定一位能看记录的员工；员工名单里一位员工改到安保部。
3. 新增三个场所，打印二维码（A4，每张有场所名称）；换掉其中一个的码，旧码扫了提示认不出。
4. 安保部的员工登录柚子饭堂：底部有「工作台」，里面有「巡场」；别的部门的员工看不到，直接调接口也被拒。
5. 用「直接扫」打开第一个场所的码：打卡成功；2 分钟内再扫提示刚打过卡、只记一次；断网扫第二个：显示等联网补交，联网后自动补上，后台标「离线补登」。
6. 后台「今天」：两个场所巡过、第三个标「还没人巡」；「巡场记录」筛选、导出的条数与页面一致；作废一条（写原因）后不算数。
7. 指定的那位员工在手机「工作台 → 巡场记录」里看到同样的清单；没指定的人看不到。
8. 停用一个场所：扫了提示已停用；记录照样在。
