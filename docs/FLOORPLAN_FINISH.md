## 1. 开单即占用（D37 / D39）

店主 11-02 定（D37）：派对房、宠物轰趴房、娱乐室按「有开单即占用」算，结算或退单后释放。钟单是技师服务的单据，这三类房间不派技师，所以另做一张**使用单**。

| 项 | 做法 |
| --- | --- |
| 哪些房间 | 空间台账里业态是「派对房」「宠物轰趴房」「娱乐室」的在用空间（规则里的「开单即占用业态」，默认这三种，后台可改，待确认） |
| 开单 | 平面图点房间 →「开单」：填**在店客人的手牌**（使用人，账算在他的手牌账单上）、人数、备注。开单即「使用中」。同一间房同时只能有一张开着的使用单（数据库唯一索引兜底，两台终端同时开单只有一张成功）。场次费等到前台挂到使用人的手牌账单上（侧栏「去前台挂账」打开他的账单，与前台挂账同一个口径）。写操作带操作编号，断网时走「结果待确认」 |
| 释放 | 手动「结束使用」；使用人结账、撤销来访（误开的牌）时自动结束（结账预览提示）；开错了「撤单」（写原因；与作废明细同一条更正时限：店员只能撤自己开的、时限内的，超出由店主处理；挂过的场次费另到前台作废）。只追加，记经办人；有开着的使用单的空间不能停用、改业态 |
| 计费 | 不另建账本，费用是手牌账单上的普通明细（价目表项目）。开单时不挂费、不强制挂费（待确认） |
| 房态 | 有开着的使用单 →「使用中」（新的房态颜色，图例加一项）；没有 → 空闲。房间侧栏显示使用单：使用人手牌号、开单时间、已用时长、人数，可结束、撤单、给使用人挂账 |
| 实时位置 | 开单：使用人到那间房；结束、撤单：离开那间房（只在现在就在那间房时），与开房、退房同一套 |
| 自检 | `check` 加一项：开着的使用单的使用人都在店、账单没结；结过账、撤销了来访的客人没有开着的使用单 |
| 对账包 | 加一份当天的使用单清单（房间、使用人手牌、开单与结束时刻、时长、经办人、撤单原因） |
| 权限 | 开单、结束、撤单沿用「客房操作」（前台、收银、值班经理默认有），后台配置业态清单要「设置」 |
| 锁顺序 | 开单：来访（共享锁，挡住同时结账、撤销）→ 空间一行（`FOR NO KEY UPDATE`，与空间台账停用、改业态串行，不挡外键检查）→ 当前位置；结束、撤单：使用单一行 → 当前位置；结账、撤销来访：在各自已有的锁之后，锁这几位客人开着的使用单（id 升序），再清位置。与派钟（来访 → … → 空间共享锁）同为「来访在空间之前」。写进 AGENTS.md |

演示数据：场景块在 `X201` 派对房加一张开着的使用单（新的演示客人「演示客人丁」），平面图上 `X201`「使用中」；`showcase-expected.json` 跟着改。

## 2. 对客导览（第四段）

需求：区域级、中英双语、可大屏显示，视觉与现有 Illustrator 导览图（「平面地图 L1-L3.pdf」：区域色块、中英双语、动区静区配色、卫生间与电梯图标）同风格。对客只到区域级：**不显示房号、房态、人员**。

| 项 | 做法 |
| --- | --- |
| 页面 | 门店主导航「导览」（`/guide`）：按楼层画在用底图（去掉图上的文字、淡显），同一区域的空间轮廓（含补画的）填同一种颜色（区域色块），区域的中文名、英文名写在区域轮廓按面积加权的中心，设施画图标，图下是图例；楼层切换。底图按批次号取（`/api/guide/floors/<层>/svg?b=<批次>`）：只给在用的那一批、可以缓存；页面还停在换底图之前时那个地址不给、也不让浏览器缓存，页面每分钟刷新后按新的批次号取（Codex 复审 `c0a1a7d`：原来不看批次号，换回旧底图后会把新一批的图当成旧一批的显示）。**大屏模式**（`/guide/screen`）：铺满一屏、没有导航与操作，按设定的秒数自动轮播楼层（底部有进度条），可点楼层按钮或 ← → 手动换层，Esc 退出，右上角可进浏览器全屏；每分钟取一次数据 |
| 配色 | 区域按「导览分类」上色：动区（娱乐、餐饮、水区）暖色、静区（休息、客房、SPA、按摩）冷色、公共（接待、大堂、走道）浅中性色；「后场」（员工区、技师休息区、布草间）**不显示**。分类在后台给每个区域选，也可以给单个区域指定颜色；没选的按公共 |
| 文字 | 区域名用空间台账的中文名、英文名（v0.7.14 已有），没有英文名的只写中文；不写房号 |
| 图标 | 卫生间、电梯、楼梯、前台 / 接待、出入口、更衣室、餐厅、吸烟区（待确认）。默认从在用底图里不带编码的文字按关键字认（卫生间 / 洗手间 / WC、电梯、楼梯、前台 / 接待、出入口、更衣）；后台可以挪位置、隐藏、补加、改中英文文字，按楼层保存（存图纸坐标，换了底图也能对上位置），可以随时按新底图重新识别（只替换自动识别的，手工加的不动）。改过文字的图标（与这种图标默认的中英文不同，如「VIP 电梯」）在导览图上图标下写出中英文，图例里单独一项；默认文字的图标图上只画图标，图例写默认的中英文（Codex 复审 `0cf0505`：原来改的文字对客页面上看不到） |
| 谁能看 | 新权限「看对客导览」，默认所有岗位都有（后台「岗位权限」可以去掉）；只有这一项能进的账号登录后直接进大屏模式。导览不算门店的工作页面：只用 ERP 的后勤（物资、采购、对账）照旧没有 ERP 顶栏的「返回门店」（v0.7.3 验收 E2），要看导览直接打开 `/guide`。页面上没有房号、房态、人员与任何经营数据（接口与底图都不带） |
| 后台 | 「空间台账 → 对客导览」：每个区域的导览分类与颜色（与台账的其他修改同一把锁、带版本号）；图标（按在用底图识别、点图补加（带操作编号：没收到结果再补加不会多出一个）、挪位置、隐藏、改中英文标签）；大屏轮播秒数（店主，默认 15 秒，5–300）；打开导览页与大屏模式预览 |
| 尺寸 | 门店大屏（1920×1080）、门店电脑、平板、手机都能看，不出现横向滚动 |

## 3. PDF 底图（第四段）

验收标准是「给一份新 DWG 或 PDF，30 分钟内产出新底图与差异报告」。DWG / DXF 已在 v0.7.15 完成，这一版加 PDF。

| 项 | 做法 |
| --- | --- |
| 收什么 | AutoCAD 等打印出的**矢量 PDF**（有真实的线与文字层，例如出图 PDF）；上传入口、大小上限、批次、预览、比对、启用全部与 DWG 同一套 |
| 怎么读 | 在转换进程里用 `pdfjs-dist`（固定 6.4.299，只在转换进程里加载）读每页的矢量路径（直线、折线、矩形；曲线切成短线；变换与表单矩阵、页面旋转都算上；只做裁剪的路径不算）与文字（内容、位置、字号、方向），转成与 DWG 相同的中性图元，之后走同一条分楼层、围合房间、出底图、比对的链路；每页一块，页与页横向隔开 50 米 |
| 图层 | PDF 带可选内容组（图层）名的，按名字走 v0.7.15 的图层白名单（文字按字形对上所在的图层）；没有图层的，所有线当结构线（`PDF-墙`）、所有文字当区域文字（`PDF-区域文字`），报告里提示「PDF 没有图层，家具、标注线也参与围合，例外可能偏多」 |
| 比例 | PDF 的长度是纸上的点（1/72 英寸），要乘图纸比例才是实际尺寸。上传时填了比例就按填的（「按页面大小打印」的 PDF 上写的比例不准，要能改正，待确认）；没填按页面上的比例文字（「1:100」「比例 1:150」「SCALE 1:200」，出现最多的那个）；都没有时转换失败并写明「请在上传时填写比例」。填的与页面上写的不同时，转换报告提示核对。同一份 PDF 改了比例重传会重新转换成新的一批（去重按文件、转换程序版本与上传时填的比例；比例相同或都没填的回到原来那一批，Codex 复审 `0cf0505`） |
| 转不出的 | 扫描件（整页是图片）、文字已转曲的 Illustrator 导览 PDF（没有房号文字）：转换失败，报告写明原因（没有可用的线 / 没有房号文字） |
| 楼层 | 每页按页面里的楼层标题认（与 DWG 同一规则），认不出的按页里房号的楼层位多数 |

## 4. 图纸治理（第四段）

| 项 | 做法 |
| --- | --- |
| 入库登记 | 上传时登记**图纸来源**（设计方 / 门店 / 其他）、**版本或说明**、**收图日期**；与文件名、大小、摘要、上传人一起记在批次上 |
| 原图纸 | 上传时可勾「保存原图纸」：勾上的把原文件存进库（与批次分表、只追加，与上传上限相同），店主、店总能下载（记审计）；默认不勾，只记摘要（沿用 v0.7.15 的默认，待确认） |
| 底图档案 | 所有批次按时间列出：来源、版本、收图日期、上传人、状态（转换中 / 待启用 / 在用 / 已换下 / 失败）、启用与换下的人、时间和原因。**已换下的批次照样能打开**：每层底图、房间轮廓、例外清单、与现在的台账比对、**启用（或换回）时记下的台账比对**、批次比对、转换报告（只读，不能补画） |
| 在用历史 | 一条时间线：哪天起用的哪一批、谁启用、因为什么换下 |
| 换回旧底图 | 已换下的批次可以「换回这一批」（写原因，至少 2 个字），原来在用的换下（换下原因记同一句）；与启用同一套确认与 `FLOORPLAN_STALE` 防护：页面看到的在用批次与在用历史版本（在用历史最新一行的编号，每启用、换下、换回一次都变，只增不减）有一个对不上就拒绝，迟到的重发不再换。只比在用批次不够：能换回以后在用批次会 A → B → A 回到原样，迟到的「换回 B」会把后来换回的 A 又换下（Codex 复审 `0cf0505`）。启用新的一批时也可以写原来那批为什么换下（选填）。原来规则是已换下的不能再启用、只能重传 |
| 不删 | 批次与原图纸都不能删（只追加）；空间台账不跟着底图改（D6） |

## 5. 例外房间补画轮廓（前几段的尾巴）

启用后的例外编码（连到走廊或图外、几个编码连成一片、文字附近找不到空地）在房态图上只显示位置点，前台点不到房间范围。

- 后台在这一批（待启用或在用）的底图上给例外编码**按墙角顺序点出多边形**补画轮廓（3–64 个点；超出图框、边交叉、不到 0.5 ㎡ 的拒绝），存在这一批上（转换结果本身不改，补画的另存一张表，记经办人与时间；可以重画、作废，旧的作废留历史；页面看到的这个编码的补画与这一批的补画版本（补画、作废都让它变大，只增不减）有一个对不上就拒绝——补画再作废后又回到「没有补画」，迟到的第一次补画不会把作废掉的轮廓画回来，Codex 复审 `c0a1a7d`）。编码重复的不能补画（要设计方核对）；已换下的批次只读。
- 房态图、对客导览、spaces.geojson、房间面积用补画的轮廓；预览里补画的画虚线、写「手工补画」与经办人；平面图按补画的版本重新取底图。
- 换了新的一批不沿用（新图纸照常转换；仍是例外的再补画）。
