## 1. 开单即占用（D37 / D39）

店主 11-02 定（D37）：派对房、宠物轰趴房、娱乐室按「有开单即占用」算，结算或退单后释放。钟单是技师服务的单据，这三类房间不派技师，所以另做一张**使用单**。

| 项 | 做法 |
| --- | --- |
| 哪些房间 | 空间台账里业态是「派对房」「宠物轰趴房」「娱乐室」的在用空间（规则里的「开单即占用业态」，默认这三种，后台可改，待确认） |
| 开单 | 平面图点房间（或房态看板）→「开单」：选**在店客人的手牌**（使用人，账算在他的手牌账单上）、人数、备注；可以同时挂一笔场次费（选价目项目，挂到这位客人的手牌账单，与前台挂账同一个口径）。开单即「使用中」。同一间房同时只能有一张开着的使用单（数据库唯一索引兜底）。写操作带操作编号，断网时走「结果待确认」 |
| 释放 | 手动「结束使用」；使用人结账时自动结束；开错了「撤单」（写原因，挂过的场次费另到前台作废，规则同其他明细）。只追加，记经办人 |
| 计费 | 不另建账本，费用是手牌账单上的普通明细（价目表项目）。默认开单时不强制挂费（待确认） |
| 房态 | 有开着的使用单 →「使用中」（新的房态颜色，图例加一项）；没有 → 空闲。房间侧栏显示使用单：使用人手牌号、开单时间、已用时长、人数，可结束、撤单、给使用人挂账 |
| 实时位置 | 开单：使用人到那间房；结束、撤单：离开那间房（只在现在就在那间房时），与开房、退房同一套 |
| 自检 | `check` 加一项：开着的使用单的使用人都在店、账单没结；结过账、撤销了来访的客人没有开着的使用单 |
| 对账包 | 加一份当天的使用单清单（房间、使用人手牌、开单与结束时刻、时长、经办人、撤单原因） |
| 权限 | 开单、结束、撤单沿用「客房操作」（前台、收银、值班经理默认有），后台配置业态清单要「设置」 |
| 锁顺序 | 开单：空间一行 → 来访（共享锁）→（挂场次费时接着按挂账的顺序：账单 → 明细）；结束、撤单：使用单一行；结账：在结账已有的锁之后，锁这位客人开着的使用单（id 升序）。写进 AGENTS.md |

演示数据：场景块在 `X201` 派对房加一张开着的使用单（新的演示客人「演示客人丁」），平面图上 `X201`「使用中」；`showcase-expected.json` 跟着改。

## 2. 对客导览（第四段）

需求：区域级、中英双语、可大屏显示，视觉与现有 Illustrator 导览图（「平面地图 L1-L3.pdf」：区域色块、中英双语、动区静区配色、卫生间与电梯图标）同风格。对客只到区域级：**不显示房号、房态、人员**。

| 项 | 做法 |
| --- | --- |
| 页面 | 新页面「对客导览」：按楼层画在用底图，同一区域的房间轮廓填同一种颜色（区域色块），区域的中文名、英文名写在区域范围的中间，设施画图标；楼层切换。**大屏模式**：全屏、隐藏导航与操作，按设定的秒数自动轮播楼层，适合门店大屏常开 |
| 配色 | 区域按「导览分类」上色：动区（娱乐、餐饮、水区）暖色、静区（休息、客房、SPA、按摩）冷色、公共（接待、大堂、走道）浅中性色；「后场」（员工区、技师休息区、布草间）**不显示**。分类在后台给每个区域选，也可以给单个区域指定颜色；没选的按公共 |
| 文字 | 区域名用空间台账的中文名、英文名（v0.7.14 已有），没有英文名的只写中文；不写房号 |
| 图标 | 卫生间、电梯、楼梯、前台 / 接待、出入口、更衣室、餐厅、吸烟区（待确认）。默认从在用底图里不带编码的文字按关键字认（卫生间 / 洗手间 / WC、电梯、楼梯、前台 / 接待、出入口、更衣）；后台可以挪位置、隐藏、补加，按楼层保存（存图纸坐标，换了底图也能对上位置），可以随时按新底图重新识别（只替换自动识别的，手工加的不动） |
| 谁能看 | 新权限「看对客导览」，默认所有岗位都有；门店大屏建一个只有这项权限的账号登录（后台「岗位权限」可配）。页面上没有任何经营数据 |
| 后台 | 「空间台账 → 区域」加导览分类与颜色；「空间台账 → 对客导览」：图标列表与标注、大屏轮播秒数（默认 15 秒）、预览 |
| 尺寸 | 门店大屏（1920×1080）、门店电脑、平板、手机都能看，不出现横向滚动 |

## 3. PDF 底图（第四段）

验收标准是「给一份新 DWG 或 PDF，30 分钟内产出新底图与差异报告」。DWG / DXF 已在 v0.7.15 完成，这一版加 PDF。

| 项 | 做法 |
| --- | --- |
| 收什么 | AutoCAD 等打印出的**矢量 PDF**（有真实的线与文字层，例如出图 PDF）；上传入口、大小上限、批次、预览、比对、启用全部与 DWG 同一套 |
| 怎么读 | 在转换进程里用 `pdfjs-dist`（固定版本，与 LibreDWG 一样锁死）读每页的矢量路径（直线、折线、矩形；曲线折成折线）与文字（内容、位置、字号、方向），转成与 DWG 相同的中性图元，之后走同一条分楼层、围合房间、出底图、比对的链路 |
| 图层 | PDF 带可选内容组（图层）名的，按名字走 v0.7.15 的图层白名单；没有图层的，所有线当结构线、所有文字当区域文字，报告里提示「PDF 没有图层，家具、标注线也参与围合，例外可能偏多」 |
| 比例 | PDF 的长度是纸上的点（1/72 英寸），要乘图纸比例才是实际尺寸：先认页面上的比例文字（「1:100」「比例 1:150」），认不出时上传时填，都没有时拒绝并写明原因 |
| 转不出的 | 扫描件（整页是图片）、文字已转曲的 Illustrator 导览 PDF（没有房号文字）：转换失败，报告写明原因（没有可用的线 / 没有房号文字） |
| 楼层 | 每页按页面里的楼层标题认（与 DWG 同一规则），认不出的按页里房号的楼层位多数 |

## 4. 图纸治理（第四段）

| 项 | 做法 |
| --- | --- |
| 入库登记 | 上传时登记**图纸来源**（设计方 / 门店 / 其他）、**版本或说明**、**收图日期**；与文件名、大小、摘要、上传人一起记在批次上 |
| 原图纸 | 上传时可勾「保存原图纸」：勾上的把原文件存进库（与上传上限相同），店主、店总能下载；默认不勾，只记摘要（沿用 v0.7.15 的默认，待确认） |
| 底图档案 | 所有批次按时间列出：来源、版本、收图日期、上传人、状态（转换中 / 待启用 / 在用 / 已换下 / 失败）、启用与换下的人和时间。**已换下的批次照样能打开**：每层底图、房间轮廓、例外清单、当时的台账比对与批次比对、转换报告（只读） |
| 在用历史 | 一条时间线：哪天起用的哪一批、谁启用、因为什么换下 |
| 换回旧底图 | 已换下的批次可以「换回这一批」（写原因），原来在用的换下；与启用同一套确认与 `FLOORPLAN_STALE` 防护。原来规则是已换下的不能再启用、只能重传 |
| 不删 | 批次与原图纸都不能删（只追加）；空间台账不跟着底图改（D6） |

## 5. 例外房间补画轮廓（前几段的尾巴）

启用后的例外编码（连到走廊或图外、几个编码连成一片、文字附近找不到空地）在房态图上只显示位置点，前台点不到房间范围。

- 后台在这一批的底图上给例外编码**点选多边形**补画轮廓（也可以拉矩形），存在这一批上（转换结果本身不改，补画的另存一张表，记经办人与时间；可以重画，留历史）。
- 房态图、对客导览、房间面积用补画的轮廓；预览与批次比对里标「手工补画」。
- 换了新的一批不沿用（新图纸照常转换；仍是例外的再补画）。

## 6. 迁移 `036`（只加表、加列）

- `space_usages`：使用单（编号、空间、使用人的来访与账单、人数、备注、状态、营业日、开单 / 结束 / 撤单的人和时刻、撤单原因、操作编号）；同一空间只有一张开着的（部分唯一索引）。
- `zones` 加导览分类、导览颜色；`guide_markers`：导览图标（楼层、种类、图纸坐标、中英文标签、来源（自动 / 手工）、隐藏、版本号）。
- `floorplan_batches` 加图纸来源、版本说明、收图日期、PDF 比例、换下原因；`floorplan_originals`：保存的原图纸（批次、文件内容），与批次分表；`floorplan_room_outlines`：补画的轮廓（批次、编码、多边形、经办人、时刻、作废）。
- 设置：开单即占用业态清单、导览大屏轮播秒数。
- 升级后没有使用单、没有图标、区域都按公共、批次的登记信息为空，原有功能不变。
