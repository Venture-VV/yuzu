# 会员体系 v2（福田 / 宝安统一等级与资金；设计稿）

店主 2026-11-03 发来《福田店与宝安店会员体系——用户侧规则与权益全景总览》（整理日期 2026-11-02，下称「会员文档」），要求「理解这份文档，设计下怎么开发」。本稿把会员文档落到系统上：哪些由系统算、哪些是门店服务只在系统里显示，数据怎么存，分几版做，哪些规则要店主先定。规则未定的先按「建议默认」做并标「待确认」，汇总在 `PENDING_DECISIONS.md`「会员体系 v2」；店主的决定先写进那里与 `ROADMAP.md` 再开发。

会员文档里的规则分三种：**统一制度**（已确认，照做）、**配置方案**（已保存、待发布的权益清单，系统做成后台可配、默认不对客开放）、**待明确**（系统不替店主补规则，按下面的建议默认做并可改）。

## 0. 与现在的系统有什么不同

| 事项 | 现在（v0.7.21） | 会员体系 v2 |
| --- | --- | --- |
| 等级 | 1–9 级，按累计充值（含旧系统累计）实时算出来，不存、不降级；改门槛会把所有人重新定级 | L0–L6 七档，L1–L6 各分初、享、尊三阶，共 19 个状态；**存下来**，按事件变化（充值升档、消费升阶、到期保级或降级），每次变化记一条只追加的记录；改规则只影响以后 |
| 赠金 | 充值套餐写死的赠送额，或有权限的人手填 | 按充值后所在档的比例（L2 5%、L3 8%、L4 10%、L5 15%、L6 18%）；手填仍要权限 |
| 单笔最低充值 | 没有 | 5,000 元（店主可授权例外，待确认） |
| 会籍周期 | 没有 | 自最近一次升档起 365 天；到期按周期内消费完成度保级、给 90 天补充期或降一档 |
| 扣款顺序 | 设置项，默认先本金后赠金 | 统一先本金后赠金（沿用默认，后台不再让改） |
| 权益 | 开卡礼、升级礼、生日礼、充值赠券（券） | 门店权益清单（福田 49 项、宝安 99 项，按档阶起点、次数、门店）：券类按月发，服务类显示资格并登记使用，折扣类在结账时按规则算；首充礼、升级礼、保级礼、节日关怀、会员挑战按事件发 |
| 邀请、赠送会籍 | 没有 | 每月一次邀请低一档体验；高档会员赠送低一档记名会籍 1 个月 |
| 老卡迁移 | 期初导入带「累计充值」，只用来算等级 | 按可核的累计充值定档（进初阶），余额全额转入，周期从迁移开卡日起；L6 不能迁移直通 |
| 两店 | 一套系统一家店，没有门店维度 | 两店统一等级与资金，权益按到店门店的清单兑现（见第 7 节，要店主定怎么接） |

不做（会员文档也没定，或不是系统的事）：积分；亲友卡；池里商业 14 家品牌用储值消费（另一套收银，接口要对方配合）；PAJAMA、新生乐园如果不用本系统收银，它们的权益只在会员详情里显示资格、由那边核销；短信、公众号推送（没有对客渠道，到期提醒先做成名单给客户经理）。

## 1. 档级、阶位与周期（统一制度）

| 档级 | 名称 | 充值门槛 | 赠送比例 | 享阶（周期消费 ≥ 门槛 30%） | 尊阶（≥ 60%） |
| --- | --- | --- | --- | --- | --- |
| L0 | 青溪 | 免费注册 | — | — | — |
| L1 | 云涧 | 5,000 | 0 | 1,500 | 3,000 |
| L2 | 潭影 | 10,000 | 5% | 3,000 | 6,000 |
| L3 | 观澜 | 30,000 | 8% | 9,000 | 18,000 |
| L4 | 望岳 | 50,000 | 10% | 15,000 | 30,000 |
| L5 | 山海 | 100,000 | 15% | 30,000 | 60,000 |
| L6 | 归墟 | 300,000 | 18% | 90,000 | 180,000 |

名称、门槛、比例、30% / 60%、365 天、90 天都放在后台「会员规则」里，可改；改了只影响以后的充值与到期判断，已记下的状态不重算。金额一律整数分。

**升档（充值）**：单笔充值，或「年度累计充值」（含本笔）达到更高档的门槛时，升入那一档的**初阶**，会籍周期从这一天重新算 365 天。年度累计的口径待确认，建议**滚动 365 天**（不因升档清零，避免 3 万 + 2 万分两次充的人到不了 5 万档）。一笔充值可以连跳几档，直接进最高达到的那档。升档在充值的同一事务里完成（会员一行已经锁住），记一条状态变化。

**赠金**：本笔实收 × 充值**后**所在档的比例，算到分、分以下舍去；不补发以前几次的差额（会员文档写「是否补齐待明确」，建议不补）。赠金进现有的赠金批次（有效期沿用「赠金有效天数」设置，默认长期，待确认）。充值套餐保留为常用金额的快捷按钮，赠金不再写死在套餐里。

**升阶（消费）**：周期内的「净储值消费」达到本档门槛的 30% 升享阶、60% 升尊阶。净储值消费 = 本金与赠金的消费（两店都算）− 反结账冲回 − 退款单退回储值的部分；现金、微信等非储值付款不计（会员文档写「计入两店的本金与赠送金消费」）。升阶在消费的同一事务里完成；之后反结账使消费回落，阶位不降，但到期判断按回落后的数（待确认）。

**到期（保级、补充期、降级）**：每天营业日开始时扫一遍到期的会员（同生日礼、赠金过期的定时任务）：

| 周期内净储值消费 | 处理 |
| --- | --- |
| ≥ 本档门槛 60% | 保级：档级不变、阶位回初阶（待确认），新周期从原到期日起算 365 天；发保级礼 |
| 30%–60% | 进入 90 天补充期（档级、阶位不变）；补充期内累计（从原周期开始算）达到 60% 当即保级，新周期仍从原到期日起算；补充期满仍不足按下一行处理（待确认） |
| < 30% | 降一档，进下一档的尊阶，新周期从到期日起算；L1 降到 L0（不分阶，待确认） |

降档不收回已发的赠金与券。到期前 90、60、30、7 天进「会籍到期提醒」名单（会员、档阶、到期日、完成度、差多少），客户经理据此联系；没有短信渠道之前不自动发消息。

**L0**：注册即是，不分阶、没有周期，不会降级。

## 2. 门店权益清单（配置方案）

会员文档附录里的每一项权益在后台「会员权益」里是一行：编号（QY-001、CUS-…）、名称、门店（福田 / 宝安 / 两店）、类别、起点档阶（如 L3·初）、内容与使用条件、状态（草稿 / 已发布 / 暂缓）。**导入后全部是草稿**（会员文档写明「全部按待发布配置理解，不表示已向会员开放」），店主或店总逐项发布。高档阶自动包含低档阶已发布的权益；同名权益在不同档阶的次数不同时，按会员当前档阶取最高的那一行，不相加（会员文档：「不代表所有同类券自动累加」）。

按怎么兑现分四类：

| 类别 | 例子 | 系统怎么做 |
| --- | --- | --- |
| 券类 | 每月 2 次 8 小时浴资、每月 1 次按摩足浴项目券、娱乐畅玩券每月 2 次、KTV 包房 4 小时每月 3 次 | 每项挂一个券模板（现有的代金券 / 折扣券 / 兑换券）和次数、周期。**按自然月发**（待确认）：每月营业日第一天给符合档阶的会员发本月的券，有效到月底；月中升档、升阶的当场补发差额。去重键「会员 + 权益 + 月份」，不会重复发。结账用券沿用现有流程 |
| 折扣类 | 包房房费折扣（宝安 3 万 7.5 折 … 30 万 5 折）、同行消费 88 折每月 2 次、会员日 88 折 | 结账时按规则自动算折扣、单独成行记账，与现有「优惠 / 免单」、券怎么叠加要店主定（第 6 节）。在定之前不开放 |
| 服务与资格类 | 会员通道、高峰优先、VIP 更衣柜、专属浴服、管家、停车、贵宾厅、衣物护理 | 会员详情按到店门店列出「可享」；有次数的（贵宾厅每月 1 次、衣物护理每月 1 次）由服务的同事点「登记使用」，系统数次数、到上限提示。VIP 更衣柜沿用现在的手牌等级限制（改成按新档级） |
| 事件礼 | 首充礼、升级礼、保级礼、生日礼、节日关怀、会员挑战（月内到店 4 次得 24 小时浴资） | 现有发券规则加事件：首充、升档（每次升档都发，不再是「每人每条规则只发一次」）、升阶、保级、节日（后台列节日日期）、到店次数。赠送会籍得到的身份不发升级礼 |

PAJAMA、新生乐园、池里商业的权益先导入为「服务与资格类」，只显示、登记使用；那几个业态要在本系统收银时再改成券类或折扣类。

## 3. 邀请体验与赠送会籍

两种都是给对方一个**临时身份**（档级、起止日期、来源会员），到期自动回到原来的身份；临时身份只享权益、不发升级礼、不进保级判断。

| 方式 | 做法（建议默认，待确认） |
| --- | --- |
| 低一档邀请体验 | 在档会员（L2 起）每月 1 次，邀请一位非会员或低档会员体验「本人档级减一」的初阶，期限 7 天（会员文档没写期限）；受邀人每人 12 个月内只能被邀请一次 |
| 赠送记名会籍 | 起点按权益清单（福田保存方案为 L3·尊起每月 1 次）；受赠人得到「赠送人档级减一」的初阶，期限 1 个月；期内充值达到这一档门槛即转正（按第 1 节升档，周期从充值日起算），未达到到期失效 |

赠送的是体验资格，不能赠送本金或赠金。

## 4. 老卡迁移与已有会员上线

**老卡迁移**（会员文档第六节）：沿用现在的期初导入（`import-opening`），加「迁移定档」：按导入的「累计充值」（须系统可核）对应档级——5,000 → L1 初、10,000 → L2 初、30,000 → L3 初、50,000 → L4 初、100,000 → L5 初；30 万档不能迁移直通（要新充值达到 L6 门槛）。本金、赠金全额转入（现在已经是），会籍周期从迁移开卡日起算。不发首充礼、升级礼。核不了累计充值的按 L0 进来，由店主手动定档（要写原因，见第 8 节）。旧权益券的迁移：有清单再按券导入，默认不迁。

**已有会员上线**（测试服演练库、以后的正式库）：v2 上线那天按每位会员现有的累计充值（含旧系统累计）用同一张对应表定档、进初阶，周期从上线日起算；没有充值的进 L0。上线前现在的「等级门槛」设置停用。

## 5. 福田老会员召回活动

一次性活动（截止 2026-12-14 营业结束，不含 12 月 15 日）：按核实余额分两组（3 万至不足 5 万、5 万及以上）发不同的券包，同行消费 88 折，SPA 或按摩 5 折券与 88 折不叠加。系统能用现有的券直接做：建好券模板（有效期到 12-14），按名单批量发（现在只有逐个发，要加「按名单批量发给会员」）。**这只在福田用本系统收银时才有意义**；福田在 12-14 之前不上系统的话，活动照福田现在的方式做，系统不做。

## 6. 要店主先定的事（汇总在 `PENDING_DECISIONS.md`「会员体系 v2」）

第一期（等级与会籍）开工前要定：

| 编号 | 事项 | 建议默认 |
| --- | --- | --- |
| M1 | 系统先给哪家店用；两店通卡什么时候、用一套系统还是两套 | 先按一家店（汤崎价目表的宝安店）做，数据里预留门店；通卡另立项（第 7 节） |
| M2 | 年度累计充值的起止 | 滚动 365 天，含本笔，不因升档清零 |
| M3 | 分次升档是否补赠；续充按哪档比例 | 不补以前的差额；按充值后所在档的比例 |
| M4 | 单笔最低 5,000 元是否对每笔充值（含续充）都适用 | 是；店主、店总可授权例外（同现在的超额充值授权） |
| M5 | 赠金有效期 | 沿用「赠金有效天数」设置，默认长期 |
| M6 | L6 是否邀约准入 | 先只按门槛，不另设邀约 |
| M7 | 保级后阶位；补充期满未达标；L1 到期不足 | 保级回初阶；补充期满按不足 30% 降一档；L1 降到 L0 |
| M8 | 计入升阶、保级的消费 | 净储值消费（扣反结账、退款单退回的储值）；非储值付款不计；反结账不降已得的阶位 |
| M9 | 已有会员上线怎么定档 | 按累计充值（含旧系统）对应档级进初阶，周期从上线日起；L6 要新充值 |
| M10 | 到期提醒渠道 | 系统里的提醒名单，客户经理联系 |

后几期开工前要定：券类权益按自然月还是入档月发、未用的能否结转（建议自然月、不结转）；折扣类权益与「优惠 / 免单」、券、彼此之间能否叠加（建议同一张结账单只取一种会员折扣、不与券同用，会员日与同行二选一）；包房低消与房费折扣怎么组合；邀请体验的期限与人数；节日清单；会员日（福田每周三、宝安每月 8 日）适用的范围与例外。

## 7. 两店（通卡）

会员文档的统一制度是两店统一等级与资金，但「实际通卡及迁移的启用时间尚未有完整凭据」。现在每套系统是一家店、一个数据库（钱包在业务的同一事务里记账，这是账不出错的基础）。两种接法：

| 接法 | 做法 | 代价 |
| --- | --- | --- |
| A. 一套系统管两家店（建议） | 一个数据库，所有单据加「门店」（班次、结账、手牌、客房、库存……），各店的电脑都连这一套；会员、钱包天然共用 | 改动遍及所有模块，要一版专门做；两店之间的网络必须稳定（断网时那家店不能结账，要有预案） |
| B. 两套系统，会员钱包放在中心 | 各店照旧，各自结账时远程调用中心的钱包 | 结账与扣储值不在一个事务里，断网、超时会出现「扣了钱没结账」或反过来，要补一整套对账与冲正；不建议 |

建议先按一家店把会员体系 v2 做完、用起来；通卡等店主定启用时间后按 A 单独立项。v2 的数据从一开始带「门店」字段（权益的门店、消费发生在哪家店），通卡时不用再改会员这部分。

## 9. 数据（草案）

- **会员状态**（`members` 上加列，会员一行已经是钱包的锁）：档级 0–6、阶位 0–2（初 / 享 / 尊，L0 为空）、周期开始、周期到期、补充期到、临时身份（档级、到期、来源会员、种类），加版本号。
- **状态变化记录**（只追加）：会员、时间、从哪档阶到哪档阶、种类（注册 / 迁移定档 / 充值升档 / 消费升阶 / 保级 / 进入补充期 / 降档 / 临时身份开始 / 结束 / 手动调整）、相关的充值或消费、当时的周期消费、经办人、原因。会员详情的「等级历史」改读这张表，不再用充值记录倒推。
- **会员规则**：设置里的一行（同现在的前台规则），改动留历史。
- **权益清单**：权益一行（编号、门店、类别、起点档阶、次数与周期、挂的券模板、条款、状态、版本号）；发放与使用记录（会员、权益、月份或日期、去重键）。
- **自检**加：每位会员当前状态 = 最后一条状态变化的结果；L1 以上都有周期；阶位不低于周期消费对应的阶位；没有过了到期日还没处理的会员（允许定时任务一天的延迟）；权益发放没有超过次数。
- 现在限定 1–9 级的地方（手牌的 VIP 等级、券模板与发券规则的等级）改成 0–6 档级。
