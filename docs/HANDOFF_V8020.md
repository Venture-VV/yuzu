## 4. 验收要点

1. **开关**：新建的库里登录，主导航有钟房、餐饮、客房；ERP 侧栏有员工食堂、安保巡场对应的后台入口与「布草洗涤」。从 8.0.19 的库升级：原来关着的这些都变成开；售次卡、点单密码、员工自己登记没变。关掉任意一个，刷新后入口消失、不会被默认顶回来。
2. **成本**：给一样物料按采购单收两次货（两个价），「库存 → 成本」里平均成本 = 加权平均；耗用以后平均成本不变、耗用成本 = 数量 × 平均成本；作废一张收货单，平均成本按原金额冲回。没有「看成本」权限的人看不到「成本」页签，用料列表里也没有成本。
3. **零售扣库存**：给一个不进厨房的项目设用料（1 瓶水）→ 前台挂账、结账 → 一分钟内（或点「现在扣一次」）库存少、单据里多一张说明是「销售出库（自动扣料第 N 批）」的耗用单，经办人「自动扣料」。反结账 →「待扣料」里出现一条冲回（负数）→ 重新结账后轧平，不再出库。库存不够时照样能结账，「待扣料」标「库存不够」，入库后自动扣。
4. **配方扣料**：给一道进厨房的菜设配方（含损耗）→ 点单 → 出品屏点「出餐」→ 扣料；「撤回」冲回；已出品再退菜不退料；结账时这道菜不再按销售扣一遍。
5. **自动补货**：把时间改到一分钟后，等它跑（或点「现在跑一次」）：有供应商的建议按供应商各一张草稿，备注「自动补货 日期」，经办人「自动扣料」；再跑不重复建。关掉以后不跑。一样只卖过一天、挂了用料的零售品卖断货以后（待扣料里有它）：补货建议照常提它，行上写「欠着没扣 N」，建议量把欠的算进去；物料定成「按需采购」以后不提、自动补货也不给它建草稿。
6. **布草**：加品类 → 新增 100 → 送洗 60 → 收回 50 / 破损 3 / 丢失 2：总数 95、在洗 5、在店 90，洗涤费 =（50 + 3）× 单价；作废收回单数量冲回；送洗过的新增单不能直接作废。对账表导出是 CSV。
7. **客房点餐**：住客在住时，点单页输房号能找到他，默认勾着「送到客房」；出品屏那道菜写着「客房 W301」。没住店的客人没有这个勾。
8. **会员房价**：房型设 L3 起 ¥260（门市 ¥300）。散客、L1 会员入住是 ¥300；L3 会员的入住弹窗提示会员价 ¥260，入住单与房费都是 ¥260。发布了客房折扣权益（如 L3 7.5 折）以后：新来的 L3 会员提示「结账时能打 7.5 折，比会员价更低，按门市价入住」；之前按会员价入住的那位结账时没有客房折扣可选。
9. 账目自检（`node dist/server/cli.js check`）全部通过；`/api/frontdesk/checks`、库存自检没有新增失败项。

## 5. 做过的反向验证

- 成本：把「作废收货」改成不带原金额时，用例「作废收货按原金额冲回」失败（平均成本回不到原值）——所以作废带着原流水的金额。
- 扣料：`processStockUsage` 里把「用途」写成固定文字时全部批次开单失败（用途只能选门店维护的清单）——自动生成的耗用单用途留空，种类看说明与批次。
- 布草：迁移清单把 `138` 放错位置时 16 条迁移 / 升级用例失败——清单按号排序。
- 会员房价：没有 `discountableLines` 时，按会员价入住的房费结账仍能再打 QY-011（用例「不叠加」会失败）。
- 合并前 Codex 审查 `b850838` 的两条成本：把 `applyMove` 与成本报表的改动撤掉时，新加的两条用例（零元进货、台面日耗品领到部门）都失败；改回来通过。

## 6. 已知的限度

- **成本是 8.0.20 起才记的。** 之前的库存流水没有金额，报表里单列「没记成本」的条数；起算成本是估的（最近进价或参考价），标「估」。要准确的期初成本，上线前请按真实进价做一次盘点或核对物料的参考价。
- **项目毛利是理论值**：销售额 − 现在的配方 × 现在的平均成本。配方、成本变了，历史期间的毛利跟着变；真实耗用以耗用单为准。
- **退款单不动库存**（JX9）；东西真的退回来了，走盘点或报损的反向。
- **扣料是异步的**：结账、出品后最长约一分钟库存才变（或手动点「现在扣一次」）。冲回（反结账、撤回出品）如果一直没有后面的正数来抵，会一直留在「待扣料」里（负数），下次盘点按盘盈处理。
- **洗涤费不自动进应付**（JX11）：只有对账表，付款走付款申请或报销；与 8.0.21 的财务一起做。
- **会员房价按入住时定死**：住店期间会员升档、降档不改已经入住的房价；换房不改价（与原来一样）。
- **演示库没有预置数据**（见第 2 节）。
- 小程序线的开关没有跟着默认开（KG4）；要一起开请交给小程序开发会话，或明说让主线代改。
