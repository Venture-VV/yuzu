## 2. v0.7.16 房态图（定稿）

### 2.1 入口与权限

- 「客房」页顶部「房态看板 / 平面图」切换，视图记在地址里（`/rooms?view=map`），刷新、返回都还在平面图。门店主导航已经满了，1280×720 下不再加入口。
- 看得到「客房」的岗位都能看（客房入住 `room.operate`、客房打扫 `room.housekeep`、收银 `frontdesk.checkout`）：`GET /api/floormap` 与「客房」页同一组权限；在用的底图（`GET /api/floorplans/active` 与每层 SVG）v0.7.15 已经给这些岗位开了。
- 开房、退房等按钮照各自的权限显示，平面图只是另一个入口，不另开权限；钟房选房间、换房间是 `technician.dispatch`（派钟另要 `frontdesk.operate`，与原来一样）。

### 2.2 数据从哪来（一处口径）

| 内容 | 接口 | 刷新 |
| --- | --- | --- |
| 楼层、底图、房间轮廓与文字位置 | `GET /api/floorplans/active`（在用那一批） | 只取一次；`/api/floormap` 带回的在用批次变了（店主启用了新的一批）才重新取 |
| 空间台账（编码、楼层、区域、业态、容量、面积、显示名、可售、在用、别名、挂接的客房房间） | `GET /api/floormap` 的 `spaces` | 平面图打开时每 5 秒 |
| 技师房的钟（记了房间、客人在店、还没结束的钟单：技师、手牌、项目、钟数、上钟时间、计划下钟） | `GET /api/floormap` 的 `sessions` | 每 5 秒 |
| 客房的房态与在住客人 | `GET /api/rooms`（房态看板，同一个口径） | 平面图打开时每 5 秒（看板 15 秒） |

图上的编码按编码对上空间台账（停用的也对上，画成灰色）。每个空间的状态由共用的纯函数 `spaceStatus`（`src/shared/floormap.ts`）算出，图上的颜色、图例、侧栏都用它，服务端测试也测它。

### 2.3 状态与颜色

| 状态 | 颜色 | 什么时候 |
| --- | --- | --- |
| 空闲 | 浅绿 | 客房已打扫可入住；技师房没有钟单 |
| 在住 | 柚黄 | 客房有在住的入住单（停用、不可售也照看板显示） |
| 待上钟 | 浅橙 | 技师房派了钟、技师还没上钟 |
| 服务中 | 湖蓝 | 技师房有技师在钟上（优先于待上钟）；编码后写「钟单数 / 容量」，如「2/4」 |
| 待打扫 | 浅红 | 客房退房后还没打扫 |
| 维修 | 灰 | 客房在维修 |
| 未挂接 | 白底虚线 | 「客房」空间还没挂客房房间（在「后台 → 客房 → 房间」挂接） |
| 其他业态 | 浅紫 | 派对房、宠物轰趴房、娱乐室……目前没有业务单据，只显示业态 |
| 停用 / 不可售 | 浅灰 | 空间台账里停用或不可售、没人用；挂的客房房间停用 |
| 台账里没有 | 米色虚线 | 图上有这个编码、空间台账里没有（以台账为准，请在台账里补上） |

技师服务类业态：SPA、按摩、踩背、头疗、足浴、投影足浴（台账里新写的业态默认不算，待确认）。

### 2.4 画法与操作

- 楼层切换（默认编码最多的一层）；底图是那一层的 SVG（作为图片放进来，不执行图里的内容），空间是多边形，没配上轮廓的编码（例外）画位置点；编码写在文字位置，放大 2 倍以上再写显示名；字号随缩放按 1/√倍数变小。
- 筛选：业态多选（不在里面的变淡）、只看空闲、搜编码 / 显示名 / 别名（回车定位：换到那一层、放大到至少 3 倍、移到中间、闪几下并打开侧栏）。
- 缩放平移：滚轮（以鼠标为中心）、双指捏合、拖动（移动超过 6 像素不算点击），「缩小」「放大」「适应屏幕」，1–12 倍；拖动时直接改图层的变换，不重画房间。画布按楼层的长宽比定高度，最高一屏。
- 图例常显，写每种状态在这一层的个数；台账里有、图上没有的空间列在图下面（按编码点开）。
- 侧栏（宽屏在右边，窄屏在图下面、点了房间自动露出来）：
  - 客房：房间、房型、状态；在住时写手牌、入住与预离、房费与押金。按钮按状态与权限：空闲「开房」；在住「查房」「续住」「换房」「押金」「退房」；待打扫「打扫好了」、维修「维修好了」、空闲「改房态」。全部用「客房」页原来的对话框与接口（入住、入住单、退房核对、改房态），结果待确认的处理照旧。
  - 技师房：这间房里的钟（技师、手牌、项目 × 钟数、上钟时间、剩几分钟或超时几分钟），「去钟房」。
  - 其他：业态、楼层与区域、容量、面积、别名；停用、不可售的写明。
  - 台账里没有的编码：写图上的原文，提示到空间台账补上。

### 2.5 钟单记服务的房间（迁移 `034`）

- `technician_sessions.space_id`（可空，引用空间）；已有的钟单为空，提成、对账、报表都不看它。钟房日志的 `kind` 加 `room`（换房间）。
- 派钟对话框「房间（可不选）」：只列在用、可售的技师服务类空间，按楼层分组，写占用（空闲、服务中 n、待上钟 n、已满 n/容量）；选的房间算进操作编号的摘要（不选时与升级前完全一样）。服务端核对：空间存在、在用、是技师服务类、可售；房间满了不拦（待确认）。
- 钟单卡片（上钟中、待上钟）显示房间，点开「换房间」：换、补选（前台挂账建的钟单没有房间）、清掉；请求带上页面看到的房间，对不上（别人刚换过、超时后迟到的旧请求）拒绝 `SESSION_SPACE_STALE`，已经是这间照常返回；记钟房日志「房间 S301 → S302」「选房间 …」「清掉房间 …」。派钟日志写「房间 …」。
- 空间台账：房间里还有没结束的钟单（客人在店）时，这个空间不能停用、不能改成非技师服务的业态（`SPACE_HAS_SESSIONS`）；改成别的技师服务业态、改显示名照常。
- 加锁：派钟在技师队列之后、建钟单之前给房间加共享锁；换房间先锁钟单一行，再给房间加共享锁；空间台账停用、改业态锁空间一行（排他）后只查里面没结束的钟单、不锁钟单（AGENTS.md 锁顺序）。
- 自检：`check` 加一项「钟单记的房间是在用的技师服务类空间」（没结束的钟单）。

### 2.6 性能与验收

- 首屏：底图一层一张 SVG（v0.7.15 实测 84–208 KB）+ 一层的多边形；合成的单层 300 个空间（20×15 网格，客房 / SPA / 足浴 / 按摩 / 派对房五种业态混着，带钟单）从点「平面图」到 300 个空间都画出来，浏览器验收要求 2 秒内（门店电脑、平板横竖屏、1280×720、手机都跑）。
- 流畅：同一份数据下在页面里连续 30 帧、每帧一次滚轮缩放，要求平均每帧不超过 50 毫秒；拖动平移改的是图层变换，不重画房间。
- 真实流程（门店电脑）：样例空间台账（`docs/data`）与样例底图（v0.7.15 的合成图纸）启用、W301 挂客房房间 → 钟房派钟选房间 T301 → 平面图上 T301 服务中「1/1」、W301 空闲、W302 未挂接、T303 台账里没有、X201 其他业态，图例、筛选、搜索定位、缩放 → W301 开房 → 在住 → 查房 → 退房 → 待打扫 → 打扫好了 → 空闲 → 钟房换房间到 T302，平面图 5 秒内跟着变 → 下钟后变回空闲。
- iPad 实机：浏览器验收用 1024×768、820×1180 的触屏模拟；实机手感（双指缩放）请门店真机测试时确认。

## 3. v0.7.17 第一级实时位置（初稿）

### 3.1 数据结构（按二级定位预留）

- **刷卡点登记**：每个读卡器（编号、名称、所在区域或空间、在用），后台维护；16 个 RC300 的位置由现场补。
- **位置事件**（只追加）：谁（客人 = 来访 / 手牌；技师）、在哪（空间或区域、楼层）、怎么知道的（来源：刷卡点、发手牌、消费、点单、开房、退房、上钟、下钟、结账离场……）、哪条业务单据、什么时候；为第二级预留坐标、精度、设备编号几列，现在为空。
- **当前位置**：每个人一行，最新一条事件写进去（当前所在空间 / 区域 / 楼层、时间、来源）；离场后清掉。
- **区域轨迹**：由位置事件按时间排出「进入—离开」段，接口按段返回；第二级来了只是事件更密。
- **上报即定位**：`POST /api/locations/report`（设备桥、以后的 UWB 网关调用）：报「某张卡在某个读卡器 / 某个点」，服务端写事件、更新当前位置。RQ-001 设备桥做好之前用合成数据测试。

### 3.2 业务动作怎么推导位置

| 动作 | 推导 |
| --- | --- |
| 发手牌入场 | 客人在接待区 |
| 刷卡点刷卡 | 客人在那个读卡器所在的区域 |
| 消费入账 | 按消费项目所在的区域（项目或部门对应区域，后台配置；没配的不推导） |
| 餐饮点单 | 客人在桌台所在的区域（桌台挂区域） |
| 客房开房 / 退房 | 客人在那间房 / 离开那间房 |
| 技师上钟 / 下钟 | 技师在钟单记的那间房 / 回到技师休息区（没记房间的只记「服务中」） |
| 结账离场 | 客人不在店，当前位置清掉 |

### 3.3 平面图上

- 区域上显示在场人数，点开看名单（手牌号、进入时间、最近一次动作）；技师显示在房间里。
- 只显示手牌号与技师名，不显示会员姓名、手机号。
