## 2. v0.7.16 房态图（定稿）

### 2.3 状态与颜色

| 状态 | 颜色 | 什么时候 |
| --- | --- | --- |
| 空闲 | 浅绿 | 客房已打扫可入住；技师房没有钟单 |
| 在住 | 柚黄 | 客房有在住的入住单（停用、不可售也照看板显示） |
| 待上钟 | 浅橙 | 技师房派了钟、技师还没上钟 |
| 服务中 | 湖蓝 | 技师房有技师在钟上（优先于待上钟）；编码后写「钟单数 / 容量」，如「2/4」 |
| 待打扫 | 浅红 | 客房退房后还没打扫 |
| 维修 | 灰 | 客房在维修 |

### 2.4 画法与操作

- 楼层切换（默认编码最多的一层）；底图是那一层的 SVG（作为图片放进来，不执行图里的内容），空间是多边形，没配上轮廓的编码（例外）画位置点；编码写在文字位置，放大 2 倍以上再写显示名；字号随缩放按 1/√倍数变小。
- 筛选：业态多选（不在里面的变淡）、只看空闲、搜编码 / 显示名 / 别名（回车定位：换到那一层、放大到至少 3 倍、移到中间、闪几下并打开侧栏）。
- 缩放平移：滚轮（以鼠标为中心）、双指捏合、拖动（移动超过 6 像素不算点击），「缩小」「放大」「适应屏幕」，1–12 倍。手势进行中整张图作为合成层缩放平移，不重画房间与文字；停 0.15 秒后按最后的倍数清晰重画（字号、线宽跟上）。300 个房号每帧重画在没有显卡加速的机器上每帧要 30–40 毫秒，这样做之后跟满帧一样。画布按楼层的长宽比定高度，最高一屏。
- 图例常显，写每种状态在这一层的个数；台账里有、图上没有的空间列在图下面（按编码点开）。
- 侧栏（宽屏在右边，窄屏在图下面、点了房间自动露出来）：
  - 客房：房间、房型、状态；在住时写手牌、入住与预离、房费与押金。按钮按状态与权限：空闲「开房」；在住「查房」「续住」「换房」「押金」「退房」；待打扫「打扫好了」、维修「维修好了」、空闲「改房态」。全部用「客房」页原来的对话框与接口（入住、入住单、退房核对、改房态），结果待确认的处理照旧。
  - 技师房：这间房里的钟（技师、手牌、项目 × 钟数、上钟时间、剩几分钟或超时几分钟），「去钟房」。
  - 其他：业态、楼层与区域、容量、面积、别名；停用、不可售的写明。
  - 台账里没有的编码：写图上的原文，提示到空间台账补上。

### 2.5 钟单记服务的房间（迁移 `034`）

- `technician_sessions.space_id`（可空，引用空间）与 `space_version`（房间的版本号，每换一次加 1）；已有的钟单为空、版本 0，提成、对账、报表都不看它们。钟房日志的 `kind` 加 `room`（换房间）。
- 派钟对话框「房间（可不选）」：只列在用、可售的技师服务类空间，按楼层分组，写占用（空闲、服务中 n、待上钟 n、已满 n/容量）；选的房间算进操作编号的摘要（不选时与升级前完全一样）。服务端核对：空间存在、在用、是技师服务类、可售；房间满了不拦（待确认）。
- 钟单卡片（上钟中、待上钟）显示房间，点开「换房间」：换、补选（前台挂账建的钟单没有房间）、清掉；请求带上页面看到的版本号，对不上拒绝 `SESSION_SPACE_STALE`，已经是这间照常返回（不改版本号、不记日志）；记钟房日志「房间 S301 → S302」「选房间 …」「清掉房间 …」。派钟日志写「房间 …」。
- 结果不明（超时、断网）：不走「结果待确认」——换房间不涉及钱，与钟房的上钟、下钟一样靠状态兜底：请求带的是版本号（只增不减），中间有过任何修改（哪怕「A 换成 C 又换回 A」），迟到的旧请求都会被拒绝，不会盖掉后来的修改；页面提示「不确定换好了没有」并刷新钟房看板，按看板上现在的房间再选（v0.7.16 审查 P1 的处理）。
- 空间台账：房间里还有没结束的钟单（客人在店）时，这个空间不能停用、不能改成非技师服务的业态（`SPACE_HAS_SESSIONS`）；改成别的技师服务业态、改显示名照常。
- 加锁：派钟在技师队列之后、建钟单之前给房间加共享锁；换房间先锁钟单一行，再给房间加共享锁；空间台账停用、改业态锁空间一行（排他）后只查里面没结束的钟单、不锁钟单（AGENTS.md 锁顺序）。
- 自检：`check` 加一项「钟单记的房间是在用的技师服务类空间」（没结束的钟单）。

### 2.6 性能与验收

- 首屏：底图一层一张 SVG（v0.7.15 实测 84–208 KB）+ 一层的多边形；合成的单层 300 个空间（20×15 网格，客房 / SPA / 足浴 / 按摩 / 派对房五种业态混着，带钟单）从点「平面图」到 300 个空间都画出来，浏览器验收要求 2 秒内（门店电脑、平板横竖屏、1280×720、手机都跑）。
- 流畅：同一份数据下在页面里连续 30 帧、每帧一次滚轮缩放，要求平均每帧不超过 50 毫秒。
- 实测（开发环境的无头浏览器，没有显卡加速）：首屏 0.28–0.39 秒（门店电脑 0.34、平板横屏 0.37、平板竖屏 0.35、1280×720 0.39、手机 0.28）；连续滚轮缩放每帧 19–29 毫秒（改成合成层缩放之前是 38–41 毫秒，文字重画占大头）。
- 真实流程（门店电脑）：样例空间台账（`docs/data`）与样例底图（v0.7.15 的合成图纸）启用、W301 挂客房房间 → 钟房派钟选房间 T301 → 平面图上 T301 服务中「1/1」、W301 空闲、W302 未挂接、T303 台账里没有、X201 其他业态，图例、筛选、搜索定位、缩放 → W301 开房 → 在住 → 查房 → 退房 → 待打扫 → 打扫好了 → 空闲 → 钟房换房间到 T302，平面图 5 秒内跟着变 → 下钟后变回空闲。
- iPad 实机：浏览器验收用 1024×768、820×1180 的触屏模拟；实机手感（双指缩放）请门店真机测试时确认。

## 3. v0.7.17 第一级实时位置（定稿）

第一级 = **业务推导定位**（D17、D24）：不加硬件，精度到区域与房间，位置停在上一次业务动作，等下一次动作才更新。位置来自两处：刷卡点刷卡（16 个 RC300；设备接入在 RQ-001，之前用后台「模拟刷卡」与合成数据），以及发牌、挂账、开房、上下钟、结账这些业务动作。结构按第二级预留：第二级（UWB、蓝牙信标）只换数据源，走同一个上报接口、写同样的表。

### 3.1 谁、在哪、三种状态

- **人**：在店客人（按来访跟踪，换牌后跟着来访走，显示现在的手牌号）、技师。不洗浴的桌台客人、技师以外的员工不跟踪。
- **在哪**：空间台账里的空间（房间）或区域，带楼层。推不到台账上的不记（客房没挂空间、项目没配区域、后台没选接待区）。
- **状态**：在某处 / 位置不明（离开了某处、去向不明：退房，或没设技师休息区时下钟）/ 离店（客人结账、撤销来访；技师下牌）。平面图只画「在某处」的人；「位置不明」的客人 = 在店客人里没有位置的，侧栏只写人数。

### 3.2 数据结构（迁移 `035`，按二级定位预留）

| 表 / 列 | 内容 |
| --- | --- |
| `location_readers` 刷卡点 | 编号（唯一，读卡器上贴的号）、名称（如「接待 1」）、装在哪（区域或空间，二选一）、在用、备注、版本号（修改对不上拒绝）；不能删除，不用了停用 |
| `location_events` 位置事件（只追加） | 谁（来访或技师）、当时的手牌号；事件（在某处 / 离开 / 离店）；楼层、区域、空间；来源（见 3.3）；哪条业务单据（类型 + 编号）；哪个刷卡点；发生时刻与记录时刻；是否生效（迟到的只记不改，见 3.4）；上报的操作编号与内容摘要。**第二级预留**：`x`、`y`（毫米，底图坐标）、精度（毫米）、设备编号，现在都为空 |
| `location_tracks` 轨迹段 | 谁、楼层 / 区域 / 空间、进入时刻（这一段第一条事件）、最近一次事件、离开时刻（换到别处、离开、离店那一刻）、事件数。同一个地方连续的事件并成一段，每人最多一段没结束。第二级来了只是事件更密，段还是按「进入—离开」 |
| `current_locations` 当前位置 | 每人一行：**当前所在空间** / 区域 / 楼层、状态、进入时刻、最近一次事件、当前轨迹段。离店、下牌后位置清空（行留着，作为这个人的写入锁） |
| `service_items.zone_id` | 项目在哪个区消费（后台配，用来推导挂账的客人在哪） |
| 设置 `location_rules` | 开关（默认关，待确认）、接待区（发手牌后在哪）、技师休息区（上牌、下钟后在哪） |

### 3.3 业务动作怎么推导位置

| 动作 | 推导 | 来源 |
| --- | --- | --- |
| 发手牌入场 | 客人在接待区（后台没选接待区不记） | 发牌 |
| 刷卡点刷卡 | 客人或技师在刷卡点装的区域或空间 | 刷卡 |
| 挂账（含手牌点单、挂账派钟） | 客人在项目配的区域；一次挂了几个不同区域的项目，按项目多的区域，一样多按先挂的；都没配的不记。派钟马上上钟（或加钟）的，接着按钟单的房间记（房间比项目的区域准） | 消费 |
| 客房开房、换房 | 客人在那间房（房间挂了空间才记） | 开房 / 换房 |
| 客房退房、撤销入住 | 客人离开那间房，位置不明 | 退房 |
| 上钟 | 技师与客人在钟单记的房间（没记房间的不记，钟房照样显示服务中） | 上钟 |
| 在钟上换服务的房间 | 技师与客人到新房间（还没上钟的换房间不动） | 换房间 |
| 下钟、退钟、结账时一起下钟（只算上了钟的；还没上钟的钟单结账时收尾不动） | 技师回技师休息区；没设休息区（或开关关着）的离开那间房、位置不明；客人不动 | 下钟 |
| 技师上牌 / 下牌 | 上牌：在技师休息区（没设的清掉前一天留下的位置）；下牌：离店 | 上牌 / 下牌 |
| 结账离场、撤销来访 | 客人离店，当前位置清掉 | 结账 / 撤销来访 |

- 补录（按纸质应急单的实际时间补录）的动作不推导位置：补录时客人早已不在那里。
- 开关关着：不推导、刷卡上报拒绝；但离店、撤销来访、下牌照样清掉已有的位置（不留下离店客人的位置）。
- 反结账重开的客人没有位置，等下一次动作。
- 位置写在业务事务里、业务都做完之后，用存档点隔开（等锁最多 2 秒）：位置写不进去（例如等锁超时）只是这一次不推导，业务照常生效、不报错，服务日志记一行。
- 离开（退房、下钟没设休息区）只在这个人现在就在那里时才记：已经被刷卡推到别处的，不因为退了原来的房而变成位置不明。从没记过位置的人离店不留事件。

### 3.4 上报接口（上报即定位）

`POST /api/locations/report`，例：

```json
{ "opId": "8c0e…", "source": "reader", "readerCode": "R01", "tagCode": "A023", "at": "2026-11-02T10:00:00+08:00" }
```

- **谁**：`tagCode`（手牌号，服务端找持这张牌的在店客人）或 `technicianNo`（技师工号），二选一。
- **在哪**：`source = "reader"` 给 `readerCode`；`source = "position"`（第二级预留）给 `spaceCode` 或 `zoneId`，可带 `x`、`y`、`accuracy`（毫米）与 `deviceId`。第二级来了只是设备改报 `position`，服务端写同样的事件、轨迹与当前位置。
- **时刻**：`at` 可不给（按服务器收到的时刻）；不能早于 24 小时、不能晚于服务器 2 分钟。
- **操作编号**：同一个编号原样重发返回原结果、不重复记；同一个编号内容不同拒绝（`OP_KEY_REUSED`）；确认作废了的编号拒绝（`OP_ABANDONED`）。
- **结果待确认**（Codex 复审 PR #33）：后台模拟刷卡与其他登记一样——发出前把操作编号与原请求（含刷卡的时刻，按服务器时间）存在本机并读回核对，存不了就不发；结果不明时在「空间台账」页面上方查回、按原内容重新提交或确认作废（`/api/erp/ops/:key?type=location_report`，作废后原请求晚到也不记），有待确认的不能再刷。RQ-001 的设备桥同样按操作编号重发，不能换编号重报。
- **迟到的事件**：比这个人最近一次位置还早的只记事件、不改当前位置与轨迹（返回 `applied: false`）。
- **拒绝**：手牌没有在店客人（`TAG_NOT_IN_STORE`）、上报的时刻早于这张手牌发给现在这位客人（入场或换到这张牌，`REPORT_BEFORE_TAG`：手牌退回后又发给别人，上一位客人迟到的刷卡不算到现在这位头上）、技师不存在、刷卡点不存在或停用、空间或区域停用、开关关着（`LOCATION_OFF`）。
- **返回**：`{ eventId, applied, replayed, current }`——`current` 是上报之后这个人在哪（离店、位置不明时为空）。
- **谁能调**：新权限「上报位置」，默认店主、店总（后台模拟刷卡）。RQ-001 的设备桥用一个只有这项权限的账号登录调用；设备注册与鉴权在 RQ-001 协议 v0.1 里定，请求体不变。读卡器读到的卡号与手牌号的对应也在 RQ-001 定，这一版按手牌号报。

### 3.5 平面图上看

- 「客房 → 平面图」加「人员」图层（有「看实时位置」权限、开关开着时才有，默认打开）：
  - 区域写在场人数（区域没有轮廓，标在它的空间轮廓的中间）；有人的房间角上写人数。
  - 侧栏「在场」：在店客人 N（有位置 a、位置不明 b）、在岗技师 M；按楼层、区域列出名单——手牌号或技师工号与姓名、在哪、几点进来、最近一次动作。点一个人：换到那一层、定位到那里，并打开他的轨迹（进入—离开的段与原始事件）。
  - 点房间的侧栏加「在这里」：现在在这间的客人与技师。
- 只显示手牌号与技师，不显示会员姓名、手机号；和平面图一起每 5 秒刷新。
- 接口：`GET /api/locations/current`（在店客人与今天在岗——上了牌、没下牌——的技师；带在店客人数、在岗技师数）；`GET /api/locations/tracks?visitId=…` 或 `?technicianId=…&date=…`（轨迹段 + 原始事件，事件最多给最近 500 条）。
- 「人员」可以关掉（只看房态）；找人：手牌号、技师工号或姓名，回车定位到那间房或那个区域。
- 新权限「看实时位置」：默认店主、店总、值班经理、收银（前台岗位）；后勤不看（待确认）。

### 3.6 后台「空间台账 → 实时位置」

- 开关、接待区、技师休息区；
- 刷卡点：新建、修改（带版本号）、停用；每个刷卡点可以「模拟刷卡」（输手牌号或技师工号，走「结果待确认」，见 3.4），RQ-001 之前用它试；
- 项目所在区域：价目项目按分类列出，逐个或整类选区域；
- 与空间台账同一组权限（店主、店总）。

### 3.7 锁与并发

- 位置写在业务事务的最后：业务行都锁好之后，只锁每个人的当前位置一行（同一事务里先客人：来访 id 升序，再技师：id 升序），之后不再等其他业务锁。
- 位置事件、轨迹段、当前位置不用外键引用业务表（来访、技师、楼层、区域、空间、刷卡点、员工），只在三张表之间引用：外键检查会给被引用的业务行加共享锁，锁着当前位置时再去等业务行（结账锁着来访、最后等当前位置）会互相等死（Codex 复审）。引用的编号都来自刚读到的行，这些行也不删除。
- 刷卡上报先取操作编号的咨询锁（与确认作废串行，同一个编号已经记过的直接返回原结果），再只锁当前位置一行，读来访、技师不加锁；拿到锁后再核对客人还在店、还拿着这张手牌。
- 同一个人第一次记位置时同时来两条：当前位置行靠唯一索引只建一次，后到的等先到的提交后接着记。
- 刷卡点修改带版本号，只锁刷卡点一行。

### 3.8 自检（`check`）

- 当前位置与这个人最后一条生效的事件一致（「最后」按生效的先后，即事件编号：离开、离店总是生效，时刻可能早于前一条）；
- 每人最多一段没结束的轨迹，且与当前位置一致；
- 离店的客人、下了牌的技师没有当前位置（下牌之后又刷卡的照样记，只看下牌那一刻之前的位置有没有清掉）。
- 平面图上的在岗技师与在岗人数同一口径：停用了的技师不列。
