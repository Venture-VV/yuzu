# 8.1.9 · ERP 供应链：零采备用金面板与库管入库

店主 2026-11-18 转来《ERP 系统新增需求汇总》：「这是 erp 供应链的新需求，8.1.9 主要更新这个内容」。两条：

1. **备用金可视化面板（供应链零采专用）**：申用 → 占用额度 → 报销补单 → 自动回补，全程在 ERP 里留痕，余额实时可见。
2. **库存「库管入库」**：与「新建收货入库」一样，只是不用选采购单；另有台账模板下载与一键导入。

需求原文第二部分说的「两套采购逻辑分流」：

- 供应商采购（先打款后采购）：照旧走采购单 → 按采购单收货 → 应付或报销。
- 网购零采（备用金先采后报销）：本版新加的路径。在面板上申用 → 下单 → 到货走库管入库 → 补采购单（已有功能）→ 在面板上提交报销（未补单 / 已补单 + 采购单）→ 财务在「费用报销」登记 → 确认后自动回补。

默认做法见 `docs/PENDING_DECISIONS.md`「8.1.9」：零采备用金 BJ1–BJ8，库管入库 KR1–KR6，都待店主确认。迁移 `182`（零采备用金）、`183`（库管入库），登记在 `docs/ROADMAP.md` 第 7 节。

## 1. 现状

- 已有的「备用金」（v0.7.7，`docs/EXPENSES.md`）按部门记账：
  - 打款 BY、报销 BX（钱从哪来：备用金或公司直付）、退回 / 补付 TH / BF、每日平账；
  - v0.7.29 起还有部门备用金台账（保管人、定额）。
- 它只记「钱打出去了、报销了多少、退回了多少」，没有下面这些：
  - 「申用」这一步（谁、哪天、为什么、买什么、多少钱）；
  - 「占用 / 可用」的口径；
  - 报销时的补单情况。
- 报销单由成本核算登记（`expense.manage`），采购经办登记不了。
- 收货：
  - 迁移 `029`（#19）起，总仓收货一律按采购单（`docs.ts` 的 `PO_REQUIRED`）；
  - 没有采购单的只有急采（采购登记，进部门小仓，有上限）。
- 收货单本来就有 `no_po` 一列；没有采购单的收货可以「补采购单」（`backfillPo`），补单只把原收货单挂上采购单，不再入库、不再记应付。

## 2. 零采备用金

### 2.1 口径

- **总额**：在「ERP 设置 → 报销与备用金」里填（店主），按门店存。没填时面板写「还没配置总额」，不能申用。
- **申用**：
  - 一笔一行，写申请人、申用日期、用途说明、采购内容、金额；
  - 登记即占用；
  - 单号 `LC`（零采），按申用日期编号。
- **占用** = 没作废、还没报销完的申用金额合计；**剩余可用** = 总额 − 占用。
  - 申用金额不能超过剩余可用（BJ3）；
  - 总额改小以后剩余可能是负的，面板标红「超出总额」，要先报销再申用。
- **报销完成**：这笔申用挂的报销单（BX）已确认。
  - 确认那一刻起它不再占用，剩余可用自动加回（自动回补），不另记回补单据；
  - 报销单后来被冲销的，这笔申用又回到占用。
- **待报销笔数** = 还在占用的申用笔数。面板上分开写：没提交的、已提交等财务登记的、财务登记了等确认的。

### 2.2 一笔申用的状态

状态大多从报销单推出来，不另存（与采购流程图的做法一样）。

| 状态 | 条件 | 占用 |
| --- | --- | :---: |
| 待报销 | 登记了，还没提交报销 | ✓ |
| 已提交报销 | 供应链在面板上提交了（补单情况必填），等财务登记报销单 | ✓ |
| 报销审核中 | 财务登记了报销单，报销单待确认或被退回 | ✓ |
| 已报销 | 报销单已确认（自动回补） | — |
| 已作废 | 申用作废（写原因） | — |

- 报销单撤回或冲销以后，这笔申用回到「已提交报销」，财务可以重新登记。
- 只有没挂着有效报销单的申用才能撤回报销、作废。

### 2.3 报销（未补单 / 已补单）

- 在面板上点一笔申用的「报销」，选：
  - **未补单**：还没补采购单；
  - **已补单**：要选对应的采购单（已确认或已关闭的采购单，可按单号、供应商搜）。
- 再写一句说明（选填），提交后状态「已提交报销」。
- 「未补单」的以后补了采购单，在面板上点「更新补单」改成已补单、选采购单；已报销的也能改，补单只是记录，不动钱。
- 财务（成本核算）在「费用报销 → 登记」里：
  - 「钱从哪来」多一个选项 **零采备用金**；
  - 选它以后从「已提交报销」的申用里勾这张报销单报的是哪几笔（可以几笔合一张）；
  - 勾的申用都已补单、而且是同一张采购单的，登记页按那张采购单带出明细，与「转报销」一样；
  - 经办人带第一笔的申请人，部门带设置里的归属部门。
  - 其余与原来的报销一样：发票、税点、科目、预算、门槛与审批中心、冲销。
- 报销金额可以和申用金额不一样（实际花的）。面板与登记页都写出两个数，不拦。申用一确认报销就整笔不占用：没花完的钱本来就还在备用金里。

### 2.4 权限

| 操作 | 店主 | 采购经办 | 成本核算 | 其他 |
| --- | :---: | :---: | :---: | :---: |
| 看面板与台账、导出（`pool.read`，新） | ✓ | ✓ | — | — |
| 申用、提交 / 撤回报销、更新补单、作废申用（`pool.manage`，新） | ✓ | ✓ | — | — |
| 设总额与归属部门（`settings.manage`） | ✓ | — | — | — |
| 登记报销时选「零采备用金」和要报的申用（原有的 `expense.manage`） | ✓ | — | ✓ | — |

- 「仅供供应链岗位使用，其他角色不可见」：新权限默认只给店主与「采购」职责（BJ1）。
- 财务登记报销时只看得到「已提交报销」的那几笔（单号、申请人、日期、采购内容、金额、补单与采购单），看不到面板。
- 店主要给别的岗位，在后台「岗位权限」加。

### 2.5 数据（迁移 `182_petty_pool.sql`）

- `petty_pool_uses`：
  - 一笔申用一行：门店、单号、申用日期、申请人、用途说明、采购内容、金额、备注；
  - 报销提交：`claim_state`（open / submitted）、补单 `backfill`（pending / done）与采购单、提交人与时间、说明；
  - 作废：人、时间、原因；
  - 操作编号 `client_key`（唯一）、版本号、合成数据标记。
  - 约束：已补单 ⇔ 有采购单；提交了报销 ⇒ 补单情况已填。
- `expense_claim_pool_uses`：报销单 ↔ 申用（主键两列）。
  - 一张报销单可以报几笔；一笔申用同时只能挂一张有效的报销单（待确认、退回、已确认），在锁里核对。
- `expense_claims.pay_source` 加 `pool`：在当时的约束上追加。原来「备用金 ⇔ 有打款」的约束不变，`pool` 不选打款。
- 操作编号与「确认作废」加业务类型 `pool_use`（申用），照 `162` 的写法在当时的约束上追加。

### 2.6 加锁与幂等

- **申用**：操作编号的咨询锁（与「确认作废」串行）→ 本店零采备用金的咨询锁（同一家店的申用串行，在锁里算占用与剩余）→ 写申用。
  - 读报销单状态、总额不加锁；
  - 同一时刻报销单被冲销、申用回到占用，占用可能短暂超过总额，面板照实显示。
- **提交 / 撤回报销、更新补单、作废**：只锁申用一行（带版本号，对不上拒绝），读采购单不加锁。
  - 撤回、作废在锁里核对没挂着有效的报销单。
  - 原样重提（内容一样、状态已经是要的）直接返回。
- **登记报销（零采备用金）**：操作编号的咨询锁 → 这几笔申用（id 升序，`FOR UPDATE`；核对没作废、已提交、没挂着有效的报销单）→ 采购单 → 发票 → 预算（与原来一样）→ 写报销单与关联。
  - 报销单的确认、退回、撤回、冲销不锁申用：申用的状态是推出来的。
  - 没有「先锁申用再锁报销单」以外的路径。

### 2.7 接口

| 用途 | 接口 |
| --- | --- |

| 台账导出 | `GET /api/erp/pool/export` |

| 申用 | `POST /api/erp/pool/uses` |
| 提交 / 撤回报销、更新补单、作废 | `POST /api/erp/pool/uses/:id/{submit,unsubmit,backfill,void}` |
| 可选的采购单 | `GET /api/erp/pool/po-options?q=` |
| 设置 | `GET /api/erp/pool/settings`；`PUT /api/erp/pool/settings`（店主，规则锁） |
| 登记报销时可选的申用 | `GET /api/erp/expenses/pool-uses`（`expense.manage`） |
| 结果待确认 | `GET /api/erp/ops/:key?type=pool_use`；`POST /api/erp/ops/:key/abandon` |

### 2.8 页面

- ERP 导航「供应链」组多一项 **零采备用金**（`/erp/pool`）。是新的 ERP 模块 `pettyPool`，依赖库存与费用：功能开关默认开。
- 顶部四个数：总额、已占用、剩余可用、待报销笔数；下面一条占用条（已占用里分「没提交」「已提交」「审核中」三段）。
- 台账：
  - 每笔一行：单号、申用日期、申请人、用途说明、采购内容、金额、状态、补单（采购单号）、报销单（单号与状态）、操作；
  - 窄屏改成卡片；
  - 点开看详情：时间线，申用 → 提交报销 → 财务登记 → 确认回补。
- 申用弹窗：申请人默认自己，日期默认今天，金额输入时就提示剩余可用。
- 费用报销登记页：「钱从哪来」多「零采备用金」，选了显示可选的申用；报销单详情写出报了哪几笔申用。

### 2.9 自检

「费用与备用金」自检多一条 **零采备用金一致**：

- 「零采备用金」的有效报销单都至少挂一笔申用，挂的申用都已提交、没作废；
- 一笔申用最多挂一张有效报销单；
- 只有「零采备用金」的报销单挂申用。

## 3. 库管入库

### 3.1 做法

- 收货单加一个标记 `direct`（库管入库）。其余与「新建收货入库」完全一样：
  - 表头：单据日期、供应商（必选）、一起验收的采购（选填）、收货人；
  - 明细：物料、送达、合格实收、拒收与原因、单价、批号与效期；
  - 确认入库即进总仓、算成本；挂账供应商记应付，现付供应商不记应付（货款走报销）；
  - 冲销、退供应商与原来一样。
- 唯一差异：不选采购单。所以：
  - 明细直接选物料、填单价（与以前直接收货一样）；
  - 单子上标「库管入库」；
  - 没有采购单的可以「补采购单」（已有功能：补单只挂上采购单，不再入库、不再记应付）。
- 入口：
  - 库存页「新建」里多「库管入库」，地址 `/inventory/direct/new`；
  - 修改 `/inventory/direct/:id/edit`；
  - 权限与收货一样（`inventory.operate`）。
- 「当前阶段使用」：库存设置里加开关「库管入库」（KR5，默认开）。关了以后入口隐藏、接口拒绝（`DIRECT_RECEIPT_OFF`），已经入的照旧。
- 待办「缺采购单」照旧列出没补单的库管入库，写「库管入库 · 待补采购单」。

### 3.2 台账模板与一键导入

- 库存页「库管入库」旁边：
  - **下载模板**：Excel，三个工作表：
    - 入库台账：表头一行，橙色必填、灰色选填，供应商与物品是下拉，点到单元格有提示；
    - 填写说明；
    - 选项：供应商、物料与它的单位、规格。
  - **导入台账**：选 Excel 或 CSV → 逐行核对、预览 → 一键生成库管入库单（已确认入库）。
- 列：

  | 列 | 必填 | 说明 |
  | --- | :---: | --- |
  | 入库日期 | ✓ | 不能晚于今天 |
  | 供应商 | ✓ | 供应商档案里的名称或编号 |
  | 物品名称 | ✓ | 物料档案里的；同名的写物料编号 |
  | 物料编号 | | |
  | 送达数量 | ✓ | |
  | 合格实收 | | 空着按送达数量；比送达少要写拒收原因 |
  | 单位 | | 空着按库存单位；写采购单位时按包装换算 |
  | 单价 | ✓ | 元，每采购单位（与页面上一样） |
  | 金额 | | 选填，用来核对：与数量 × 单价差 1 分以上的标出来 |
  | 拒收原因 | | |
  | 批号、生产日期、到期日 | | 管效期的物料到期日必填（或生产日期 + 保质期） |
  | 收货人 | | |
  | 单据分组 | | 同一组的合成一张单；空着按「入库日期 + 供应商」合 |
  | 备注 | | |

- 合单：
  - 按「入库日期 + 供应商 + 单据分组」合成库管入库单；
  - 一张最多 100 行（与单据上限一样），超过的按顺序拆开；
  - 一份最多 500 行。
- 一键导入：
  - 在一个事务里建单、逐张确认入库，有一行有问题整份不写；
  - 同一份文件（按内容摘要）只能导入一次（重复入库会多出库存）。
- 加锁：
  - 操作编号的咨询锁（业务类型 `receipt_import`，与「确认作废」串行）→ 同一份文件的咨询锁 → 写导入记录；
  - 之后每张单走收货单原来的锁（物料 id 升序）。
- 数据（迁移 `183_direct_receipts.sql`）：
  - `inv_docs` 加 `direct` 与 `import_id`；约束：库管入库只能是收货单、不是急采；
  - 新表 `receipt_imports`：导入记录，文件摘要唯一；
  - 操作编号与「确认作废」加 `receipt_import`。

### 3.3 自检

「收货都有采购单」改成：

- 收货都有采购单；
- 没有的是急采（不超过上限），或者是库管入库。

应付、成本、库存的自检不变：库管入库与按采购单收货走同一套入库与应付。
