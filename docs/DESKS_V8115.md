# 8.1.15 · 前台拆成发卡台与收银台

> **版本号**：原排 8.1.14。同一天品牌部的三条（[PR #134](https://github.com/Venture-VV/yuzu/pull/134)，另一个开发会话）先合进 `main`、用了 8.1.14，按「版本号按合并先后取下一个」（`docs/GOVERNANCE.md` 第 4 节），这一批发 **8.1.15**；设计与交接的文件名也跟着叫 `DESKS_V8115.md`、`HANDOFF_V8115.md`（`HANDOFF_V8114.md` 是品牌部那一批的）。

店主 2026-11-19 发来《前置操作平台面板拆分 & 功能调整需求》。原文与没写细的默认做法在 `docs/PENDING_DECISIONS.md`「8.1.15：前台拆成发卡台与收银台」FS1–FS14（都待确认）。这一版没有迁移。

## 1. 要解决什么

现有「前台」一个面板里既发牌又结账，功能混在一起、权责不清。需求是按业务环节拆成两个一级面板：

- **发卡台**：客人入场。接待、发手牌、会员等级识别、换牌；不参与账单结算。原前台除「选一张手牌查看账单」以外的功能都平移过来。
- **收银台**：最终结账。选手牌看账单，项目只读，不能加项目、不能换牌；带折扣、赠送权益的项目在小票上写明；赠送、折扣类权益在小票与账单上写经办人；衔接管家部、客户部的签赠。

读到的做法里，这次用上的：

| 别人的做法 | 出处 | 这次怎么用 |
| --- | --- | --- |
| 「结账」是单独一项权限，与开单、改单分开 | Floreant 的 Settle Ticket；SambaPOS 把收款按岗位给 | 我们原来就分开（「接待发牌、挂账、换牌」与「结账收款」），这次把页面也按这两项分开 |
| 出了账单以后不让再改单；TakePOS 没有这道护栏，论坛里有人报收银打完小票再删行、把差额拿走 | SambaPOS 的账单锁；Dolibarr 论坛 | 收银台的明细整个只读：不能加、不能作废、不能转。要改回发卡台，由有权限的人改，照旧留原因 |
| 收银只管找单、看单、收款；手动折扣、改价要更高一级 | Odoo 的三级收银权限 | 照旧：「优惠 / 免单」由值班经理及以上当场授权，店员不能自己抹零 |
| 敲桌号「跳」到那一单；另有按状态筛的单子清单 | Odoo 餐饮；QloApps 前台按状态筛、标「待付款」；Kamra 的「今天」一屏 | 收银台左边是待结账清单，直接敲牌号回车就打开；可以只看有消费的、按金额或在店时长排 |
| 赠送的行留在单子上、标「赠」、带预设的原因，从合计里减 | SambaPOS 的 Gift | 小票上被签赠、券、会员折扣抵到的行标「赠」「券」「折」；「优惠与赠送」一栏逐笔写名称、事由、金额 |
| 储值、积分算收款方式，折扣算优惠，分开写 | ERPNext 的积分抵扣；Odoo 小票 | 小票分成「优惠与赠送」与「收款」两栏：储值、次卡、团购券在收款里，签赠、券、会员折扣、优惠 / 免单在优惠里，另写「共优惠」「优惠后应付」 |
| 选了顾客马上显示等级与积分；会员才有的操作，选了会员才出现 | Odoo；ERPNext；fuint 的会员等级权益 | 发卡台的客人卡与接待发牌选了会员时显示档阶与基础权益；收银台的「发放签赠」只在客人是会员时出现 |
| 作废要写原因，留下谁、做了什么、为什么 | Kamra；Odoo | 原来就有（作废、撤销、反结账都留原因与经办人），不变 |
| 账没结清不让走，并给出去处理的入口，不是一句「不行」 | Kamra；Odoo 关班前的「去看未结的单」 | 结账对话框里原来就有（钟没下、菜没上、房没退各有提示与入口）；这次发卡台给有结账权限的人加「去收银台结账」，收银台明细有误时写明去哪改 |

读到的范围里没有先例的一条：**没有一个项目在小票上逐笔写「这笔赠送 / 折扣是谁给的」**。它们写收银员、写授权（SambaPOS 的赠送可以要管理员密码），但经办人只在后台日志里。这一条照店主的需求做，写法见第 4 节。

## 3. 两个台

### 3.1 入口与权限（FS1、FS2）

- 门店主导航里「前台」换成「发卡台」「收银台」，发卡台在前。发卡台沿用 `/frontdesk`（旧链接、书签照旧打开），收银台是 `/cashier`。
- 两个入口都按「查看在店手牌与手牌账单」显示（前台 1 细化起再按各自的权限分，见第 7.2 节）。台里的操作照现有权限，服务端的接口与权限一条没改：
  - 发卡台的操作要「接待发牌、同行绑牌、挂账、换牌」；
  - 收银台的结账要「结账收款」，反结账、退款单、挂账各自的权限不变。
- 要把人分开的，现在在后台「岗位权限」按岗位去掉其中一项。同一个岗位里再按人分，这一版没做（FS2，等店主说）。

### 3.2 发卡台（FS3–FS6）

- 手牌板、牌号快检、接待发牌、找客人、锁牌 / 解锁、补录纸质单、自检，与原前台一样。
- 手牌板上会员的卡片写档阶的短写（如「L3」，全称在客人卡上），接待的人一眼分得出身份；L0 不写。
- 点在店的手牌，右边出**客人卡**（窄屏是侧滑）。它不是账单：
  - 身份：会员名、档阶（保级期、体验身份照旧标出）、能用几级 VIP 柜、储值余额；散客写散客与备注。
  - 基础权益（会员才有）：哪几项打几折（折扣各有适用范围，写权益的名称）、浴票延迟、本月可享的服务几项、手上能用的券几张（其中签赠几张）。
  - 票种（可以改）、同行组。
  - 已挂的项目：名称、数量、金额、谁挂的、几点；挂错的在这里作废（规则不变：本人在时限内，或有更正权限）。
  - 操作：加项目、换牌、再发同行手牌、与在店客人同行、明细转到别的手牌、退出同行、撤销误开的牌。
- 底下写已挂合计（不含门票）。没有应收、没有「门票此刻多少」、没有预结账与结账、没有结账记录。
- 有结账权限的人，客人卡底下有「去收银台结账」，带着这张手牌过去。

### 3.3 收银台（FS7、FS8）

- 左边是**待结账清单**：在店的手牌一行一张，写牌号、分区、客人与档阶、在店多久、已挂多少、同行组；会员手上有能用的券标「券」，有签赠标「赠」。
  - 直接敲牌号回车就打开（与发卡台一样的盲打）。
  - 可以筛：全部、有消费、同行、在店超过 6 小时；可以按牌号、金额、在店时长排。
  - 顶上写在店几位、未结合计。
- 右边是**只读账单**：
  - 抬头与发卡台的客人卡一样（牌号、客人、档阶、同行）。
  - 明细按来源分组，每一行写谁挂的、几点；没有作废、加项目的入口。已作废的折叠在下面，照旧留痕。
  - 门票（此刻多少、下一档几点）只显示，不能改票种。
  - **权益与优惠**：这位客人现在能用的会员折扣、签赠券（渠道、发放人、授权人、事由）、券、次卡，各写能抵多少或为什么不能用。结账时在结账对话框里选，规则不变（一张结账单一张券，不与优惠 / 免单同用）。
  - 有「发放签赠」权限的人可以在这里当场给这位会员发签赠，渠道默认「前台」，发完马上出现在上面。
  - 底下是已挂合计、含门票此刻应收、预结账（F8）、结账（F9）。
  - 明细有误时的一句提示：收银台不改单，请到发卡台处理（有权限的人能点过去）。
- 页面顶上：结账记录（反结账、退款单都在里面）、平台核销、补录纸质单、自检；班次跨了营业日的提醒、扫码收款没入账、验过券没结账的提示条在这里（都是收款的事，发卡台不显示）。
- 没有换牌、加项目、同行、撤销的入口。

### 3.4 两个台之间（FS12–FS14）

- 快捷键：发卡台 F2 接待发牌、F4 加项目；收银台 F8 预结账、F9 结账。
- 补录纸质单的状态两个台共用。
- 「结果待确认」：结账、退款单回收银台；发牌、挂账、换牌、转明细回发卡台。
- 客房「打开手牌账单」去收银台；楼面图「去前台挂账」去发卡台。

## 4. 优惠、赠送与经办人（FS9–FS11）

### 4.1 数据

都是结账时原来就记下的，这次只加读法：

| 类别 | 记在哪 | 经办人 |
| --- | --- | --- |
| 签赠 | 收款明细里的券 → 发券记录（8.1.9 起有授权人、渠道） | 发放人、授权人、渠道、事由 |
| 券抵扣 | 同上 | 手动发的写发券人与事由；按规则、会员权益、小程序领取、批量发的写来源，不写人 |
| 会员折扣 | 收款明细里的权益与折扣 | 按档阶自动打，写几折；经办是收银 |
| 优惠 / 免单 | 收款明细里的授权人与原因 | 授权人、原因 |

- 结账单接口多返回一项 `perks`：每笔的类别、名称、金额、说明、渠道、经办人、用在哪几条明细上。
- 次卡、会员储值、团购券不算优惠（预付或平台结算），照旧写在收款里。
- 以前结的单一样读得出，不用补数据。

### 4.2 小票

浏览器打印的 80mm 结账单与网口小票机同一个写法：

```
足疗 60 分钟 [赠]              ¥198.00
水果拼盘 [折]                   ¥68.00
小计                           ¥266.00
===================================
应收合计                       ¥266.00
优惠与赠送
签赠 · 足疗体验券             -¥198.00
  管家部 · 发放 张三 · 授权 李四
  生日关怀
会员折扣 · 结账折扣             -¥6.80
  9 折，按会员档阶自动打
共优惠                         ¥204.80
优惠后应付                      ¥61.20
收款
微信                            ¥61.20
```

- 明细行上的标记：被签赠抵到的标「赠」，券「券」，会员折扣「折」。优惠 / 免单是整单的，不标在行上。
- 「收款」一栏只列真收的钱与预付抵扣（储值、次卡、团购券、挂账）。
- 收银员照旧在小票抬头。

### 4.3 页面上

- 结账完成的确认页、「结账记录」里的结账单详情、桌台结账的完成页用同一个部件：多一栏「优惠与赠送」，每笔带经办人，最后「共优惠」。「流水」里的订单详情是另一个部件，这一版没动（收款明细照旧逐笔列着，含券与优惠的备注）。
- 收银台的账单在结账前显示「能用的」，结账后显示「用了的」。

## 5. 不改的

- 记账、加锁、幂等、营业口径一条没动；`src/server/modules/frontdesk/` 里只在读结账单的地方加了一段只读查询。
- 服务端没有因为拆面板加新的拦截：能不能发牌、能不能结账照旧按权限。
- 桌台结账（餐饮）不在这次范围里，它的结账单一样多了「优惠与赠送」。

## 7. 前台 1 细化：结账预览分列、入口按权限显示

《浴族系统需求汇总》前台 1 的两条细化（`docs/YUZU_REQ_V8115.md` 第 1 节「前台 1」、第 3 节 G），默认做法在 `docs/PENDING_DECISIONS.md`「8.1.15 追加」YB2、YB3、YB5–YB8（待确认）。没有迁移、没有新权限、没有新接口；预结账的返回多两个只读字段；记账、加锁、幂等一条没动。

### 7.1 结账预览分列

收银台的「预结账」里，每张手牌一张卡、底下一张合计，都分六列。对话框够宽时六列排成一行，窄了排三列、两列（按对话框自己的宽度，不按屏幕）。列名 12 像素、金额 16 像素；没有的格子写一条横线。

| 列 | 写什么 | 从哪来 |
| --- | --- | --- |
| 门票 | 此刻算出来的门票，小字写票种与档；还没选票种的写「结账时选票种」 | 结账预览（与结账同一套计价），结账时按结账那一刻重新算 |
| 餐饮 | 已挂的餐饮合计、几项 | 账单明细里来源是「餐饮」的。一份套餐是一条（套餐里含哪几样只在出品单上拆开），加料是单独的一条 |
| 客房 | 已挂的房费合计、几项 | 来源是「客房」的 |
| 服务 | 技师服务、洗浴项目、其他的合计、几项；有「其他」（丢牌赔偿等）时小字写出多少 | 来源是「技师服务」「门票与洗浴项目」「其他」的；超时加收也在这里（YB5） |
| 优惠 | 会自动带上的会员折扣能省多少（绿色、带减号），写在那位会员的手牌上，小字写档阶与几折 | 结账预览里省得最多的那一项会员折扣（YB6） |
| 押金 | 在住的客房还押着多少、哪间房 | 新字段：在住（没退房）的入住单的押金，收的减退的（YB7） |

- 合计底下两句话：优惠写是谁的哪一项、结账时自动带上、省多少，另有几张券可用（其中签赠几张）、由收银员在结账时选；有押金时写哪间房还押着多少、退房时退、不在手牌结账里抵。
- 「应收（含门票）」照旧是明细加门票，不含押金、不减折扣；有会员折扣时旁边另写「带上会员折扣后」多少——收银员选了券或优惠 / 免单就不带这项折扣，所以不直接从应收里减。
- 门票与优惠还在算的时候格子里写「…」，已挂的明细先列出来；算不出来出一条「门票与优惠没算出来」带重试，预结账本身没取回来出「预结账没取回来」带重试（`LoadFailed`）。
- 归列的规则 `previewBuckets`、列名 `PREVIEW_COLUMNS` / `PREVIEW_COLUMN_LABELS` 在 `src/shared/frontdesk.ts`；页面是 `VisitDialogs.tsx` 的 `PreviewColumns`；押金在 `previewBills`（`src/server/modules/frontdesk/visits.ts`）里多查一遍，只读。
- 「去结账」「关闭」改成 48 像素高；对话框加宽一档（六列才排得成一行）。

### 7.2 两个台的入口按权限显示

- 主导航里：有「接待发牌、同行绑牌、挂账、换牌」的看得到发卡台，有「结账收款」的看得到收银台，两项都有的两个都看得到；两项都没有、只有「查看在店手牌与手牌账单」的两个都看得到（进去只能看）；连查看都没有的都看不到。规则是 `src/shared/frontdesk.ts` 的 `deskEntries`，`src/client/components/storeNav.ts` 只给这两行加了显示条件。
