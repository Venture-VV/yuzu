# 交接：小程序第三期 3b 邀请好友、3c 扫码点餐（小程序线）

**合并顺序**：主线 v0.7.28 的 PR（#54，入口 `createTrialInviteFromMp`、`orderFoodFromMp` 与只读的 `diningMenu`、`mpDiningTables`、`mpOpenBill`，迁移 `051`）先合；小程序线把 `main` 合进来以后再交。迁移 `061`、`062` 接在主线的 `051`–`060` 后面（ROADMAP 第 7 节已登记，`063` 预留给 3d 预约）。

3b、3c 都不动钱：3b 建的是会员体系的临时身份（主线的规则），3c 的菜挂在顾客自己的手牌账单上、结账照旧在前台。按普通功能验收。对顾客开放要等 yuzu 正式切换（ROADMAP 第 3 节 M5）；在那之前只在演示库上用模拟微信联调。

## 1. 范围（`docs/MP_PHASE3.md` 第 2、3 节）

**3b 邀请好友**（MP30、MP31）
- 邀请人：「我的 → 邀请好友」看还能邀请几次、好友能体验的档阶与天数，发一个邀请码（7 天内有效、只能用一次），用分享卡片发给好友；没人领的可以收回。发出去没人领的占着本月的次数，收回、过期的退回。
- 好友：打开卡片 → 用微信手机号快速验证领取。已有会员的，档级要低于体验的档级；还不是会员的，填姓名当场开卡（L0、渠道「老带新」、发开卡礼，与前台一样），顺带绑上这个微信。
- 规则、拒绝照主线 v0.7.25 的「邀请体验」：每位会员每月 1 次、受邀人 12 个月内只能被邀请一次、同一时间只有一个临时身份。赠送记名会籍（QY-042）先不放进小程序（MP31）。
- 后台「微信小程序 → 邀请好友」（新权限 `mp.invite`：店主、店总）：开关、最近的邀请。

**3c 扫码点餐**（MP32、MP33）
- 在店的会员（手牌挂上了会员卡）在「我的 → 点餐」点菜，扫桌上的码写送到哪张桌；进厨房出品单、扣估清，挂在自己的手牌账单上，与服务员在点单页下单一样（经办人系统账号「小程序」）。
- 只能点店里勾了的、进厨房的菜；只限男宾或女宾的只列这张手牌能点的；一单最多 20 份、¥500；自己不能退菜，退菜请服务员。
- 「我的 → 我的账单」：在店手牌上点了什么、多少钱、菜做到哪了。
- 后台「微信小程序 → 扫码点餐」（新权限 `mp.food`：店主、店总）：开关、可点的菜、桌码（A4 打印）、最近的点单。

## 3. 环境与配置

- 门店 yuzu、网关都不加环境变量。
- 桌码用门店系统已有的 `MP_CODE_SECRET`（会员码的签名密钥）签名；没配的门店后台没有桌码，顾客照样能点、不写桌号。
- 演示库照旧：网关 `MP_MOCK_WECHAT=true` 时用模拟微信；好友领取的手机号快速验证用模拟的 `mock-phone-<手机号>`。

## 5. 验收要点

**3b 邀请好友**
1. 默认关着：「我的」没有入口，发起回 403；没有 `mp.invite` 的岗位看不了、改不了后台。
2. 邀请人：L0 不能邀请（写原因）；够格的发一个码，同一个编号重提返回同一个码；没人领的占着本月的次数（再发拒绝），收回的退回；点了以后才换绑的（带旧的绑定版本号）拒绝。
3. 好友：
   - 已有会员、这个微信绑着的：用这位会员的手机号领；手机号对不上拒绝；档级不够低拒绝；
   - 还不是会员的：没填姓名回 `NAME_REQUIRED`；填了当场建档、渠道「老带新」、顺带绑上这个微信；会员已经绑了别的微信的，领到了但不绑，写说明；
   - 同一个编号重提返回第一次；被领走的、收回的、过期的、自己发的都拒绝；两个好友同时领只有一个领到；
   - 结果不确定时确认作废：已经领到了回那一次，没有的登记作废、原请求晚到也不生效。
4. 邀请人看得到好友（名字只露第一个字）与体验到哪天；后台看得到各状态多少与最近的邀请。
5. `check` 全过。

**3c 扫码点餐**
1. 默认关着：点餐页写没开放，下单回 403；后台开了但餐饮功能关着照样没开放；「我的」的入口跟着开关；没有 `mp.food` 的岗位看不了、改不了后台。
2. 点餐页：没绑定、没有在店手牌、会员卡停用都写原因、不能点；只列勾了的、进厨房的菜；男宾手牌不列只限女宾的；估清的写「今天没有了」。
3. 桌码：后台每张启用的桌台一个码（18 位数字、71 开头），A4 打印扫得出来；扫了对的码写桌名、出品单写送到这张桌；签名不对、桌停用、不是桌码的写原因；桌台改名照样认。
4. 下单：挂在会员在店手牌的账单上、进厨房、经办人「小程序」；同一个编号重提返回第一次、不多下；两次同时到只下一单。
5. 拒绝时什么都不留（账单、估清、出品单、点单记录都不变）：没勾的菜、桌码不对、价格刚改过（带的合计对不上）、估清不够、超过 20 份或 ¥500、绑定刚变过、没有在店手牌、没绑定。
6. 确认作废：已经下了回那一单；没下的登记作废，原请求晚到也不下；下单与确认作废同时到只有一个结论；别的微信用不了这个编号。
7. 结账照旧在前台；结账以后「我的账单」没有了，原编号重提照样回第一次那一单；解绑以后原编号重提拒绝。
8. 点单记录只追加（改、删都被拒）；后台看得到今天几单、最近的点单。
9. `check` 全过。
