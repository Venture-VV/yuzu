# v8.0.10 交接说明 · 点餐系统（平板电子菜单）

8.0.9（PR #91）2026-11-11 合并为 main `babf4d5`。同一天店主把后续主线的开发转到新的主线开发会话，并发来一个新需求：「目前我们的点餐系统，这个是显示在 yuzu 系统前台部分 UI 的。给你的链接是 UI 的设计师发的」——两份飞书文件是同一份设计稿《点餐系统版面模板-26.11.11》（22 屏，1024×768；一份文字可选、一份转曲）。这一版照设计稿做放在餐桌上的平板电子菜单。设计稿与各屏的对应、规则与接口见 [`docs/EMENU.md`](EMENU.md)，没定的规则按默认 DC1–DC18（`docs/PENDING_DECISIONS.md`「8.0.10」，待确认）。在 [PR #92](https://github.com/Venture-VV/yuzu/pull/92)。

## 1. 范围

### 1.1 平板点餐页（`/emenu`）

- 整页是 1024×768 的舞台，按屏幕等比缩放（4:3 的 iPad 正好铺满）。照设计稿的 22 屏：起始页 → 输入信息（手牌、桌号、人数，弹窗自带数字键盘）→ 菜单（11 种版面，横向一页一页翻；顶栏分类页签、搜索、订单、手牌）→ 菜品详情（规格、上一道 / 下一道）→ 搜索（跳到那道菜所在的页）→ 订单抽屉（未下单 / 已下单）→ 备注（忌口多选、起菜方式单选、自己写 30 字）→ 确认信息（服务员输 6 位点单密码）→ 下单成功。
- 下单：菜挂到这张手牌的账单上（与「餐饮 → 点单」同一条路径，经办人是输密码的服务员），送到厨房屏，出品单上写送到哪张桌、整单备注；另写一张点餐单（`emenu_orders`，只追加）。价格读价目表，估清、下架、过了供应时段的菜标「已售罄 / 已下架 / 当前时段不可售」、点不了；页面每 15 秒向门店系统取一次菜单。
- 与门店系统所有写操作一样带操作编号：提交前把编号与原请求（不含点单密码）存在平板上并读回，存不了不发；超时、断网、5xx 进入「结果待确认」——查回、原样重新提交（再输密码）、确认作废（再输密码）之后这台平板才能下新的一单。
- 这一次点餐（手牌、桌号、人数、没下单的菜、备注）存在平板上，页面被系统刷新了还在；没人动超过设置的分钟数（默认 10）回到起始页、清掉没下单的菜；点顶栏的手牌可以结束这一次点餐；长按起始页的版权行 3 秒退出登录。
- 设计稿之外补的 13 处界面与两处出入（页码点、结束点餐、结果待确认、提示条……）列在 `docs/EMENU.md` 第 3.11 节，请设计师过目。

### 1.2 与设计稿的吻合

设计稿 PDF 里每个文字、图形的位置与字号用脚本量出来写进代码；做好以后每一屏截图与设计稿渲染图逐处比对位移（同样用脚本），校到 1 像素以内（英文与数字因为换了字体，字形本身略有不同）。几处做法值得知道：

- **字体**：中文朱雀仿宋（设计稿用的，SIL OFL，随应用打包，按字符区间分成小文件）；英文与数字设计稿用的是 ABC Arizona Flare 的**试用版**（商业字体，没有授权不能随应用发），用开源的 Average Sans 顶替（字高、数字宽窄最接近；数字 0 与字母 O 分得清），字距照它补过，宽度与设计稿对得上（DC14：要不要买授权）。
- **行框**：朱雀仿宋自带的行高信息在苹果与安卓 / Windows 上取值不同，直接用的话文字上下会差零点几个字高。字体列表最前面放了两个只规定行框尺寸的小字体（各 612 字节，没有常用字的字形），行框与设计稿 PDF 里的文字框一样，各平台排出来位置一致。说明与生成办法在 `src/client/features/emenu/emenu.css` 开头。
- **细边**：设计稿的 0.5 描边画在一层不占位置的框上（0.5px 的 border 在普通屏算 1px，会把里面的字挤偏）。
- 按钮、页签里的字不靠浏览器自动居中，按设计稿的位置定位。

### 1.3 后台「电子菜单」（`/admin/emenu`，权限「维护电子菜单」，默认店主、店总）

| 分区 | 内容 |
| --- | --- |
| 分类与版面 | 分类（名称、英文名、供应时段、排序、停用）；每个分类一页一页排：选版面（11 种）、往位置里放菜、竖排小标题，旁边是照平板样子画的实时预览；整批保存、带版本号（别人先改过会被拒，`EMENU_CHANGED`） |
| 菜品图文 | 展示名、英文名、名称后的小字、介绍、属性行、展示图与特写图（浏览器里压缩后上传，单张不超过 1 MB，按内容去重）、规格（各挂一个价目项目，一个项目只能在一道菜里）、停用；「从价目表生成初稿」把挂了出品档口、还没进电子菜单的项目各建成一道菜，按价目表的类别排成「文字陈列」页 |
| 设置 | 平板点餐的开关（**默认关**）、起始页氛围大图、版权行、忌口与起菜方式的选项、多久没人动回到起始页、不在供应时段的分类显示还是不显示 |

开头列出还差哪几步才能用（餐饮功能没开、没有菜品、没排版面、没有平板账号、没人有点单密码、桌台名称里没有数字……）。规则总表多一组「点餐系统（平板电子菜单）」。

### 1.4 岗位「点餐平板」与点单密码

- 新岗位 **点餐平板**（`tablet`）：给放在餐桌上的平板登录用的设备账号，只有「打开平板点餐」一项权限，登录后直接进 `/emenu`，门店系统别的页面进不去、别的接口回 403；不能带库存与采购职责。
- **点单密码**：服务员在平板上确认下单用的 6 位数字，系统生成、只显示一次（不让自己挑：撞上别人的时候等于告诉他别人的密码），库里只存前三位与 scrypt 摘要。后台「员工账号」里给人生成、重新生成、收回；本人在「修改密码」页也能自己重新生成。要有「餐饮点单」+「前台挂账」权限的岗位才用得上。输错限次与登录共用：这台平板 15 分钟内错 5 次锁 5 分钟。

## 3. 验收要点

1. 登录页与导航栏显示 `v8.0.10` 与 SHA；`check` 全 ✓（多一条「平板点餐单与餐饮明细一致」）。
2. **后台准备**：「餐饮」里建出品档口、把几道菜挂到档口、开启餐饮功能；「电子菜单」里给几道菜配英文名、介绍、图片（其中一道配大份、小份两个规格），建两个分类（一个设供应时段、一个全天），11 种版面各排一页，预览与平板上一致；同一页同一道菜放两次、空页保存被拒；两个窗口同时改同一个分类，后保存的被拒（`EMENU_CHANGED`）；打开平板点餐。
3. **账号**：「员工账号」新建岗位是「点餐平板」的账号；给一位前台生成点单密码（只显示一次），本人在「修改密码」页重新生成后旧的马上失效。
4. **平板账号登录**（1024×768，或真的 iPad）：首次登录改密码后直接进起始页；打开 `/frontdesk`、`/admin` 回到点餐页，调门店系统别的接口被拒（403）。
5. **输入信息**：手牌只输数字能找到；数字对得上两张在店的牌时让选；没有在店客人的牌提示；桌号建了桌台的只能填建过的（只输数字也行，重了让选），没建桌台的照输入的记。
6. **逐屏对照设计稿**：位置、字号、颜色（截图在 `docs/screenshots/emenu/`）。
7. **点菜**：单规格直接加、多规格进详情选；搜索跳到那一页；未下单里加减；备注选两项加自定义。
8. **确认下单**：密码错提示、错 5 次这台平板锁 5 分钟；没有点单权限的员工的密码被拒；对的密码下单成功——前台这张手牌的账单上多了这几道菜（经办人是这位服务员），厨房屏上有送到的桌号与整单备注，`check` 全 ✓。
9. **估清**：厨房把一道菜设成剩 1，一台平板点走，另一台 15 秒内变「已售罄」；两台同时下单只有一台成功。
10. **时段**：把分类的时段改成已经过了，平板 15 秒内不显示这一类（设置成「显示但不能点」时标「当前时段不可售」），这时下单被拒。
11. **结果待确认**：下单时断网 → 弹待确认；恢复后查回已生效 / 重新提交不重复 / 作废后原请求不再生效。
12. **没人动回到起始页**：把设置改成 1 分钟验；点顶栏的手牌结束点餐。
13. **开关关着**：`/emenu` 提示没有开启，其余页面与升级前一样；从 8.0.9 的库升级后 `check` 全 ✓。
