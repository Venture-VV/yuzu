## 2. ① 小程序第三期的入口（迁移 `051`）

小程序线在自己的事务里调用，代码在 `src/server/modules/mp-entries.ts`。

**共同的约定**
- 每次调用带 `claimKey`：小程序线自己的记录编号，正整数或 64 字以内的字母、数字、`_`、`-`。
- 同一个 `claimKey` 只生效一次：再调用返回第一次的结果，`replayed: true`；内容不同的拒绝，`MP_CLAIM_CONFLICT`。去重记在新表 `entry_claims`（只追加），预约那一块也用。
- 经办人是系统账号「小程序」。
- 锁：先取 `claimKey` 的咨询锁（同一个 `claimKey` 的两次调用排队），之后与前台同一套。

### 2.1 3b 邀请好友：`createTrialInviteFromMp(tx, deps, { inviterId, invitee: { phone, name? }, claimKey, at? })`

- 规则、拒绝码与前台 v0.7.25 的「邀请体验」相同，用的是同一段代码（`member-trials.ts` 的 `createTrialTx`）：
  - `TRIAL_SELF`；
  - `TRIAL_NOT_ALLOWED`：邀请人不够档、本月次数用完、已停用；
  - `TRIAL_INVITEE`：好友不够条件；
  - `MEMBER_CHANGED`、`PHONE_EXISTS`、`TRIAL_ACTIVE`。
- 好友还不是会员：当场建档、发开卡礼，渠道「老带新」（店里的渠道来源里有这一项、启用中时）。没给姓名回 400（`field: name`）。
- 建档、开卡礼、临时身份在一个存档点里：拒绝时一起撤回，调用方的事务还能接着用。
- 返回 `{ trial, replayed }`，`trial` 与前台会员详情里的一样。
- 「这个月还能邀请几次、好友能体验什么」：用只读的 `trialOptions(db, inviterId, date, phone?)`（`member-trials.ts`）。

### 2.2 3c 扫码点餐：`orderFoodFromMp(tx, deps, { memberId, items: [{ itemId, quantity, note? }], tableCode?, expectedTotal?, claimKey, at? })`

- 与服务员在点单页下单同一条路径（`frontdesk/bills.ts` 的 `postChargesTx`）：挂在这位会员在店手牌的账单上、扣估清、进厨房出品单、记实时位置。
- 只能点进厨房的菜。会员同时只有一张在店手牌（已有的唯一索引）。
- 一单最多 20 份、¥500（N1，`MP_FOOD_ORDER_LIMITS`）。
- `tableCode` 是桌台名称（不分大小写）。出品单写「送 X 桌」，厨房屏上显示，并标「小程序点单」。
- `expectedTotal`：带了就核对，价格刚改过时拒绝。
- 拒绝码：
  - `NO_OPEN_VISIT`、`DINING_DISABLED`；
  - `DISH_NOT_KITCHEN`、`DISH_SOLD_OUT`、`ITEM_GENDER`；
  - `PRICE_CHANGED`、`MP_ORDER_LIMIT`；
  - `TABLE_NOT_FOUND`、`VISIT_CHANGED`。
- 返回 `{ visitId, tagCode, orderNo, deliverTo, total, lines, replayed }`。
- 退菜照旧请服务员作废明细；结账照旧在前台。

## 3. ② 派对房计费（迁移 `052`，N2、N3）

**后台**：「客房 → 派对房等：开单即占用」卡片里，按业态设计费：
- 房费项目：价目表里的项目，它的价格就是每小时多少，它的分类就是部门营业额里的部门（例如建一个「派对房房费」，分类「派对房」）；
- 起步时长（默认 60 分钟）；
- 计费单位（15 / 30 / 60 分钟，默认 30）；
- 开台费项目：可选，按它的价格收一次。

选的项目要启用，不能是技师项目。只改业态的旧页面不会把计费清掉；去掉一个业态时，它的计费一起去掉。没设计费的业态照旧不收费，所以升级后什么都不变。

**怎么算**：用了多久按「开单 → 结束」，分钟向下取整。
- 起步以内按起步算；之后每个计费单位计一次，不足一个单位按一个单位。
- 房费记一条明细：数量 = 几个单位，单价 = 每小时价 × 单位分钟 ÷ 60，四舍五入到分。名称是「派对房房费（每 30 分钟）」。
- 开台费记一条。
- 例：每小时 ¥300、起步 60、每 30 分钟，用了 95 分钟 → 计 120 分钟 → 4 × ¥150 = ¥600。

**什么时候挂**：结束使用时，挂到使用人的手牌账单上。
- 明细来源记「其他」，部门按项目的分类。
- `space_usage_charges` 记下这条明细是哪张使用单的房费 / 开台费，以及用了多久、按多久计费（只追加）。
- 使用人结账前要先结束（`USAGE_UNCHARGED`）。结账预览列出这几间房、到此刻用了多久、房费约多少，有客房权限的在结账对话框里点「结束使用并挂房费」。
- 不在结账时自动结束：免得结账金额与核对时不一致，也免得漏收。
- 撤单（开错了）、撤销来访不收。
- 房费项目停用了：结束时拒绝（`USAGE_PRICE_ITEM`），请店主改计费。

**会员的包房房费折扣（QY-011，N3、M44）**：派对房的房费明细只在它的营业日是周一至周四时打；开台费、其他消费不打。这些明细在结账的折扣、券的计算里都标出来，与客房房费同一个折扣。

**页面**：
- 平面图侧栏：「到现在房费约 ¥X」；
- 结束使用的对话框：写计费方式与到此刻的金额，结束后提示挂了多少；
- 结账对话框：「结束使用并挂房费」。

**锁**：结束计费的使用单是「来访 → 账单 → 使用单一行 → 当前位置」，与结账同一个顺序；不计费的照旧只锁使用单一行。

## 4. ③ 预约（迁移 `053`，N4；小程序第三期 3d，MP34–MP37；客房电话预订，飞书 Q17）

**三种**
- **技师**：需要技师的项目 + 技师或「不指定」。时长按项目的服务时长，没写按 60 分钟。能约的技师：在职、能做这个项目（技师等级与项目档位，与派钟相同）。
- **派对房等**：开单即占用的房间（启用、可售）+ 时长（2 / 3 / 4 小时可选）。
- **客房（电话预订）**：房型 + 预计到店。保留到预计到店后 60 分钟，过了自动释放、记爽约。

**能不能约（占时段）**：「待确认」「已预约」的预约占时段；到店、取消、爽约的不占。
- 技师：同一位技师不重叠；还要避开他正在上的钟、排着的钟（按钟数 × 时长算）。「不指定」按这个时段空着的技师数，减去同一时段别的「不指定」预约。
- 派对房：同一间房不重叠；正开着的使用单当作占到「此刻 + 60 分钟」。
- 客房：当天这个房型的预约数不超过房间数（启用、不在维修的）；当天的还要减去在住的。
- 时段：每个营业日 11:00 到次日 02:00，半小时一格，要在结束前做完；最远约 7 天后。前台、电话可以约格子之间的时刻（例如 14:10）；小程序只能选格子。

**来源与状态**
- 前台、电话：直接「已预约」。小程序：「待确认」，前台点「确认」。
- 不收订金、不动钱（MP36）。会员可以不填：写客人姓名或电话也行。小程序的一定是会员。
- 改时间、改技师带版本号，别人刚改过拒绝（`BOOKING_CHANGED`）。

**到店**：客人先在前台接待开手牌，再在预约看板点「到店」、填手牌号。
- 派对房：直接用这张手牌开使用单（开单即占用，备注「预约 YY…」），之后照常结束、计费。
- 技师：去钟房派钟（指定了技师的选这位、点钟）。
- 客房：去客房开房（选这个房型的一间）。
- 手牌没有在店客人拒绝（`TAG_NOT_IN_STORE`）。

**每分钟的自动处理**（应用自己跑，与会员到期处理同一个定时）
- 小程序的预约开始前 60 分钟还没确认的，自动取消（MP35）；停机后补跑时，过了开始时间的也是取消，不算顾客爽约。
- 过了开始时间 30 分钟还没到店的，记爽约（MP37）；客房按保留时间。
- 一张一个事务；锁住以后按最新的时间再核对，刚改到以后的不动。

**爽约限制（MP37）**：90 天内爽约 3 次的会员，最后一次之后 30 天不能在小程序预约（前台、电话照常能约）。小程序：每人同时最多 2 个没到店的预约（MP34）；开始前 2 小时以内不能自己取消，请打电话给门店。

**页面**
- 门店导航「预约」（权限「预约」，店主、店总、值班经理、店员默认有）：按天看，技师、派对房等、客房分三组；新建、确认、改时间、到店、取消、记爽约。写操作与前台一样有「结果待确认」。
- 后台「预约」：上面这些数字都能改（只有能改经营规则的岗位），规则总表里有。

**接口（前台）**：`GET /api/bookings?date=`（看板）、`GET /api/bookings/slots`（可约时段）、`GET /api/bookings/:id`、`POST /api/bookings`（新建，操作类型 `booking_create`）、`POST /api/bookings/:id/change`（`confirm` / `reschedule` / `arrive` / `cancel` / `no_show`，操作类型 `booking_change`）、`GET|PUT /api/admin/booking-rules`。

## 5. ④ 次卡（迁移 `054`，N5）

**卡种**（后台「价目与套餐 → 次卡」，能管理价目的岗位）：能抵哪些价目项目、哪些票种，几次（1–100），售价，有效期（天，空为长期；默认 365 天）。改卡种只影响之后卖的卡——卖出去的卡记下当时的名称、能抵什么、几次、售价与到期日。停售的卡种不再出现在售卡里。

**售卡**（会员详情「次卡 → 售次卡」，前台岗位都能做，权限「售次卡」）：
- 只卖给会员（停用、已合并的不行）；现金类收款（现金、微信、支付宝、银行卡、其他），记到经办人当班的班次；
- 是收款、不是营业额（与充值一样）：进交班的应有现金（现金部分）、日结的「次卡」一节、对账包 `12-次卡.csv`；
- 页面上看到的卡种版本、售价与此刻的不一致时拒绝（`COUNT_CARD_TYPE_CHANGED`）；
- 动的是钱：超时、断网、回复 500 时「结果待确认」，在卡片上方查回、按原内容重新提交或「确认作废」（业务类型「售次卡」）。

**结账「用次卡」**（手牌结账对话框里的「次卡」）：
- 这次结账客人里的会员的可用卡（没过期、还有次数）列出来，写这张卡这次最多能抵几份；员工点「+」选抵几次；
- 一次抵一份：价目项目一份是一个数量，门票一位客人一份；单价高的先抵（同价先门票）；几张卡按卡号先后依次抵，前面抵掉的后面不再抵。页面与服务端用同一个分配算法，服务端在结账事务里按此刻的明细重新算，金额、次数对不上拒绝（`COUNT_CARD_CHANGED`）；
- 收款方式「次卡」：是会员的预付消费，与会员储值一样算营业额（应收、净营业额里都有）、不算实收；部门营业额按明细原价算，不分摊；
- 不和券、会员折扣、优惠 / 免单同时用（与它们之间一样二选一；用了次卡就不打会员折扣）；一张结账单最多 5 张卡；桌台结账不能用；
- 别的会员的卡不能用（`COUNT_CARD_NOT_IN_CHECKOUT`），同行朋友请合并到同一张结账单；
- 反结账：用掉的次数退回（过期的卡退回后由每分钟的自动处理再作废）。用过的卡之后退了卡的，那张结账单不能反结账（`COUNT_CARD_REFUNDED`：退卡时已按剩下的次数退了钱）。
- 退款单（离店后部分退款）照旧只退现金类收款；次卡抵的部分要更正请反结账。

**退卡**（店主、店总、值班经理，权限「退次卡」）：退剩下的全部次数；默认退 售价 × 剩下次数 ÷ 总次数（舍到分），可以改少、不能多（`COUNT_CARD_REFUND_EXCEEDS`）；现金从经办人当班的钱箱退，扫码、银行卡、其他登记退款单号或写明怎么退；不能作废。

**过期**：过了有效期没用完的次数作废，不退钱（每分钟的自动处理，一张一个事务）。日结里单列。

**旧次卡期初**：`node dist/server/cli.js import-count-cards <旧次卡.csv> --operator <店主账号> [--batch 备注] [--apply]`。表头：手机号、会员号（二选一）、卡名、能抵的项目、能抵的票种（名称，顿号隔开）、总次数、剩余次数、原售价（元，可空，退卡时按它折算）、到期日（可空）。只记次数、不是收款、不进交班；默认只预览，有一行不对整批不写。

**日结、交班、对账包、自检**：
- 日结「次卡」一节：售卡收款（按方式）、退卡、结账使用（净次数与按项目价的金额）、过期作废、期初、当天结束时还剩几次；升级前确认的日结按 0 补齐；
- 交班：本班次卖的卡、退的卡；应有现金加卖卡的现金、减退卡的现金；
- 对账包 `12-次卡.csv`：当天次数的每一笔变动；
- 自检：每张卡剩几次 = 变动之和；结账收款里的「次卡」= 那张结账单的使用记录；退卡单与卡一致。

**锁**：售卡：操作编号的咨询锁 → 经办人的班次（共享锁）→ 会员一行（共享锁）→ 卡种一行（共享锁）；退卡：操作编号的咨询锁 → 班次（共享锁）→ 卡一行；结账用次卡、反结账退回：在结账已有的锁（含券）之后按卡的 id 升序锁卡；过期：一张一个事务、只锁那张卡；改卡种只锁卡种一行、带版本号。

**迁移 `054`**：新表 `count_card_types`、`count_cards`、`count_card_refunds`（只追加）、`count_card_moves`（只追加）；结账收款加方式 `count_card`（记卡与次数）；「确认作废」加业务类型 `count_card_sale`、`count_card_refund`。不改已有的行。

## 10. ⑨ 按钱箱交班（迁移 `059`，N11）

**交班方式**（后台「经营规则」→「交班方式」）：「按人交班」（默认，就是现在的做法）或「按钱箱交班」；钱箱清单默认一个「1 号钱箱」，编号保存后不变，不能删、只能停用。**切换不用等大家交班**：开着的班照旧到交班为止，之后新开的按新做法。

**按钱箱交班**：开班时选钱箱、登记备用金；同一个钱箱同时只有一个开着的班次，已经开班的钱箱点「加入」。收款（充值、结账、反结账、退款单、退储值、次卡、客房押金……）记到经办人此刻所在的班次，就是他加入的钱箱的班次。可以中途「离开钱箱」（下班、换钱箱）：班次照常开着，钱等交班时一起点；之后本人的收款不再记进来（收款前要先开班时整笔拒绝）；离开之前开始、离开之后才入账的收款整笔拒绝（「这笔没有入账」，加入钱箱后重新办理）。一位员工同时只在一个班次上。**交班**：此刻在这个钱箱上的人（或值班经理及以上）点钱交班，在上面的人一起离开；应有现金的算法不变（备用金 + 这个钱箱所有人收的现金 − 退的现金……）；交班表另列「各人经办」（每人结账几张、充值几笔与金额），反结账、退款单、退储值都写明是谁办的；跨钱箱退款选钱箱时显示钱箱名。停用的钱箱还开着班时照样能加入、交班，不能再新开。会员工作台的储值消费（不是收款，只作参考）按每人在钱箱上的时段算。

**按人交班**：与原来一样（一人一个班次，本人交本人的班，值班经理及以上可以替交）；班次上只有开班人自己，不能加入、离开。

**看得到的地方**：交班页（钱箱名、在上面的人与时段、离开钱箱、各人经办）、交班表（浏览器打印与小票机）、对账包的「05-交班」（员工一列写钱箱与待过的人）、看板「当班中」（钱箱名与此刻在上面的人）、后台规则总表。

**锁**：开班：本人此刻不在任何班次上（当班成员的唯一索引兜底）→ 新班次（「一个钱箱一个开着的班次」唯一索引兜底）；加入：班次一行（共享锁，与交班串行）→ 写当班成员；离开：只锁本人那条当班成员（交班时也改它，二者串行）；收款照旧在锁业务行之前对经办人此刻所在的班次加共享锁（经当班成员找），交班照旧只对班次加排他锁，在上面的人一起离开（触发器改当班成员）。

**迁移 `059`**：班次加钱箱与钱箱名；当班成员表 `shift_members`（只追加：加入、离开各记一次；升级时已有的班次按开班人补一行，开班时加入、已交班的在交班时离开）；开班人自动加入、交班时一起离开（触发器）；原来的「一人一个未交班班次」唯一索引换成「一位员工同时只在一个班次上」，另加「一个钱箱一个开着的班次」。不改已有的行。前台自检加「班次与当班的人一致」。

## 11. ⑩ 旧 EBC 逐笔流水只读导入（迁移 `060`，N12）

**做什么**：旧系统（EBC）导出的会员逐笔流水（充值、消费、赠送、退卡、调整……）按模板导入两张只读表，会员详情「旧系统流水」里看（含合并进来的档案的，新的在前，一次 20 条，「更早的」往前翻；没有旧流水的会员不显示这一块）。**只读、不进正式账**：不写余额流水、不改会员余额与档阶，余额照旧以期初导入为准。

**模板（CSV，UTF-8 或 GBK 都行）**：列 `手机号, 旧卡号, 姓名, 时间, 类型, 金额, 赠金, 余额, 赠金余额, 单号, 门店, 经办人, 备注`（也接受英文表头 `phone, legacy_no, name, time, type, amount, bonus, balance, bonus_balance, doc_no, store, operator, note`）。时间、类型、金额必填，手机号与旧卡号至少一个。时间写 `YYYY-MM-DD` 或 `YYYY-MM-DD HH:MM[:SS]`（「/」「.」也行），按门店时区。金额单位元、最多两位小数，可以是负数（照旧系统的正负，可以带 ¥ 与千分位）。类型照原文保存，另按关键字归类（退 → 退款，消费 / 扣 → 消费，充值 / 储值 → 充值，赠 / 送 → 赠送，调 / 冲 / 撤 → 调整，其余为其他），只用于显示的颜色。一次最多 10 万行。

**认会员**：先按旧卡号（有效的期初导入记下的，同一个旧卡号对应两位会员时不按它认），再按手机号。认不出的行**不导入**（预览与结果里列出行号），其余照常导入；格式不对的行有一行就**整批不导入**。

**导入与作废**（店主；与期初导入同一项权限）：后台「期初导入」页下方「旧系统逐笔流水（只读）」选文件 → 预览（认出几行、几位会员、按旧卡号 / 手机号各几行、认不出的行、时间范围与各类合计）→ 确认导入；或命令行 `import-member-history <流水.csv> --operator <店主账号> [--apply]`（默认只预览）。带操作编号，同一编号重提返回第一次的结果；**同一份文件（内容摘要相同）只能有一批有效导入**。导入记录可以整批作废（写原因），作废后页面上不再显示，同一份文件可以重新导入。

**锁**：只写自己的两张表，不锁业务行；同一份文件同时导入两次靠「一份文件一批有效导入」的唯一索引兜底。

**迁移 `060`**：新表 `member_history_imports`（导入批次：来源、文件名与内容摘要、行数、认出 / 没认出的行、几位会员、时间范围、经办人、作废）与 `member_history_rows`（每行一笔：会员、怎么认出的、时间、类型原文与归类、金额、赠金、余额、赠金余额、单号、门店、经办人、备注、原始内容）；流水行只读，导入记录只能作废一次。不改已有的行。
