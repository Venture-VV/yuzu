# 浴族设计语言

**城市度假 × 山野自然 × 年轻当代。** 一间开在城市里的年轻山野汤泉：米白纸感的底色、石材般的线条、松林绿的秩序，再用一点柚黄让界面有呼吸感。品牌表达集中在登录页、侧栏和少数氛围位置，工作区保持清楚、轻快、数字好读。

令牌定义在 `src/client/styles.css` 的 `@theme` 中，组件在 `src/client/components/`。动效见 [`UI_V8016.md`](UI_V8016.md)，三台目标设备见 [`DEVICES.md`](DEVICES.md)，二级页签与后台的信息架构见 [`IA_V8017.md`](IA_V8017.md)。字号、公共部件清单与「写成检查的约定」三节是工程治理三期（`GOVERNANCE.md`）按现状补的。

**金额语义固定**：本金 = 松林绿，赠金 = 柚黄，实收 = 湖水青，撤销 = 陶土红。同一种钱在所有页面颜色一致，避免把收款、储值消费、赠金混成一个含义不清的数字。

### 深浅两套主题（8.1.15）

《浴族系统需求汇总》系统整体：深浅两套主题，文字对比度不低于 4.5 : 1。

- **只换变量**：`src/client/styles.css` 里 `:root[data-theme='dark']` 一段把上表的令牌换成深色的值，页面照旧写 `bg-paper`、`text-ink` 这些色名，不为深色另写一套类。`<html data-theme>` 由 `src/client/lib/theme.ts` 设：用户菜单「外观」（浅色 / 深色 / 跟随系统）与后台、ERP 顶栏的小按钮里换，记在这台设备的浏览器里，默认浅色。
- **一律浅色的页面**：对客的（平板电子菜单、导览大屏、扫码打开的页面）、要出纸的（打印）、工作台（画布要和对客看到的一样）、登录页（`themeLocked`）。
- **写页面时**：颜色只用令牌——不写十六进制（`npm run check:gov` 记数，只降不升），不写 `bg-white` / `text-white`（深色里会变成刺眼的白块）；橙色的字用 `text-ember-deep`，柚黄、橙色色块上的字用 `text-on-bright`；深底条（`data-surface="rail"`）里照旧写 `text-paper`，那里的「纸色」指回浅色。
- **核对**：`tests/theme-contrast.test.ts` 从样式表读两套变量，逐对核对常见的「字 / 底」（正文与次要文字在四种纸色上、各语义色在自己的浅底上、色块上的字、主导航）都不低于 4.5 : 1，`ink-4` 不低于 3 : 1。改颜色、新加一种写字的颜色先跑它，并把它常见的底加进清单。

## 字体

- 中文：设备系统字体（苹方 / 鸿蒙 / 微软雅黑），保证阅读与离线可用。
- 拉丁字母与数字：**Plus Jakarta Sans**（可变字重，随应用打包），金额统一使用等宽数字（`.num`）便于纵向核对。
- 品牌展示：**Instrument Serif** 斜体，只用于 `yuzu` 字标与少量英文 / 数字标题，不用于中文。
- 金额组件 `<Money>`：¥ 符号缩小、分位弱化，一眼读出整数部分。

## 形状与层次

- 圆角：8（小按钮、标签）/ 12（按钮、输入框）/ 16（卡片）/ 22（弹层）。
- 阴影克制：卡片只有极浅的投影，弹层使用较深的柔和阴影。
- 触控区域：主要操作按钮高 48–56px，列表行 ≥ 56px，步进器按钮 36px。

## 布局

- **会员工作台**（≥1280px）：左栏搜索与会员列表，中栏会员身份与余额，右栏为「今日概览」或正在进行的充值 / 消费流程。会员信息在操作期间始终可见、位置不变。1280–1535px 两侧栏收窄为 288 / 380px，≥1536px 为 320 / 400px。
- 余额卡片按**卡片自身宽度**（容器查询）决定排列：宽度足够时合计 / 本金 / 赠金三栏并排，否则合计单独一行、本金与赠金并排。金额不截断、不缩略。
- 侧栏内的卡片不允许被压缩，屏幕较矮时整栏滚动。
- 900–1279px（平板横屏）：两栏，流程以右侧面板滑出。
- < 900px（平板竖屏）：单栏，列表与详情切换。
- 流水在宽屏为表格，平板为卡片列表。

## 流程与状态

- 充值、消费都是三步：**填写 → 核对 → 完成**。核对页展示会员、金额、扣款构成和「之前 → 之后」余额；完成页用数字过渡动画说明余额变化。
- 「结果待确认」的操作关闭面板后不会丢失：页面顶部显示黄色提醒条，进入对应流程时先处理原操作，再开始新的一笔。
- 每种状态都同时用文字和图形表达：成功（描线勾）、失败（红色提示）、待确认（黄色提示 + 查询按钮）、空状态（线描小图 + 一句话 + 操作）、加载（骨架屏）。
- 动效只用于帮助理解结果（弹层滑入、余额数字过渡、勾选描线），尊重系统「减少动态效果」设置。

## 键盘

`/` 搜索会员 · `↑ ↓ Enter` 选择 · `R` 充值 · `X` 消费 · `N` 新建会员 · `Esc` 关闭面板。按钮上以小键帽提示。

## 字号

页面里的字号是直接写的（`text-[13px]`），没有进令牌。2026-11-18 实测 4,198 处、32 种，九成集中在八种：

| 字号 | 处数 | 用在哪 |
| --- | --- | --- |
| 13px | 1,081 | 正文、表格、表单 |
| 12.5px | 1,033 | 次要文字、表格里的说明、密一点的列表 |
| 12px | 806 | 标签、辅助说明、角标旁的字 |
| 14px | 318 | 强调的正文、按钮、小标题 |
| 13.5px | 243 | 介于正文与小标题之间（多在前台与会员工作台） |
| 11.5px | 179 | 辅助说明、时间、单号 |
| 15px | 165 | 卡片里的小标题、主要按钮 |
| 11px | 111 | 角标、最弱的说明 |
| 16 / 18px | 122 | 卡片标题、弹窗标题 |
| 20 / 22 / 24 / 26px | 116 | 页面标题、要一眼看到的数字 |
| 其余 18 种 | 约 120 | 9–10.5px 是打印页与图上的小字；28px 以上是金额大数字与展示位；14.5、17、19、21 各几十处以内 |

**规矩**：

- 新页面只用上表里已有的字号；治理基线（`npm run check:gov`）会拦下新出现的字号。
- 优先用最常见的那几档：正文 13、次要 12.5 或 12、强调 14 或 15、标题 16 / 18 / 22。
- 13.5、14.5、11.5、10.5、9.5 这些半号和 17、19、21 是历史形成的，不要再扩散；它们要不要并到相邻的整数档（会动 500 多处的外观）等店主定（`PENDING_DECISIONS.md` ZL2）。
- 平板电子菜单、员工手机端、UI 工作台有各自的版面规格（`EMENU.md`、`CANTEEN.md`、`WORKBENCH_V811.md`），不照这张表。

## 写成检查的约定

下面这些不靠自觉，`npm run check:gov` 会查（`GOVERNANCE.md` 第 8 节）：

- 页面代码里不新写十六进制颜色（颜色用上面的令牌：`text-pine`、`bg-paper-2`、`var(--color-clay)`）；插画、打印页、房态图、设计工具里已有的记了基线。
- 不出现新的字号。
- 判断断网用 `lib/connection`，不看 `navigator.onLine`；判断「服务端明确没处理」用 `lib/api` 的 `isRejected`，不手写 `status < 500`。
- 新的定时取数用 `lib/livePoll` 的 `useLivePoll`，不用 `refetchInterval`。纯界面的计时器（倒计时、轮播）照常用 `setInterval`，不在此列。
- 行内样式（`style={{ … }}`）里不写 dvh，用类名（`h-dvh`、`max-h-[88dvh]`）。
- 列表里的部件要有 `key`（`npm run lint`）。
