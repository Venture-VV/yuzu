## 1. 现状（v0.7.11）

- 退供应商单按原收货单的价格算金额；确认（或负责人确认）后立即从原收货单的仓出库，挂账供应商记「退货扣款」（应付流水负数），并直接冲减原收货单的未付。原收货单已经付清时，未付会变成负数，没有地方再用。
- 付款必须全部核销到具体货款（收货单、期初未付），不能登记预付款；没有供应商退款。
- 低库存提醒按物料上的固定数量，只看总仓。
- 供应商、期初未付只能逐条登记。
- 员工的职责可以随意组合；「需要负责人确认的单据」按单据类型开关，没有金额门槛。

## 2. 退货待供应商确认（#20）

1. 物资经办或采购经办登记退货（选原收货单，按原收货价算金额）→ 提交；「退供应商」需要确认且金额超过门槛时，负责人确认。
2. 之后进「待供应商确认」：库存、货款都不动，货还在原收货单的仓里；单据内容不能再改。
3. 与供应商谈妥后，采购经办（或店主）登记供应商的答复（新权限「登记供应商对退货的答复」，默认给采购经办，岗位权限里可调）：
   - **供应商已同意**：写明同意日期、对方联系人或说明 → 单据生效：从原收货单的仓出库（库存不够时拒绝）；挂账供应商记退货扣款。
   - **供应商不同意**：写明原因 → 单据撤回，库存不动。
   - 只同意退一部分：先登记「不同意」撤回，再按同意的数量重新登记。
   - 等待期间登记人、负责人与采购经办可以撤回（写原因）。
4. 待供应商确认的退货在库存工作台列出，超过 7 天标红。
5. 退货扣款先抵原收货单还没付、也没在待确认付款里的部分（有待确认的付款时不去抢那部分，免得付款确认时超额）；多出来的是这张退货单的**退货余额**，见第 3 节。
6. 冲销已生效的退货：当月、物资经办或成本核算；退货余额已经核销或退款的，要先冲销那一笔。

现付供应商的退货：生效时出库，不记应付；供应商退回的钱登记为供应商退款（关联这张退货单，不记应付）。

迁移前已生效的退货照旧算数：迁移按「付款优先」补记它抵了原收货单多少（原收货单已经付清的，超出的部分记为退货余额），不改金额、不改流水。

## 3. 预付款、退货余额、核销与供应商退款（#25、#20）

供应商往来分两边：

- **应付**：挂账收货的货款、期初未付。未付 = 金额 − 付款核销 − 核销抵扣（退货抵原收货单也是一笔核销）。
- **可抵扣**：
  - **预付款**：付款时没核销到具体货款的部分（付款金额 − 付款核销）。
  - **退货余额**：退货扣款里没抵到原收货单的部分。

可抵扣的两种用法：

- **核销**（对账付款）：把可抵扣的金额核销到这个供应商以后的应付（收货、期初未付）；不动钱、不记应付流水，只改未付。登记即生效，不用负责人确认（待确认）；冲销同其他财务单据（当月，对账付款、成本核算）。
- **供应商退款**（对账付款）：供应商把钱退回原付款账户；登记退款日期、方式、凭据，挂账的记应付流水「供应商退款」（正数，把负的往来余额补回来）。登记即生效（待确认）；冲销同上。

付款登记：核销合计可以小于付款金额，差额记为预付款（页面上要勾选「其余记为预付款」）；仍然不能大于付款金额。付款的预付部分已经核销或退款的，要先冲销那一笔才能冲销付款。

供应商余额 = 应付流水合计 = 应付未付合计 − 可抵扣合计；负数表示供应商欠我们。对账单加「核销」「供应商退款」两类，应付货款页列出每个供应商的可抵扣。

## 4. 运费单独记费用（#15）

- 费用科目加「运费」；报销按采购单时可以单独加一行运费（不对应物料）；按次报销也可以选运费。
- 运费不进物料成本、不进收货金额；采购台账、费用汇总按「运费」单列。
- 一般情况仍按含运费的到货价记，不用另外操作。

## 5. 按可用天数提醒（#22）

- 物料加「提醒天数」（1–90 天，可空）：一般用品建议 7 天，新鲜食材 1–2 天。
- 日均用量 = 近 28 天（后台「规则总表 → 库存与采购」可调，待确认）这个仓的用量 ÷ 天数：总仓按领料、直接领用、报损；部门小仓按耗用（盘点差异为耗用）、报损、直接领用。退供应商、冲销不算用量。
- 可用天数 = 结存 ÷ 日均用量；少于提醒天数时提醒：总仓在库存工作台，部门小仓在「本部门小仓」。
- 没设提醒天数，或这个仓近期没有用量的，仍按原来的「低库存提醒数量」（只看总仓）。

## 6. 供应商与期初未付批量导入（#16）

- ERP「应付货款 → 导入」：下载模板 → 上传 CSV 或 Excel（CSV 在页面上自动识别 UTF-8 / GBK；Excel 读第一张工作表，最多 2000 行）→ 预览（逐行校验：编码重复、名称为空、结算方式、金额与日期格式、供应商不存在）→ 写入。有错误的行不写入，整份文件要么全写、要么不写。
- 供应商：编码、名称、联系人、电话、结算方式（挂账 / 现付）、备注；编码已存在的拒绝，不覆盖。
- 期初未付：供应商编码、金额、截至日期、备注；写入后按「期初」规则走确认（超过门槛的进负责人待办，可以一次确认整批）。
- 同一个文件（按内容摘要）只能写入一次；导入记录留经办人、时间、行数。
- 真实业务数据：门店环境须店主同意才执行（同其他导入）。

## 7. 分岗不兼任（#17 后半句）

- 五组职责：仓库（物资经办）、采购（采购经办）、部门（部门申购）、财务（对账付款、成本核算可以同时有）、负责人（确认）。员工的职责只能在一组里；店主不受限制。
- 后台保存员工时拒绝跨组（`DUTY_CONFLICT`，停用的员工不查）；已有跨组的员工不自动改，后台员工页标出来提示（不进 `check`），下次保存这名员工时要先改成一组。
- 单据上原有的限制照旧：一起验收的采购不能是自己、急采验收不能是登记人。

## 8. 免确认门槛（#18）

- 后台「规则总表 → 库存与采购」加「免确认门槛」（默认 ¥2,000.00，可调）：采购单、报损、退供应商、付款、期初未付、期初库存，在设为「需要负责人确认」时，金额不超过门槛的也不用确认，提交即生效。
- 金额按提交时的单据金额判断；报损没有价格，按物料参考价估算，没有参考价的照旧要确认。
- 总仓盘点调整照旧要确认；部门小仓的盘点照旧不用确认；急采照旧要仓库到部门验收。

## 9. 迁移 `030`（只加不改）

- `inv_docs`：状态加「待供应商确认」；加供应商答复的经办人、时间、说明几列（生效后不能改）；单据、明细保护触发器按新状态更新（待供应商确认时内容不能改）。
- 新表：核销（可抵扣 → 应付；含冲销几列）、供应商退款（含冲销几列）；`ap_entries` 加「供应商退款」类型与关联列；审批记录加新单据类型与动作；操作编号与「确认作废」登记认核销、供应商退款两种业务。
- 迁移前已生效的退货：补记它抵原收货单的核销（见第 2 节）。
- 费用明细的科目加「运费」；物料加「提醒天数」；导入记录表。
- 设置：免确认门槛、用量统计天数（设置表，不改结构）。

## 10. 自检

- 每个供应商：应付流水合计 = 应付未付合计 − 可抵扣合计。
- 核销、退款都不超过可抵扣余额；核销不超过对方的未付。
- 待供应商确认的退货没有库存流水、没有应付流水。

跨组兼任的员工只在后台员工页提示，不进 `check`（不是账的问题）。

## 11. 实现说明（v0.7.12）

- **锁顺序**：
  - 付款、期初未付、核销、供应商退款与它们的冲销：供应商（`FOR NO KEY UPDATE`）→ 可抵扣的一方（付款、退货单）→ 应付的收货单（id 升序）→ 期初未付（id 升序）。
  - 退货生效（登记供应商同意）：退货单 → 原收货单 → 物料（同其他库存单据）；不锁供应商。原收货单在锁内重算还没付的部分，与付款、核销串行。
  - 冲销收货单、退货单：先锁单据，再查有没有核销、退款引用它；核销、退款登记时锁住可抵扣的一方再核对状态，两边谁先拿到锁都不会漏查。
  - 批量导入：同一个文件按内容摘要加事务级咨询锁；写期初未付时按供应商 id 升序锁供应商。
- **接口**：`POST /api/inventory/docs/:id/supplier-answer`（同意 `{ agreed: true, date, note }`；不同意 `{ agreed: false, note }`，note 写原因）；`GET /api/payables/suppliers/:id/credits`；`/api/payables/offsets`、`/api/payables/refunds`（列表、按操作编号查、详情、登记、`/:id/void` 冲销）；`/api/payables/imports`（列表、`/preview` 预览、登记写入、`/:id/approve-openings` 负责人一次确认整批）。
- **结果待确认**（AGENTS.md）：核销、供应商退款与费用报销一样，提交前把操作编号与原请求存在本机并读回核对（存不了就不发请求）；断网或超时后在应付货款页上方按原编号查回、按原内容重新提交（同一编号只登记一次），或在服务端确认作废（`/api/erp/ops`，类型 `ap_offset` / `supplier_refund`，作废要能登记这项业务），作废后原请求晚到也不登记；还有一笔待确认时不能再登记同一类的新一笔。
- **权限**：登记供应商答复 `supplierReturn.answer`（采购经办）；核销、供应商退款 `payable.manage`（对账付款）；冲销 `finance.void`（对账付款、成本核算）；导入供应商要能编档案（`inventory.master`），导入期初未付要 `payable.manage`。
- **退货抵了原收货单多少**记在退货单的 `return_applied_cents`：挂账的退货生效时 = min(退货金额, 原收货单当时还没付的部分)；现付的退货为 0（整笔等供应商退款）；迁移前已生效的现付退货记为整笔（以前的退款已按旧办法处理）。
- **演示数据**：免确认门槛设为 0（全部要负责人确认，固定预期里的待确认单据才会停在待确认）；采购（周一）与对账付款（钱芬）分成两个人；退货 SR-001 由店主确认、周一当天登记供应商同意。
