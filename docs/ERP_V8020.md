# 8.0.20 设计 · 进销存做深 + 客房点餐、会员联动房价

排期见 `docs/SCHEDULE_V8020.md` 第 2 节；默认做法 JX1–JX8 店主 2026-11-14「全部都按照默认」已确认，本文件里再细分出来的（JX9 起）标「待确认」，记在 `docs/PENDING_DECISIONS.md`。功能开关都默认开（KG1–KG4，迁移 `126`）。

现状（开工前读代码核对的）：

- 物料只有参考价（`ref_price_cents`，按采购单位），没有成本；库存流水 `stock_moves` 不记金额。唯一的估值在呆滞报表里，按最近一次进价。
- 库存流水只有一个写入点 `applyMove`（`modules/inventory/common.ts`），调用前物料行已经按 id 升序锁住——同一物料所有仓的收发本来就是串行的。
- 买一赠一的赠品出库（8.0.4）是现成的样子：结账事务里只写一条待出库记录，不碰库存；每分钟的任务再按那条记录自己的操作编号开「耗用单」、反结账时作废。
- 价目项目 `service_items` 没有和物料的关系；餐饮的菜就是带档口的价目项目，出品单 `kitchen_items` 有 `queued → cooking → done → served`，可以撤回（`undo`），退菜不分出没出品。
- 客房：住客一定有来访与手牌，房费挂在来访的账单上；房型只有一个价，`room_stays.rate` 入住时定死；会员折扣（QY-011 之类）结账时对「客房」明细打折。
- 采购：补货建议只读；`createPo(action:'save')` 能建草稿，草稿算在途、不会重复建议。

## 1. 成本核算（JX-C，迁移 `127`）

**口径**：移动加权平均，含税到货价（与 `inventory_price_basis` 一致），按物料全公司一个成本（不分仓；仓与仓之间挪动不改成本）。

- `materials.avg_cost_e4`：每个库存单位的平均成本，单位「万分之一分」（整数；1 元 / 件 = 1,000,000）。`materials.cost_estimated`：成本是估的（升级时按最近一次进价、没有进价按参考价回填），第一次真的入库重算后变成否。
- `stock_moves.unit_cost_e4`、`cost_cents`：这一笔流水当时的单位成本与金额（出库为负）。升级前的流水这两列是空的，报表写「没记成本」。
- `applyMove` 多一个可选的 `valueCents`：
  - **收货**（带金额入库）：`新平均 = (全部结存 × 原平均 + 这次金额) ÷ (全部结存 + 这次数量)`；全部结存 = 总仓 + 各部门小仓。
  - **作废收货、向供应商退货**（带金额出库）：反过来算；结存减到 0 时平均成本保持不变。
  - **其余**（领用、退回、耗用、报损、盘点调整，以及它们的作废）：按当时的平均成本记金额，不改平均成本。期初入库：物料还没有成本时按参考价起算。
  - 「还没有成本」= 平均成本是 0 **而且还是估的**。按进价收过货、平均成本真的是 0 的（赠送、零元进货）就按 0 算，不拿参考价顶（合并前 Codex 审查 `b850838`）。
- 取整：金额四舍五入到分；平均成本向最近的整数取整。重算在已经锁住的物料行上做，不另加锁。
- **报表**（ERP「库存 → 成本」，只读）：库存金额（按物料、按仓）；部门耗用成本（按部门、用途、日期段；按「耗用、报损」的流水认，不按单据类型认——台面日耗品领到部门、急采进部门小仓时记在领料单 / 收货单下面的那笔耗用也算，作废冲回的跟着减）；项目毛利（日期段内已结账的数量与金额 × 配方按当前平均成本算的**理论成本**，页面写明是理论值）。看得到的人：有「看成本」职责的（与营销成本同一个做法）。

## 2. 用料与配方、销售与出品扣库存（JX-A、JX-B，迁移 `128`）

**一张表管两样**：零售品（一瓶水 = 物料 1 瓶）就是只有一行的配方。

- `item_recipes`（项目的用料，带版本）：`item_id`、`version`、`status active|retired`、`warehouse_id`（从哪个仓扣，空 = 按规则里的默认）、`note`；同一项目同时只有一份在用（部分唯一索引）。改用料 = 旧的停用、写一份新版本，已经发生的扣料不回头改。
- `item_recipe_lines`：`material_id`、`qty_milli`（一份用多少，库存单位的千分之一）、`loss_bp`（损耗率，万分比，0–5000）。一份实际扣 = `qty × (1 + 损耗率)`，按物料的小数位向上取整。
- **什么时候扣**（JX3）：
  - 进厨房 / 水吧的（有出品单的明细）：出品单到「出品完成」（`done`）时扣；撤回到制作中 / 排队时冲回；补录的（一建就是已上桌）建单时扣。退菜：没出品的本来就没扣，已出品的不退料。
  - 不进厨房的（零售、不走出品的饮品）：结账生效时按结账单上有效的明细扣；反结账冲回，重新结账再扣。
  - 退款单不动库存（JX9）：退款单只记钱、不记是哪件东西；东西真的退回来了走盘点或报损的反向。
- **怎么扣**（学赠品出库，业务事务里不碰库存锁）：
  - 业务事务里只往 `stock_usage_events` 追加一行（只增不改）：`kind sale|recipe`、`sign +1|-1`（冲回是一条 −1，指向原来那条）、来源（结账单 / 出品单）、物料、仓、数量、营业日。
  - 每分钟的任务 `processStockUsage`：按「种类 + 仓 + 物料」把还没入账的事件**轧差**——正的减冲回的；净数大于 0 且库存够的，合成一张「耗用单」（用途写「销售出库」或「配方耗用」，系统经办），一轮一个仓最多一张；净数是 0 的直接记成已轧平；净数小于 0 的留着，等后面的正数来抵（反结账后通常马上会重新结账）。
  - 库存不够的那样物料先不扣、留着（JX1：不拦结账、不拦出品），列在「待扣料」里，库存补上后自动扣。数据库不允许结存为负，所以不是记负数，而是「欠着没扣」，数量看得见。
  - 批次 `stock_usage_batches` 带自己的操作编号；开单后没记下结果的，下一轮按操作编号对账（已经开出来的认下，没开的放回去重来）。
- **规则** `stock_usage_rules`：`enabled`（默认开）、`saleWarehouseId`、`recipeWarehouseId`（默认总仓；配方上可以单独指定）。关着时不记事件。
- **页面**：ERP「库存 → 用料与扣料」：哪些项目设了用料、编辑用料（选物料、数量、损耗率、从哪个仓扣）、待扣料（缺货的、等着轧差的）、最近的出库批次。没设用料的项目不扣，和现在一样。
- **锁与幂等**：记事件在结账 / 出品的事务末尾，只插入、不加锁；出品单一行本来就锁着，同一张出品单「完成 ↔ 撤回」的事件是串行的；结账单一行锁着，同一张结账单只记一次（唯一索引：来源 + 物料 + 符号 + 第几次）。任务先取「扣料任务」的咨询锁（同一时刻只有一个在跑），开单走库存单据原来的锁。

## 3. 自动补货（JX-D，迁移 `129`）

- 规则 `auto_replenish`：`enabled`（默认开）、`time`（默认 05:30，门店时区）。
- 每天过了这个时间，任务把「补货建议」里有供应商的行按供应商各建一张**采购单草稿**（系统经办，备注「自动补货 日期」），不提交；没有供应商的行只在记录里写「缺供应商」。同一天只跑一次（`replenish_runs` 的日期唯一）；草稿算在途，第二天不会重复建议。
- **与补货方式（迁移 `161`，`docs/ERP_PURCHASING.md` 第 5.1 节）的配合**：自动补货只按补货建议的 `groups` 建草稿，识别为不用备货的（按需采购、建过资产卡片、一次性采购）不建。两处接上了：① 挂在某个在用用料（第 2 节）里的物料算「档案里标明是消耗品」，自动识别时算常备——第一天就卖断货的话后面的扣料都欠着、没有第二天的用量，不接上会被认成一次性采购；② 总仓欠着没扣的净数（第 2 节的待扣料）当成已经用掉，从可用数量里减（可用 = 结存 + 在途 − 欠着没扣的），没有用量、没设提醒数量但已经欠着的也提、把欠的补上。
- 规则在哪改：开关与时间在「ERP 设置 → 采购规则」与「采购 → 补货建议」顶上（同一张卡片）；按用料扣库存的开关在「ERP 设置 → 库存与审批开关」与「库存 → 用料与扣料」顶上；规则总表各有一行。
- 页面：「采购 → 补货建议」顶上写今天自动建了几张草稿、点进去确认或删掉。原来写的是「生成需求单草稿」：需求单草稿箱是每个人自己填到一半的表单，系统没法替人建；采购单草稿才是「等人确认」的东西（JX10）。

## 4. 布草洗涤（JX-E，迁移 `138`）

- ERP 新模块「布草洗涤」（供应链组，依赖库存——洗涤厂用供应商档案）。
- `linen_items`：布草品类（浴巾、浴衣、床单……）、总数、每件洗涤费。`linen_docs` + `linen_doc_lines`：送洗单、收回单（实收、破损、丢失）、报废单、新增单；只增不改，作废留原因。
- 三个数随单据走：在洗 = 送洗 − 收回 − 丢失；在店 = 总数 − 在洗；总数因新增、报废、丢失而变。
- 几家洗涤厂洗同一个品类时，收回按**这一家**手里的数量核对（有效的送洗 − 收回，在品类的锁里算），不只看加起来的在洗数；这一家已经收回过的送洗单不能直接作废（合并前 Codex 审查 `b850838`）。
- 开单的操作编号走全店的「结果待确认」：提交前把编号与原请求存在本机，没收到结果时关掉弹窗、刷新以后页面顶上还能查回、按原内容重新提交或确认作废（业务类型 `linen_doc`，迁移 `140`）。洗涤厂的可选名单随布草页一起返回，有布草权限就能取（值班经理默认没有「查看库存」）。
- 洗涤费：收回单按「实收件数 × 每件洗涤费」记金额；按洗涤厂、按月出对账表（可导出）。**这一版不自动记进应付货款**（应付流水现在只认收货单一类来源，硬塞会把对账与核销搞乱），付款照旧走付款申请或报销；记应付与 8.0.21 的财务一起做（JX11）。

## 5. 客房点餐（JX-F，没有迁移）

- 住客本来就有手牌与账单：按房号下单 = 先由房号找到在住的入住单与来访，再走现有的手牌点单（同一套锁与操作编号）。出品单的「送到哪」写「客房 W301」（住哪间在挂账的事务里、核对完操作编号之后才查；操作编号的摘要只算「送到客房」，不算房号——点单生效但回复丢了以后客人换了房、退了房，按原样重提照样返回第一次的结果）。
- 点餐页的找客人可以输房号（同一个输入框：不是在店的手牌号就当房号找），住店的客人多一个「送到客房」的勾。没有另设规则：客房与餐饮两个开关都开着就能用（原来想加的 `room_rules.roomService` 没有做）。不另收送餐费（JX7）。

## 6. 会员联动房价（JX-G，迁移 `139`）

- `room_type_member_prices(room_type_id, grade 1–6, price)`：某一档起的会员价（高档没单独设的，用比它低的最近一档）。在后台「客房 → 房型与房价」的房型里填。
- 入住办理：手牌对应的来访绑了会员时，按会员当时的档阶（含体验中的临时身份）取会员价，写进 `room_stays.rate`；另记 `list_rate`（门市价）与 `member_grade`。办理前页面先问一次报价（`GET /api/rooms/quote`），提交带 `expectedRate`，对不上照旧拒绝（`PRICE_CHANGED`）。
- **不叠加、取低的**（JX8）：
  - 入住时如果这位会员的折扣类权益对客房的折后价比会员价还低，就不用会员价（按门市价入住，结账时照常打折）。
  - 用了会员价的入住单，它的房费明细结账时不再参加会员折扣（同行优惠同理）；券不受影响。
- 续住、夜审、超时加收都按入住时定的价，和现在一样。
