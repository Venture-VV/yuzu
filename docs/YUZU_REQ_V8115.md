## 3. 各块的做法

### A. 前台：NFC、风控、异常（`src/server/modules/frontdesk/`，高风险目录）

**A1 手牌芯片号与刷卡发牌**
- `hand_tags.card_uid`（可空；同一门店里不重复）。后台「手牌池」里给一张牌绑芯片号：点「绑定」后刷一下，或手输；可以解绑。
- `GET /api/frontdesk/tags/by-card?uid=`：芯片号 → 牌号与现在的状态。
- 接待发牌对话框：
  - 读卡器刷到一张牌：牌号填进现在这一位客人、这一行高亮，不提交；回车（或点「确认发牌」）才发。
  - 同一次接待里重复刷同一张：提示「本次已刷」。
  - 读不出来写明原因：读卡器没连上、没读到卡、这张卡没绑手牌、牌已停用、已锁定、已在店、分区不符；随时可以手输（手输一直在）。
  - USB 读卡器当键盘用的（把卡号打进输入框再回车）：输入框里打进来的不是牌号时按芯片号查一次。
- 对话框上有一行读卡器的状态（已连接 / 没连上，没连上时写「请手输牌号」）。
- 断网：发牌请求照旧先存本机再发；网络恢复时本机自动按原编号核对——已经生效的清掉，没生效的原样重提一次（同一个编号，不会重复发牌），被明确拒绝的留在「结果待确认」里等人处理。
- 浏览器的 Web NFC 要 HTTPS，内网 http 用不了：走设备模块的读卡通道（本机终端 / USB 读卡器）。

**A2 发牌前风控**
- 黑名单：新表 `guest_blacklist`（会员或手机号、姓名、原因、登记人、解除人与原因）。会员详情里「加入黑名单 / 解除」（值班经理及以上）；后台有清单。发牌时命中的会员**拒绝**，提示原因与登记人。
- 未结离店（欠款）：这位会员名下有没处理完的「未结离店」待办（见 A3）时警示，要值班经理及以上当场授权才能发（新的授权用途 `checkin_risk`），授权人、时间、原因记在这次来访上。
- 当日重复到店：提示「今天第 N 次到店」（写上一次的牌号与离店时间），不拦。
- 预约：这位会员今天有待到店的预约时带出来（项目、时间、技师、备注），发牌成功后自动标「已到店」并挂上这张牌。
- `GET /api/frontdesk/members/:id/risk` 给页面预先看；发牌接口里再核对一遍（页面看到的不算数）。

**A3 发牌后的异常**
- 超时在店：12 / 24 / 72 小时三级（黄 / 橙 / 红，各配文字「超 12 小时」等），手牌卡片与收银台清单上都有。
- 客人卡上的「异常处置」：
  - 提醒：记一条「已提醒」（谁、几点、备注）。
  - 加收：挂一笔「超时加收」（金额、原因；值班经理及以上或当场授权），就是一条手动金额的明细，结账时一起收。
  - 上报：记一条上报，指给一位责任人，进「异常待办」。
  - 临时外出 / 返回：来访标「外出」，手牌板上这张牌写「外出」；牌照旧占着，不能发给别人；回来点「返回」。
  - 手牌丢失：一个入口走完「锁旧牌、收赔付、换新牌」（就是换牌对话框预先选好丢失）。
  - 未结离店：记一条待办（应收多少、责任人），这位会员下次来店发牌时会被拦下来授权；真要把钱记成挂账，照旧在收银台用「挂账」结。
- 新表 `visit_incidents`（只追加，处理结果另记）；发卡台顶上「异常待办」一个入口，列没处理完的，能指派、能写处理结果。
- 都进来访的「经办记录」。

### B. 餐饮：桌台动作、台账合并、出品口权限（`src/server/modules/tables.ts`、`dining*.ts`）

**B1 桌台动作**
- 桌台多一个状态：可用 / 待清台 / 维修中。结账以后是「待清台」，点「清台」才回到可用（设置里可以关：关了结账后直接可用，与原来一样）。
- 维修 / 停用：要原因与预计恢复时间；维修中不能开台；「恢复」回到可用。
- 并台：选主台与附台（都在用餐中）。附台标「并入 某台」，账单不搬动（明细还在各自的账单上，可追溯），结账时主台带着附台一起结（现有的多桌一起结）；附台不能单独结。
- 拆台：解除并台，各结各的。
- 换台照旧。
- 新表 `table_events`（只追加：并台、拆台、清台、维修、恢复，带经办人与时间）；桌台的「历史」把它与开台、换台、撤台、结账排在一起看。
- 加锁顺序写进 `docs/LOCKING.md` 第 1 节的桌台那一行。

**B2 台账合并退菜**
- 「退菜记录」页签去掉，旧地址跳到台账并带上「退菜」筛选。
- 台账的类型筛选：全部 / 正常 / 退菜 / 赠送 / 折扣。赠送 = 被签赠券抵掉的行；折扣 = 被券或会员折扣抵到的行（8.1.15 结账单里记的「抵到哪几行」）。
- 退菜的行多三样：原因、审批方式与审批人、责任岗位（退菜时选：服务员 / 厨房 / 水吧 / 果吧 / 客人原因 / 其他，记在审计里，不改明细表）。
- 汇总里加「退菜率」（退菜份数 ÷ 全部份数，另写金额占比）。
- 导出跟着筛选。

**B3 出品口权限与房号备注**
- 新权限「在某个出品口下单」：餐厅 / 水吧 / 果吧各一项；原来有「餐饮点单」的岗位三项都有。
- 新职责「康美部」：默认有餐饮点单与水吧、果吧两项（没有餐厅）。点单页只显示有权限的出品口，服务端逐行核对。
- 点单时「手牌号」与「房号」至少填一项：
  - 只填房号：按房态中心里这间房现在登记的客人找到手牌（或在住的客房）；找不到就拒绝。
  - 都填：账记在手牌上，房号写在送达位置。
- 整单备注：写进这一单每道菜的出品单（厨房出品屏、点菜单）。
- 配送人归属不做限制（需求里写了待管理层定）。

### C. 菜品管理（新模块）
- 餐饮里多一个页签「菜品管理」（有权限的人才看得到）。
- 一张表看全部菜品：名称、分类、出品口与小类、档口、价格、上架 / 下架、今天的沽清、图片（电子菜单里有图的带出来）。
- 新增 / 编辑：名称、分类、价格、出品口、档口、图片、规格、做法、加料、套餐。
  - 规格沿用价目里的档。
  - 做法：这道菜可选的做法（不加钱），点单时选了写进出品备注。
  - 加料：这道菜可加的料（另外的价目项目），点单时另起一行、备注写「配 某菜」。
  - 套餐：一个价目项目，带「含哪几样」，下单时一行、出品单上列出来。
- 上下架：一点就生效（点单页、电子菜单马上不显示）。
- 改价：单独一项权限，写改价记录（改前、改后、谁、几点、原因）；以前的订单照下单时的价（明细上本来就留着当时的价）。
- 维护权限按出品口分三项；没有某个出品口权限的看得到、改不了。
- Excel：导出全部菜品；导入（先预览再生效，逐行写问题）。

### D. 房态中心（新模块，建在空间台账上）
- 一级入口「房态中心」。原来的「客房」页（房态看板、平面图、派对房）并进来。
- 房间来自空间台账（`spaces`），按「房型」分 Tab；房型后台可配（名称、排序、对应空间台账的哪几种业务类型、是不是技师服务的房间）。默认给出：按摩房、足浴房、SPA 房、休息大厅、宠物轰趴房、客房。
- 状态（颜色都配文字与图标）：空闲（绿）、在用（蓝）、待清（黄）、维修（红）、已预订（灰）。
  - 在用：有登记中的服务、在用的派对房、在住的客房。
  - 待清：服务结束 / 退房以后；点「清洁完成」回空闲。待清的房间不能登记。
  - 维修：要原因与预计完成时间。
  - 已预订：预约看板里今天订了这间的。
  - 改状态要权限，都留痕。
- 每个 Tab 顶上：总数、空闲、在用、待清、维修；另有「总览」。
- 点卡片登记：手牌号（刷卡或手输，带出会员与等级）、项目、档次、指定技师、出单员（工号）、备注、开始时间；必填的没填不能提交。登记 = 挂账 + 派钟 + 占房一步做完。
- 卡片上：房号、状态、客人、技师、已用时长、金额。
- 动作：换房（单与计时不动，记原房与新房）、退房（先看结账预览；没结清不能退）、续钟（按档加收、计时跟着）、并房、维修；房间历史看全部轨迹。
- 客房照旧走入住单，卡片与动作沿用原来的。

### E. 技师（钟房、排位、技师管理）
- 钟房：搜索框（姓名、工号、花名、拼音首字母）；按技师类型、可做项目筛，条件能叠加、写明现在生效的；按状态排（空闲、上钟、排位、休假）。
- 排位播报：叫号时播「排位号 + 技师号或花名 + 房间」；音量、一键静音（静音时页面上明显写着）、重播、手动叫号；几台终端同时开着时只有选成「主播报」的那一台播。
- 技师管理（门店页面，四个页签）：
  - 名册：工号、姓名、花名、类型、等级、可做项目、入职时间、状态。
  - 组别：分组、组长。
  - 班次：排班表、临时调班。
  - 休假：申请、审批；批了的当天自动不进排位。
- 与钟房、排位实时联动。

### F. 会员
- 新增会员两步：先选卡类型（电子卡 / 实体卡 / 匿名卡），再填表；选的类型在表单顶上，能回上一步改。
  - 实体卡：要卡号与押金（押金是负债，不进储值、不算营业额，记进班次的现金）；之后能挂失、补卡。
  - 匿名卡：手机号不强制。
- 表单：必填姓名、手机号（匿名卡除外）、卡类型、会员等级；选填性别、生日、来源渠道、推荐人、备注、偏好项目。
  - 等级：默认按规则自动；手动指定要有调整等级的权限或当场授权。
  - 手机号唯一；修改要授权（原来就有）。
  - 哪些字段显示、哪些必填，后台按门店配。

### G. 整体
- 「估清」→「沽清」（小程序线的目录不改，另告诉小程序线）。
- 前台 1 的细化：结账预览分列；两个台的入口按各自的权限显示。
- 导航按业务域分组：前台、餐饮、房态、技师、会员、财务、设置；有二级菜单、能折叠。
