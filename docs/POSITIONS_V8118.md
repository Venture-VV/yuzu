# 组织架构与岗位（8.1.18）

店主 2026-11-20 发来《组织架构与岗位体系》表格（四张表：组织架构与岗位体系、三级管理员权限总览、分部门岗位职权配置、后台配置说明），要求：

> 根据表格内容帮我完成后台配置说明表格里的序号 1 到 7 任务，系统里的岗位权限内容也需要帮我重新更新，按照表格里「分部门岗位职权配置」划分。注意：表格 1「组织架构与岗位体系」表里的岗位名称有两个职位的对应表里的两个管理员职别，比如「部门负责人 / 部门员工」和「高级管理员 / 管理员」分别就是部门负责人对应高级管理员，部门员工对应管理员；
> 还有一个任务就是，处理掉旧岗位之后，新创建的账号会按照现在这一套规则来创建，对于老账户的话，在更新完这版后重新第一次登录需要重新提示账户重新岗位分配权限，让现在的旧帐户自己手动重新选择，选择确认之后则不再提示。

表 4 第 8 条「待确认事项」店主没让做，照默认做法写在 `docs/PENDING_DECISIONS.md` 的 GW 表里。默认做法 GW1–GW9 都待确认。迁移 `194`。

## 1. 表 4 的七条怎么落地

| 序号 | 配置项 | 落地 |
| --- | --- | --- |
| 1 | 清除旧岗位 | 后台「员工账号 → 添加员工」不再给九个旧岗位与库存职责，改成「部门 → 岗位」：总裁 / 总经办成员 / 十三个部门各一个负责人、一个员工（`src/shared/positions.ts` 的 `POSITIONS`）。点餐平板、他店查询、设计师是设备与专用账号，不是组织里的岗位，放在「专用账号」里照旧建（GW3）。 |
| 2 | 最高职能 | 总裁 = 超级管理员 = 原来的「店主」：全部权限，管理员工账号、修改经营规则、导入期初这三项只有总裁有。迁移时店主账号直接定成总裁。 |
| 3 | 新增大客户部 | 部门下拉里有「大客户部」，下设负责人（高级管理员）与员工（管理员）；管家部、客户部的业务权限（客户对接、管家服务、签赠、权益登记）给大客户部（GW2）。 |

## 2. 权限怎么算

- 员工档案多了 `position`（岗位）。有岗位的：**岗位模板 → 后台按岗位的调整 → 个人微调**，依次生效（`permissionsOf`，`src/shared/permissions.ts`）。没有岗位的（还没重新选岗的老账号、专用账号）照旧按旧岗位与职责。
- 权限项还是原来那一百四十多项（服务端逐项校验不变），另加一项「管理本部门员工账号」（`staff.dept`）。每项归到表 3 的一列（`PERMISSION_COLUMN`）：

| 列 | 例子 |
| --- | --- |
| 本人经办记录 | 看对客导览、看设备状态、打印到小票机、查看当日流水与日结（收银交班要看当班的流水，GW4） |
| 本部门台账 / 报表 | 历史营业日、导出流水、技师业绩、会员总览、货款与对账、费用报销、合同、应收台账、巡场记录 |
| 跨部门数据 | 经营总览、ERP 营业数据、成本、各部门小仓、操作审计、实时位置、营销成本、会员到期名单 |
| 业务录入 / 下单 | 充值、消费、发牌挂账、结账、点单、出品、派钟、客房、查看库存与入库、采购、布草与零采备用金（含查看）、报销登记、开票…… |
| 单据审核 / 审批 | 审批中心、负责人确认、作废与冲销、反结账、退款单、确认日结、各种当场授权 |
| 会员与券管理 | 发券、作废券、停用会员、合并会员、改会员手机号、发签赠、黑名单 |
| 账号与权限配置 | 管理员工账号（总裁）、管理本部门员工账号（负责人）、审批规则 |
| 基础数据 / 价格配置 | 经营规则、价目与套餐、会员规则、券模板、菜品与改价、技师名册、物料与供应商档案、采购规则、设备、手牌池…… |

- 每个岗位只拿表上打了 ✔ 的那几列里、与本部门业务相关的权限（`POSITION_DEFAULTS`）。`tests/positions.test.ts` 逐列核对：员工没有审核、账号、基础数据、跨部门；只有财务部员工有本岗账务、只有大客户部员工有权益登记；负责人除财务部外都有「管理本部门员工账号」；跨部门、会员与券按表；除总裁外没有一个岗位有基础数据。
- 表上「基础数据 / 价格配置」全是 ✘：价目、菜品、券模板、会员规则、技师名册、物料与供应商档案这些，默认只有总裁能改；要下放给某个岗位，总裁在「岗位权限」里勾上（GW4）。
- 岗位另带一个「旧岗位」与职责（`legacyRole`、`duties`），只给按旧岗位判断的几处用：审批的「店总」组（总经办成员）、「财务」组（财务部负责人带对账付款、成本核算）、「法务」组；店主专属的操作（总裁）；客户部的客户经理（大客户部）；康美部的点单；外联部员工同时带物资与采购（店主定库存采购归外联部，不受「分岗不兼任」限制，GW5）。不决定权限。
- 「有财务职责的账号看不到营销成本」（HY14）照旧：财务部负责人带财务职责，后台加了也不生效。

## 3. 负责人管本部门员工（GW6）

表 2 写高级管理员「管理本部门员工账号与权限（在授权范围内）」，表 3 除财务部外负责人的「账号与权限配置」都是 ✔（本部门员工）。做法：

- 负责人进得了后台的「员工账号」（不进后台首页），只看得到本部门「员工」岗位的账号；能新建、改姓名与领料小仓、停用、重置密码。
- 不能建负责人、别的部门的人、专用账号；不能给个人微调、不能改岗位权限（那是总裁的）；不能生成点单密码、改挂哪几家门店。
- 多门店时只管挂的门店都在自己能进的门店里的员工（没挂门店的按本店算）：不然登录店 A 的负责人能重置只挂店 B 的同部门员工的密码，再拿这个账号进店 B（Codex 安全审查 `49a64d0`）。
- 领料小仓只能配自己档案里的那个（或不配），别的部门的小仓只有总裁能配：员工岗位多半带「本部门小仓」，配错了就能动别的部门的耗用、报损、盘点（Codex 安全审查 `4e118c1`）。
- 总裁单独给过「加权限」微调、或配了别的部门小仓的员工，也不归负责人管（名单上看不到，改不了、重置不了密码）：不然负责人重置密码就能拿到总裁给这个人的例外（Codex 安全审查 `6dfff92`）。
- 服务端核对（`src/server/modules/staff.ts` 的 `staffScope`），页面只是不给入口；改完返回的名单同样只有本部门员工；重置密码把范围写进 UPDATE（核对之后总裁调走了这个人，这一次就不生效）。

## 4. 老账号第一次登录选新岗位（GW7）

- 迁移 `194`：店主账号定成总裁（不用选）；点餐平板、他店查询、设计师与系统账号不用选；其余在职、停用的老账号都标 `needs_position`。
- 这些账号这一版以后登录（含已经登录着的：下一次请求），先改密码（要改的话），然后整屏「选择你现在的岗位」：选部门 → 选岗位 → 确认。没选之前除了会话本身的几个接口（`/api/auth/*`、营业日），别的接口都回 `403 POSITION_REQUIRED`（`guard`、`guardAny`；只要求登录的业务接口——开票申请、自定义字段、会员规则——用 `sessionReady`）。
- 选完不再提示，也不能自己再改（要改找总裁）。
- **按原来的岗位与职责限定能选的部门**（`selfSelectablePositions`；店主 2026-11-20 定方案 B）。只按级别封顶时，前台店员能给自己选「财务部员工」，马上就有付款、回款登记（Codex 安全审查 `02d66df`）。现在：
  - 前台店员：一线部门（前厅、男宾、女宾、娱乐、餐饮、康美、保健）的员工；值班经理：一线部门的负责人或员工；
  - 后勤人员：人力行政、出品、工程与男宾、女宾的员工；部门申购职责另加一线与后勤部门的员工；康美部职责：康美部员工；法务：人力行政部员工；
  - 物资经办、采购经办：外联部员工；库存采购负责人：外联部负责人或员工；对账付款、成本核算：财务部员工（财务部负责人只由总裁在后台定）；
  - 客户经理、管家员工：大客户部员工；管家经理：大客户部负责人或员工；
  - 店总：总经办，一线、后勤、大客户部的负责人或员工（财务部、外联部要有对应职责）。
  - 几样合起来算（例如后勤人员带物资经办，能选后勤部门员工与外联部员工）。总裁谁也选不了；选不到自己岗位的找总裁在后台改。
- 后台员工名单上自己选的标「自选岗位」，审计里记「自选新岗位」（原来的岗位、职责与选的岗位）；总裁在「编辑」里改了岗位以后不再标。总裁在后台先给老账号定了岗位的，本人登录也不用再选。

## 5. 没做的与以后

- **按部门过滤数据**（「只看本部门的台账」「不可查看其他部门敏感数据」）：权限是按模块开关的，这一版只决定能不能用某个模块；同一个模块里的数据（例如当日流水）不按部门切开。要按部门切，得先把营业数据、单据记到部门上，另排（GW9）。
- 表 4 第 8 条待确认事项：总经办分不分负责人与成员（现在只有「总经办成员」一个岗位，高级管理员）；财务部、外联部负责人的跨部门可见范围（现在照表：财务看全店财务数据，外联看供应商、采购、库存）；大客户部是否独立管大客户券与权益（现在大客户部负责人能发券、作废券、发签赠，不能维护券模板）。见 GW 表。
- 演示数据：演示库的账号照旧是旧岗位（不提示选岗），浏览器验收用例按它们写；要把演示账号换成新岗位，由测试会话改演示数据与用例。
- 旧岗位的「岗位权限」表还在（第二个页签），给还没选岗的老账号与专用账号用；老账号都选完以后可以收掉。
