## 0. 升级后会看到的变化

- **点单页**：菜单区先出现「餐厅｜水吧｜果吧」三个大入口，选了才列菜；下单成功后又回到三个入口。
  - 从桌台点「点单」进来也是先选。
  - 菜篮可以混点几处的菜，一起下单。
- **桌台页**：上面一排分区卡片（全部、散桌、景观包厢、休闲水吧区、休息果吧区；有不在这四个里的桌时多一张「其他区域」）。
  - 点一张只看这个区，下面写出这个区的明细。
  - 原来写成「大厅」「包间」的桌在「其他区域」里，后台改桌时换成四个分区之一就好。
- **点菜单**：桌台详情、点单页「还没上的菜」旁边多一个「点菜单」按钮，打开像一张点餐小票，每道菜盖一个章：已上、未上、制作中、已出餐、已退。
- **估清页、台账、退菜记录**：分组、筛选改成按「全部｜餐厅｜水吧｜果吧」与小分类，原来按价目分类的那排标签没了。
  - 台账导出多一列「价目分类」，退菜记录多一列「分类」。
- **后台「餐饮 → 出品档口与菜品」**：每道菜在出品档口旁多一个「点单分类」下拉，每个价目分类一组可以「整类设为…」。
- **后台「餐饮 → 桌台」**：建桌、改桌时「分区」从四个里选。

## 1. 范围

1. **点单分类**（CF1–CF3，`docs/DINING_V817.md` 第 1 节）
   - `@shared/dining`：
     - 入口与小分类：`DINING_OUTLETS`（餐厅：餐饮、酒水；水吧：手作饮料、糖水、调酒；果吧不分）。
     - 编码 `slotKey` / `parseSlotKey`（`restaurant:餐饮`、`fruit`），显示 `slotLabel`（「餐厅 · 酒水」「果吧」），全部 `ALL_DINING_SLOTS`，筛选 `slotMatches`。
     - 默认归类 `diningSlotOf`，前后端同一个函数，从上往下第一条对上的：
       1. 价目分类正好叫酒水、手作饮料、糖水、调酒（「餐饮」是统称，不算）；
       2. 价目分类带果吧、调酒 / 鸡尾酒、糖水、酒；
       3. 出品档口名带果吧、水吧；
       4. 价目分类带饮品 / 饮料 → 餐厅 · 酒水；
       5. 其余 → 餐厅 · 餐饮。
   - 迁移 `181`：`service_items.dining_outlet`（空为没设）、`dining_group`。约束是入口三选一、小分类不超过 8 个字、没入口时小分类为空；入口为空时 `IN (...)` 得 NULL，所以约束里写明了 `IS NOT NULL`。
   - 接口：
     - `PUT /api/admin/dining/items` 每道菜多带 `slot`（编码或 `null` = 按默认），不带不改。档口与分类可以分开改，至少带一样；配不上的编码 400。改了记审计「调整了菜品的点单分类」（`items_slot_updated`）。
     - `GET /api/admin/dining` 的菜带 `slot`、`slotAssigned`。
     - `GET /api/dining/menu` 的菜带 `outlet`、`group`。
2. **点单页**（CF4，第 2 节）：`features/dining/slots.tsx` 的 `OutletEntry`（三个入口，窄屏一处一行）、`OutletFilter`、`GroupChips`；`OrderTab` 没选入口时显示入口，选了以后上面一排换一处、下面小分类，「全部」按小分类分段；下单成功、从桌台进来时回到入口。
3. **桌台分区**（CF5、CF6，第 3 节）：`TABLE_ZONES`；`TablesTab` 的分区卡片（`table-zone-*`，窄屏左右滑）与详情（`table-zone-detail`），选的区记在地址 `?zone=`；后台 `TableDialog` 的「分区」下拉（原来写了别的区域的标「原区域」）。接口照旧接受 12 个字以内的任何区域。
4. **厨房出品**：不动。
5. **沽清列表、台账、退菜记录**（CF7，第 5 节）
   - 估清页按 `ALL_DINING_SLOTS` 分组、可筛，每道菜旁写出品档口。
   - `GET /api/dining/ledger` 与导出加 `outlet`、`groups`（英文逗号隔开）；行带 `outlet`、`group`（`category` 仍是价目分类）。导出的「分类」是点单分类，另有「价目分类」；文件名带上筛的哪一处。原来的 `categories` 参数照旧能用。
   - `GET /api/dining/voids` 与导出同样加 `outlet`、`groups`，行带分类，导出多一列「分类」。
   - 都按菜现在的点单分类算（与价目分类一样，不是下单时的快照）；先查全、再在内存里筛，查询本身没有条数上限。
6. **点菜单**（CF8、CF9，第 6 节）
   - `GET /api/dining/receipt?session=<开台>` 或 `?visit=<来访>`（只给一样），只读、不加锁。
     - 权限：「餐饮点单」或「结账」。
     - 按每次下单分段：同一张出品单号；没有出品单的按同一次挂账。
     - 每道菜的状态 `receiptLineState`；合计只算有效的。
     - 已结账、撤台、离店的接口照样返回（只读）；页面上的入口只在桌开着、客人在店时有。
   - `features/dining/ReceiptDialog.tsx`：
     - 小票纸：上下锯齿边（`styles.css` 的 `.receipt-paper`）、进度条、状态章。
     - 「只看还没上的菜」。
     - 开着时 10 秒刷新：数据在 React Query 里，定时刷新走共用的 `useLivePoll`（后台不取、断网不取、回到页面与网络恢复时马上取；Codex 审查 `156d9c6` 指出原来直接用了 `refetchInterval`）。
     - 窄屏上状态章在上、份数金额在下。
   - 样子参照常见的火锅店点餐小票，没有用任何品牌的名字、标志。
7. **三台目标设备**（DV1–DV4）

   - `docs/DEVICES.md` 写了三台设备的规格、网页大小与怎么核对。
   - `e2e/target-devices.spec.ts` 在门店电脑这一组里另开四个窗口，逐页核对：

## 4. 验收要点（测试服更新到 v8.1.7 以后；真机上由店主或 Codex 走）

1. **后台「餐饮 → 出品档口与菜品」**：没设的写「默认（…）」；改一道菜的点单分类、整类设为某一类，保存后点单页跟着变。
2. **后台「餐饮 → 桌台」**：新建一张桌，分区选「景观包厢」；桌台页点「景观包厢」只看这个区，下面写空闲、用餐中、人数、待上菜、合计；刷新还在这个区。
3. **点单（商米 V3 真机）**：
   - 点单页先出三个入口；选水吧、按「糖水」筛、换到果吧（没有小分类那排）；
   - 菜篮里几处的菜都在，下单以后回到入口；
   - 从桌台详情点「点单」进来也先选入口。
4. **点菜单（商米 V3 与 D3 Pro 真机）**：
   - 厨房屏上把一道菜做完、出餐，前台点「上菜」，点菜单里那道菜的章依次变成制作中、已出餐、已上；
   - 退掉的一道划掉、不算金额；「只看还没上的菜」只剩没上的；
   - 结账以后接口照样返回这一桌（只读，`closed` 为真）；页面上的两个入口跟着开着的桌、在店的客人，结账、离店以后就没有了。
5. **估清、台账、退菜记录**：「果吧」都能筛出来；台账导出的「价目分类」与日结的部门对得上。
6. **三台真机**：各打开「网络与同步」页记下「本机屏幕」一行，与 `docs/DEVICES.md` 的表对一下（DV1–DV3）；点单、桌台、点菜单在三台上都不横着滑、按钮点得到。

## 5. 已知的限度

- 点单分类的入口与小分类固定在代码里（CF1）；要增减改 `DINING_OUTLETS`。
- 台账、退菜记录按菜现在的分类算：后台改了某道菜的分类，查以前的日子也按新的。
- 点菜单不打到小票机（第 7 节）。
- 平板电子菜单（`/emenu`）的分类照旧按后台「电子菜单」里排的，不跟点单分类走。
- 三台设备是在浏览器里按尺寸与触摸模拟的；网页大小以真机的「本机屏幕」为准。商米 D3 Pro 的客显（副屏）这一版没有页面。
