- **资金候选**：结账、报表、对账包的部门口径改为读快照；转单会作废明细、在别的手牌上新增明细。账错、串单（转到不对的客人）、越权、破坏前台 / 桌台 / 储值原有流程是阻断项。

## 1. 范围

| 项 | 内容 |
| --- | --- |
| 部门营业额快照 | 结账时（手牌、桌台）按结账那一刻的有效明细记下每个部门、每个项目的数量与金额；优惠按金额比例分摊到分、尾差按最大余数补；反结账按原快照冲回；改价目、改分类不影响已结的单 |
| 报表 | 看板「经营总览」、今日看板、ERP 营业数据的部门营业额读快照（柱条是应收，备注写优惠）；对账包「03-部门参考表.csv」加「优惠分摊」「净额」两列 |
| 转单 | 前台账单「更多 → 明细转到别的手牌」：原明细作废（原因写明转到哪张手牌）、目标手牌新增同样的明细、留转单记录；权限与作废明细相同；房费、餐饮的菜、钟房派的钟不能转 |
| 自检 | 加「部门营业额快照与结账单一致」「转单记录与明细一致」（`check` 前台部分多两项） |

## 2. 验收要点

| # | 操作 | 预期 |
| --- | --- | --- |
| D1 | 结账：门票 ¥499 + 两项消费，带优惠（值班经理授权） | 对账包 03 每项的「优惠分摊」合计 = 优惠；与日结的应收、优惠一致，「核对」一致；`tests/cashier.test.ts` 有 ¥10 分到三项的具体数字 |
| D2 | 结账后在后台把其中一个项目的分类改掉 | 已结账单的部门不变；之后结的按新分类 |
| D3 | 反结账带优惠的结账单 | 当天的部门营业额与优惠分摊一起冲回 |
| D4 | 桌台结账 | 同样有快照（自检「部门营业额快照与结账单一致」全 ✓） |
| D5 | 从 v0.7.5 的演示库升级 | 迁移 025 给已有结账单补记快照；`check` 全 ✓；升级前后各报表的部门营业额数字不变（只多了优惠） |
| D6 | 补录结账（按实际时间）到某项明细转走之前的时刻 | 这张结账单的部门快照不含之后才转走的明细，与结账金额一致；转过去的那位结账时只算一次（`tests/cashier.test.ts`「代码审查的修正」） |
| D7 | 前一天带优惠的结账今天反结账、按同样的项目换了优惠重结 | 当天部门营业额里这个部门照样列出（应收 0、优惠是差额），对账包 03 的优惠合计与日结一致 |
| T1 | 店员把自己刚挂的一项转到另一位在店客人的手牌 | 原手牌明细作废、原因「转到手牌 X：原因」；目标手牌多一项，挂账人是这位店员；两边账单金额对 |
| T2 | 店员转别人挂的、或超过作废时限的 | 拒绝（403）；值班经理可以 |
| T3 | 目标手牌不在店 / 就是这位客人 / 限女宾的项目转给男宾 | 拒绝，写明原因 |
| T4 | 房费、餐饮的菜、钟房派的钟 | 对话框里不能勾，写明原因；直接调接口拒绝（`LINE_NOT_MOVABLE`） |
| T5 | 转单时断网（响应丢失） | 结果待确认：查回 / 原样重提只转一次；顶部「去处理」回到转单对话框 |
| T6 | 转过来的明细随目标手牌结账 | 进目标手牌的结账单与部门快照；原客人照常结门票 |
| T7 | 转单的同时目标客人在别的终端换了牌 | 拒绝（`TAG_CHANGED`），明细不动；刷新后按新牌号重转 |
