## 1. 架构

```
顾客手机 · 微信小程序
      │  HTTPS（已备案的域名）
      ▼
小程序网关 · 阿里云最低配服务器（公网只开 443）
      │  微信登录、手机号验证、微信支付下单与到账通知、限流、展示内容缓存
      │  不存会员、余额、券、订单
      │  Tailscale（只放行到 yuzu 的小程序端口）
      ▼
门店 Mac mini · yuzu（唯一的正式账本）
      ├─ /api/mp/*          顾客接口，单独一个端口：只能读写网关报上来的那一位已绑定会员
      └─ 管理后台「小程序」   员工用的运营页面（店内局域网 / Tailscale，不上公网）
```

- **为什么要一台公网服务器**：小程序只能访问在小程序后台登记过的 HTTPS 域名，域名要 ICP 备案；yuzu 只开在门店局域网与 Tailscale 里，不绑公网域名、不做端口转发（`DEPLOY_MAC_MINI.md` 第 1、10 节）。网关就是部署手册第 11 节给美团、抖音回调预留的那台小服务器，一台机器两用。
- **只有一个账本**：会员钱包是唯一的储值账本，任何时候只有一个正式记账库（AGENTS.md、ROADMAP 第 2 节）。网关不存业务数据，只缓存对外展示的内容（门店信息、价目、导览、活动图）。自带会员储值的小程序 SaaS 会另起一本账，不接。
- **管理后台不上公网**：yuzu 给网关单开一个端口，上面只有 `/api/mp/*`；Tailscale 只放行网关到这个端口。网关服务器被攻破也碰不到管理后台。
- **顾客身份与员工账号分开**：员工照旧 cookie 登录、同源检查（`src/server/app.ts`）不变；`/api/mp/*` 只认网关的服务密钥，不认员工会话。
- **门店断外网**：店内照常收银；小程序的展示页照常打开，绑定、查余额、充值暂停并提示「门店系统连接中」。充值单先在 yuzu 建好再去微信下单；到账通知送不进门店时微信会重发，yuzu 恢复后主动查单补记，按操作编号去重，不会重复入账（第二期细化）。
- **两家店**：按会员体系 v2（`docs/MEMBERSHIP.md`），本系统只服务宝安店，福田店只开放只读查询。小程序里门店信息两家都放（地址、营业时间、电话、导航）；会员、余额、券只来自本系统（MP5）。

## 2. 代码与目录（MP1）

| 目录 | 内容 |
| --- | --- |
| `miniprogram/` | 小程序前端：原生小程序 + TypeScript；样式照 VI 自己写（没用 TDesign，组件少、品牌感更好控制）；用微信开发者工具打开这个目录，说明见 `miniprogram/README.md` |
| `src/gateway/` | 小程序网关（Fastify）：微信登录换 openid、手机号验证、微信支付下单与回调、限流、展示内容缓存、转发到 yuzu |
| `src/server/modules/mp/` | yuzu 的顾客接口 `/api/mp/*`：绑定会员、会员码、余额与流水、券、门店信息与价目、导览 |
| `src/client/features/mp/` | 管理后台「小程序」模块（第 5 节） |
| `src/shared/mp.ts` | 前端、网关、yuzu 共用的类型与校验 |

- **不多建数据库**：小程序前端没有库，网关不存业务数据；yuzu 的新表放在小程序线自己的迁移里，测试照旧用现在的测试库（`tests/mp-*.test.ts`）。
- **CI**：小程序目录单独一个检查「小程序：类型检查 · 单元测试」（`miniprogram/` 下 `npm run check`，有自己的 `package.json` 与锁文件）。每个 PR 都跑、不按路径分：只要半分钟，而且它连同 `src/shared/mp.ts` 等共用类型一起检查，yuzu 改了接口这里会报错。CI 的测试步骤由测试会话复核。
- **发布**：yuzu 照旧按 `package.json` 打 `vX.Y.Z`；小程序前端用 `miniprogram/package.json` 自己的版本号，经 `miniprogram-ci` 上传体验版，店主在微信后台提交审核、发布。`miniprogram/` 加进 `.dockerignore`，门店的镜像不带它。
- **网关怎么部署**：Compose 里单独一个服务，只在网关服务器上启用，门店 Mac mini 不跑；与 yuzu 共用镜像还是单独的小镜像，第一期定。

## 4. 绑定与账号（MP6）

| 项 | 做法 |
| --- | --- |
| 小程序用户 | 微信 openid（以后要接公众号再加 unionid） |
| 绑定 | 用微信的手机号验证拿到手机号，等于某位会员的手机号就绑定；一位会员只绑一个微信，一个微信只绑一位会员 |
| 对不上 | 只能浏览，提示「请到前台开卡或核对手机号」（MP3）；不建会员 |

| 手机号验证的费用 | 微信 2023 年起按次收费（当时每次成功约 0.03 元，有 1000 次免费额度，以微信后台为准）；每位会员只验一次 |

## 6. 服务器与环境

| 环境 | 网关地址 | 连到 | 小程序版本 |
| --- | --- | --- | --- |
| 正式 | `api.<域名>` | 门店 Mac mini 正式服的小程序端口 | 正式版 |

- 演练库（`yuzu-test`）不接小程序：它不记真实业务，也不放演示数据，顾客侧的联调用演示库。
- 微信支付联调（第二期）：在演示库上用 0.01 元真实付款，测完退回；不往演练库、正式库写测试数据。

设计要点（默认做法；没定的记在 `PENDING_DECISIONS.md`「微信小程序」MP9–MP12）：

- **只认网关**：`/api/mp/*` 只挂在 yuzu 单开的小程序端口上（`MP_PORT`，没设就不开），员工用的 8080 上没有这些接口；网关带服务密钥（`MP_GATEWAY_KEY`，只放两边的 `.env`），yuzu 比对摘要。小程序端口上没有员工会话、管理后台和静态页面。
- **绑定记录只追加**：解绑记一行（经办人、原因），不删；同一时刻一个微信、一位会员各只有一条有效绑定，数据库唯一索引兜底。绑定先取这个微信的咨询锁，再锁会员一行（共享锁）、写绑定记录；不碰钱包，不等前台的锁。带操作编号，网关重试不会绑两次。
- **会员码只用来认人**（MP9）：前台查找框接会员码归主线（#42 合并后主线下一版做），接上之前小程序不对顾客开放；代替报手机号，不代替用储值付款时的核对。码由 yuzu 签发（密钥只在 yuzu），每 60 秒换一次；前台扫码盒扫进会员查找框，yuzu 在本机校验签名、时间、绑定和会员状态。门店断外网时小程序拿不到新码，前台照旧按手机号找会员；网关不存能生成会员码的密钥。
- **图片**（MP10）：门店、轮播、项目介绍的图片照 v0.7.8 采购单图片的做法存数据库、随备份走；网关缓存后发给小程序。
- **网关会话**（MP11）：小程序登录后网关发 7 天的会话，里面只有 openid，不放手机号；会话密钥只在网关。
- **模拟微信**：假登录、假手机号只在 development 实例可用，trial、production 的 yuzu 拒绝模拟绑定，与 seed 命令一样没有绕过开关。小程序按版本选网关；网关在 `/v1/health` 报告自己是不是模拟微信，开发版、体验版跟着用模拟（「我的」页填演示会员的手机号绑定），正式版一律用真的微信。
- **小程序页面**（④）：
  - 首页服务入口只放第一期能用的四个（会员码、价目表、楼层导览、联系门店）；第二、三期的功能上线时再加，不放「即将开放」。
  - 标志：店主 11-03 定用品牌书 / VI 的几何字（方案 B），已换上。首页版头与会员卡用竖版方形主标志（VI 第 59 页），滚过版头的导航栏用横版（VI 第 61 页加大字距的版本），英文字标 TOUCHILL 取自品牌书第 24 页、与主标志同宽；源文件 `miniprogram/assets-src/brand/*.svg`（按区域取出的原矢量路径），页面用生成的 PNG。版头没有轮播时用门店照片，再没有用木色底。
  - 只做浅色（米白底），不跟手机的深色模式。
  - 会员相关的数字（余额、流水、券、会员码）不存手机，门店连不上时显示「门店系统连接中」；展示内容（门店信息、价目、导览）存一份，最多 7 天，用旧的时标「之前的信息」。
  - 绑定的「结果待确认」（Codex 审查 #42）：点绑定前把操作编号存在手机上（存不了不发）；结果不确定（断网、超时、门店出错）时请门店系统确认作废这个编号，已经绑上就回「已绑定」、还没有就登记作废（原请求晚到也不会绑定），以这个回答为准；确认之前「我的」页显示「绑定结果待确认」、不能再点绑定。手机号验证的 code 只能用一次，所以不原样重提，每次点绑定用新的操作编号。
  - 后台的写操作都做「结果待确认」（`src/client/features/mp/mpPending.ts`，Codex 审查 #42）：提交前把操作编号和原请求存在浏览器上（存不了不发），没收到结果时这一页上方显示，刷新后照样在，处理完之前这一处不能再办。
    - 新建轮播：按编号查回，查不到的按原内容重新提交（同一编号，不会多建）或确认作废；作废登记在小程序线自己的表里（迁移 `044`）。
    - 解绑：那条绑定解绑了就有结论；没有的按原内容重新提交（同一编号，只解绑一次）。
    - 改开关、门店信息、轮播、项目介绍：都带版本号（开关的版本号存在 `mp_rules` 里，每保存一次加一）。版本号变了就有结论——原请求要么已经改上，要么因为版本号对不上永远不会生效；没变的按原内容重新提交（同一版本号，不会改两次），或「放弃这次修改」：按现在的内容、用原来的版本号保存一次（内容不变、版本号加一），原请求晚到被拒。
  - 手机或浏览器上的待确认记录读不出来（读存储出错，或存着的内容认不出）不当作没有（本地 AI 预检 #42 的 P1）：小程序「我的」页显示「绑定记录暂时读不出来」、不能绑定，后台这一页上方提示、什么都不能提交；原来的记录原样留着，读得出来后照常确认。已经绑定的微信不受影响（只能有一条有效绑定，晚到的原请求绑不上别的会员），读不出来的记录直接删。
  - 流水与会员卡一样，先作废这位会员到期的赠金再查；小程序同时取两者时，后到的等先到的作废提交后再查，所以流水结尾的余额与会员卡一致。
  - 会员码页调亮屏幕、不息屏，离开时恢复；二维码只编码数字（小程序里自己生成，用独立解码器测过）。
