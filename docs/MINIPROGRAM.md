## 1. 架构

```
顾客手机 · 微信小程序
      │  HTTPS（已备案的域名）
      ▼
小程序网关 · 阿里云最低配服务器（公网只开 443）
      │  微信登录、手机号验证、微信支付下单与到账通知、限流、展示内容缓存
      │  不存会员、余额、券、订单
      │  Tailscale（只放行到 yuzu 的小程序端口）
      ▼
门店 Mac mini · yuzu（唯一的正式账本）
      ├─ /api/mp/*          顾客接口，单独一个端口：只能读写网关报上来的那一位已绑定会员
      └─ 管理后台「小程序」   员工用的运营页面（店内局域网 / Tailscale，不上公网）
```

- **为什么要一台公网服务器**：小程序只能访问在小程序后台登记过的 HTTPS 域名，域名要 ICP 备案；yuzu 只开在门店局域网与 Tailscale 里，不绑公网域名、不做端口转发（`DEPLOY_MAC_MINI.md` 第 1、10 节）。网关就是部署手册第 11 节给美团、抖音回调预留的那台小服务器，一台机器两用。
- **只有一个账本**：会员钱包是唯一的储值账本，任何时候只有一个正式记账库（AGENTS.md、ROADMAP 第 2 节）。网关不存业务数据，只缓存对外展示的内容（门店信息、价目、导览、活动图）。自带会员储值的小程序 SaaS 会另起一本账，不接。
- **管理后台不上公网**：yuzu 给网关单开一个端口，上面只有 `/api/mp/*`；Tailscale 只放行网关到这个端口。网关服务器被攻破也碰不到管理后台。
- **顾客身份与员工账号分开**：员工照旧 cookie 登录、同源检查（`src/server/app.ts`）不变；`/api/mp/*` 只认网关的服务密钥，不认员工会话。
- **门店断外网**：店内照常收银；小程序的展示页照常打开，绑定、查余额、充值暂停并提示「门店系统连接中」。充值单先在 yuzu 建好再去微信下单；到账通知送不进门店时微信会重发，yuzu 恢复后主动查单补记，按操作编号去重，不会重复入账（第二期细化）。
- **两家店**：按会员体系 v2（`docs/MEMBERSHIP.md`），本系统只服务宝安店，福田店只开放只读查询。小程序里门店信息两家都放（地址、营业时间、电话、导航）；会员、余额、券只来自本系统（MP5，待确认）。

## 2. 代码与目录（MP1）

| 目录 | 内容 |
| --- | --- |
| `miniprogram/` | 小程序前端：原生小程序 + TypeScript，配腾讯 TDesign 小程序组件库；用微信开发者工具打开这个目录 |
| `src/gateway/` | 小程序网关（Fastify）：微信登录换 openid、手机号验证、微信支付下单与回调、限流、展示内容缓存、转发到 yuzu |
| `src/server/modules/mp/` | yuzu 的顾客接口 `/api/mp/*`：绑定会员、会员码、余额与流水、券、门店信息与价目、导览 |
| `src/client/features/mp/` | 管理后台「小程序」模块（第 5 节） |
| `src/shared/mp.ts` | 前端、网关、yuzu 共用的类型与校验 |

- **不多建数据库**：小程序前端没有库，网关不存业务数据；yuzu 的新表放在小程序线自己的迁移里，测试照旧用现在的测试库（`tests/mp-*.test.ts`）。
- **CI**：小程序目录单独一个检查（类型检查与单元测试），按改动路径触发；具体改法在第一期的 PR 里写明，CI 的测试步骤由测试会话复核。
- **发布**：yuzu 照旧按 `package.json` 打 `vX.Y.Z`；小程序前端用 `miniprogram/package.json` 自己的版本号，经 `miniprogram-ci` 上传体验版，店主在微信后台提交审核、发布。`miniprogram/` 加进 `.dockerignore`，门店的镜像不带它。
- **网关怎么部署**：Compose 里单独一个服务，只在网关服务器上启用，门店 Mac mini 不跑；与 yuzu 共用镜像还是单独的小镜像，第一期定。

## 4. 绑定与账号（默认，待确认）

| 项 | 做法 |
| --- | --- |
| 小程序用户 | 微信 openid（以后要接公众号再加 unionid） |
| 绑定 | 用微信的手机号验证拿到手机号，等于某位会员的手机号就绑定；一位会员只绑一个微信，一个微信只绑一位会员 |
| 对不上 | 只能浏览，提示「请到前台开卡或核对手机号」（MP3）；不建会员 |

| 冻结的会员 | 能看不能用：会员码、充值不可用 |
| 手机号验证的费用 | 微信 2023 年起按次收费（当时每次成功约 0.03 元，有 1000 次免费额度，以微信后台为准）；每位会员只验一次 |

## 5. 运营后台：yuzu 管理后台「小程序」模块

照 ERP 的做法（`docs/ERP.md` 第 1 节：同一套系统、同一个数据库，模块可开关），默认关闭，店主在后台开。只放 yuzu 还没有的：

| 内容 | 说明 |

| 首页轮播与活动 | 图片、标题、起止日期、点了去哪（项目、价目、导览） |

## 6. 服务器与环境

| 环境 | 网关地址 | 连到 | 小程序版本 |
| --- | --- | --- | --- |
| 正式 | `api.<域名>` | 门店 Mac mini 正式服的小程序端口 | 正式版 |
| 测试 | `api-test.<域名>` | 测试服 A 演示库（`yuzu-demo`）的小程序端口 | 开发版、体验版 |

- 网关服务器：阿里云最低配（深圳），公网只开 443，登录走 Tailscale；正式、测试两个网关进程放在同一台上。不用测试服 A 当网关：A 对公网全关，还收着异地备份。
- 小程序按运行的版本自动选地址（开发版、体验版连测试，正式版连正式），体验版连不到正式服。
- 演练库（`yuzu-test`）不接小程序：它不记真实业务，也不放演示数据，顾客侧的联调用演示库。
- 微信支付联调（第二期）：在演示库上用 0.01 元真实付款，测完退回；不往演练库、正式库写测试数据。

## 7. 手续（店主办，和开发同时进行）

- [ ] 用营业执照注册小程序（企业或个体户主体；个人主体开不了微信支付，也用不了手机号验证），做微信认证（约 300 元 / 年）
- [ ] 服务类目「生活服务 > 洗浴保健」：官方列的资质示例有公共场所卫生许可证、公众聚集场所投入使用营业前消防安全检查合格证、健康合格证、建设工程消防验收意见书；以后做线上点餐，餐饮类目还要食品经营许可证
- [ ] 小程序备案（新上架的小程序必须先备案）
- [ ] 买域名、做 ICP 备案（经验上三周左右，各省不同）
- [ ] 申请微信支付商户号并绑定小程序（第二期用，可以先办）
- [ ] 小程序后台填「用户隐私保护指引」（用手机号验证前必须填）
- [ ] 问当地商务部门：线上卖储值（预付消费）有没有备案或资金存管的要求
- [ ] 阿里云最低配服务器一台（网关）
- [ ] 小程序后台生成「代码上传密钥」，IP 白名单填网关服务器的固定 IP（`miniprogram-ci` 从那台上传体验版）；密钥只放服务器的 `.env`，不进 GitHub

## 8. 两条开发线怎么协作（建议，待店主确认）

店主 10-29 定「只有开发会话改业务代码」，起因是资金轨、平台轨两个会话在同一批文件里并行，合并冲突越来越多（ROADMAP 第 7 节）。小程序几乎都是新目录，可以并行，但要按目录分清：

| | 主线（原开发会话，`claude/confident-lamport-hlxsnl`） | 小程序线（`claude/nice-gauss-3p3urd`） |
| --- | --- | --- |
| 做什么 | yuzu 本体：v0.7.22 整理、会员体系 v2（v0.7.23–v0.7.25）、评测反馈、切换 | 小程序、网关、`/api/mp`、后台「小程序」模块 |
| 改哪些文件 | 已有的全部模块；会员、钱包、券、结账、前台的核心只由主线改 | 只写第 2 节的目录；`app.ts`、权限表、路由表这类登记处只加挂接的几行 |
| 版本号 | 只有主线改 yuzu 的版本号（`package.json` 等五处） | 不改 yuzu 的版本号，代码随主线的下一个版本一起发；小程序前端用自己的版本号 |
| 迁移号 | `039`–`042` 已登记（`040` = v0.7.23，`041`、`042` 留给会员体系 v2 第二、三期）；之后从 `045` 起 | `043`（第一期）、`044`（第二期）。只建自己的表、只用外键引用会员和券，不改已有的表，和主线的迁移谁先合并都行 |

- **开工时间**：PR #38（107 个文件的代码整理）已于 2026-11-03 合并。店主确认本节后，小程序线从最新 `main` 开始写代码；在那之前只做文档、可点击原型与手续准备。
- **要核心加能力时**（例如第二期「外部支付入账」的入口）：小程序线在主线当前的 PR 上留言写清需求，由主线做；或主线同意后，由小程序线开一个只改这一处的小 PR。
- **合并**：店主照旧在 12:00 / 21:00 合并；任何一边合并后，另一边先同步最新 `main` 再继续。冲突只会在登记处和升级测试里的迁移清单，由各自的会话解决。
- **测试**：测试会话照旧预检两条线的每个 PR；小程序的真机测试由店主安排的本机 AI 用微信开发者工具做（云端会话装不了开发者工具）。
- 店主确认后，同步改 AGENTS.md「提交、PR 与评论」的分工与 ROADMAP 第 7 节的「只有开发会话改业务代码」。
