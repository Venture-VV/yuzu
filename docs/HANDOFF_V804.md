店主 2026-11-08 发来《浴族会员体系整改需求汇总》与《会员体系整改需求表》（11 项：P0 3、P1 4、P2 4），让开发会话「对系统的会员体系板块进行完善，注意更改在其他板块的影响（小程序、前台、经营数据），必要时看看功能是否重复、进行重构」。设计见 [`MEMBERSHIP_V804.md`](MEMBERSHIP_V804.md)，需求没写细的按默认 HY01–HY20（[`PENDING_DECISIONS.md`](PENDING_DECISIONS.md)「会员体系整改（8.0.4）」，待确认，店主不改就按它做）。飞书开放平台这次在云端会话里连不上（网络代理拒绝），需求按店主发来的两份文件整理。

## 1. 范围（相对 v8.0.3）

### 1.1 P0

- **01 权益按档阶分级**：后台「会员权益」默认「按档阶」看：L0–L6 每档一行，点开只见这一档的初 / 享 / 尊三阶，每阶分「本阶起享」与「另有 N 项低档阶的权益」；券按面值从高到低（HY17）。没挂在权益、发券规则上的券模板按限定的最低档·初阶放，不限的放 L0（HY18），没有「未分级」。原来的清单在「按类别」（`?view=list`）。
- **02 VIP 柜归会员权益**：「会员权益」第三个视图「VIP 柜」（`?view=vip`）：各档能用几级柜、当场授权开关，权限「维护会员权益」（店主、店总，HY04）。会员规则、手牌与前台里不再有 VIP 柜；旧入口 `/admin/vip-lockers` 跳过来；原来的值由迁移 `088` 原样搬到 `vip_locker_rules`。发牌、换牌的核对结果不变。
- **03 取消次卡入口**：价目与套餐没有「次卡」页签，会员详情不显示「售卡」，接口拒绝新售（`COUNT_CARD_SALES_CLOSED`，HY05）；已售的次卡照常结账用、退卡、打印。要恢复售卡告诉开发会话（设置 `countCardSales`）。

### 1.2 P1

- **04 充值当日的储值消费比例**（HY01–HY03）：会员在某个营业日充了值，这一天用储值付的钱不超过「当天第一笔充值前的余额 + 当天充值实收 × 70%」。充 10 万的新会员当天最多用 7 万。会员详情、消费核对页、结账的储值支付显示「今日储值可用」；超了拒绝（`RECHARGE_SPEND_CAP`，带剩余额度），不能当场授权放行。比例在「经营规则」改，空 = 不限。原来的固定单笔上限（默认 50 万，超了要授权）保留。
- **05 标签**（HY06、HY19）：自定义字段全部转成标签（字段名做分组，填过的值都做标签、填过的会员都挂上，原来的值留在档案里不删）；另建「客群」下的「亲子客」「商务客」。后台「会员与渠道」维护标签（店主），新建、编辑会员时挂标签；会员列表按标签筛选；数据看板「会员总览」按标签导出名单。
- **06 批量发券**（HY07、HY08、HY16）：「券与会员权益 → 批量发券」按档级、标签圈会员（一次最多 2,000 位），先预览人数再发，每人 1–10 张；每批 200 位一个事务，断了每分钟接着发、同一人不发两次；走「结果待确认」（作废登记加 `coupon_campaign`）。通知两个开关：
  - 短信进待发箱，阿里云短信在 `.env` 配（`SMS_PROVIDER=aliyun` 与密钥、签名、模板，见 `.env.example`），没配的留在待发箱、发券单详情里导出名单手动发；每条最多试 3 次；
  - 会员端提醒：到账当天起「您收到 N 张券」（最多 30 天），到期前 7 天（发券时可改 1–30）起「券 N 天后到期」，券都用完、作废的不再弹，看过记已读。读写在主线（`listMemberNotices`、`markMemberNoticeRead`），小程序的接口与弹窗由小程序线接（第 4 节）。
- **07 充值记录与消费记录**（HY09）：会员详情原来的「余额记录」拆成两块，默认展开、各列最近 20 笔（「显示全部」看全部）；每块「查询与导出」里按种类、营业日起止查，分别导出 CSV（记审计）；上面「收支比例」是两块当前查询条件下的合计（同一次查询算出来，与明细合计一致）。

### 1.3 P2

- **08 使用率看板**（HY10）：「券与会员权益 → 使用率」按发放时段圈一批券：发放、领取、核销、领取率、核销率、核销金额，按券 / 发放方式 / 会员权益 / 会员档级分别看，可按档级、标签圈；服务类权益另列登记次数与人数；导出（记审计）。「会员权益」页上方「看使用率」进这里。原来的「统计」（按发生日期）留着，口径不同。
- **09 买一赠一券、生日礼**（HY11–HY13）：
  - 券模板加种类「买一赠一券」：买的项目、赠的项目（默认同一个）、最多抵；账单上有买的项目、又有赠的项目（同一项目要 2 份）才能用，抵赠的那份里单价最低的一份。
  - 模板可选「核销后赠品自动出库」（物料、每份数量、仓）：结账记一条待出库，每分钟由系统账号「赠品出库」开直接耗用单，库存流水照常记账；出不了的记失败、在「营销成本」里补库存后重试；反结账没出库的取消、已出库的冲销当月的单（跨月的记冲销失败，仓库手工处理）。出库不挡结账。
  - 生日礼（发券规则与权益清单的生日礼）改成生日前 N 天到账（「会员规则」里改，默认 3，0–30），到账那天到生日当月底之间补发；2 月 29 日平年按 2 月 28 日。
- **10、11 营销成本测算**（HY14、HY15）：数据看板新页「营销成本」，实核口径：券按结账抵扣、赠金按用掉的、会员折扣按结账记的（反结账、撤销的冲回），服务类权益按登记次数 × 测算单价（只在这一页填，留审计）；赠品出库的状态与重试；导出（记审计）。新权限「营销成本测算」默认店主、店总，**有财务职责（对账付款、成本核算）的账号一律没有**，后台岗位权限加了也不生效。测算的数只在这一页现算，不进日结、交班、对账包、营业数据与财务凭证。

### 1.4 对其他板块的影响与整理（设计稿第 11 节）

- **前台**：结账的储值支付显示今日剩余额度、超额拦截；结账可用买一赠一券；VIP 柜核对改读新设置（结果不变）；会员详情加标签、两块记录、去掉售卡。
- **经营数据**：日结、交班、对账包、营业数据的口径不变（买一赠一的抵扣与其他券一样记「券抵扣」）；营销成本不进任何报表。
- **重复功能**：VIP 柜两处设置合成一处；自定义字段与标签合成标签一套；两处生日礼抽成同一个「生日前 N 天」的判断；单张发券与批量发券共用写发券记录的代码；使用率看板与营销成本共用同一套分组。
- **浏览器用例跟上新页面**（`4ba6a40`）：会员列表上方的「按标签筛选」下拉框的选项也是 option，查找会员限定在「会员列表」里；会员权益默认按档阶，原来核对清单的用例先切「按类别」；「充值」按钮的查找排除「充值记录」的展开按钮。

### 1.5 版本号

12. **11**：对账付款（`qianfen`）、成本核算的账号：数据看板没有「营销成本」，接口 403；在后台把「营销成本测算」加给后勤岗位，有财务职责的仍然 403；日结、对账包里没有营销成本的数。
