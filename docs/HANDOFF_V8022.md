# v8.0.22 交接说明 · 多门店、多店多仓、多公司主体、AI 辅助（这一批的收尾版）

店主 2026-11-14 排期的三版里的第三版（`docs/SCHEDULE_V8020.md` 第 4 节），店主 2026-11-15 定为这一批的收尾版：「请继续下一步开发，这次开发请你进行目前所有开发任务的收尾工作」。设计 `docs/MULTISTORE_V8022.md`（多门店、多店多仓、多公司主体、价目按店）、`docs/AI_V8022.md`（AI 辅助）；MD1–MD7 店主 2026-11-14「全部都按照默认」已确认，细分的 MD8–MD21 标「待确认」（`docs/PENDING_DECISIONS.md`）。迁移 `153`–`158`。

## 0. 升级后马上会看到的变化（请先读）

- **只有一家店时与 8.0.21 一样。** 现有数据全部归「本店」（代码 `HQ`，名称取设置里的门店名），已有单据内容不改；没有换店按钮，看板没有「合并」开关，库存没有「调拨」页签，合同与银行账户没有主体选择。
- 后台「人员与行政」多一个分区「门店与主体」（门店、公司主体、门店之间的储值结算表）；员工档案多一项「门店」（多选）。新建第二家店以后：能进几家店的人左侧导航多一个换店按钮（显示当前门店的代码），看板多「本店 / 合并 N 家」，库存多「调拨」，在第二家店里「价目与套餐」多「本店价」。
- 数据看板「经营总览」顶上多一块「昨日小结」，看板多一个页签「问数」；ERP 首页多一行昨日小结（生成好了才有）。**没配 `YUZU_AI_API_KEY` 时一条数据都不发出去**：小结只有当天的数字、写「还没配置模型服务」，问数写「还没配置」，合同表单上没有「AI 看一下条款」。
- 后台「对外接口」多一行「AI 辅助」与一块开关（整项、小结、问数、条款提示、推企业微信、拒答换模型、每人每天问几次；都默认开，KG1）。
- 没有新权限：门店与主体要「门店设置」，员工挂门店要「员工账号」，调拨要「库存操作」（看要「查看库存」），储值结算表与 AI 小结、问数要「看经营总览」，条款提示要合同权限。

## 2. 迁移、演示数据与固定预期

- `153`：门店、主体、员工挂门店、按店的设置、会话的当前门店，回填「本店」「本公司」，现有员工都挂本店。`154`：二十多张表加 `store_id`（默认 `yuzu_store()`，本店不设任何上下文、默认就是本店），手牌、设备、房间、技师、桌台、空间等的唯一约束改成「门店 + 编号」。`155`：仓库加门店与名称、调拨单与明细，「确认作废」的业务类型、单据与流水的种类在当时的约束上追加。`156`：财务单据加 `entity_id`（默认当前门店的主体）。`157`：本店价。`158`：AI 小结、问数的记录，对外调用的种类追加 `ai`。都是加表、加列、追加约束，不改已有数据；`159`、`160` 没用上。
- **演示数据没有预置第二家店**（预置了店主每一页都会多出换店与合并）：要看多门店，在演示库后台「门店与主体」新建一家（第 4 节）。`demo-prepare` 最后那一轮每分钟任务会生成前一天的 AI 小结（没配密钥只有数字；`INTEGRATIONS_MOCK=true` 时是模拟文字）。固定预期（`src/server/demo/*-expected.json`）不变。
- 升级：CI「从上一发布版本的演示库升级」在 8.0.21 的演示库上启动本版本、自检通过。

## 4. 验收要点

1. **只有一家店**：升级以后前台、看板、ERP 与 8.0.21 一样；`node dist/server/cli.js check` 全 ✓。
2. **第二家店**：后台「门店与主体」新建一家（自动有「XX 主仓」）→ 给一位员工挂本店与这家店 → 这位员工登录后左侧导航换店；换到第二家店：手牌、班次、日结、设备、客房、技师、桌台、预约都是这家店自己的（同号同名可以两家各一份），看不到、改不到本店的；本店的会员到第二家店用储值结账，流水记第二家店，「门店与主体 → 储值结算」出两家店之间的数。
3. **按店看与合并看**：看板「本店 / 合并 N 家」；`node dist/server/cli.js daily-recon --store <代码>` 出那家店的对账包。
4. **调拨**：库存「调拨」新建（总仓 → 第二家店主仓）→ 调出仓马上少、在途 → 调入按实收（少了写原因）→ 两边结存与流水对得上；在途的撤回原数退回；同一家店里的仓之间、数量超过结存的拒绝。
5. **主体**：新建第二个主体、第二家店挂上 → 在第二家店新建合同、银行账户默认是它，也可以选；合同台账按主体筛；第二家店的结账开票申请，销售方是它。
6. **本店价**：在第二家店「价目与套餐 → 本店价」改一个项目的价 → 第二家店挂账按本店价，本店照旧。
7. **AI（没配密钥）**：昨日小结只有数字、问数提示没配置、合同表单没有按钮；「对外接口」AI 辅助「没配置」。
8. **AI（`INTEGRATIONS_MOCK=true` 的独立演示库）**：昨日小结有模拟文字、「重新生成」；问数问一次（没收到结果原样再发不会多问一次）；合同「看一下」交回一条示例；后台关掉问数以后页签消失。
9. **打码**：问数时问题里写一个 11 位手机号 → 对外调用记录、发给模型的内容里只有前三后四；小结「看给 AI 的数字」里没有会员的名字。
10. 全程 `check` 全 ✓。

## 5. 做过的反向验证

- 两家店同号的手牌、同编号的设备、同房号的房间、同工号的技师、同名的桌台各自建得出来，清单只看自己店的；用别家店的手牌接待 → `TAG_NOT_FOUND`；改别家店的设备 → 找不到。
- 调拨：同一个编号原样重提返回同一张、内容不同 → `IDEMPOTENCY_CONFLICT`；同一家店的两个仓 → `SAME_STORE`；调出仓不够 → `INSUFFICIENT_STOCK`、什么都不动；实收超过调出 → `RECEIVED_OVER`；短少不写原因 → `VARIANCE_REASON`；调拨生成的单据单独冲销 → `NOT_VOIDABLE`；撤回以后再调入、调入以后再撤回 → `TRANSFER_CLOSED`。
- 主体：指定不存在的主体 → `ENTITY_INVALID`。
- AI：工具参数晚于今天、超过 92 天、多给参数 → 拒绝（模型看到的是一句话的原因）；只有经营总览权限的人拿不到会员、技师、库存、付款的工具；收银问数 → 403；同一个编号换了问题 → `IDEMPOTENCY_CONFLICT`；超过每人每天的次数 → `AI_LIMIT`；关掉 → `AI_DISABLED`；没配 → `AI_NOT_CONFIGURED`；模型拒答 → 「这个问题答不了」；模型连不上 → 小结记失败、5 分钟后再试、试满 3 次停，「重新生成」从头再来；一份生成得太久（过了 10 分钟租约）被当成中断、别人重新生成完以后，第一次的结果才回来 → 不盖掉新的、也不推送；只有一家店时要全公司的小结 → 403。

## 6. 已知的限度

- 时区全系统一个（MD12）；估清、出品档口全公司一份（MD13、MD21）；单号不带门店（MD14）；库存成本全公司一个（MD15）。
- 总仓固定是本店原来的总仓；采购单的「收货门店」、集采按门店分货这一版没有，用调拨（MD20）。
- 小程序线的入口照旧落在本店，只有扫码点餐跟着桌台所在的门店；小程序怎么选门店由小程序线另排。
- AI：模拟的问数只按问题里的字挑一样工具取一次数、原样列出来，不代表正式模型的回答；正式服在大陆直接连不上 Anthropic 的接口（MD8，店主选代理或换一家服务）；同一位员工的问数次数按门店时区的自然日算。
- 门店之间的储值结算表只是报表，不记账；两家店是同一个主体时只做参考。
