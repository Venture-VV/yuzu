# v0.7.8 交接说明 · 飞书需求 RQ-005 第二步：部门采购需求单、采购单的图片与规格；v0.7.7 审查修正（资金候选版本）

RQ-005「采购与费用闭环」的第二版。部门在系统里提采购需求，采购审核后勾选转采购单，「是否下单 / 到货 / 退货」由采购单与收货单自动回写。设计见 `docs/REQUISITIONS.md`；默认规则（待确认）见 `docs/PENDING_DECISIONS.md`「部门采购需求单与图片」。另带 v0.7.7 合并时 Codex 代码审查的四条修正，涉及报销与应付，所以按资金候选版本验收。

- **迁移 `027_requisitions.sql`**：新职责「部门申购」、员工的所属部门；图片表 `erp_images`（只追加）；需求单 `purchase_requests`、需求行与图片（通过、不采购、撤回后不能再改）；采购单行加规格 `spec`、图片 `purchase_order_line_images`、与需求行的关联 `purchase_order_line_requests`（采购单确认后不能再改）；「确认作废」登记 `op_fences` 加报销、备用金、需求单四类。只加表、列与约束，不改已有数据。
- **阻断项**：账错（报销与应付重复付款、需求单进度算错）、越权（部门申购看到别的部门的需求单、不能审核的人能通过、不能转采购单的人能转）、数据丢失（断网后重新填写造成重复登记）、破坏库存 / 采购 / 应付货款 / 费用报销原有流程。

## 1. 范围

| 项 | 内容 |
| --- | --- |
| 需求单 | ERP「采购需求单」：提需求（已有物料或新产品；新产品必须有链接和图片）、采购通过 / 退回 / 不采购、提单人修改 / 撤回；每一行显示下单、到货、退货与采购单号 |
| 转采购单 | 「待转采购单」勾选已通过的行 → 采购单表单带入：同一物料合并成一行（数量能换算的加好）；新产品选已有物料或新建物料；草稿时可以去掉某行需求的关联 |
| 图片 | 浏览器压缩后上传（单张 ≤ 1 MB、每行 ≤ 9 张）；需求行、采购单行都能挂图；采购单详情、按单收货显示缩略图，点开看大图 |
| 规格 | 采购单每行加规格（默认带物料档案的规格或需求单的详情）；采购单详情、按单收货显示 |
| 员工所属部门 | 后台「员工」编辑里选所属部门；部门申购只能给它提需求单 |
| 权限 | `request.create`（店主；部门申购）、`request.review`（店主；采购经办）；需求单查看：部门申购看本部门与自己提的，采购看全部 |
| 自检 | `check` 加「需求单与采购单一致」；费用的「现付供应商的收货不记应付」加两条（同一采购单结算方式一致、报销的采购单没有挂账收货） |
| v0.7.7 修正 | ① 报销、打款、退回补付断网后本机记下原编号与原请求，可查回、重提、作废（服务端作废登记）；② 一张采购单只认一种结算方式；③ 成本核算能取部门；④ 报销合计不截断、导出不截断 |

## 2. 验收要点

| # | 操作 | 预期 |
| --- | --- | --- |
| R1 | 后台建「后勤人员 + 部门申购」员工，不选所属部门，登录 ERP 提需求 | 页面提示没填所属部门，提交拒绝（`DEPARTMENT_REQUIRED`）；店主在员工里选了部门后可以提，部门固定为所属部门 |
| R2 | 提一行新产品：不填链接 / 不传图片 / 链接不是 http(s) 开头 | 分别拒绝（`LINK_REQUIRED`、`IMAGE_REQUIRED`）；选已有物料的行可以不填 |
| R3 | 上传一张手机大图（几 MB） | 浏览器压缩后上传成功；伪造的非图片文件拒绝（`IMAGE_INVALID`） |
| R4 | 部门申购看需求单列表、打开别的部门的需求单 | 只看到本部门与自己提的；别的部门的打开 404；前台店员进不了 |
| R5 | 采购退回 → 提单人修改后提交 → 采购通过；通过后提单人再改 / 撤回 | 回到待审核，通过后修改、撤回都拒绝（`INVALID_STATE`） |
| R6 | 两个部门各提一行同一物料（单位用采购单位），采购通过后在「待转采购单」一起勾选转采购单 | 采购单里合并成一行，数量相加，行上显示两张需求单；两张需求单的那一行都显示「已下单」并注明合并 |
| R7 | 勾选一行新产品转采购单，点「新建物料」 | 名称、规格、单位带过来；保存后加进明细，图片带过来；提交后需求单显示已下单 |
| R8 | 同一行需求再转一次采购单（另一个浏览器同时转） | 只有一张成功（`REQUEST_LINE_ORDERED`）；采购单撤回后这一行回到「未下单」可以重新转 |
| R9 | 按单收货一部分、全部、再退供应商一部分 | 需求行依次显示部分到货、已到货、退货数量；收货页每行显示规格与图片 |
| R10 | 采购单确认后，直接在数据库改它的图片或需求关联 | 拒绝（触发器）；改版后可以改 |
| R11 | 报销登记时断网（浏览器开发者工具设离线后提交），刷新页面 | 页面顶部「费用报销结果待确认」，新报销不能提交；联网后「按原内容重新提交」只登记一次；或「作废这笔」后原请求再到也不登记（`OP_ABANDONED`）。打款、退回补付、需求单同样 |
| R12 | 挂账供应商的采购单收一部分货 → 供应商改成现付 → 按这张采购单报销 | 不在可报销列表里，登记拒绝（`CREDIT_SUPPLIER`）；反过来：现付时已报销的采购单，供应商改回挂账后再收货，不记应付 |
| R13 | 只有「成本核算」职责的员工登记报销、打款 | 部门下拉有选项，能登记 |
| R14 | 从 v0.7.7 的演示库升级 | 迁移 027 后 `check` 全 ✓；原有采购单、应付、报销不变 |
