# v8.0.11 交接说明 · 巡场轮次

8.0.10（PR #92）2026-11-11 合并为 main `9afc361`、`v8.0.10` 已打上。同一天店主提了一个新需求，并要求提交到主线的 PR #95：

> 安保的巡场要按照时间单位，目前我们准备做成 3 个小时要巡场一次，单次巡场时间内，只能打卡一次，然后这个巡场间隔是可以调整的，比方说可以设置 4 小时巡场一次，或者其他时间，对于能查看巡场记录的人来说，巡场记录要做成一天之内的每次巡场的打卡数据，哪些场地没打哪些打了。

设计与算法在 `docs/PATROL_V809.md` 第 11 节；规则 XC13–XC16 在 `docs/PENDING_DECISIONS.md`「8.0.11 巡场轮次」（待确认）。这一版只有这一项，改的都在安保巡场（8.0.9）这个模块里。

## 1. 范围

| 哪里 | 改了什么 |
| --- | --- |
| 打卡（员工端口） | 按扫到的时间归到这一天的某一轮；同一个场所每轮只记一次（不论是谁打的），这一轮已经有人打过的再扫返回「这一轮已打过卡」与谁几点打的、不另记；作废以后这一轮又能打；断网补交按扫到的时间归轮 |
| 后台「安保巡场 → 设置」 | 多一项「巡场间隔」：默认每 3 小时一轮，30 分钟到 24 小时、半小时一档；从改的那一天（营业日）起按新的间隔，当天已经打的卡按新的重新归轮，以前的日子照旧 |
| 后台「今天」 | 改成「场所 × 轮」的表：格子里是谁几点打的；已经结束的轮没打的标「漏巡」，正在巡的标「待巡」；上面有这一轮的进度与今天漏巡的数 |
| 后台「巡场记录」与导出 | 多一列「轮次」 |
| 手机「巡场」（保安） | 列这一轮每个场所巡了没有（还没巡的排前面）、每个场所今天各轮的小圆点；打卡成功写第几轮 |
| 手机「巡场记录」（指定的人） | 按轮一段一段列：每轮巡了几处、漏巡哪几处；正在巡的与有漏巡的轮默认展开 |

取代的旧规则：XC5（同一个人 2 分钟内重复扫只记一次）由 XC14 取代；XC6 里「不规定频次」由 XC13 取代，路线仍不规定。

## 3. 验收要点

照 `docs/PATROL_V809.md` 第 11.3 节的 7 条：

1. 后台「设置」：巡场间隔默认「每 3 小时一轮」；不是半小时整数倍、或超出 30 分钟到 24 小时的，接口拒绝。
2. 保安扫一个场所：「打卡成功 · 第 N 轮（时段）」；同一轮自己再扫、另一位保安再扫，都提示「这一轮已打过卡」、写是谁几点打的，次数不加；扫别的场所照样成功。
3. 后台作废这一轮那条打卡以后，再扫这个场所：打卡成功。
4. 断网扫、联网补交：按扫到的时间归轮；补交的那一轮已经有人打过的，提示「这一轮已打过卡」。
5. 后台「今天」：每行一个场所、每列一轮；结束的轮没打的标「漏巡」，正在巡的标「待巡」；上面的「漏巡」数与表里一致。「巡场记录」列表与导出有「轮次」列。
6. 手机「巡场记录」：按轮列，有漏巡的轮标红、默认展开；按人筛以后别人打的写「别人巡的」。
7. 设置改成「每 4 小时一轮」：今天变成 6 轮、已经打的卡按新的归轮；以前的日子照旧按 3 小时显示。

阻断项照 `AGENTS.md`：账错、串单、越权、数据丢失、破坏旧模块自检。这一版不碰会员、钱包、结账、库存。
