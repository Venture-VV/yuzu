# UI 工作台（8.1.1–8.1.2）：设计师在系统里直接改版面

店主 2026-11-15：「我想把菜单那里，UI 版面等设计直接做开放给设计师，省的我们跟设计师一直在一版一版调整，你可以把菜单那边的设计弄成 figma 吗？或者说一步到位，直接做一个类似 figma 的这种 UI 编辑环境放在我们系统里，这样以后我们的各个子模块，比如员工食堂，小程序，平板菜单，都可以用同一套 UI 编辑环境去完成（也可以叫工作台），一定要做到傻瓜，可视化，操作简单，自由度高。你可以花 8.1.1 和 8.1.2 去完成，规划一下。」

排期见 [`docs/SCHEDULE_V811.md`](SCHEDULE_V811.md)；默认做法 GZ1–GZ12 记在 `docs/PENDING_DECISIONS.md`。店主 2026-11-15 定：**GZ3 设计师可以发布**；**GZ4 工作台就在后台，正式服公网也可以访问**（与 Z5 一致）；其余照默认、待确认。

## 0. 结论

**建议一步到位，做系统里的工作台；Figma 只当参考，不当交付物。**

- **只做成 Figma 稿解决不了「一版一版调整」**：Figma 稿是图，设计师每改一版，开发还要照着重写一遍代码、再截图核对，来回照旧。现在的电子菜单就是这么做出来的（设计稿 22 屏 → 开发照着写 → 逐屏比对截图）。
- **工作台把这一步去掉**：设计师在系统里改的那一份就是平板上显示的那一份（编辑器和平板用同一个渲染器），改完预览、发布，平板就是新样子，开发不用介入；改坏了一键回到上一版。
- **Figma 还能用**：设计师可以照旧在 Figma 里构思、出图标与插画，导出图片（PNG、SVG）传进工作台的素材库。要把现在的菜单画成一份 Figma 稿当参考，Claude 的 Figma 连接需要店主先在 claude.ai 的连接器设置里授权（这个会话现在连不上），授权以后可以另做，不影响工作台。
- **一套工作台、几个界面**：8.1.1 先做平板电子菜单（最常改、店主最想放开的），8.1.2 加员工食堂手机端，并给出小程序用的版面格式（小程序是微信原生写法，渲染组件由小程序线的 Gemini 照格式写）。
- **傻瓜**：从「现在的样子」开始改，不用从白纸画；拖、点、打字，不写代码；每一步都在平板大小的框里、用真实菜单预览；发布前自动检查（缺了下单按钮、字被截断、颜色看不清、按钮太小……）；有撤销、有版本、有回滚。
- **自由度高**：起始页整页随便排；菜单页、菜品卡片、菜篮的位置、大小、颜色、字体、圆角、阴影、图片比例都能改；可以加海报、文字、图形、自己的组件。**点菜、下单、点单密码、断网时的「结果待确认」这些逻辑不开放**——设计师改它们长什么样、放在哪，不改它们做什么，保证改版面不会改出账错。

## 1. 设计师用起来是什么样

1. 用「设计师」账号登录，只看得到工作台（看不到前台、会员、经营数据）。
2. 左上选界面（平板菜单）和屏（起始页、菜单、菜品详情、菜篮、下单……），中间是平板大小的画布，显示的是真实菜单。
3. 点中画布上任何一块，右边出现它的属性：版式（横排 / 竖排 / 网格 / 自由摆放、间距、对齐、大小）、样式（颜色、字体、字号、圆角、描边、阴影、透明度）、数据（这块显示菜名、价格还是图片）、交互（点了去哪一屏）。
4. 拖动换位置、拉角改大小，靠近别的块时自动出对齐线；左边的图层树可以拖着调前后、分组、锁定、隐藏。
5. 左边「插入」：基本元素（框、文字、图片、图形、图标、按钮）、菜单模块（分类导航、菜品网格、搜索框、菜篮按钮……）、素材库里的图。
6. 「主题」一页改全局的颜色、字体、圆角，改一处，用到它的地方一起变；有一份照汤崎品牌书（`brand/`）做好的预设。
7. 右上「预览」：在框里像客人一样点（翻分类、加菜、开菜篮），不会真下单；可以换平板尺寸、中 / 英文看；也可以在真平板上扫码打开预览。
8. 「检查」列出问题，红的（比如菜单屏上找不到下单入口）不改不能发布，黄的提醒一下。
9. 「发布」：写一句改了什么，设计师自己点发布就生效（GZ3），各台平板在空闲时换成新版（客人正在点菜时不换）；「版本」里任何一版都能「用这一版」回去，店主看得到谁、什么时候发布的。

## 3. 版面数据（一份版面 = 一棵节点树）

一个界面的版面存成一份 JSON 文档，编辑器、平板、员工食堂、小程序都读这一份：

```jsonc
{
  "schema": 1,                       // 格式版本；以后改格式写升级函数，旧版面自动升上来
  "surface": "emenu",                // 哪个界面
  "theme": { "color.brand": "#1F4D3A", "font.title": "brand-serif", "radius.card": 16 },
  "screens": { "start": { /* 节点 */ }, "menu": { }, "dish": { }, "cart": { }, "confirm": { }, "done": { } },
  "components": { "dishCard.featured": { /* 设计师自己存的组件 */ } },
  "assets": ["a3f9…"]                // 用到的素材（按内容的摘要）
}
```

节点：`{ id, type, name, layout, style, props, bind?, on?, children? }`。

| 类 | 节点 | 说明 |
| --- | --- | --- |
| 基本 | 框 `frame`、文字 `text`、图片 `image`、图形 `shape`、图标 `icon`、按钮 `button` | 框可以「自动排列」（横排、竖排、网格、换行，间距、内边距、对齐；大小固定 / 跟内容 / 撑满）或「自由摆放」（贴左右上下、居中） |
| 数据 | 重复 `repeat`、字段 `field` | 重复：按一份列表（例如某个分类的菜）把里面的模板重复一遍；字段：显示这条数据的一项（菜名、英文名、价格、图片、标签、售罄） |
| 功能块 | 各界面在代码里登记 | 平板菜单：分类导航、菜品网格（卡片模板可改）、搜索框、菜篮按钮、菜篮抽屉、备注、确认下单与点单密码、结果待确认、语言切换、手牌与桌号。逻辑在代码里，设计师改样式、位置、卡片模板 |

- **样式都是有类型的数值**：颜色、字号、圆角、阴影……可以直接填，也可以引用主题（`{color.brand}`）。**版面里没有 HTML、CSS、脚本字符串**；图片只能来自素材库（不能填外部网址）；「点了做什么」只能从这个界面登记的动作里选（打开某一屏、打开菜品详情、切分类、开菜篮、切语言……）。这样版面改得再乱也只是难看，不会注入脚本、不会把数据发到别处、不会绕过下单逻辑。
- **文字中英两份**：设计师写的文字有中文、英文两格；系统自己的提示（「已售罄」「下单」……）照用现有的中英对照。中 / EN 切换开着时，英文没填的在「检查」里报黄。
- **几种尺寸**：平板菜单照现在的做法按 1024×768 排、等比缩放到屏幕（`docs/EMENU.md` 第 3 节），竖屏可以单独调；员工食堂、小程序按手机宽度（375）排，宽了照比例放。
- **校验**：服务端用同一份格式定义（zod，`src/shared/studio/`）核对，不合格的存不进去；平板读到不认识的属性就忽略（新编辑器配旧平板也不白屏）。

## 4. 渲染：编辑器和平板用同一个

- 节点树 → React（行内样式：flex、grid、绝对定位），画布里和平板上走的是同一段代码，所见即所得。功能块渲染的是现有的组件（菜品卡片、菜篮、点单密码……），只是样式从版面里取。
- **永远有一份能用的**：没发布过、取不到、校验不过时，平板用代码里内置的「默认版面」（就是现在的样子）；发布的版面按版本号缓存，断网也照常显示上一份。
- **换版不打断客人**：平板在起始页、或 10 分钟没人碰的时候才换新版；页面角落有一个很小的版本标记，出问题时好对。
- 素材按内容的摘要存、地址不变（长期缓存）；整份版面一般几十 KB。

## 5. 草稿、预览、检查、发布、回滚

| 环节 | 做法 |
| --- | --- |
| 草稿 | 每改一步自动存（版本号对不上的拒绝：另一个人刚改过，刷新再改）；撤销、重做在本机，最多 200 步 |
| 预览 | 编辑器里可以点（用真实菜单，不下单）；「在平板上看」生成一个 30 分钟有效的预览码，点餐平板扫码进预览，预览里下单按钮是灰的 |
| 检查 | 红（不能发布）：必需的功能块不在、某一屏点不到下单、菜品卡片上没有价格、引用的素材不存在。黄（提醒）：字在某个尺寸下被截断、正文和底色对比不够（低于 4.5:1）、按钮小于 44×44、图片太大（> 1 MB）、英文没填 |
| 发布 | 写一句改了什么，生成不可改的一版（v1、v2……），列出改了哪几屏；设计师、店主都能发布（GZ3，店主 2026-11-15）。发布、回滚记审计；带操作编号，没收到结果再点一次不会发两版 |
| 回滚 | 版本列表里任何一版都能「用这一版」：照那一版新发一版（只追加，历史不丢） |
| 定时发布（8.1.2） | 指定时间生效（换季菜单、节日海报），到点前可以撤；现在用哪一版 = 没撤销、已生效的里生效时间最晚的（GZ27） |

## 6. 设计师账号与权限

- 新岗位「设计师」：只进工作台。看得到菜单内容（菜名、图片、价格——版面要绑定它们），看不到会员、账、经营数据。
- 两项新权限：「工作台 · 编辑」（改草稿、传素材、预览），「工作台 · 发布」（发布、回滚、定时）。**店主 2026-11-15 定设计师可以发布（GZ3）**：设计师、店主两样都有；别的岗位要的在后台「岗位权限」里加。发布、回滚都记审计（谁、什么时候、改了什么），改坏了店主或设计师一键回滚。
- **设计师在哪儿改（GZ4，店主 2026-11-15 定）**：工作台就在后台（「工作台」分区，地址 `/studio`），设计师用自己的账号直接登录正式服的后台改、发布，草稿不影响平板。正式服对公网开放以后在公网也能上（与 Z5「公网也能上」一致）；对公网开放之前照 `docs/RELEASE_V800.md` 第 2.3 节做完加固、办好 ICP 备案，在那之前设计师经 Tailscale 进。公网上的保护照已有的：HTTPS、登录按来源 IP 限次（Z4）、设计师岗位的接口只放工作台（别的接口一律 403，用例核对）、上传的图只认图片格式、SVG 去掉脚本。演示库上做好再搬到正式服的「设计包导入导出」照旧在 8.1.2 做，作为可选。

## 7. 平板菜单（8.1.1 第一个用上）

- **屏**：起始页与输入信息、菜单、菜品详情、搜索、订单抽屉（菜篮）、备注、确认下单与点单密码、下单完成、售罄 / 下架 / 不在时段的样子、结果待确认（`docs/EMENU.md` 第 3 节）。
- **内置的「默认版面」= 现在的样子**：把现在的各屏原样搬进版面格式；浏览器用例逐屏截图，和改造前比对（1024×768、1180×820 两个尺寸，差异 < 0.5%），做到客人看不出换过。
- **内容照旧在后台「电子菜单」维护**：菜名、图片、价格、分类、版面页（哪几道菜在哪一页）都不动；工作台管的是长什么样、放在哪。
- **逻辑一行不改**：菜篮、点单密码（开关照 8.0.15）、操作编号、结果待确认、没人动回起始页、中 / EN 切换、动效套件都照旧，只是外观从版面里取。
- **设计师能改的**：起始页整页（海报、品牌、按钮位置都随便）；菜单页的分类导航放左边还是上边、多宽，菜品网格几列、卡片模板（图的比例与大小、菜名价格标签放哪、字体字号、售罄与推荐的样子）；菜品详情、菜篮抽屉、确认下单的样式；全局主题；动效的强弱（动效套件的三档）。
- **分两步（GZ13，8.1.1 实现时细分）**：8.1.1 开放主题（全局颜色、中英文字体，弹窗、抽屉跟着变）、起始页整页、菜单页上的装饰与翻页圆点；菜单页 11 种版式里面（照片、菜名、价格放哪——卡片模板）这些位置是照设计稿一处处量的、还连着放大一档的另一套位置，8.1.1 仍写在代码里，**8.1.2 做成可编辑的模板**（与组件、变体一起，第 13 节）。原计划菜单页本身与顶栏的位置也在 8.1.2 放开，实现时改成仍不动（GZ22）：卡片模板已经能把每一块挪到页面上任何地方，而菜品详情、订单抽屉、加菜的飞入动画都按顶栏在最上面排。

## 8. 员工食堂与小程序（8.1.2）

- **员工食堂**（柚子饭堂，`docs/CANTEEN.md` 第 21 节）：同一个 React 渲染器。8.1.2 开放首页与饭卡码页（GZ26；菜单页、「我的」以后看需要）；**饭卡码那一块的大小、留白、颜色锁定**（扫不出来就打不了卡），只能改它周围。
- **小程序**（微信原生写法，归小程序线；**格式说明见 [`docs/STUDIO_MP.md`](STUDIO_MP.md)**，8.1.2 第 1 步已交付）：主线交付三样——
  1. 格式说明：小程序能用的节点与属性（一个子集：flex 排列、绝对定位、文字、图片、图形、按钮、重复、字段；不用 CSS 网格，网格用「换行 + 固定列数」表达）；编辑器选「小程序」界面时只显示这些属性；
  2. 一组样例版面与 React 渲染器在 375 宽下的截图（`tests/fixtures/studio/mp/`），给小程序那边逐张比对；
  3. 读已发布版面的入口（主线的一个函数，小程序线在 `/api/mp` 里转出去，不另建表）。

  小程序线（Gemini）在 `miniprogram/` 里写一个递归渲染的自定义组件，Codex「小程序助手」在开发者工具里与样例截图比对。小程序里只开放首页、活动页、会员页这类展示页；充值、支付、退款页只开放样式（颜色、字体），不开放结构。
- 以后加界面（对客导览、门店电视屏、海报……）照同一个办法：在代码里登记这个界面的屏、功能块、动作、必需项与尺寸，编辑器就能用。

## 9. 怎么实现（给开发与测试）

- **代码位置**：格式与界面登记 `src/shared/studio/`；服务端 `src/server/modules/studio/`（草稿、版本、素材、预览码、发布、回滚、检查）；编辑器 `src/client/features/studio/`，地址 `/studio`；渲染器 `src/client/studio-render/`（平板、员工食堂打包时只带渲染器，不带编辑器）。
- **编辑器自己写**（React，与现有页面同一套），拖放、缩放手柄、框选这几处难写的用成熟的开源小库（MIT 许可，装之前核对许可、体积与版本，固定版本号）。评估过 Puck（MIT 的可视化页面搭建器）：适合「一块一块往下排」的网页，不适合画板式的自由摆放，数据格式也跟它的组件配置绑在一起，小程序那边没法照着渲染，所以不用它做底子。
- **加锁与幂等**（写进 `AGENTS.md`）：存草稿只锁这份版面一行（带版本号）；发布：操作编号的咨询锁（与「确认作废」串行）→ 版面一行 → 写新版本；回滚同发布；素材按内容摘要存（唯一索引去重，不加锁）；预览码只写自己一行。不碰任何业务表的锁。
- **用例**：格式与升级函数的单元用例；渲染器的快照；接口的集成用例（权限、版本号冲突、发布与回滚、重复提交、设计师进不了别的接口）；浏览器用例：设计师改颜色、挪一块、预览、发布，平板显示新版，回滚，店主在审计里看得到谁发布的；默认版面与改造前逐屏截图比对。

- **默认版面 = 原来的样子**：首页竖排、间隔 16、左右 16（原来是外壳的留白，柚子饭堂把外壳的 16 让给版面，设计师可以改）；饭卡码页居中、上 8、左右 16，各段带着原来的上边距。员工、负责人的首页与饭卡码页逐屏截图（固定数据、固定时间）像素一致。
- **柚子饭堂**：`src/canteen-app/studio.tsx` 取版面（登录着、联网时一次，存在手机上）、写主题色（老颜色名字跟着走）、`CanteenScreen` 照版面画；`pages/Home.tsx`、`pages/Code.tsx` 的各段搬进功能块，内容一字没改。
- **员工端口**：`GET /api/canteen/studio`（发布的那一版，组件已展开）、`/api/canteen/studio/assets/<编号>`（只给发布过的员工食堂版面里用到的）、`/api/canteen/studio/preview/<预览码>`（员工食堂的预览码、30 分钟），都要登录、只读。
- **不带 zod**：格式里不依赖 zod 的常数与小工具分到 `src/shared/studio/core.ts`，渲染器只从 `core`、`components`、`surfaces` 取；柚子饭堂只认「是员工食堂的版面」就用（服务端存、发、生成预览码时都核对过）。包从 127.6 KB 到 139.6 KB（gzip）。
- **编辑器**：员工食堂的各段画示意（`phoneBlocks.tsx`），在工作台里主题色、字体变量全写上（`themeVars(doc, true)`：这里没有柚子饭堂的样式表）；底色「无」画成柚子饭堂的暖白；预览弹窗写明在员工手机上加 `?studio=预览码`。
- **用例**：`tests/canteen-studio.test.ts` 4 条、`tests/studio-format.test.ts` 加 2 条、`e2e-canteen/studio.spec.ts` 1 条（发布以后员工手机上照新的样子、饭卡码照旧、用完发回默认）。

**第 4 步：定时发布、批注、「谁在改」、中英文案、设计包（GZ27–GZ30，迁移 `166`）**
- **定时发布（GZ27）**：
  - 发布弹窗选「现在 / 定时」，定时填这台电脑上的日期时间（最早 2 分钟以后、最晚 60 天以内，服务端按数据库的时钟核对，`STUDIO_SCHEDULE`）；定时的照旧带操作编号、走「结果待确认」，原请求摘要里带上生效时间。
  - 现在用哪一版（平板、员工手机、小程序线都走 `studioPublishedRef` / `readPublishedStudio`）：**没撤销、已经生效的里面生效时间（没定时的按发布时间）最晚的，同时的取版本号大的**。到点前又发了一版：先用新发的，到点照样换成定时的那一版（发布弹窗里写着）；回到某一版、「现在就用这一版」马上生效。
  - 撤销：编辑器「版本」里没到点的那一版有「撤销定时」（`POST /api/studio/<界面>/versions/<版>/cancel`，要「工作台：发布」）；撤了这一版永远不生效，撤销记在只追加的 `studio_version_cancels`（谁、什么时候、原因），再撤一次原样返回；已经生效的（`STUDIO_ALREADY_LIVE`）、不是定时的（`STUDIO_NOT_SCHEDULED`）撤不了；记审计 `studio_cancel`。
  - 看得到：编辑器顶上「⏰ 几号几点换版」（点开「版本」），版本列表里「定在…生效」「谁撤销了」「现在用的」，后台「工作台」首页写着下一次定时换版。
- **批注（GZ28）**：右栏「批注」（顶栏也有入口，带没解决的条数）：「加一条批注」再点画布上要说的地方（挂在点到的那一块上），写一句「留言」；回复挂在第一条下面（只一层，`STUDIO_COMMENT`）；第一条「解决了」以后画布上的圆点不见，「显示已解决的」里可以重新打开。在「版式」里点「加一条批注」先回到普通画布；「别的屏」的批注点一下跳过去。写了不能改、不能删；没发出去（或不知道发没发出去）的重发用同一个操作编号，服务端原样返回那一条（改了字再发、上一次其实记下了的拒绝 `IDEMPOTENCY_CONFLICT`，刷新就看得到）；每 30 秒刷新一次。按界面、按门店分；后台「工作台」首页写着几条没解决。
- **谁在改（GZ29）**：编辑器开着每 15 秒（和窗口回到前台时）报到一次，顶上写着同一个界面、同一家店的编辑器还有谁开着（45 秒没报到的不算）；只记在服务进程里、不进数据库，不锁、不拦，同时改照旧是后存的提示刷新。
- **中英文案（GZ30）**：「更多 → 中英文案」把一份版面里自己加的字（文字、按钮、数据字段前后的字，连同组件里的）列成一张表，中英对着改（进草稿、可以撤销），「只看英文没填的」；「导出 CSV」（带 BOM，Excel 打开不乱码；编号、屏、名字、中文、英文）给人翻译，「导回来」按编号对上、只改有变化的（字前后的空格原样保留：共用的 CSV 读法加了 `trim: false`，别的导入照旧去空白）。共用的纯函数在 `src/shared/studio/copy.ts`。内置功能块里的字（菜名、版权行……）照旧在后台对应的设置里改。
- **设计包（GZ30）**：「更多 → 设计包」：「导出设计包」先存草稿，再把存好的草稿连同用到的图存成一个 `.json`（`GET /api/studio/<界面>/pack`）；「选设计包文件」导进来（`POST`，最大 64 MB）：界面要对得上，每张图按内容重新核对（格式、SVG 去脚本、内容与编号对得上，`STUDIO_PACK`），按内容存（同一张只存一份），版面按现在的格式与界面登记核对（红的拒绝）——**不改草稿**，交回编辑器换上（可以撤销），照常自动存草稿、检查、发布；记审计 `studio_pack_import`。
- **顶栏**：中英文案、设计包收进「更多」；不到 1400 宽时顶栏的按钮只留图标（鼠标停上去有说明），1024–1600 宽都排成一行。发布、版本、提示里的「平板」按界面写（平板 / 小程序 / 员工手机）。
- **用例**：`tests/studio-collab.test.ts` 5 条（定时与撤销、按生效时间取现在用的、批注、谁在改、设计包）、`tests/studio-copy.test.ts` 3 条；浏览器 `e2e/studio.spec.ts` 加一段：店主也开着编辑器（「谁在改」）、设计师在画布上批注 → 店主回复 → 设计师标解决、中英文案改英文并导出、设计包改一句导进来、定时发布再撤销（平板照旧用原来那一版）。
