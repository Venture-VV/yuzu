# ERP 财务与法务审批 · 开发规划与排期

店主 2026-11-05：「目前财务法务审理的部分还不够全……规划下后面财务跟法务相关审批流程怎么开发，拍个期。」

依据：《ERP 补充方案 · 财务与供应链》《ERP 待整改项清单》《ERP 三流合一》三份材料（整合方法见 [`ERP_PURCHASING.md`](ERP_PURCHASING.md) 第 1 节），对照现有系统。v0.7.29 先做采购的五项；本文是之后的财务、法务审批怎么做、什么时候做。日期是开发会话的计划，店主可以调；每一期开工时再登记版本号、迁移号与待确认的默认。

## 1. 现在有的审批与控制点

| 环节 | 现状 |
| --- | --- |
| 采购单 | 草稿 → 提交 → 负责人确认；超过免确认门槛（默认 ¥2,000）才要确认；确认后改价改量走改版、留旧版本 |
| 报损、退供应商、付款、期初 | 同一套「负责人确认」开关与门槛 |
| 盘点调整 | 总仓的调整要负责人确认；差异没有原因与比例门槛 |
| 费用报销 | 超过门槛（默认 ¥2,000）要负责人确认；发票类型、税点、用途固定选项 |
| 备用金 | 打款、退回、补付登记即生效；每笔打款单独平账，超 7 天没平标红 |
| 冲销 | 财务岗只能冲当月的，写原因；所有单据只追加、留经办人 |
| 分岗 | 仓库、采购、对账付款、成本核算、负责人分岗不兼任（#17） |
| 待办 | 「审批待办」汇总负责人要确认的单据 |

缺的是：审批只有「负责人确认」一级、只按金额一个门槛；没有合同、付款节点、质保金、发票台账、预算；法务审查（合同条款、用印）完全在系统外；审批意见只有退回原因，没有逐级意见；部门账号能看到别的部门的数据（清单 #20，P0）。

## 2. 设计原则

1. **一个审批中心**：所有要审批的单据（采购、合同、变更、付款、报销、备用金、报损、盘点差异、退货）走同一套规则与待办，不在每个模块各写一套。现在的「负责人确认」平移成审批中心的默认规则，行为不变。
2. **按金额与类型分级，只拦异常**：门槛以下直接过；超过的按规则走一级、二级或三级；审批人按岗位或指定人，可以或签（一人批即可）或会签（都要批）。
3. **每一步都留痕**：谁、什么时候、同意 / 退回 / 意见；审批过的单据锁定，改要走变更。
4. **合同四要素是字段，不是附件**：单价与税率、付款节点、质保比例与期限、验收标准，付款计划与质保金从这里来。
5. **钱按节点走**：无单不付、无票不核、到期必提醒（演示稿第 7 页）。
6. **手机只做审批**：审批人在手机上看单据要点、批或退，其余操作在电脑上。

## 4. 各期怎么做

### 4.1 v0.7.30 审批中心

> **已做完（2026-11-05，[PR #65](https://github.com/Venture-VV/yuzu/pull/65)，迁移 `073`、`075`）**：按 `docs/APPROVALS.md` 实现，规则没定的按默认 A1–A10（`PENDING_DECISIONS.md`「审批中心」，待确认）。与下面的计划有两处细化：店主在每一级都能审（指定的人停用时单据不会卡住）；数据隔离这一版核对并补了部门账号的两处漏洞（图片、需求单自检），报销、备用金部门账号本来就没有权限。交接见 `docs/HANDOFF_V0730.md`。

- **审批规则**：每条规则 = 单据类型 + 金额区间（含下限、不含上限）+ 部门（可空 = 全部）→ 审批链（一到三级；每级是岗位或指定人；或签 / 会签）。命中多条取最具体的一条；都没命中的按「门槛以下直接过」。
- **审批单**：单据提交时按规则生成审批单与各级待办；每级同意进下一级，退回回到经办人并写原因；全部同意后单据生效（与现在「确认」的效果相同）。审批人不能审自己提交的单据。
- **审批待办**：一页看全部要我批的（按单据类型筛），单据要点、金额、经办、上一级意见一屏可见；可以批量同意同类小额单据；超过 24 小时没批的提醒；请假时可设代理人。
- **手机审批页**：竖屏，只做看与批（演示稿「移动端只做三件事」）。
- **平移**：现有的采购单、报损、退供应商、付款、期初、报销的「负责人确认」变成默认规则（门槛与现在一样），迁移时不改任何已有单据的状态。
- **盘点差异审批**（清单 #2）：差异超过 2% 或 ¥500 的盘点行必须写原因，走审批后才生效。
- **数据隔离**（清单 #20）：部门账号只看自己部门的需求单、小仓、报销与备用金；仓库看总仓与各小仓；店主、负责人、财务看全部（岗位可在「岗位权限」调）。
- **急采待补单**（清单 #1）：急采收货超过 3 天没补采购单的，升级到负责人待办。

### 4.2 v0.7.31 合同与法务审查

> **做完（2026-11-06，v0.7.31，[PR #66](https://github.com/Venture-VV/yuzu/pull/66)；交接见 `docs/HANDOFF_V0731.md`）**：设计稿 `docs/CONTRACTS.md`，迁移 `077`（台账、提交记录与审查清单、变更单、用印、扫描件）、`078`（采购单挂合同）；计划里要店主先定的四件事按默认 C3、C5、C6、C7 做（`PENDING_DECISIONS.md`「合同与法务审查」，待确认）。与下面的计划有一处细化：签署与用印的先后不限，归档要两样都有。

- **合同台账**：合同号、类型（采购 / 服务 / 租赁 / 其他）、相对方、签订日、起止日、总价与税率、附件（扫描件）；四要素做成字段：
  - 单价表（物料或服务、含税单价、税率，运费卸货谁承担）；
  - 付款节点（预付 / 到货 / 验收 / 质保，比例与触发条件）；
  - 质保（比例、起算日的依据、期限）；
  - 验收标准（按什么验、谁签字、不合格怎么扣）。
- **合同审查流程（法务）**：起草（业务）→ 财务审核（金额、付款节点、发票与税率）→ 法务审核（按审查清单逐条：主体资质、标的与规格、价格与税、付款、交付验收、质保售后、违约责任、争议解决、保密、期限与续签；每条「通过 / 要修改 / 风险提示」并写意见）→ 负责人审批 → 签署（签订日、签署人）→ **用印登记**（印章种类、份数、用印人、日期，走审批）→ 归档。退回修改留每一版的内容与意见。
- **采购单挂合同**：有合同的采购单选合同，单价超过合同价、数量超过合同剩余量时提示，超过的要在审批里写原因。
- **变更单**：改价、改量、延期走变更单，保留旧版本与变更原因，按金额同样走审查与审批。
- **到期提醒**：到期前 60 天进待办，没续签的标红；没有合同的零星采购照旧走「询价记录 + 到货即付」（v0.7.29 的询价比价）。

### 4.3 v0.7.32 付款流

> **开工（2026-11-06）**：迁移从 `080` 起（`ROADMAP.md` 第 7 节已登记）；设计稿与待确认的默认值写好后补在这里。

- **付款计划**：合同生效后按付款节点自动排期；节点条件满足（到货 = 收货单已生效，验收 = 验收合格，质保 = 质保期满且没有质量问题登记）才「可付」；每期看得到「为什么现在能付 / 还不能付」。
- **付款申请审批**：经办选计划行或应付发起申请 → 财务审核（三单、发票）→ 负责人审批（按金额分级）→ 出纳登记付款（现有的付款登记、核销照旧）。没到节点的提前付款要写原因，多一级审批。
- **三单匹配**：采购单、收货单、发票自动比对，差异超过 1% 或 ¥50 挂起人工确认，其余直接过；付款前必须三单齐全（现付的照旧走报销）。
- **质保金台账**：一合同一条，单独挂账、不混应付余额；到期前 30 天进待办；未收回不结项。
- **本周应付**：每周一推送未来 4 周的付款计划与资金缺口，一键导出。

### 4.4 v0.7.33 费用预算与发票台账

- 部门 × 费用科目的月度额度；报销与备用金支出实时占用；超过 80% 黄灯提示，超过 100% 走审批中心加一级审批（不打断正常报销）。
- 进项发票台账：票号、开票方、金额、税额、税率、认证状态、到期日；报销与付款登记时选或建发票；异常（重号、税率不符、过期）自动标记；认证到期前 7 天进待办。拍照识别以后再接，先做拍照上传。

### 4.5 v0.7.34 供应链 P1 收尾

供应商准入与评分、部门耗用用途、呆滞与周转、验收标准模板化、在线对账确认，见总表；都按审批中心与合同的结构接上，不另起审批。

## 5. 风险与依赖

- **规则先定**：审批人、金额分级、合同模板、付款比例、预算额度都要店主定；开工前用默认值并标「待确认」，不等。
- **顺序不能乱**（演示稿第 14 页）：审批中心先上，合同才有地方审；合同四要素录准了，付款计划才准。
- **平移不改历史**：审批中心上线时已生效的单据保持原状态，只有新提交的走新规则。
- **小程序线并行**：小程序线的版本不受影响；两条线各用各的迁移号。
