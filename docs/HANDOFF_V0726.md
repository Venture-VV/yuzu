# v0.7.26 交接说明 · 会员体系收尾：储值退回、线上收款入口、停用 / 换号 / 合并、同行优惠

店主 2026-11-04 合并 v0.7.25 后开工，同日说「这次 PR 把会员体系都做完」。设计稿 `docs/MEMBERSHIP_FINISH.md`，默认做法见 `docs/PENDING_DECISIONS.md`「会员体系 v2」M69–M81（M50 浴票延迟的分钟数店主已定，其余待店主确认，店主不改就按它做）。

**储值退回与线上收款动的是储值**（钱包余额减少 / 增加），按资金候选版本验收（快速开发周期：CI 全绿后店主合并，验收在 main 的 v0.7.26 标签上补做）。同行优惠是优惠、不是收款，与 v0.7.25 的会员折扣同一套。

## 3. 验收要点

| 编号 | 项 | 怎么验 |
| --- | --- | --- |
| Q1 | QY-004 默认 | 新库导入清单：QY-004「浴票延迟」草稿，L1·初 起 30 分钟、各档阶表每一档 30 / 60 / 90；从 v0.7.25 升级、QY-004 没动过的同样补上，改过的不动 |
| R1 | 退储值的授权 | 店员打开会员详情「储值与账户」→「退储值」：值班经理授权被拒「不能授权退储值」，店主或店总授权后退回；授权只能用一次、5 分钟内有效、金额改了要重新授权 |
| R2 | 分配与原收款方式 | 会员先现金充 6,000、再微信充 10,000，退 12,000：分配为「微信那一笔 10,000（填退款单号）+ 现金那一笔 2,000（选钱箱）」；有期初余额的退到期初那一行时由员工选方式；页面打开后会员又消费了一笔，提交被拒「退回的明细与核对时不同」 |
| R3 | 赠金扣回 | 本金 10,000、赠金 1,000，退 2,500：扣回赠金 250；本金退到 0 时赠金全部扣回；赠金不退钱 |
| R4 | 降档 | 本周期靠充值升到 L3 的会员，退到滚动累计充值不够 3 万：当场降到够得上那一档的初阶，会籍周期不变，状态变化「储值退回」；**连续退回接着降**（充 3 万到 L3，先退 2 万降到 L2，再退清降到 L0，两次的核对都写明会降到哪一档）；最多降到靠充值升上来之前的档级（手动调到 L2 再充到 L3，退清回到 L2）；只靠保级、手动调整、上线定档留在这一档的不降 |
| R5 | 账 | 日结「储值」一节有「储值退回」与按方式的行，储值余额核对式平；退现金的那个班次交班表应有现金减少；看板与 ERP「营业数据」「退储值 −¥X · N 张」；对账包有 `11-储值退回.csv`；退储值单没有作废按钮 |
| R6 | 结果待确认 | 提交时断网、超时或回复 500：卡片上方结果待确认、「退储值」灰着；查回、按原内容重提只退一次；确认作废后原请求晚到被拒 `OP_ABANDONED` |
| O1 | 线上收款（接口级） | 主线没有对外接口，用 `tests/wallet-online.test.ts` 核对：同一个交易单号再到返回第一次的充值单、金额或会员对不上拒绝；不进班次；首充最低、单笔上限拒绝；停用照样入账并标出；合并掉的记到目标会员。小程序线接上后按小程序第二期的交接验收 |
| O2 | 线上收款的报表 | 有线上充值的营业日：日结「充值实收」下「其中线上（小程序）」、打印与导出一致；看板单列；充值单详情「渠道 小程序」与交易单号；员工名单里没有「小程序」 |
| S1 | 停用 / 启用 | 店主停用（写原因）：会员详情标「已停用」，充值、储值消费被拒，结账不享会员折扣与浴票延迟，接待按散客 VIP 柜，不能邀请；有在店手牌时停用被拒；启用后照常；记录列在「储值与账户」；店员看不到这两个按钮 |
| S2 | 换手机号 | 店员改手机号：不写原因保存被拒；写了原因保存时弹出当场授权，值班经理授权后改好，记录写「张经理授权」；值班经理自己改不用授权；新号码已是别的会员的照旧拒绝 |
| G1 | 合并的前提 | 来源会员有在店手牌、体验中、有能用的券、今天有储值消费、已停用，核对页列出原因、「确认合并」灰着；目标会员不能是自己、不能是已合并的 |
| G2 | 合并的结果 | 来源（本金 3,000、赠金 300）并进目标：目标余额加上这两项，赠金批次的到期日不变；来源会员标「已合并到 X」、余额 0、不能编辑 / 接待 / 退储值；目标取两位里高的档阶（来源高时记「合并」）；之后目标的滚动累计充值把来源的算进去 |
| G3 | 合并以后的限制 | 来源会员合并之前的储值消费不能撤销、对应结账单不能反结账（`MEMBER_MERGED`）；期初导入到已合并的会员被拒 |
| G4 | 与接待并发 | 接待已核对、还没写来访时合并提交：接待被拒 `MEMBER_MERGED`，原档案不在店；接待先锁住会员时合并等它、再核对时看到在店手牌拒绝；接待核对之后会员被停用：接待被拒 `MEMBER_CHANGED`，重新提交按散客接待（`tests/member-admin.test.ts` 用持表锁的办法复现三种交错） |
| C1 | 同行优惠的配置 | 「会员权益」里 QY-041：同行的门票、带 1 位、L6·初 起 2 位、没填折扣，发布被拒「请填写起点的折扣」；去掉同行几位发布被拒「请填写起点能带同行几位」；填 80（8 折）后发布，列表写「同行的门票（带 1 位，L6·初 起 2 位）」 |
| C2 | 结账自动带上 | L3 会员与两位散客、一位别的会员合并结账：会员折扣「同行的门票 <手牌>」，打手牌号在前的那位散客的门票（门票一样贵时），金额 = 门票 × 20%（四舍五入到分）；别的会员不算同行；L6 会员带 2 位；只结会员自己时不出现 |
| C3 | 与本人的折扣比 | 再发布一项本人门票 9 折：同行优惠省得多就用同行优惠，一单一种；停用的会员什么折扣都不享 |
| C4 | 入账 | 结清后收款明细「会员折扣」备注写同行的手牌；部门营业额快照「门票」分到的优惠 = 会员折扣；`check` 全 ✓ |
| U1 | 从 v0.7.25 升级 | 应用 `047`：没动过的 QY-004、QY-041 补上默认（仍是草稿）；升级前的充值、结账照常；`check` 67 项全 ✓ |
