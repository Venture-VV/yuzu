# v0.7.15 交接说明 · 飞书需求 RQ-004 第二段：底图转换

店主 2026-11-01 合并 v0.7.14 后开工 RQ-004 第二段「底图转换」：设计方的编码图（DWG）在系统里转换成按楼层的简化底图与房间轮廓，与空间台账比对后由店主或店总启用，第三段房态图用启用的那一批。设计与编码图实测见 `docs/FLOORPLAN.md`；默认做法（待确认）见 `docs/PENDING_DECISIONS.md`「底图转换」。

- **迁移 `033`**：
  - 新表：
    - `floorplan_batches` 转换批次：文件名、大小、摘要、格式、转换程序版本、状态（转换中 / 待启用 / 转换失败 / 在用 / 已换下）、失败原因、转换报告、用时、上传与启用的人和时间；同一份图纸（摘要）、同一版转换程序只有一批（失败的除外），同时只有一批在转换、一批在用；不能删，文件信息与转换结果不能改，状态只能往前走；
    - `floorplan_floors` 每层底图：楼层、标题、宽高（10 毫米一单位）、图框、SVG；
    - `floorplan_rooms` 房间轮廓：每个编码一行，状态、连成一片的编码、封门洞半径、轮廓（只有配上的才有）、文字位置、面积；
    - 底图与轮廓只追加，不能改、不能删。
  - 只加表；升级后没有批次，空间台账、客房都不变。
- **新依赖**：`@mlightcad/libredwg-web` 0.8.1（开源 LibreDWG 的 WebAssembly 版，GPL-3.0，版本固定），只在转换进程里加载。转换进程的入口打包成 `dist/server/floorplan-worker.js`。
- **阻断项**：
  - 越权：值班经理、前台能上传、预览或启用；前台岗位能看到没启用的批次的底图。
  - 一次有两批在用；同一份图纸转换出两批；转换中的批次能启用；转换失败、已换下的能启用。
  - 转换结果被改、被删；启用后原来在用的没换下。
  - 按图纸改了空间台账（以台账为准，D6）。
  - 转换卡死主进程（前台操作被拖慢）或转换失败后应用不能用。
  - `check` 不是全 ✓；破坏原有空间台账、客房功能。

## 1. 范围

| 项 | 内容 |
| --- | --- |
| 读图 | DWG（LibreDWG 0.8.1 的 WebAssembly 版）与 ASCII DXF（自带解析）；二进制 DXF、其他文件拒绝。展开块参照、去掉外部参照的图层前缀、凸度圆弧、镜像、文字对齐。读不了的写明「读不了这个文件……（LibreDWG 错误码 N）」 |
| 转换 | 图层白名单（墙柱门窗楼梯电梯画进底图；完成面、门套、门的未开虚线只参与围合；区域文字是房间名与房号；家具、天花、机电、填充、标注等剔除）；按空隙分楼层，楼层由房号的楼层位或图上标题定；从房号文字点围合房间轮廓（详见 `docs/FLOORPLAN.md` 第 3 节）；每层一份 SVG |
| 例外 | 连到走廊或图外 / 几个编码连成一片 / 文字附近找不到空地 / 编码重复，预览里写处理办法；可以带着例外启用（确认框写明个数） |
| 转换进程 | 单独的子进程（只带运行需要的环境变量），限时 15 分钟；同时只转换一份（`FLOORPLAN_BUSY`）；应用重启时没转完的记失败 |
| 上传 | 后台「空间台账 → 底图」：DWG / DXF，≤ 30 MB（`FLOORPLAN_TOO_LARGE`），格式不对 `FLOORPLAN_FORMAT`；图纸文件本身不保存；同一份图纸重传回到原来那一批（200，`replayed: true`），失败的那份可以重传 |
| 预览 | 楼层切换、底图 + 房间轮廓（点房间看原文与面积）、放大缩小；例外清单；与空间台账比对；与在用的那一批比对；转换报告（图层清单与用途、提示、读图与转换用时、内存峰值）；下载 `spaces.geojson` |
| 启用 | 店主、店总；待启用的才能启用（其余 409 `FLOORPLAN_NOT_READY`）；原来在用的变「已换下」；操作审计记上传、启用 |
| 只读接口 | `GET /api/floorplans/active`（在用那一批的楼层与房间，房间按编码对上台账的空间 `spaceId`、显示名）；`GET /api/floorplans/<批次>/floors/<楼层>/svg`（在用的那批前台、客房服务员、收银也能看，其余批次只有后台能看，否则 404；带 `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'`） |
| 命令行 | `floorplan-convert <图纸> [--out 目录]`（不碰数据库）、`floorplan-sample <文件.dxf>` |
| 自检 | `check` 加一项「底图批次与房间轮廓一致」（比 v0.7.14 多一项；完整演示库上共 45 项） |
| 谁能用 | 店主、店总（与空间台账同一组权限：经营规则设置、价目与套餐）；值班经理、前台 403 |

## 2. 演示数据与固定预期

- 演示数据不变（没有底图批次）。验收用 `docs/data/` 下的合成样例图纸（全是编的，不是门店图纸）：
  - `floorplan-sample.dxf`：两层。L3 有 T301、T302、T303、V312、W301、W302 六间配上轮廓，W303 与 W305 之间没有隔墙（连成一片），W306 朝走道开了 3 米宽的洞（连到走廊）；L2 有 X201、X202。共 11 个编码、8 个配上轮廓、3 个例外。
  - `floorplan-sample-v2.dxf`：第二版。T303 改成 T305（同一位置换编码），W306 的洞改成门（配上了），X202 拆掉。
  - 编码与 v0.7.14 的样例台账 `space-zones-sample.csv`、`space-ledger-sample.csv` 对应：导入样例台账后，第一版与台账比对是「图上有、台账没有」T303、W303、W305、W306、X202，「台账有、图上没有」U310，「原始标注变了」T302（图上 1人间、台账 2人间），对上 6 个。
  - 固定预期见 `src/server/demo/floorplan-expected.json`；`node dist/server/cli.js floorplan-sample <文件>` 也能写出第一版。
- 门店的编码图（需求文档附件）**不进仓库**；开发环境的实测结果见 `docs/FLOORPLAN.md` 第 2 节（95 个编码全部配上轮廓）。在测试服上用真实图纸验收须店主同意，且只用命令行 `floorplan-convert`（不写数据库）或演示库。
- `check` 比 v0.7.14 多一项（四套演示数据加旧账样例的演示库上是 45 项；各环境以「比升级前多一项、全 ✓」为准）。
