## 2. 检查结果

### 2.1 发版机制：没问题

- `v8.0.0` 由 CI 自动打：「版本标签」认 `X.Y.Z` 格式，main 上 CI 通过后按 `package.json` 打。部署脚本 `scripts/update.sh` 也按 `package.json` 认版本号。
- CI「从上一发布版本的演示库升级」会从上一个标签 `v0.7.33` 升到这一版再核对。`v0.7.33` 已经打在 PR #73 的合并提交 `85bb0f0` 上；PR #72 合并时 CI 被运行机换版本卡住，PR #73 修好了。
- 0.7.33 → 8.0.0 没有新迁移。

### 2.2 代码里随这个 PR 改了的

这几项默认都不改现在的行为，只有正式服上设了对应的环境变量才生效。

| 项 | 原来 | 现在 |
| --- | --- | --- |
| 登录 Cookie 的 Secure | `compose.yaml` 没把 `COOKIE_SECURE` 传进容器，`.env` 里设了也没用 | 传进去；正式服走 https 时设 `COOKIE_SECURE=true` |
| 信任反向代理 | 主应用不认转发头。正式服在 Caddy 后面时，所有请求的来源 IP 都是 Caddy，审计日志记不到真实 IP | 加 `TRUST_PROXY`（填代理的地址），来源 IP 与 https 按代理转来的算 |
| 端口开在哪 | `compose.yaml` 把 8080 开在所有网卡上；云服务器上 Docker 发布的端口会绕过主机防火墙 | 加 `APP_BIND`；正式服设 `127.0.0.1`（只给本机的 Caddy）或 Tailscale 地址 |
| 安全响应头 | 只有 `nosniff` | 加 `X-Frame-Options: SAMEORIGIN`（不让别的网站嵌进去，防点击劫持）、`Referrer-Policy: same-origin`；HTTPS 的 HSTS 在 Caddy 上加 |

测试：`tests/instance.test.ts` 核对 `TRUST_PROXY` 的读法、信任代理时登录记下真实来源 IP 与 Cookie 加 Secure；`tests/admin-v060.test.ts` 核对响应头。

### 2.3 正式服放阿里云以后要改善的

**正式服接真实业务之前必须做的：**

1. **门店外网断了前台就停。** 原来正式服放门店，就是为了外网断了局域网照常收银（ROADMAP 第 6 节）。现在正式服在云上，要做三件事：
   - 门店宽带加 4G / 5G 自动切换，并实测一次；
   - 预编号的纸质应急单照旧（ROADMAP 第 9 节），恢复后用「补录纸质单」按实际时间补录；
   - 值班经理会切线路、会用纸质单。
2. **前台终端怎么连正式服。** 备案前正式服不对公网开放：安全组关掉全部入站，SSH 也走 Tailscale。两种连法：
   - 前台电脑、iPad 各自装 Tailscale；
   - 或者门店 Mac mini 做 Tailscale 子网路由，门店局域网经它连到正式服。
3. **门店的网口打印机。** 小票机是服务端直接连打印机的 9100 端口（RQ-001），云上的正式服连不到门店局域网。要让 Mac mini 做 Tailscale 子网路由，广播门店网段，阿里云服务器接受这条路由。以后也可以改成由门店的终端转发打印，另排。
4. **备份放哪。** 正式服每小时的备份写在同一台云服务器上，服务器坏了备份会一起没。要做三件事：
   - 异地副本改传到门店 Mac mini：`.env` 的 `OFFSITE_TARGET` 指 Mac mini 的备份账号，经 Tailscale；
   - 照旧加密传阿里云 OSS，并开云盘自动快照；
   - 恢复演练与冷备都在 Mac mini 上做。
5. **正式服用哪台机器。** 建议单独一台，不和演练库、演示库同机；原来的规划是 4 vCPU / 8 GB、开云盘快照。要是用原来测试服 A 那台，先把上面的演练库、演示库撤掉、备份归档，再装正式库（演示库的登录页显示演示账号密码）。

**对公网开放之前（ICP 备案以后）做的：**

6. **ICP 备案**由店主办，一般两三周。备案之前正式服只经 Tailscale。
7. **Caddy 做 HTTPS 反向代理**：原样透传 Host（写操作的同源校验比 Origin 与 Host），加 HSTS。正式服 `.env` 设 `COOKIE_SECURE=true`、`TRUST_PROXY=127.0.0.1`、`APP_BIND=127.0.0.1`；安全组只开 443（80 只用来跳转和签证书）。
8. **登录限次按来源 IP。** 现在只按账号在内存里计数（同一账号 15 分钟错 5 次锁 5 分钟）。放到公网以后，别人能反复把店主账号锁住，换着账号试也没有按 IP 的上限。建议 8.0.1 改，规则要店主定（Z4）。
9. **管理后台、ERP 要不要只在店里和 Tailscale 内打开**，公网只给前台用得到的页面（Z5）。

**员工食堂、小程序：**

10. **员工食堂的局域网用法（K18）。** 正式服不在门店局域网里了：
    - 备案前：员工连店里 Wi-Fi，经 Mac mini 转发到正式服的员工端口（Mac mini 上一个反向代理：局域网 8090 → Tailscale → 阿里云，正式服的 `CANTEEN_TRUST_PROXY` 设 Mac mini 的 Tailscale 地址），员工入口地址填 `http://<Mac mini 局域网 IP>:8090`；
    - 备案后：直接用 `https://staff.<域名>`。
11. **小程序网关。** 原定单独一台阿里云最低配，经 Tailscale 只连 yuzu 的小程序端口。正式服也在阿里云以后，网关可以和正式服同机，也可以放同一个专有网络（Z3）。小程序端口照旧不对公网开放。

**其他：**

12. 门店现有试用实例（`trial`）照原定停用、不转正；Mac mini 改做测试服前先备份归档。
13. 看门狗与企业微信告警（`scripts/watchdog.sh`）在正式服上照样配，再加阿里云的云监控告警。
14. CI 用的 `actions/checkout@v4` 等跑在 Node 20 上，GitHub 已在强制换 Node 24（现在只是警告），以后升到 v5。
